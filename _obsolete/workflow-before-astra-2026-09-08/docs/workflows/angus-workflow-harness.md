# Angus 工作流：结果与证据优先

2026-09-07 按用户 A358 授权精简。流程帮助完成任务，不取代判断；不要为满足流程而增加未请求的工作。

## 目标与自主边界

先判断本轮要回答什么、交付什么、可以改变什么。任务清楚时直接执行到该范围的完成条件；使用合理假设并说明关键影响。当前明确授权可以修订历史设计方法，但不能覆盖系统安全边界、未授权外部操作和游戏规则真源。

缺少关键资产先尝试修正路径或寻找已登记副本；仍无法看到就说明限制。不从文件名猜图像，也不因无关资料未读完而停工。

## 按后果确定验证强度

| 情形 | 默认做法 |
| --- | --- |
| 解释、单点建议、小文本修订 | 直接回答或修改，针对性检查 |
| 风格探索、生图、隔离 mock | 看实际参考和产物，验证本轮想判断的效果；不是天然高风险 |
| 布局/交互重构、代表性装配 | 核验真实内容与核心操作，重要变化做独立 UI/UX 交叉检查 |
| 正式替换、跨系统变化、批量资产 | 合同/消费者、受影响状态、运行证据与回退路径 |
| 删除、外部发布、不可逆/授权外操作 | 确认精确目标及所需权限，不借“继续”扩大范围 |

`workflow-gates.yml` 描述可机器读取的产物和条件，不能只因出现“生图/世界地图”词就触发全部生产检查。Godot、GUI 崩溃、Git 交接使用各自已有专门验证，仅在实际触及时执行。

## 精简协作与输出

复杂任务可以用范围便笺，长期资产线更新现有状态页；普通任务不强制 Router Card 或 Delivery Manifest。用户界面输出自然语言：结果、必要视觉证据、重要改动与遗留问题。只有确实需要决策时清楚说明选项和后果；不固定三行格式或报告条数。

委派具体独立问题，明确证据与写权限。父级承担整合责任，可逆设计分歧自行判断；只把关键偏好、玩法语义、新权限或不可逆代价交给用户。详细角色范围见 `../onboarding/subagent-collaboration-improvement.md`。

## 验证与停止

检查受改动影响的断言、状态和直接消费者。通过且依赖未变化的证据可沿用并标注来源，不为了“全面”重复跑同一套检查。文档/技能修改不触发游戏截图或 Godot 全量 smoke；修改运行场景则不能以文档检查代替运行验证。

没有证据就不声称通过；自动检查通过也不等于审美通过。完成用户请求后交付，不自发开启下一阶段、下一批付费生成或正式接入。

## 失败之后改变方法

重复返工、范围/证据误判或用户明确要求复盘时，用现有记录写清原因、方法变化、验证结果。一次反馈不自动变成永久规则；不强制失败两轮后停工等用户重写需求，也不重复同一失败方法消耗资源。

有安全且在范围内的替代方法就尝试；需要新权限、缺少不能推断的关键选择或工具不可用而无等价路径时说明阻断。用户说“不改文件/先别落地”首先是范围指令，不是自动要求写一份复盘文件。

## 规则维护

每类规则只在所属真源维护，模板引用而不重复全部规程。新增硬门槛应有具体失败机制、适用范围和可执行检查；经验数字未在目标尺度验证前只是起点。定期删除失效、重复或只服务历史页面的门槛，不以历史编号数量衡量成熟度。
