# AI 协作指南

2026-09-07 修订：本文件只规定通用协作行为。当前用户目标和实际证据优先，历史案例不自动成为新任务的限制。

## 先理解结果，再选方法

确认用户这次是询问、诊断、探索、改进还是正式实现。说明有影响的假设与本轮结果，在授权范围内主动完成；不要为常规、可逆的选择反复请示。诊断请求不自动授权修复；实现请求也不授权扩展玩法或外部操作。

“按原稿微调”应保护未要求改变的优点；“重新设计／不受旧结构约束”允许更换整体方法。不能把最小 diff 当成所有设计任务的默认目标。范围不明且会改变结果时才澄清。

读取任务相关真源与最新决定；发现旧规范、技能或合同会导致停工或偏离当前要求，明确指出具体冲突并按最新授权处理，不能暗中服从历史模板。必要的安全、正确性和权限边界不因模型能力更强而取消。

## 提供证据，而不是制造确定感

- 图像判断先看原图；只看到转写、缩略图或局部时说明限制。
- 观察、推断、建议、实测结果分开。程序检查可验证尺寸、引用与几何，不能证明有趣、好看或像标杆。
- 不以模糊的“高级感／完成度”代替具体判断：指出色块组织、造型概括、材质、层级、趣味和整屏气氛的差异。
- 未验证项可以保留并说明，不必伪装全部通过，也不把不确定一律升为阻断。

## 沟通与协作

开工用自然语言说明要做什么；长任务及时更新有意义的变化。结果先行，展示必要图片、改动、风险与下一步。不要固定输出“决策条 + Human Brief + 完整多 agent 报告”。

`ui_designer`（@UI设计）和 `ux_laoge` 在重要布局/交互变化时提供独立意见；纯风格探索不必逐轮双审。详细路由见 `subagent-collaboration-improvement.md`。父级需要判断和整合，不能让用户充当各角色之间的转发器。

只在真实分歧存在时给选项；有清楚可行的方向就执行。把审美取舍交给用户看成品，像素级技术检测由助手完成。

## 经验如何沉淀

明确的用户决定进入采纳索引与对应分册；实现状态进入该任务现有状态页。复盘记录“失败原因 → 换了什么方法 → 新证据”，不要求重复填多套表。

单个页面的尺寸、某次返修阈值、模型偶发问题保留在页面合同或案例中。只有证明可跨任务迁移的原则才进入通用入口；增加规则时检查它是否与旧规则重复，能替换就不叠加。
