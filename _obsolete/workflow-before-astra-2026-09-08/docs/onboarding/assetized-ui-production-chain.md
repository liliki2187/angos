# UI 资产链：先成立，再装配，最后扩产

2026-09-07 修订。目标是把标杆中的美术表现可靠地带到可用游戏界面，不是完成固定十二步表格。按本次任务需要进入下面的工作，不要求每轮走完整条链。

## 1. 先让整体效果成立

适合风格探索、整体重构、配色变体、视觉目标。

直接看原始标杆、用户选定稿与当前实际效果，明确各参考图负责的维度。提炼大形、色彩关系、细节密度、材质与趣味，而不是复制旧组件模板。先做能回答主要审美问题的整屏或区域效果；用户要生图就用真实生成工具。

本阶段可以只保留大致功能职责，不必先冻结 exact rect、所有字号、atlas 或整个组件库存。已确认“不许改变”的内容继续保护；正在探索的结构不要假称已兼容旧实现。纯风格稿、真实内容概念稿与运行截图明确区分。

同一方案的配色变体应保护用户要求不变的构图/内容；颜色比较先看角色分工、明度层级和冷暖关系，不先用统一色差阈值否决风格方向。

## 2. 尽早证明关键部分可以真实装配

整体方向有依据后，选最能暴露风险的代表区域或整屏纵向切片，放入真实图片和有代表性的最大内容，验证：

- 内容数据如何进入，文字如何排版，图片怎样复用而不拉伸/任意裁切；
- 动态文字与美术底板是否真正对准，状态是否共享稳定结构；
- 展开、锁定、选择、主要操作及回流能否正确表达；
- 大块面、纸物件关系、色彩和趣味在真实显示尺寸下是否保留。

可以为了排除技术风险提前做隔离的 HTML/Godot 小实验，不代表正式接入或美术通过。不必先造全页黑白线框或冻结所有组件才能验证一个高风险点；也不要批量做完所有素材后才第一次填入真实文字。

依结果选择拆层方式：背景/独立装饰可用位图；动态文字、数据与交互通常由运行时承载；复杂可复用壳体有需要再做九宫格、独立透明件或固定母版。整图作预览底图可以，但不能冒充可复用组件。

## 3. 在已验证方向上扩产与集成

批量生产前，记录实际要复用的组件身份、尺寸/适配、层级归属、可写区、热区、状态、内容来源与允许烘焙项。合同应来自真实装配发现的问题，不是任意数字的堆积；变更合同要迁移其实际消费者。

先用代表件验证缩放、alpha 边缘、字体、状态及运行接线，再按相同规律扩展。不固定“每轮一件”或“全部件一起出”的产能规则；按重复性、风险和当前授权组织批次。

进入正式运行界面前，检查受影响的真实状态、长内容、输入反馈、场景加载与资源引用，提供真实截图；动态问题提供视频或动图。atlas、manifest 等仅在实际交付格式需要时制作，不能因做过技术样本就自动宣告正式生产冻结。

## 4. 不可互相替代的证据

| 证据 | 能回答 | 不能代替 |
| --- | --- | --- |
| 风格稿/生图 | 构图、色彩、材质、情绪、吸引力 | 字体与交互运行验证、复用合同 |
| 真实内容合成 | 图文归属、容量与组合效果 | 实际热区、数据和事件接线 |
| 隔离运行切片 | 所覆盖状态的装配与交互可行性 | 全屏美术通过、未覆盖流程 |
| 正式运行截图/动态 | 实际实现的视觉与反馈 | 未测试状态、用户视觉认可 |
| 自动检测 | 尺寸、比例、路径、具体断言 | 好看、有趣、符合标杆 |

技术通过而美术不成立，不能扩成美术母本；局部漂亮但整屏割裂，也不能升为整屏目标。用户确认审美方向不等于所有工程项通过。

## 5. 最少而足够的记录

复用已有任务状态页，记录当前目标稿、实际产物身份、已验证/未验证、最新决定和下一步即可。复杂交接可用 `../workflows/templates/delivery-manifest.md`；无需每轮新建 Router、Manifest、报告、合同、复盘五份文档。

ChatGPT 画布等可选侧车用于讨论和对比，不是额外审批阶段，也不替代仓库真源或运行证据；采纳后同步实际责任文件即可，不强制填写整套侧车协议。

现有项目合同仍约束使用它的运行资产。历史页面的阶段号、B2 专项阈值和失败次数不再是新设计的通用前置门槛。原流程快照仅供审计；风险和委派规则分别见工作流说明与协作说明。
