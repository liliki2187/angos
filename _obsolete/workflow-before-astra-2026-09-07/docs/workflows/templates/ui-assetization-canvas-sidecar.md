# 资产化 UI：ChatGPT 画布侧车卡（试行）

> **用途**：把画布限制成“一页、一个问题”的临时工作台，帮助合同推演或证据对照；不新增资产化阶段、产物类型或真源。
> **适用**：桌面 16:9 的 Angus UI 资产化任务。
> **不适用**：正式生图、切图、atlas / manifest 制作、Godot / HTML 装配、运行截图生成。

## 2. 合同工作台开场词（阶段 0-4）

```text
你正在协助 Angus 的桌面 16:9 资产化 UI 合同推演。
本画布只回答一个问题：【填写问题】。
当前产物类型是：【从 workflow-gates.yml 选择一种】。
只使用我提供的真源路径与真实字段快照；缺失内容标“未知”，不要自造运行数据。
最多展示 2-3 个必要状态或方案，优先检查功能分区、容量、最长文案、状态差异、组件比例和整屏回填。
结尾必须分开写：能证明什么、不能证明什么、建议裁决、需要回写的仓库文件。
不要声称美术通过、可切图、生产资产或 Godot 运行通过。
```

## 3. 评审工作台开场词（阶段 7、10-11）

```text
你正在协助 Angus 的桌面 16:9 资产化 UI 证据对照。
本画布只回答一个问题：【填写问题】。
当前产物类型是：【filled_state_text_mock / runtime_state_preview / production_candidate 中与本轮相符的一种】。
只并排组织我提供的目标稿、真实内容预览、真实 Godot / HTML 截图和关键局部；不要重画、补生成或伪造缺失证据。
逐项标明每张图的来源、状态、它能证明与不能证明什么，并记录用户裁决：通过 / 调整 / 否决 / 未决。
结尾列出需要回写的仓库文件和下一步允许 / 禁止执行的动作。
画布预览、导出图和文字总结都不能冒充运行截图或生产真源。
```

- **未回写及原因**：
- **`repo_sync`**：完成 / 未完成。
- **下一步允许做**：
- **下一步禁止跳到**：
- **侧车状态**：`closed` / `retired` / `open`。

只有 `repo_sync=完成` 且侧车状态为 `closed` 或 `retired`，已采纳结论才可进入下游。画布不会自动读取或修改仓库；仓库中的 GDD、合同 JSON、manifest、代码、STATUS 与设计采纳记录仍分别承担正式真源。
