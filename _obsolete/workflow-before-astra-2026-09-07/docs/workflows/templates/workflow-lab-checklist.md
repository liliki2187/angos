## 建议实验类型

### 1. 产物类型判定实验

- 抽取 5-10 个近期截图 / 稿件。
- 标注每个产物类型。
- 写明它能证明和不能证明什么。
- 通过标准：能主动降级至少一个不合格产物。

### 2. 阶段跳转实验

- 给定当前阶段，例如 `no_text_style_draft`。
- 输出合法下一步和禁止下一步。
- 通过标准：不把 `atlas / manifest / 切图` 放到过早阶段。

### 3. Agent 调用预算实验

- 同一任务分别按 tiny / normal / risky / production 跑 Router Card。
- 通过标准：tiny 不开大会，risky 不漏关键 agent。

### 4. 截图验收实验

- 对同一截图做整屏、局部裁切和反向读法。
- 通过标准：能发现整屏观感掩盖的局部问题。

### 5. 沉淀分层实验

- 选取用户纠错案例。
- 判断进入 casebook、patterns、design-decisions、onboarding hard rule 或暂不沉淀。
- 通过标准：不会把所有案例直接升级为顶层硬规则。

### 6. 第一屏可读性实验

- 同一任务先输出三行决策条，再输出 Human Brief 和 Router / Manifest / gate 术语版。
- 决策条必须只回答：结论、影响、下一步。
- 通过标准：用户只读前三行，也能判断当前是否通过、会挡住什么、下一轮要让 AI 做什么。
- 失败标准：第一屏超过三行，或出现 checklist、agent / gate 名称、阶段标签，用户仍需要追问“所以这是什么意思”。

### 7. 格式不过度泛化实验

- 同一批任务混入普通解释、完成汇报、进度更新、workflow gate 和 Loop Log。
- 每条先判定回复模式，再决定是否使用决策条。
- 通过标准：只有判断、卡住、返工、需要裁决的回复使用决策条；普通回答像正常对话，不套模板。
- 失败标准：所有回复都变成 `结论 / 影响 / 下一步`，导致日常沟通生硬、可读性下降。

### 8. 风格稿组件倾斜拦截实验

- 抽取 5-10 张近期世界地图 / 地区任务台 / 派遣签批台风格稿，包含至少 2 张已知信息面倾斜失败样本。
- 对每张图裁切核心信息面：左侧任务卡、右侧票据 / dossier、CTA 文本槽、按钮底板、底部票据、头像 / 状态槽。
- 在裁切图上画水平 / 垂直参考线，判断每个承载动态内容的正面是否近似 0 度。
- 通过标准：能主动把任一可写纸面、CTA 或任务卡内框倾斜的图降级为灵感图 / 偏差案例，而不是继续标为真实内容风格稿或生产候选。
- 失败标准：只看整屏观感、只说“整体方正”，没有局部裁切或参考线；或者把斜切装饰误当成可写正面通过。
