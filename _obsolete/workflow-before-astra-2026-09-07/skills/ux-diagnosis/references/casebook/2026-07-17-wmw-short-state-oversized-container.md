# WMW 短状态使用过大容器

- **场景**：WMW 世界地图整屏已确定三栏与组件形式，但两条只读世界状态使用完整大纸卡，A5.1 下方又用大面积无交互文件袋收口。
- **调用**：现有 UI 改进，先由 UX 老哥做容器审计，再由 UI Designer 出精确结构稿。
- **判断**：问题不是缺功能，而是信息量 / 容器量失配。短状态大卡会被误读为可点击二级任务；纯装饰大面会被误读为隐藏面板。
- **用户反馈**：整体方向大致正确，但回执只需下方一小条，进入地区 CTA 下方空白区域明显过大。
- **可迁移规则**：资产化 UI 不仅检查“能否装下”，还要反向检查“是否装得过空”。已有 frozen 类与新职责密度不匹配时，新建 compact variant，不能直接拉扁或因形式已确定而原样复用。`NO_TEXT / NO_HIT` 物件仍需限制前景面积与边框重量。
- **不升级原因**：项目级防线已同步到 workflow gate 与 harness；该文件只保留 WMW 具体案例。

## 同日复发：空容器被改成空背景

- **复发现象**：第二轮把左下日程器从 246px 压到 182px，底部露出 64px；把右下 231px 文件袋改为 62px 浅袋口，下面露出 169px 无框背景。结构稿还主动标注 `UNFRAMED BREATH / WORLD BACKGROUND / NO TEXT / NO HIT`。
- **用户纠正**：用户明确指出左下和右下仍有大片空白，结构显然不合理。
- **判断补充**：删掉错误容器只是第一步。若同等面积没有转交给真实职责，而只是改名为呼吸区或背景，问题仍然存在。左栏应恢复完整日程链，右栏应由既有地区任务情报与底锚 CTA 组成全高档案变体。
- **新增防线**：有界栏位必须检查“最后一个真实职责到栏底的距离”和“空余面积的所有权”。超过正常安全边距且没有职责归属时，不能通过结构 Gate。

## 同日第三层复核：压小后仍是重复信息

- **复发现象**：v3 已把回执压为两条 450×90，但用户追问它们“有什么用”。核对后发现红线重复左下推进后果与右侧限时任务，深链重复右侧任务类型；两组七格还暗示不存在的按日同步推进。
- **用户授权**：用户同意尝试删除，或重新思考该区域的真实职责。
- **判断补充**：组件通过体量审计不代表通过信息架构审计。常驻模块必须独占回答一个玩家问题；否则应删除。只有真实推进 / 结算差量才适合作为条件覆盖回执，当前值和计数不能伪装成“最近变化”。
- **新增防线**：在 container-volume 之后增加 unique-player-question；默认布局不得为了填满保留重复状态。
