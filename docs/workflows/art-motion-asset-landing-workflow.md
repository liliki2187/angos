# 美术资源 / 动效资产落地工作流试行版

状态：experimental v0.2
首个样例：3D 骰子框内物理感动效，见 `docs/screenshots/2026-07-03-dice-3d-v7-prototype/`。  
适用对象：3D 骰子、UI 动效、2D 角色动作、特效、单件美术资源、可交互美术小组件。  
不替代：成熟的资产化 UI 工作流；涉及完整界面仍按 UI 资产化链路与对应 UI/UX 规则执行。

核心硬规则：凡需要审核动态效果，交付物必须包含真实动图或视频（GIF / animated WebP / MP4 / WebM 之一，或等价本地可播放页）。截图只能作为关键帧补充，不能替代动态演示。

第二硬规则：程序动效 blockout 不能冒充美术资源落地。如果用户要求 Image 生成骰面、2D 动作帧、UI 动效帧、道具贴图、模型材质或其它可见美术资产，交付前必须提供源图 / atlas / GLB / 帧序列等资源文件、切分或绑定产物、引擎内真实运行截图，以及 GIF / 视频。只有程序色块、临时材质、Label、SVG / Canvas / GDScript 绘图时，只能标为 `motion_blockout`。

第三硬规则：先验对象几何不变量，再进切图和 runtime。方形骰面、方形 icon、头像、动作帧、特效帧或规则 atlas，必须先确认源图比例、网格单格比例、pivot、裁切边界和允许透明留白。以骰面为例：单面源图必须是 1:1；4x3 atlas 的总画布必须是 4:3；把长方形 cell 后处理压成方形不能算通过。

几何不变量、功能面正交阈值与文字安全区的统一定义以 [`ui-geometry-and-text-safety-gates.md`](./ui-geometry-and-text-safety-gates.md) 为公共真源；本文件涉及这些规则时按该文档执行，不另行维护副本。资产一旦承载规则文字（如骰面属性字、点数、警示符号），文字安全区规则同样适用。

## 1. 为什么需要新链路

资产化 UI 的成熟链路是：

`结构/功能合同 -> 无字图 -> content_rects/no_text_rects/hit_rects -> 真实内容回填 -> runtime 截图 QA`

美术资源和动效不是同一种问题。它们的关键合同通常不是文本安全区，而是：

- 物体是否有体积、轴心、接触点和材质方向；
- 动作是否有起势、主动作、接触、余波、落定；
- 运动是否被限制在目标槽位内；
- 最终可读面、关键姿态或角色情绪是否成立；
- 资源是否能被引擎复用，而不是只是一张好看的图。

所以美术 / 动效资产应采用：

`意图合同 -> motion/art blockout -> bitmap/model asset pass -> runtime cell preview -> 状态矩阵 -> production candidate`

## 2. 产物分级

### 2.1 `motion_blockout`

用途：验证动作节奏、空间范围、锚点、接触感、是否打断玩家阅读。  
可以很丑，可以用临时材质和临时模型。  
必须真实运行或至少真实截图，不只给曲线描述。

允许用户判断：

- 这个动效有没有表达出“发生了什么”；
- 位移是否太大、太小、太乱；
- 起势、冲击、余波、落定是否清楚；
- 多个对象同时动时是否抢戏。

禁止用户在此阶段判断：

- 最终材质是否漂亮；
- 字体 / 贴图 / UV 是否最终；
- 角色 UI 布局是否最终；
- 这个资产是否能进生产。

给用户看的最低标准：

- 1 个短动态图，优先 GIF / animated WebP / MP4，能看出起势、主动作、冲击、回弹和停顿；
- 3-6 张关键帧截图，覆盖静止、主动作、接触、落定；
- 明确标注这是 `motion_blockout`；
- 说明“本轮能判断什么 / 不能判断什么”；
- 自检确认没有明显越界、空白、崩溃或完全看不懂的帧。

### 2.2 `asset_read_proof`

用途：验证模型、轮廓、比例、材质大方向、体积感。  
对于 3D 骰子，就是看它是否真像一个可玩的实体骰，而不是发光卡片、折纸、塑料块或 UI 图标。

允许用户判断：

- 第一眼是否像目标物；
- 体积、倒角、边缘、材质是否接近 Angus；
- 和同组资产是否同一家族；
- 是否值得进入贴图 / atlas / 动效细化。

禁止声称：

- 六面贴图方向已锁；
- runtime 全状态已可用；
- 已能替换正式资产。

### 2.3 `atlas_or_rig_contract`

用途：验证资源如何被引擎稳定复用。  
静态 / 3D 资产看 atlas、UV、材质槽、pivot、命名；2D 角色动作看骨骼、插槽、帧序列、动作命名；特效看粒子参数和触发点。

必须回答：

- 哪些层是美术层，哪些层是运行时动态层；
- 哪些内容可替换，哪些内容不可替换；
- 哪些状态必须覆盖；
- 最终 QA 看截图、视频、还是状态矩阵。

如果上一阶段只有程序色块或临时材质，本阶段不能直接跳过。必须至少补齐一项真实资产来源：Image 生成图集并切成 tile、模型 / GLB、Sprite 帧序列、材质贴图、骨骼 rig 或粒子贴图；否则仍停留在 `motion_blockout`。

几何检查必须发生在切图前。推荐先用 `scripts/validate_image_asset_contract.py` 检查单图方形或 atlas 网格单格比例，再执行裁切脚本；如果源图失败，不能靠重采样、拉伸 plane、调 UV 或运行时缩放进入下一阶段。

### 2.4 `runtime_cell_preview`

用途：把资源放回真实目标槽位，只验证局部承载，不重做整页 UI。  
对于骰子，就是放进角色框体；对于 2D 角色动作，就是放回角色卡或事件舞台；对于 UI 动效，就是放回实际按钮 / 卡牌 / 弹窗槽。

允许用户判断：

- 资源在真实尺寸下是否仍然成立；
- 是否抢主流程视线；
- 是否遮挡文字、头像、状态、按钮；
- 是否和 UI 承载物同调。

禁止跳到：

- 全页面重构；
- 全状态上线；
- 未经矩阵验证的 production candidate。

### 2.5 `production_candidate`

用途：准备进入正式资源替换或主流程接入。  
必须至少具备：

- 资源文件或生成脚本稳定；
- 状态 / 动作 / 贴图矩阵明确；
- 真实 runtime 截图或录屏；
- 已知缺陷列表；
- 替换范围清楚；
- 不会顺手改变正式 UI 结构。

## 3. 什么时候给 Angus 看

应该给用户看的时机：

- `motion_blockout` 已经能回答一个核心问题，例如“框内是否仍有物理感”；
- 同一问题至少有 2-3 个关键帧，而不是单张偶然好看的图；
- 自检能明确说出“本轮不要判断什么”；
- 继续往下做会增加返工成本，例如开始做贴图、GLB、骨骼、atlas、正式接入之前。

不应该给用户看的时机：

- 画面空白、崩溃、明显越界，还没有排除技术错误；
- 只有一张静态图，却要求用户判断动效；
- 只有好看的材质图，却要求用户判断能否进引擎；
- 还没说清产物类型，容易被误认为正式候选；
- 为了展示动效而改了正式 UI 布局。

## 4. 3D 骰子试点规则

当前目标不是做真实桌面物理骰，也不是展示独立 3D 舞台，而是做“2D 界面承载的俯视 / 斜俯视 3D 判定骰子”。
参考方向更接近《苏丹的游戏》式桌面 UI 中的判定盘 / 卡槽物件：界面主体仍是 2D，骰子只是嵌在判定槽中的 3D 读感资产。

### 必须保留的物理信号

- 重量：起跳前轻压，落地时影子加深；
- 翻转：短时间内有明确 3D 轴向变化；
- 接触：有触地帧、压缩感、阴影贴地；
- 余波：小反弹或轻微摆动；
- 结果落定：最终结果面回到可读状态。

### 必须限制的空间

- 骰子中心位移控制在角色框体宽度的约 15%-25%；
- 快翻时允许局部接近边界，但不能离开角色框；
- 多颗骰子同时动时可以错开 40-90ms，避免机械同步；
- 最终落点必须回到角色槽内的稳定位置。

### 当前 v7.3 / v7.4 / v7.5 样例结论

v7.3 产物类型：`motion_blockout`。它验证了框内运动、起跳、快翻、接触阴影和落定节奏，但问题是过于像独立 3D 场景，不够像实际游戏中的 2D UI 判定槽。

v7.4 产物类型：`ui_carrier_motion_blockout`。它把斜俯视 3D 骰子放回 2D 判定盘 / 角色槽承载中，优先验证 2D 界面尺度、俯视 3D 读感、槽内约束和最终结果可读性。

v7.5 产物类型：`runtime_cell_preview_v0`。它把骰子放进带任务目标、角色槽、结果预览和提交操作的局部判定弹窗中，优先验证真实信息压力下的骰子可读性、主操作不被抢占、结果停顿是否足够明确。

v0.7 产物类型：`bitmap_face_runtime_preview`。它补齐了 v0.6 的流程缺口：用 Image 生成无字骰面图集，切出 `dice_face_*` tile，贴到 Godot 3D 骰子的顶面 / 侧面，再用 Godot 导出真实运行 GIF。该层可以判断“生成美术资源是否真的进入 runtime”，但仍不验证 Blender / 正式模型精度、正式 UV 展开、边角连续纹理、锁定 / 污染 / 重投全状态和正式判定弹窗包装。

2026-07-06 复盘修订：v0.7 源 atlas 未通过几何不变量 Gate。源图是 `1254x1254`，但按 4x3 切分后单格约为 `313.5x418`，不是方形骰面。后续导出的 `512x512` tile 是重采样结果，只能证明 runtime 贴图链路可行，不能证明骰面资产规格成立。v0.7 必须降级为失败案例，下一轮应重新生成单张方形骰面或真实 4:3 atlas。

2026-07-07 复盘修订：v0.11 简化骰面进入 Godot 后，用户指出顶面和侧面交界仍能看到像空洞一样的缝隙。成因是运行时把骰面作为 6 张独立 decal / plane 贴在圆角 cube 外面，为避免 z-fighting 又把贴片内缩，导致贴片之间露出底壳；即使把面片放大，两个贴片自带的暗边框叠加后也会读成黑缝。后续 3D 骰子不得把“独立贴片 + 露底壳”称为封闭骰体通过。`runtime_cell_preview` 最低要求是：相邻骰面交界必须读作实体倒角 / 连续边带 / UV 接缝，而不是空缝、黑洞、透明线或两张卡片拼在一起。临时预览可用覆盖到边缘的 face cap + 实体 edge band 消除空缝；生产候选必须进一步使用正式 UV 展开、GLB / Blender 模型或等价连续材质方案，并裁切检查顶-侧、侧-侧、角点三类接缝。

2026-07-07 v0.12 产物类型：`glb_uv_runtime_preview`。本轮用脚本生成可被 Blender 打开的 GLB、3x2 方形骰面 UV atlas、封闭倒角 mesh，并在 Godot runtime 中替代独立贴片，验证顶 / 侧接缝不再读为空缝。由于本机没有 Blender，本轮不是 Blender-authored `.blend`，也不是最终美术师精修模型；它只证明“封闭 GLB + 正式 UV 承载 + Godot 运行预览”这条落地链路可行。

2026-07-07 v0.13 产物类型：`glb_uv_runtime_preview + text_safe_contract`。本轮修正 v0.12 顶面信息挤压问题：标题、数值徽章和图案水印必须各有独立安全区，不能因为避开图案而把汉字和点数叠在一起。对小尺寸 3D 骰子，图案默认是低优先级水印；规则信息（属性汉字、点数、黑骰符号）由可控文字层 / atlas 层承担，并在 Godot 真实运行截图和 GIF 中验证。若三者同时出现但没有 `title_rect / value_rect / watermark_rect` 或等价 manifest 字段，本轮不得进入 production candidate。

2026-07-07 v0.14 产物类型：`glb_uv_runtime_preview + number_priority_contract`。本轮修正 v0.13 后续反馈中的数字权重问题：在游戏真实视角下，点数 / 异常符号属于玩法信息，必须比图标水印更大、更亮、更稳定。图标只做小面积低透明度水印，不能为了保留图案而压缩 `+2` 或黑骰警示符号。后续小尺寸骰面默认验收顺序为：先看顶面属性和数值是否能读，再看图标是否提供风格联想，最后才看装饰纹理是否丰富。

2026-07-07 v0.17 口径修订：用户确认常态小尺寸骰面暂时直接不要图像 / 图标，只保留属性名和点数 / 异常符号。后续骰子动效验证不得继续把角落小章、水印、边角半露图案作为常态骰面默认项；它们只能作为 hover、放大详情、结算截图、教程说明或宣传图的可选层。下一轮 `runtime_cell_preview` 重点改为验证 `理性 +2` 等两层信息在 3D 斜俯视、小尺寸、运动停顿中的松弛排版与可读性。

未通过 / 未验证项：最终模型精修、正式 UV 展开、中文动态文字的贴图化 / 字形 atlas、正式角色判定弹窗接入、苏丹式或 Angus 正式装饰风格、完整交互状态矩阵。
下一步合法阶段：单张方形骰面图资产迭代、`atlas_or_rig_contract`、Blender / GLB 模型 pass，或接入真实判定弹窗状态矩阵。
禁止直接跳到：正式弹窗替换、生产候选、全状态上线。

## 5. 可复用到其他资产

### UI 动效

先做 `motion_blockout`：只看按钮、卡片、纸条、印章、弹窗的起势和反馈。  
过关后再进入材质、粒子、音效和正式接入。

### 2D 角色动作

先做 3-5 个关键姿态：idle、anticipation、action、impact、settle。  
不要一开始就做完整表情包或全方向动作。  
角色动作必须先验证“在真实角色卡尺寸下是否看得出情绪 / 行为”。

### 特效

先做触发点和时长 blockout：出现位置、持续时间、遮挡范围、消散方向。  
不要先追求漂亮粒子；先确认它不遮挡关键文字和按钮。

## 6. 最小交付模板

每次美术 / 动效中间版给用户看时，至少说明：

```text
产物类型：
本轮验证：
本轮不验证：
截图 / 录屏：
通过项：
未通过项：
下一步允许：
禁止跳到：
```

这套模板的目的不是增加流程感，而是保护中间版本：让丑稿能被正确评价，也让看起来不错的草稿不会被误当成生产资产。
