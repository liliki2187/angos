# 几何与文字安全公共 Gate 真源

> **用途**：UI 资产化链路（`docs/onboarding/assetized-ui-production-chain.md`）与美术 / 动效资产链路（`docs/workflows/art-motion-asset-landing-workflow.md`）共用的几何、正交与文字安全规则。两条链路只引用本文件，不得各自维护措辞不同的副本。
> **机器可读对应**：`docs/workflows/workflow-gates.yml` 的 `hard_gates.ui_geometry`。阈值或触发条件变更时，两处必须同步。
> **最后更新**：2026-07-10（补状态徽章标杆留白、运行时字形完整性与照片配料来源纯度 gate；合同对齐不得替代标杆视觉校准）

## 1. 几何不变量 Gate（切图 / 贴图前）

任何美术资源在进入切图、贴图、manifest、runtime 或 GIF 验收前，必须先写出对象的几何不变量并验证：

- 方形资源（骰面、方形 icon、头像 tile）源图必须 1:1；规则网格 atlas 的单格必须满足目标比例（如 4x3 骰面 atlas 必须 4:3 总画布）。
- 卡牌、票据、按钮、角色帧、地图 pin、特效帧必须先声明目标比例、pivot、裁切边界和是否允许透明留白。
- 源图比例错误时，不得靠重采样、拉伸 plane、调 UV 或运行时缩放伪装通过；失败图只能归档为偏差案例。
- 检查入口：`scripts/validate_image_asset_contract.py`（单图方形 / 网格单格比例）、`scripts/ui-contracts/validate_class_contract.py`（class 合同一致性与回填边界）。

## 2. 功能面正交 Gate（ui_geometry_gate）

### 2.1 核心规则

- 承载动态文字、按钮文案、状态、数值、头像或 hit rect 的 UI 正面必须 square-on、axis-aligned、可测量；默认容忍倾斜不超过 **1 度**。
- 斜切、透视、折角、夹子、叠纸、票据舌片、阴影只能进入背景 / 外轮廓 / `no_text_rects`，不得进入 `content_rects` / `hit_rects`。
- 风格稿中任一核心信息面倾斜，降级为灵感图 / 偏差案例，不得称为 `filled_state_text_mock`、`no_text_asset_master` 或 `production_candidate`。
- Prompt 必须写一票否决句：`front writable paper faces are square-on and axis-aligned; no tilted/skewed/perspective writable document faces; angled sheets are background decoration only`。

### 2.2 自动触发（不等用户提醒）

当本轮交付或评审对象是资产化 UI 风格稿、生图稿、有字 mock、无字资产母版、运行预览或生产候选，且画面存在动态文字、CTA、hit rect、头像状态、数值、任务卡、票据、dossier、纸面或地图 pin 标签时，父级 Codex 必须主动触发本 gate。凡要宣称“正交通过 / 可继续拆资产 / 可进 manifest / 可进 runtime / 可作为生产候选 / 视觉验收通过”，必须附证据；没有证据只能写“几何未验证”。

不强制触发：纯文字讨论、低保真结构线框且不声称视觉通过、无动态内容或 hit rect 的纯装饰图、只复述已有验收结论。

### 2.3 最低证据

- 至少裁切 3 个核心信息面；存在右侧 dossier / 票据、任务卡 / 列表项、CTA / 按钮底板、底部状态票据或主文字纸面时优先裁切这些区域。
- 每张裁切图有水平 / 垂直参考线，或等价角度测量说明。
- 逐项写明：该核心面通过 / 未通过；斜的是可写正面还是装饰层；几何结果允许下一步做什么、禁止跳到什么。
- 只给整屏图、没有核心组件裁切或参考线，不得宣称“正交通过”。

## 3. 双通行证：text_geometry_pass 与 art_shell_geometry_pass

- 文字层水平不等于通过。曾出现文字是正的、底层按钮框 / 纸面是斜的失败案例。
- 交付含动态文字、按钮、状态数值或 hit rect 的图时，必须同时给出：
  - `text_geometry_pass`：文字 / 安全框正交；
  - `art_shell_geometry_pass`：底层美术壳（纸面、按钮壳、文本槽、状态槽、action plate）正交。
- QA 参考线必须贴住真实 bitmap 美术边缘；安全框正而底壳斜，判定失败并退回 no-text 壳重建。

## 4. 图像等比与图槽契约

- `image_aspect_pass`：照片、缩略图、头像、证据图、地图 inset 不得非等比拉伸 / 压扁；只能等比 cover crop、等比 contain 留边，或重设组件槽比例。
- `image_slot_contract_pass`：来源于已认可标杆图 / 上一版 UI 的组件，必须保留原本配合好的图槽比例、快照构图和信息区关系；不得先改图槽宽高比，再用 cover crop 牺牲主体内容“填满”新槽。

## 5. 文字安全区通用规则

- 可写区必须从图像真实颜色模块推导（`visible_color_module_rect -> carrier_rect -> inner_rect -> glyph_bbox`），不得先画理想 safe-zone 骗过验收。
- 半调、套印、纸纹、低多边形尖角、折痕、贴纸边、阴影不得穿过动态文字区域。
- 3D / 动效资产承载规则信息时同样适用：如骰面的 `title_rect / value_rect / watermark_rect` 必须各有独立安全区，规则信息（属性字、点数、警示符号）优先级高于装饰图案。

配套规则：

- **残留扫描的执行时机**：`old_content_leftover_scan` 等颜色签名类扫描必须在**状态换色之前**执行；换色会改变残留像素的颜色签名使扫描失效（B2.5 案例）。换色后的检查只能用结构性对比（分层重建断言、配料纯度），不能用颜色签名。
- **修复判定与验证判定必须独立**：禁止用同一个颜色阈值、连通组件分类器或“保护区”同时决定“保留什么”与“是否已清干净”。二者共享判定式时会共享盲区；至少一个 gate 必须基于独立结构事实（合同 bbox / 中心、图层 provenance、源像素复用、空底盘截图）。B2.6 的清理器和 `atlas_baked_state_glyph_pixels` 共用 `is_badge_outer_ring_component`，因此同时漏掉旧靶心圆弧。
- **证据依赖顺序固定**：源失败探针 → 未叠图标的空底盘 → 状态换色底盘 → runtime 图标配料 → Python 合成 → Godot 合成。前一层未通过不得用后一层合成图遮掩；文件生成与截图非黑只证明证据可读。
- **合同证明边界**：合同校验只证明当前记录内部一致，不自动证明槽位符合已采纳标杆。视觉复审发现稳定偏差时，先量测标杆与成品，再由用户裁决“素材失败还是合同显式升版”；禁止把旧 frozen 字段当成不可质疑的美术真理，也禁止执行方擅自改合同。
- **源提取与目标装配解耦**：提取完整图标 / 装饰形状时不得先用目标槽裁源；先在宽搜索区得到完整源 bbox 与透明配料，再由目标槽负责等比装配。目标槽内无溢出不能证明源形状未被截断。
- **压平中间产物不得回流为配料源**：含上层覆盖元素或框体的 atlas / 运行截图只能用于对照，不能再裁成底层照片。即便来源文件正确，裁源 bbox 仍必须通过内容区域与边缘污染检查。
- 探针脚本参考实现：`scripts/ui-contracts/wmw/` 下打样与规程脚本；新资产线可直接复用其 gate 实现。
- 测量容差必须写明依据（如"旧 manifest fit 偏移 0-5px，故容差 ±10px"），禁止无依据阈值（教训：gate E 首版 ≤2px 拍脑袋，必然失败）。
- 判定式（如 is_photo / is_cream）必须逐帧自适应或逐样本验证后再部署，绝对颜色阈值默认只对校准样本有效（教训：单帧调参的判定式在另外三帧上全错，窗口测量偏差达 101px）。

## 5.2 人工目检清单（不可程序化项的兜底真源）

以下项目当前无法可靠程序化，交付前必须定点 200%-300% 放大目检并贴截图，缺目检不得宣称通过：

- [ ] 内容与壳的贴合处（圆弧下、各边缘）：无缝、无残带、无重影；
- [ ] **覆盖元素（徽章 / badge / 夹子）与底层内容的叠放**：无双环、无重影、无源帧错位贴片（B2.3 badge 坐标贴片双环案例）；
- [ ] **clean badge base 无语义残影**：在未叠运行时图标的 atlas / shell 中，badge 内芯不得出现旧状态符号的浅色线条、暗色圆弧、阴影、靶心、三角、锁、勾影子；先看空底盘，再看图标叠层，禁止只看最终合成图；`atlas_baked_state_glyph_pixels = 0` 不能替代本项（B2.6 selected badge 旧靶心暗色残影案例）；
- [ ] **状态徽章视觉 gutter 与字形完整性**：对照已采纳标杆检查到真实卡框唇的留白、环与内芯的光学中心、字形是否完整且四边有稳定呼吸空间；命中合同矩形不能替代本项；
- [ ] **退役足迹底板连续性**：移动 / 删除旧组件后，原足迹未被新组件覆盖的区域不得出现涂抹、模糊扩散、竖向拉丝、色带或纹理方向突变；必须能追溯到显式底板 / 边框配料；
- [ ] **覆盖图标线稿纯净**：地球等覆盖元素只显示自身线稿 / 必要抗锯齿；弧下与线稿内部不得出现第二个圆盘、月牙、旧照片快照或底盘残影；
- [ ] 同类组件横向对比：无肉眼可辨的几何 / 质感不一致；
- [ ] 合成质感：无"补丁感"（色带、突兀渐变、纹理断裂）；
- [ ] 文字与底面：像同一系统，不像默认 Label 贴图；
- [ ] 状态语义独占性：强调色（如 selected 绿）只出现在对应状态。

**目检判读口径（2026-07-09 起硬规则）**：目检结论必须**逐帧、逐检查点**写 PASS / FAIL 进 manifest，禁止写整批 "pass"。来源案例：B2.3 的 466 manifest 写"300% 目检 pass"，而三处缺陷（圆盘旧图叠层、底边残留带、badge 双环）在其自己贴出的 465 QA 板上清晰可见——目检图做了，判读却批量盖章。贴出目检截图 ≠ 目检判读正确。

**判读职权升级（2026-07-09 二次判读失误后追加，硬规则）**：B2.4 改为逐点判读后，执行方仍对"badge 内芯颜色明显错误"的检查点写了 PASS——连续第二轮判读失误，证明**执行方自检判读不可靠**。自此：

1. 每个 PASS 必须附**可核验依据**（实测数值、色相对比、与母版/标杆的具体对照说明），只写 "PASS" 无依据视为未判读；
2. 执行方自检结论只构成"证据就绪"，**不构成"通过"**；"通过"判定由复核方（父级 AI 或用户）基于 QA 板作出；
3. 能转成数值对比的目检点（如颜色一致性）必须按缺陷→gate 闭环转为程序 gate，人工目检只留真正无法量化的项。

新缺陷类型出现时，按产线文档 §7.5 缺陷→gate 闭环：当轮进上表（可程序化）或进本清单（不可程序化），二选一，不许悬空。
