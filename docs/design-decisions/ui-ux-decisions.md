### A5. 角色骰与任务入口的感知层落地
- **来源**：2026-05-08 三个界面表现层讨论。
- **机制**：前三个界面的后续落地应从“标识和说明”升级为“玩家操作真的不同”。任务配置页以“本次骰池预览”为核心，让玩家感知自己正在构建骰池；角色骰详情要采用更像骰面展开的表现方式，参考 `Slice & Dice` 中骰子六面展开的认知模型，让玩家能把角色能力直接联想到“骰子”；任务入口按真正改变操作的类型组织，降低类型标签堆叠带来的认知负担。
- **已修订（2026-05-08 · 首轮落地口径）**：首区任务入口按白色调查、红色截稿、深度链、黑骰入口组织；危险只作为任务卡与地图点上的感叹号 / 高难标记，不再和这些入口并列为任务类型。
- **已修订（2026-05-09 · 深度链地图入口交互）**：深度连续任务在地图上不再完整展示所有链路节点，也不保留灰色旧环；地图只显示当前最新任务入口。入口采用规整叠层任务页：默认态提示“多个任务合一”，hover 只轻微预展开，点击后同一组卡片展开为线性链，只显示当前环与下一条 `?` 线索。
- **已修订（2026-05-11 · 地图标签避让）**：区域地图中的任务点、线索点与可展开深度链入口需要渲染后避让机制。深度链、黑骰、高危入口优先保留原位；普通任务和线索标签让位，避免动态任务或长标题互相压盖。复查后补充：该机制必须按默认态、hover 态、点击展开态，以及宽 / 中 / 窄视口验收，避免只在单一桌面截图中看似成立。
- **已修订（2026-05-13 · 竖屏手机截图口径）**：当前阶段暂时不考虑竖屏手机端使用；常规原型 / UI 回归后续不额外制作竖屏手机或极窄长页截图，以节省时间和对话负载。只有用户明确要求，或任务本身就是移动端 / 窄屏适配问题时，再做对应截图。
- **已修订（2026-06-02 · 桌面 16:9 顶层硬规则）**：用户明确要求 Angus 当前完全不需要移动版。后续游戏 UI、HTML / Godot 原型、视觉实验页和截图验收默认只面向桌面 16:9；不主动设计移动端、触屏版、窄屏版、移动端断点或移动端专用布局，也不把移动端截图作为默认交付项。只有用户在当前任务里明确要求移动端时，才可作为一次性例外处理，并需说明不改变“不做移动版”的顶层规则。
- **已修订（2026-05-14 · 派遣角色骰视觉语法）**：派遣配置页里只要展示完整 6 面角色骰，候选角色卡、已选角色槽和角色详情都应优先使用骰子立方体摊开的长尾十字架 / dice net 结构。横向 chip 行只能作为极小摘要、日志或一次性道具简表，不能替代角色骰的核心展示。压缩候选卡高度时也不得牺牲“看起来像骰子”的核心感知。当前 HTML 原型已将新版派遣配置的候选角色卡和已选角色槽改回 dice net；一次性道具仍保留横向 chip 摘要。
- **已修订（2026-05-18 · 深度链任务卡专属槽位）**：深度链任务卡不再把 `下一页：?` 放入耗时 / 危险 / 对手骰的普通标签行，也不使用 `1/4` 这类剧透总长度的表达。区域任务卡改为右侧高权重状态块 `深度调查 / 当前任务 N`，用专属槽位表达特殊任务机制；常规信息继续留在常规 meta 和需求行。
- **已修订（2026-05-19 · 深度链旧环退出任务列表）**：深度链完成一环后，旧环不应继续留在区域当前任务列表里。当前任务列表只显示每条深度链最新可做的一环；已完成旧环如需回顾，应进入日志 / 已完成记录，不使用当前可派遣任务卡语法。
- **已修订（2026-05-18 · 区域任务卡整卡入口）**：区域任务列表中的任务卡和线索卡只有一个主动作时，整张卡片承担进入 / 派遣配置入口，不再额外显示右下角 `派遣 / 抢派 / 继续调查 / 派人调查` 小按钮，避免重复入口挤压需求行、倒计时和深度链当前任务块。需要多动作或确认的场景再单独保留按钮。
- **已修订（2026-05-18 · 深度链地图入口点击语义）**：深度链地图入口的“展开 / 进入 / 收起”必须分离。第一次点击入口只展开链；展开后点击当前环任务直接进入任务界面；再次点击同一入口不负责收起。收起应由点击任务之外的地图空白、切换对象或离开当前区域完成，避免玩家想进入任务时反而把链收起。
- **已修订（2026-05-18 · 未解锁后续环提示）**：深度链展开后，未解锁的后续 `?` 环如果被点击，应弹出明确提示（如 `该任务未解锁`），不能沉默，也不能把这次点击解释成收起链条或进入当前任务。
- **已修订（2026-05-18 · 对象级反馈就地出现）**：未解锁环这类对象级反馈必须出现在被点击对象附近，不能使用远离地图对象的全局右上角 toast；后续所有地图点、任务环、卡片、角色或道具的失败 / 未解锁 / 不可用反馈都应优先锚定触发对象。
- **应用范围**：通用，影响首区任务总览、普通任务配置页、角色详情弹窗、后续黑骰与道具骰表现。
- **状态**：已采纳为 UI / 感知层落地方向；深度链地图入口已形成初步满意方案并落地到 HTML 原型。

### A6. 全球地图选择页主操作与选中区域详情
- **来源**：2026-05-13 全球地图选择 UI 实验确认。
- **机制**：全球地图先选区域，再通过主按钮“进入选中区域”。右侧从平铺所有区域改为选中区域详情；地图点与右侧区域小卡 hover / click 联动；详情用固定槽位展示可见目标、限时机会、线索、深度链；锁定区域只显示进度 / 缺口和阻断原因，不参与选中或进入；“下一天”不放在全球地图。
- **已修订（2026-05-14 · 地图点角标安全区）**：全球地图点上的进度百分比、事件数量、状态徽章等不能以未预留空间的右上角绝对定位遮挡区域名称。角标必须拥有独立布局槽位或明确安全区，并在截图验收中检查标题、角标和按钮文字的矩形不重叠。该原则同样适用于区域地图、任务卡、头像组和任何高密度按钮 / 卡片角标。
- **已修订（2026-05-14 · 地区选择与任务预览分离）**：全球地图页的真实功能是选择取材地区并进入地区页，因此右侧不能铺成可点击任务列表，也不能复用区域任务卡语法。右侧应由地区选择器、进入按钮、地区概况数值和少量只读情报预览组成；具体任务选择只在进入地区后发生。只读预览默认 2 到 3 条，不放任务操作按钮，不使用 `interactive` 交互类。
- **已修订（2026-05-14 · 主进入按钮右下角强化）**：全球地图页的主操作是进入选中地区，按钮必须作为流程终点放在右下角，并使用足够大的按钮与箭头图标。右上角不承担核心进入动作；`下一天` 等次级动作在视觉重量上必须低于主进入按钮。
- **已修订（2026-05-14 · 全球地图不推进时间）**：全球地图是地区选择入口，不显示 `下一天`。时间推进放在当前地区任务派遣 / 区域任务上下文；推进到第二天或完成到期结算后，默认回到当前地区继续派遣。
- **已修订（2026-05-18 · 区域日程推进独立）**：区域页中的日循环推进不能和任务列表共用右侧任务框体，也不能像“选中任务后的确认按钮”。`日程推进 / 推进到第 N 天 / 结束探索周` 应作为区域面板底部的独立特殊动作呈现，并附带已派遣数量、到期结算和突发任务倒计时变化摘要；任务列表只承担选择具体任务和进入派遣配置。
- **已修订（2026-05-18 · 区域页不直接结束探索周）**：区域页顶部不提供 `结束探索周 / 进入编辑部` 这类跨阶段跳转按钮；该位置应作为返回上一层的导航，回到世界探索层 / 世界取材地图。真正结束探索周只能通过日程推进、周循环或周末结算流程触发。
- **已修订（2026-05-19 · 层级返回按钮可见性）**：`返回区域`、`返回世界探索层`、`返回回合简报` 这类返回上层工作台的按钮不应被当作普通弱标签处理。它们应拥有稳定点击面积、清晰边框和一致视觉语法，低于当前主操作但不能小到难以发现；修正尺寸时不为了按钮放大改变页面整体布局。
- **已修订（2026-05-21 · 世界探索 P0/P1 方案落地）**：用户审阅实验页后确认方向。全球地图 / 世界探索页采用阶段导航、地图主语、选中地区从属详情和唯一主操作 `进入探索`；右侧只做地区情报预览，不恢复可点击任务列表；地区选择卡从重复 `可进入` 改为难度 / 推荐或解锁缺口；情报标签按成本、收益、条件、挑战、信息、状态分组；本周行动日志默认折叠，具体任务仍在进入地区后选择。
- **已修订（2026-05-21 · 情报标签语义口径）**：用户指出 `对手骰` 不是条件，而是关卡挑战；条件标签应写成 `条件：探索2`，不是 `条件探索2` 或 `条件 探索2`。后续全球地图 / 区域任务 / 派遣配置中，条件只表达玩家需要满足的需求，对手骰、危险、黑骰等压力信息使用 `挑战：...` 或专门压力槽位。
- **已修订（2026-05-18 · 父级选择与从属详情层级）**：全球地图右侧的地区信息必须从属于地区选择，而不是和地区选择形成同等重量的并列模块。地区选择卡承担可点击语法；选中地区的数值、说明和情报概况应表现为只读属性面板，降低边框、hover 和按钮感，并通过标题、缩进、内嵌或分隔关系表达“这是当前选中地区的详情”。该原则推广到所有“选择对象 -> 查看详情 -> 主操作确认”的 UI。
- **已修订（2026-05-18 · 可进入与未解锁状态距离）**：全球地图的已解锁地区和未解锁地区必须在地图点与右侧选择按钮上形成明显行动差异。已解锁地区使用主动可点击 / 可进入语法：实体按钮、金色主色、箭头、hover 和选中连接指示；未解锁地区使用锁定 / 幽影语法：虚线边框、低饱和低透明、锁标识、缺口文案、无 hover 抬升，并且不再作为 `button` 参与选择。该原则推广到所有可用 / 不可用对象。
- **应用范围**：通用，影响全球地图、区域选择、探索入口与 UI 感知层。
- **状态**：已采纳，并已落地到 HTML 完整全链试玩。2026-05-18 进一步将全球地图右侧改为“地区选择器 + 当前选中地区从属详情”的结构：选择卡强化为带箭头、hover、选中态和连接三角的按钮组；详情进入同一选择组下方，改为透明背景、左侧归属线、轻量属性行和普通情报列表，不再保留弱版卡片语法。随后已将可进入 / 未解锁状态方案套回完整全链主界面，未解锁地区不再是按钮、点击不改变选中地区；区域页日程推进也已从右侧任务列表框体移到整个区域面板底部，成为独立日程条。截图见 `docs/screenshots/2026-05-18-global-selector-detail/01-global-selector-detail.png`、`docs/screenshots/2026-05-18-global-availability-main/01-global-availability-main.png`、`docs/screenshots/2026-05-18-region-day-advance/01-region-day-advance-strip.png`。

### A7. 派遣配置页按“本次骰池”重构
- **来源**：2026-05-13 派遣配置 UI 重构讨论，用户确认直接在本体内推进并保留快速回退口子。
- **机制**：派遣配置页应围绕“本次骰池”组织，而不是平铺角色属性表。顶部固定展示任务摘要、耗时、剩余、截止与需求；中部展示已选角色槽、道具骰槽、需求覆盖、缺口与风险；下方候选角色按本任务贡献排序，hover / click 需要能即时反馈加入后会补哪些需求。临时资源与一次性道具作为补骰池手段展示，不替代角色选择。配置页主操作是“开始调查 / 开始线索调查”，全局“下一天”不应在该页作为浮动按钮抢焦点。
- **已修订（2026-05-13 · 任务摘要信息层级）**：派遣配置页顶部任务信息不能把不同层级的信息做成并列模块。任务耗时不应单独占一个 UI 模块，应并入任务标题 / 行动按钮 / 轻量 meta；探索周剩余时间是全局资源，不是任务属性，不应放在任务相关数值组里；截止日期是红色截稿 / 突发任务的特殊限制，应作为特殊状态提示或警戒条处理，而不是和常规耗时、需求并列。任务摘要区应只保留玩家做派遣决策真正需要的任务身份、类型、关键需求与特殊约束。
- **已修订（2026-05-13 · 截稿剩余时间视觉主语）**：红色截稿在派遣页不应同时显示“红色截稿”标签和红色说明条。剩余时间是该特殊约束的核心数值，应使用单一高权重倒计时块呈现，例如 `截稿关闭 / 剩余 3天`；成功 / 失败后关闭、失败伤员等后果说明降级为一行文字。
- **已修订（2026-05-18 · 候选队员位置稳定）**：派遣候选角色可以在进入页面时按任务贡献排序，但选中 / 取消选中不能改变候选池里的位置。已选顺序由上方“本次骰池”槽位表达；候选区只通过高亮表达选中状态，避免玩家点击后找不到刚刚比较的队员。该原则扩展到所有候选对象网格：选择状态不参与原列表排序。截图见 `docs/screenshots/2026-05-18-dispatch-stable-candidates/01-dispatch-stable-candidates.png`。
- **已修订（2026-05-18 · 派遣人数上限不自动替换）**：派遣配置页达到当前任务最高人数后，继续点击新角色不能自动撤下已选队员，也不能在悬停预览里模拟自动替换后的风险。系统应提示“本任务最多派遣 N 人，请先手动撤下一名已选角色”，并保持当前骰池不变。替换必须来自玩家明确撤销 / 重新选择，而不是系统隐式维护队伍。
- **已修订（2026-05-18 · 追加资源职责分离）**：派遣配置页同一组“追加骰 / 支援资源”必须保持清晰职责。一次性道具保留在追加区点击选择 / 撤回；临时线人雇佣后会成为完整候选角色，因此购买入口应从追加区消失，避免同一个按钮同时承担商店入口和阵容管理。
- **已修订（2026-05-18 · 追加资源固定槽位）**：追加区选项变少后，不应让剩余道具按钮自动拉伸填满整行。资源格应保持固定槽位和列宽，空出来的位置用于表达“这里的资源入口已被使用 / 移除”，同时维持界面节奏与品质感。
- **已修订（2026-05-21 · 候选排序标签局部采纳）**：用户审阅派遣配置实验页后明确只保留候选区的 `任务贡献`、`达标提升`、`未派遣优先` 排序标签；其它 P0/P1/P2 实验性布局改动撤回，派遣页应回到现有已认可壳层。后续若要改任务头、需求覆盖面板、骰池区或候选卡主体，必须单独提出并确认。
- **已修订（2026-05-27 · UX 修正实验页落地）**：用户要求把 `dispatch-configuration-ux-fix-lab.html` 的 UI 设计落地到正式派遣配置页。落地范围为保留现有派遣壳层的局部修正：需求覆盖改成“判定目标 / 来源拆解”的父子层级；候选角色 hover 在右侧直接显示达标率、有效点、仍缺项和来源变化；空骰池主按钮显示明确阻断原因；已选角色槽提供显式 `移出`；临时线人从“点击加入本次骰池”改为“雇佣后进入候选角色，加入时占角色槽”；候选卡的 `骰面 / 汇总` 切换必须真实改变卡片内容。

### A89. 世界地图现代纸品风格必须保留可点击体积感

- **来源**：2026-06-18 世界地图 Image2 风格稿复盘；用户要求继续靠近现代印刷纸品、高级概括地图和干净色系，但明确强调各分区、特殊区域和按钮必须有突出的体积感与功能可见性，不能为了扁平化忽视按钮功能性，同时体积感也不能回到写实老旧、金属和厚重旧档案方式。
- **机制 / 原则**：世界地图 v7 的视觉方向不是“扁平海报”，而是“现代印刷纸品里的可交互物件”。按钮、地图 pin、左侧任务 / 地区卡、底部 ticker 详情入口、筛选签和主 CTA 必须通过纸层抬升、短投影、纸边厚度、内边高光、压印、裁切、套印错位、pressed 下压和 hover / selected / disabled 状态矩阵表达可点击。体积感不得依赖写实金属、锈蚀螺丝、厚重旧办公器具、泛黄旧纸、审批表、通用手游 3D bevel 或胶囊按钮。
- **UX / 美术共识**：像素艺术判断当前跑偏点是材质叙事从现代周刊纸品滑向旧档案 / 审批表；正确体积来自纸品层叠和印刷工艺。UX 老哥判断现代纸品风格可以扁，但交互层不能扁；可点击对象必须比只读纸面更像可操作物件，并具备 `default / hover / pressed / selected / disabled / locked` 中适用状态。主 CTA 和全局推进动作继续保持空间、颜色、材质、atlas、hit rect 和确认态分离。
- **应用范围**：世界地图 v7 后续 Image2 风格稿、无字组件拆图、manifest `content_rects / no_text_rects / hit_rects`、地图 pin / 左卡 / ticker / CTA 状态 atlas、Godot 动态层 hover / pressed / selected / disabled 实现、截图验收和 `@像素艺术` 生成后复审。该原则也适用于其它现代纸品资产化 UI。
- **状态**：已采纳为世界地图 v7 现代纸品包装与交互可见性的联合 Gate。后续若视觉稿只解决老旧感却让按钮、pin、卡片或 ticker 看不出可点击，应判定为交互失败稿；若用金属、旧档案、厚重审批按钮制造体积，也应判定为美术风格回退。

### A91. 派遣签批台 V15 锁定为真实内容风格稿生产合同底稿，而非生产真源

- **来源**：2026-06-18 派遣签批台 V15 评审后继续推进；用户要求“开始下一步”。父级 Codex 按 V15 默认态、候选 hover 态、无字底图草稿和资产合同批注图推进生产规格。
- **机制 / 原则**：V15 的正式作用是冻结派遣签批台下一轮高保真生产合同，而不是替代最终美术。当前锁定的功能语法为：`已选队伍 5/5 + 1 件随队道具` 是中央签批板主语；候选员工池默认一行完整卡，hover 向上展开第二排；器材托盘默认可见但低权重；右侧签批票据承担最终复核，主结论为 `可签批 · 达标率 78%`，主 CTA 必须写清 `盖章派遣 · 2天`，避免玩家从分散字段拼签批后果。
- **资产化边界**：V15 本地图只能标注为 `filled-state capacity preview`、`role-pool hover preview`、`no-text asset master draft` 和 `contract_overlay`。它不能叫生产真源，不能直接切图替代正式无字资产，也不能作为真实内容风格稿完成版。下一步真正生产必须产出两张高保真目标图：一张无动态文字的 `no-text asset master`，一张带真实内容和代表性头像的 `filled-state text mock`；二者都要在图文融合、字体气质、头像裁切、动态字段安全区和可点击物件体积感上通过复审。
- **当前产物**：生产规格位于 `docs/plans/dispatch-signoff-imagegen/real-content-style-v15-production-spec.md`；asset contract 草案位于 `docs/plans/dispatch-signoff-imagegen/dispatch-signoff-v15-asset-contract.json`；截图汇总页位于 `docs/screenshots/2026-06-18-dispatch-signoff-packaging-v15-editorial-object/index.html`；核心截图包括默认有字容量预览、候选 hover 展开、无字底图草稿和合同批注图。
- **应用范围**：派遣签批台下一轮真实内容风格稿、高保真无字底图、组件拆图、manifest、Godot / HTML 动态层、状态矩阵、截图验收和 `@像素艺术` 生成后复审。

### A92. 派遣签批台 V16 起功能承载页必须方正，斜切只作禁写装饰

- **来源**：2026-06-18 派遣签批台 V16 继续推进；用户基于右侧斜签批票据截图明确指出“功能页面一定要是方正的，斜的界面资源很不好用”。
- **机制 / 原则**：A53 的“核心功能 UI 不得使用大角度斜透视烘焙底图承载动态文字”在派遣签批台中升级为更硬的生产约束：凡承载动态文字、数值、头像状态、按钮文案、hover / pressed / disabled 状态或 hit rect 的功能正面，都必须是 square-on、axis-aligned、可测量的矩形。斜切、纸层、折角、外侧标签、票据舌片、夹子、阴影和半调只能进入背景、外轮廓或 `no_text_rects`，不得进入正文、数值、CTA label 或可点击热区。
