### A42. 角色与概念风格参考采用“Q版主编 + 巨大周刊现实撕裂”方向
- **来源**：2026-06-10 角色设计与概念风格参考讨论；用户明确要求以当前提供的主编角色图与标题页图作为角色设计和概念风格参考。
- **机制**：后续主编 / 编辑角色与核心概念图应优先参考“高精度 Q 版黑色幽默编辑 + 巨大周刊头版 / 浏览器窗口 / 印刷物件撕开现实”的方向。角色可保留蓬乱黑发、厚框眼镜、风衣 / 编辑工装、工牌、报纸叠、印章 / 签批工具等职业符号；画面主视觉强调周刊版面作为现实改写机器，使用深蓝、红橙、米白、青色异常光、半调网点、像素城市剪影、套印错位和像素粒子。该方向是角色设计与概念风格参考，不等于把所有 UI 或角色全部像素化，也不等于回到旧报纸 / 旧档案 / 暖木复古路线。
- **应用范围**：主编 / 编辑角色设计、标题页 / 概念图、关键视觉、视觉 prompt、后续美术风格稿和宣传图方向。
- **状态**：已采纳为角色设计与概念风格参考；Riso 印刷风格与 `Nirvana Noir` 风格融合仍待本轮讨论后确认，不在本条直接写死。

### A43. 角色高清微像素四人标杆图升级为角色美术真源
- **来源**：2026-06-11 角色设计风格规范-AI包接入讨论；用户明确纠偏“角色 / 主编 / 编辑不做像素角色”的旧规则，确认当前一切以刚上传的四人标杆图为准，角色为高清微像素，并要求该图及对应规则成为真新源。
- **机制**：后续角色 / 主编 / 编辑正式视觉方向采用“高清微像素 Q 版角色 + 深蓝夜色 + 低能量都市怪谈群像”。`角色设计风格规范-AI包/` 是角色美术规则真源，`reference/01-原始基准图.png` 是角色构图、像素密度、色调、角色气质和四人群像的第一视觉真源；`风格规范-v2.0.md` 负责既有 4 角色档案，`角色设计DNA-新角色生成指南.md` 负责新角色生成蓝图。旧的“角色不做像素角色”废止，后续应改为“避免 8-bit / FC / Pico-8 / 体素低清复古像素；角色按四人标杆图高清微像素执行”。
- **应用范围**：角色头像、角色立绘、角色群像、主编 / 编辑角色、既有 4 角色、新角色设计、角色 prompt、生图参考图选择、生成后验收、`angus_character_pixel_director` 子 agent；主触发词为 `@像素美术`，`@像素角色` 保留为兼容别名。
- **状态**：已采纳并升级为角色美术真源；已同步到 `design/art-direction/angus-visual-style-guide.md`、`AGENTS.md`、`docs/onboarding/ai-collaboration-guidance.md`、`docs/onboarding/subagent-collaboration-improvement.md` 与像素美术专科 skill。

### A44. `@像素艺术` 作为美术资源与界面视觉风格守门入口
- **来源**：2026-06-11 美术资源与游戏内界面视觉风格讨论；用户明确要求后续游戏的美术资源、界面视觉风格都要由 `@像素艺术` 把关。
- **机制**：`@像素艺术` 对应 `angus_art_director`，负责只读审查 Angus 全局视觉方向、美术资源、UI 视觉包装、像素 / 半调 / 印刷材质、参考图转译、视觉 prompt 与风格跑偏诊断。它判断“是否像 Angus”，不替代 UI Designer 的布局、UX 老哥的可读性 / 操作链、SIA 的 Steam 吸引力、制作人的资产范围判断或 openrouter-image-gen 的实际生图；涉及角色高清微像素细则时，需与 `angus_character_pixel_director` 和四人标杆图协同。
- **应用范围**：游戏内可见界面、Godot / HTML 原型视觉包装、截图验收、美术资源拆分、生图 prompt、视觉风格稿、全局 UI 材质语言和后续美术资产导入。
- **状态**：已采纳为长期协作规则；已同步到 `AGENTS.md`、`skills/angus-art-director/SKILL.md`、`docs/onboarding/ai-collaboration-guidance.md`、`docs/onboarding/subagent-collaboration-improvement.md` 与 `design/art-direction/angus-visual-style-guide.md`。

### A45. 视觉风格稿生成后必须由 `@像素艺术` 复审颗粒度与标杆继承
- **来源**：2026-06-11 世界地图界面元素风格稿反馈；用户指出生成稿整体不错，但像素颗粒度不太像标杆界面的像素风，并追问生成后是否让 `@像素艺术` 看过。
- **机制**：后续 UI 风格稿、美术资源包、界面元素风格稿或生图结果，若要被称为生产标杆、资源标杆或真源候选，必须在生成后再交 `@像素艺术` 复审。复审不只看“整体是否好看”，还必须检查像素颗粒度、颗粒密度、半调 / 套印是否成为结构语言、是否继承当前标杆图、动态文字安全区是否可落地，以及是否滑向旧报纸、旧档案、泛黄纸噪点或高清摄影噪声。
- **应用范围**：世界地图 / 全球频道资源、所有 UI 视觉风格稿、生图 prompt、生成后验收、截图风格复核和后续美术资源生产。
- **状态**：已采纳为生成后验收规则。`docs/screenshots/2026-06-11-world-map-ui-style-sheet/01-world-map-ui-style-sheet.png` 经 `@像素艺术` 复审后判定不通过生产标杆，只保留为元素词汇草稿 / 偏差案例；世界地图 / 全球频道类资源默认继续对照 `docs/screenshots/2026-06-07-global-channel-style-board/05-global-channel-style-board-reference-clean-modern-pixel.png` 与 `docs/screenshots/2026-06-07-global-channel-style-board/07-global-channel-full-interface-style-draft-flat-magazine-ui.png`。

### A65. 派遣签批台干净象牙纸与像素印刷约束（回链）
- **来源**：2026-06-16 派遣签批台整屏风格稿 v2 反馈与 `@像素艺术` 二次复审；主条目见 `ui-ux-decisions.md` A65。
- **美术判断**：v2 构图与三栏功能方向可保留，但当前不能作为生产标杆；纸边、红底板、折角、破损污渍、金属夹、掉漆按钮和摄影级纸纹会把 Angus 拉向旧案卷 / 泛黄档案 / 写实旧物件，与“现代异常周刊 + 印刷物质感 + 像素材质”的正式方向冲突。
- **执行约束**：派遣签批台及同源签批纸、任务纸、员工卡、CTA、状态章的纸面应使用干净暖白 / 浅象牙新印刷纸，允许轻微纸纤维、印刷压痕、套印错位、块状半调和 2-4px 像素颗粒，但不得出现脏污、茶渍、破败、撕裂、黄褐旧档案、旧报纸、sepia、随机摄影噪声、金属锈蚀或掉漆旧机器质感。正文安全区纹理强度应降到几乎不可见，装饰颗粒必须退到 `no_text_rects`。
- **状态**：作为 A65 的美术回链已采纳；后续派遣签批台风格稿若仍出现旧档案 / 脏旧纸 / 写实旧物件倾向，应判为未通过生产标杆复审。

### A67. 地区任务地图不得被程序化低保真地图替代（回链）
- **来源**：2026-06-16 地区任务地图资源返工反馈；主条目见 `ui-ux-decisions.md` A67。
- **美术判断**：用户认可的是上一套地区任务台中间地图的深海军蓝、低多边形纸质分面、红青半调、裁切线、像素颗粒和现代编辑部地图墙气质。程序化多边形地图、简化矢量大陆、白盒调试网格和低保真 PIL / Canvas / SVG 绘图即使尺寸正确，也不具备该视觉证据链，不能作为正式地图资源或生产标杆。
- **状态**：作为 A67 的美术回链已采纳；后续 `@像素艺术` 审地区任务地图时，必须检查候选图是否继承原地图视觉源，而不是只看“没有 pin / 标签”或“内容区干净”。

### A82. 地区任务台 v3 整屏图作为视觉锁定源（回链）
- **来源**：2026-06-17 地区任务台资产 UI 化返工继续推进；主条目见 `ui-ux-decisions.md` A82。
- **美术判断**：本轮用户明确认可的是整张地区任务台图的综合视觉效果，而不只是“地图质感”单点。后续美术与 UI 落地应保留深蓝工作台、中央低多边形纸质地图、暖白新鲜印刷纸、红青套印、半调网点、夹具 / 档案 / 票据物件关系和现代杂志社工作台气质。若为了拆功能而重画成低保真地图、普通后台面板、旧档案纸、脏旧报纸或另一套配色，应判定为跑偏。
- **执行约束**：`rt_artboard_full` 可以作为视觉锁定底图和高保真恢复参考，但动态文字与可点击状态仍需由 UI 动态层或独立组件承担；美术复审重点是“功能化之后是否仍像同一张图的生产版”，而不是只看局部文本是否没出框。
- **状态**：作为 A82 的美术回链已采纳；后续地区任务台截图复审应先确认中央地图与整屏气质未被替换，再检查按钮、任务卡、右侧详情和 CTA 是否进入同一视觉系统。

### D4. 白骨生花角色展示动画先追求佛教 / 密宗概念贴合度
- **来源**：2026-06-05 白骨精“白骨生花”版本角色展示动画讨论。
- **机制**：当前概念阶段先不以脱敏包装为第一目标，而是优先挖掘佛教、密宗文化中与“白骨重生、由妖入圣、千手展开、暗中生神性”贴合的深层意象、仪式结构和视觉逻辑，形成足以指导视频设计的概念底座。
- **应用范围**：白骨生花角色设定、专属展示动画、千手展开大场面和后续视觉脚本讨论；不直接作为最终公开文案或宗教设定真源。
- **状态**：概念阶段口径已采纳；最终对外包装前仍需单独做宗教敏感性脱敏与原创化命名。

### D5. 白骨生花展示动画分段母题
- **来源**：2026-06-05 白骨精“白骨生花”版本角色展示动画讨论。
- **机制**：展示动画大方向采用“黑暗压迫开场 → 河流 / 彼岸花 / 曼陀罗过渡 → 白骨复活 → 骨生花与黑色千手展开”的段落结构。开场应有巨物、巨大符号或宏大宗教性构图，让角色显得渺小，形成庄严压迫感；中段需要解决黑暗死亡感与后段佛性显现之间的震撼过渡；千手保留黑色，强调相较传统千手更强的神秘主义、忿怒相和暗中生神性的气质。
- **应用范围**：白骨生花角色展示动画、分镜脚本、视觉参考整理和后续资产概念设计。
- **状态**：概念阶段口径已采纳；具体镜头长度、镜头语言和命名仍待后续脚本阶段细化。

### D6. 白骨观脱相应弱化恐怖直给
- **来源**：2026-06-05 白骨精“白骨生花”版本角色展示动画讨论。
- **机制**：白骨观 / 脱相段落保留“色相剥落，回到本真白骨相，再由本真重生”的精神，但公开视觉上不宜直接强调骷髅、尸骨或恐怖死亡感。更推荐用玉骨、瓷骨、月骨、骨瓷纹理、白玉骨架轮廓、衣袍空壳、倒影褪色、花瓣剥落、骨纹光路等方式表达“去皮相、见本真”，让段落偏庄严、诗性、神秘，而不是惊悚。
- **应用范围**：白骨生花角色展示动画、复活镜头、脱相视觉语言和后续脱敏包装。
- **状态**：概念阶段口径已采纳；后续分镜应避免血肉剥离、尸体特写、写实骷髅和惊吓式骨相呈现。
