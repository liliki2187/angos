## 3. 三个旧判断的复核

### 加强：评论中的判断和求助，比点赞更接近可用参与

- **事实**：「谁谈？」为 13赞 / 200评；精简攻略为 18赞 / 25评；两者都与高赞商店页呈现不同互动结构。
- **推断**：站队、求助、关键词核对等动作比单纯被看见更可能形成可回应的参与。
- **Angus 建议**：记录「有效判断 / 求助 / 灌水 / 求入口」四类评论，而非只报总评论数。
- **风险**：评论全文不可见，无法确认有效参与比例；不能将评论热度写成关系沉淀或游戏转化。

### 加强：首发、帮助、试玩/商店节点应分工，而非由一条贴承担全部任务

- **事实**：《长乐夜前夕》存在 Demo、商店页、实况和体验帖；《毕业季失踪事件》存在首发、长攻略、精简攻略和卡点反馈。
- **推断**：情境钩子、操作承接、玩家复述和 CTA 分开出现，构成可搜索的内容链。
- **Angus 建议**：每个公开事件预排「判断首帖 → 无剧透核验单 → 反馈回收 → 回访索引」四个内容位；商店页可用后才加 CTA。
- **风险**：发布日期和发布先后不可见，不能证明这些内容按此顺序造成效果；玩家内容必须自发或取得授权。

### 削弱：档案/桌面视觉本身足以驱动冷启动

- **事实**：低赞卡点帖提到结局线索遗漏；低表现体验帖涉及设备、弹窗与难度；Demo 摘要特别说明设备、时长与反馈。
- **推断**：开始和完成过程的说明、信息可读性可能至少与题材包装同样重要。
- **Angus 建议**：在视觉稿之外，优先验证阅读层级、档案可定位性、提交确认与无剧透帮助的可理解性。
- **风险**：这不是对视觉方向的否定，且样本均没有完整正文和日期，不可外推为品类共识。

## 5. 两个反例与不可照搬点

1. **高赞 CTA 不等于已转化。**商店页和 Demo 互动高，但没有 Steamworks、下载或完成后台；Angus 必须将曝光、点击、完成反馈、愿望单拆开计数。
