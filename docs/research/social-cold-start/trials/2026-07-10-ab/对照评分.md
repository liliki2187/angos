# 2026-07-10 Angus 社媒研究 A/B 对照评分

> 状态：试运行完成。本报告同时保留“模型自主编排工具时的表现”和“统一批次 / 等待协议后的质量表现”。单次试运行只用于配置决策，不宣称统计显著。

## 一句话裁决

保持 `Luna / low 原始扫描 -> Terra / medium 周度归纳 -> Sol / medium 周期复盘` 的默认组合，不把每周流水线整体升级为 `Sol / xhigh`。首次自主运行的总分是 62 对 84，但统一 MCP 批次和等待策略后变为 80 对 84；22 分表面差距中大部分来自工具编排，受控后的 4 分才更接近本轮可归因的质量差距。

## 差距究竟在哪里

### 不是召回数量

固定编排后，Luna 召回 120 条并选出 24 条，全 Sol 召回 110 条、去重 109 条并保留 24 条。至少在本轮查询上，没有证据支持“必须用 Sol 才能找到足够案例”。首次 0 对 110 的差距，是 Luna 没有自行坚持等待 RedNote 长任务，而非平台检索知识不足。

### Sol 的真实增量

1. **详情证据更完整**：全 Sol 在 6 条深挖中成功读取 5 条，默认受控组为 0 条。S01 的同质化批评、S15 的愿望单自报和 S20 的图片正文边界因此被写得更精确。不过两组的详情调用方式仍未完全冻结，这一差距不能全部归因模型。
2. **筛选更会保留反模式**：全 Sol 主动保留“高赞零评”“高参与但无游戏转化”“攻略暴露玩法弱点”等样本，避免把案例库做成爆款陈列。
3. **多了一条可改变执行顺序的洞察**：推荐、攻略、答疑、统一入口和里程碑不会自然串成转化链，应分别埋点，现阶段不先建设重型聚合站。
4. **实验变量更锋利**：除首句和提问结构外，全 Sol 提出了“入口首发即放 vs 24 小时后补放”，可直接验证评论参与与站外点击是否互相影响。

### 默认组合已经够用的部分

受控默认组同样得出了三条可执行主线：评论调查要用有效推理评论单独衡量；首个网页事件应围绕一个可恢复、可复述的操作；报纸 / 档案模板只能做识别层或维护内容，不能替代玩家判断。Terra / medium 把 24 条摘要整理成了可执行实验，没有因上游无全文而假造因果。

它当前最需要修的是协议，不是模型档位：Luna 两次自报开始时间均不可靠，受控复跑还把正式基线中的 4 个链接计入本期样本；这些问题应由自动化提示词和验收规则硬约束。

## 成本与等待

- 两个受控原始扫描的可观察运行时间接近：默认组约 17 分钟，全 Sol 约 16 分钟；本轮不能声称 Sol 更慢或更快。
- 没有拿到精确 token 与货币成本，因此不伪造单次金额。
- 按 [OpenAI 模型文档](https://developers.openai.com/api/docs/models) 的官方 API 单价作等 token 代理，Sol 每 token 约为 Luna 的 5 倍、Terra 的 2 倍；同样 token 量下，`Sol + Sol` 至少约为 `Luna + Terra` 的 2.86 倍。`xhigh` 通常还会消耗更多推理 token，因此 2.86 倍只是成本下界，不是本次实付账单。推理档位的适用边界参见 [GPT-5.6 使用指南](https://developers.openai.com/api/docs/guides/latest-model)。
- 受控后只有 4 分质量差，且唯一足以调整 Angus 执行顺序的增量可在周期复盘或少量重点全文深挖时获取，不足以覆盖每周全链路升级成本。

## 对 Angus 的直接结论

1. 冷启动第一层继续做“具体异常 + 一个有后果的编辑判断”，不用游戏功能介绍起手。
2. 评论区的主指标拆为有效推理评论率、依据条数和回访评论；点赞只代表曝光旁证。
3. 第二层用一个短网页事件承接，优先测试搜索框或按时间排序材料，不在首发事件堆满邮箱、论坛、录音等系统。
4. 统一入口先做轻量页面，并分别记录请求入口、点击、完成反馈和愿望单表达；不把推荐、攻略或里程碑帖当作自动转化链。
5. 下一轮优先验证三个单变量：首句框架、提问结构、入口出现时点。

## 配置裁决

- **长期默认保持不变**：Luna / low 原始扫描，Terra / medium 周报，Sol / medium 周期复盘。
- **原始扫描协议立即加固**：固定 3 批 x 4 条；每批最多等待 240 秒；详情最多 2 条并发；开始 / 结束时间必须实时读取；笔记 ID 不得作为发布日期；日期不可见的帖子只能算“新发现候选”，不能证明本周趋势；历史命中必须单列。
- **Sol / xhigh 按需启用**：只在 Demo、商店页、账号定位等重大节点，或每轮最重要的 3—5 条全文确实可能改变策略时做一次性深挖，不承担每周全量收集。
- **下一次判断门槛**：至少再做 2 次同协议盲评。只有默认组连续漏掉会改变内容实验或转化路径的证据，才考虑提高常规定时任务档位。
