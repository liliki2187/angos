# 原始扫描

Terra 自动任务每周在此创建一份日期文件，命名为 YYYY-MM-DD.md。

## 人读优先结构

原始扫描既是证据底稿，也是用户查看本轮发现的入口。每份文件必须先给人读结论，再给审计附录：

1. 第一屏用自然语言说明本轮真正发现了什么，不先展示查询次数、工具状态或候选大表。
2. 选择 5–8 条最有意义的发现；每条必须包含“看到了什么 / 为什么值得借鉴 / Angus可以怎么试 / 不能误读什么”。
3. 至少引用 1–3 个具体样本和可见数据，不能只写抽象趋势词。
4. 查询轨迹、计数、完整候选表、访问失败和证据边界统一放在“审计附录”之后。
5. 没有足够证据时宁可写“本轮没有形成可用发现”，不得用大量原始记录制造研究已经完成的观感。
6. 对话中的任务结果不能把人读报告再次压缩成一句话清单。至少展开 5 条重要发现；每条用 3–6 句说明具体案例、观察到了什么、为什么值得借鉴、Angus可以怎样试以及关键限制。用户不应被迫先打开文件才能理解本轮收获。

每份扫描必须包含：

- 5–8 条人读发现及其借鉴理由、可试动作和误读边界。
- 覆盖窗口和实际使用的平台入口。
- 搜索词组与新增实体词。
- 20-30条候选，或说明为什么不足。
- 高互动、中位、低表现和异常比例样本。
- 可见互动数据、采集时间、链接和证据等级。
- 与案例库的重复检查。
- 平台访问失败和待人工补看候选。

原始扫描只负责完整、诚实和可复查，不直接改写冷启动手册。
