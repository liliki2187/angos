# Angus 三界面最新结构稿 v0.1

> 日期：2026-06-24  
> 状态：低保真结构稿，用于确认骨架；不是美术稿、不是生图 prompt、不是 Godot 落地稿。  
> 范围：世界地图、地区任务界面、任务派遣 / 签批界面。  
> 约束：桌面 16:9；标杆风格只转译成组件身份，不在结构阶段强行做整屏美术。

## 0. 共通规则

- 标杆味来自组件身份：dossier、文件夹、任务 pitch 卡、field pass、签批单、票条、贴纸、快照、色票和图标 atlas。
- 动态文字、数字、按钮文案必须由运行时 UI 渲染；生图 / bitmap 只承载纸件、照片、边框、贴纸、按钮底和图标底。
- 每个页面只允许一个主 CTA。
- 红橙只用于主 CTA、危险、截稿、不可逆或红线升温；普通选中和推荐优先用橄榄 / 蓝绿 / 芥末。
- 每个拟物组件都要有正交可写区；夹子、折角、纸边、强半调、条码、斜纹和贴纸边缘默认是 `no_text_rects`。

选择一个报道地区，看懂它能不能进入、是否值得先进，然后进入选定地区。

### 1.3 组件身份

| 区块 | 标杆化身份 | 运行时承担 |
| --- | --- | --- |
| 左侧地区卡 | 彩色文件夹索引卡 | 地区名、可进入/锁定、难度、推荐、短理由 |

### 1.4 UX 初审

- P0 保护：世界地图不能出现完整任务列表、员工、骰池或成功率。
- P1 风险：右侧 `查看任务情报 · N` 必须像可点击票条，不能像正文标题。
- P1 风险：`推进一天` 若存在，必须独立为底部日程系统，不能成为第二个红 CTA。

### 2.3 组件身份

| 区块 | 标杆化身份 | 运行时承担 |

- P1 风险：左侧探索链必须同时在卡片、地图 pin、右详情和 CTA 附近反馈，否则深度链看不见。
- P1 风险：底部只做压缩回执，不能成为第二个任务详情区。

## 3. 任务派遣 / 签批界面

### 3.1 玩家目标

为当前任务选择员工和随队器材，看懂覆盖率、缺口、风险和耗时，然后签批本次派遣。

### 3.2 结构图

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ SIGNOFF HEADER                                                                │
│ [当前任务短名] [地区] [耗时] [返回任务台]                                      │
├───────────────────┬─────────────────────────────────────┬────────────────────┤
│ LEFT TASK DOSSIER │ CENTER FIELD ASSIGNMENT STAGE        │ RIGHT SIGNOFF SLIP │
│                   │                                     │                    │
│ [任务 snapshot]   │  案卷插槽台 / 本周外勤取材版          │ [可签依据摘要]     │
│ [任务摘要]        │                                     │ 覆盖 2/2           │
│ [目标/需求]       │  [role pass slot 1] [role pass slot2]│ 有效点 13/8        │
│ [危险/截稿]       │                                     │ 风险 压力+2        │
│                   │  [role pass slot 3] [spare slot]     │ 耗时 2天           │
│                   │                                     │                    │

│                   │  no central coverage table            │ 签批本次派遣        │
├───────────────────┴─────────────────────────────────────┴────────────────────┤
│ BOTTOM CANDIDATE DRAWER                                                       │
│ [员工 field pass cards...]                         [器材 / 一次性道具袋...]   │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 推荐结构方向

采用 V12 的 A 案卷插槽台作为主线，吸收 C 外勤包检查台的附件袋 / 器材袋触感，再借 B 的 `WMW 本周外勤取材版` 做轻量标题身份。

不要把中间做成路线规划、覆盖矩阵、中央骰面表或报纸排版系统。

### 3.4 组件身份

| 区块 | 标杆化身份 | 运行时承担 |
| --- | --- | --- |
| 左侧任务卷宗 | 当前任务 dossier | 为什么派人、任务风险、目标需求 |
| 中央主舞台 | 外勤案卷插槽台 | 谁去、带什么、还有哪些空槽 |
| 员工卡 | field pass / 记者证 | 角色头像、贡献、可用状态、移除 |
| 器材槽 | 附件袋 / 工具票夹 | 道具骰、补缺来源、一次性状态 |
| 右侧签批单 | 主编回执 / approval slip | 覆盖率、有效点、风险、耗时、确认 |
| 底部候选抽屉 | field pass tray | 员工候选、器材候选、筛选/补位 |

### 3.5 UX 初审

- P0 保护：遮住右侧后，中央仍必须能回答“谁去、带什么、还缺哪个槽”。
- P1 风险：右侧只做完整复核和 CTA，不能拿走中央的全部解释。
- P1 风险：中央不能用伪状态块填空；空白应通过卡片尺寸、插槽阴影、纸层和附件袋解决。

## 4. 给后续美术 / 生图 / 工程的交接

下一步不应直接画整屏高保真。建议按顺序：

1. 世界地图：右侧地区 dossier 单组件结构 + 中文填充。
2. 地区任务：任务 pitch card + 右侧 task brief 单组件。
3. 派遣签批：field pass、role slot、signoff slip 三组件。
4. 三组组件过安全区后，再做整屏标杆化母版。

每个组件至少交付：

- 无字 bitmap 底图。
- `content_rects / no_text_rects / hit_rects` overlay。
- 真实中文最长态填充预览。
- `default / hover / selected / disabled / warning` 状态矩阵。
