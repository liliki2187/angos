# 发刊完整风格稿 v2“程序换肤”偏差 Loop Log

## 结论

完整风格稿 v2 被用户否决。它只在程序界面上替换颜色、纸色与报道插画，仍保留等宽矩形卡片、细线面板和后台式分区，因此不是合格的风格稿，只能作为失败样本保留。

## 影响

- v2 不再是待冻结的美术候选，原 UI / UX / 父级 PASS 全部失去风格放行效力。
- 不得据此拆组件、制作 atlas、重制正式报道资产或进入 Godot。
- v6 继续作为功能结构与交互位置真值，但不再被误读为可见框体外观真值。

## 这次错在

1. 把“在当前 UI 布局基础上生成”错误理解成逐像素保留程序矩形，只允许换色和换插画。
2. 为避免生成模型改布局，在 prompt 中压制了夹子、贴纸、叠纸、切角和不规则纸件等标杆核心语言，结果只剩配色转译。
3. UI / UX 复审过度关注三栏几何、状态与唯一 CTA，未把“去字后能否与标杆同族”设为独立美术硬门槛，形成假 PASS。

## 修正后的风格稿定义

风格稿不是程序截图换肤，也不是生产 UI。它是实现前的整屏美术目标，用来让用户裁决这是否是 Angus /《世界未解之谜周刊》的视觉身份，并为后续组件拆分、资源制作和 Godot 包装提供视觉北极星。

必须保留的是三栏职责、双页与六槽关系、8 条候选的容量、签发链顺序、硬阻断、唯一 CTA 和交互位置。允许且必须重新设计的是卡片外壳、面板边界、纸张层级、切角、夹具、贴签、报刊结构、签批材料和全屏色彩节奏。

## 下一轮方法

1. 把 v6 当作几何 / 内容蒙版，不再当作可见形态模板；把两张 benchmark board 当作美术身份第一真值。
2. 先生成低文字或无文字的完整 filled-state 美术稿：左栏是高密度报道纸件系统，中栏是可信的展开双页周刊，右栏是签批档案 / 送印许可材料。
3. 正式中文、数值和动态状态后置为程序文字层，避免生成式伪字反向限制造型。
4. 先过“遮掉文字、缩至 25%、五秒内仍能与标杆同族”的 Gate，再检查功能结构与交互位置是否完整。
