# 发刊局部美术混入程序皮肤导致无法审阅｜Loop Log

## 结论

主头版 v3 虽然局部质量已通过 UI / UX 检查，但把它放回其余仍为程序皮肤的整屏，既不能证明它与最终美术组合成立，也会让用户难以判断局部是否适合。此前“1:1 局部＋混合整屏”不能作为用户美术批准材料；v3 降级为组件级局部暂准证据。

## 影响

- v3 不得因局部 PASS 直接反向拆层或成为生产真源。
- `02-main-head-visual-master-v3-fullscreen.png` 只证明位置和尺寸兼容，不证明未来整屏审美。
- 下一审阅单位改为中央双页区域母件；候选卡扩产和正式 Godot 继续暂停。

## 这次错在

1. 把局部美术质量和整屏组合质量塞进同一张半成品整屏图判断。
2. 未完成区域继续显示高对比程序皮肤，视觉语言、明度和边框密度污染了用户对已完成组件的判断。
3. 把 UI / UX 的局部 PASS 描述成可请求用户最终批准，忽略局部通过随时可能被区域组合推翻。
4. 仍以单组件为主要生产单位，没有优先保证同一区域组件共享纸面、层级、边界和强调色节奏。

## 修正方法（用户已确认并固化）

- 用户审阅状态分为：`局部暂准 → 区域通过 → 整屏冻结 → 运行态生产冻结`，禁止越级。
- 每轮只展示三种证据：1:1 局部、所属区域组合、未来态 1920×1080 整屏。
- 未美术化区域优先使用已批准风格稿裁片，其次使用目标风格代理层；只用于位置验证时才使用统一灰度轮廓。禁止裸露旧程序皮肤作为美术审阅背景。
- 组件从已通过的区域母件反向拆出；拆后重组必须与区域母件做差分对照，避免每个组件单独生成后组合失控。

## 当前边界

用户于 2026-07-22 要求继续按该机制落地；中央双版区域母件 v1 已成为第一组执行证据。当前仍未拆层，也未修改正式 Godot、组件合同与 GDD。
