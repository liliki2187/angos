# UI Designer 复核原文

频繁犯错的根因不是“提示词少写了扁平”，而是生产方法错了：把“整屏生图”同时当成美术设计、UI 布局和功能验证工具。模型只抓到报纸、文件夹、夹子、暗桌面等名词，自动补成电影化摄影桌景；团队又被成图的完成度迷惑，没有先用二维骨架卡死结构、状态和投放链，所以功能与风格同时漂移。

## 1. 写实漂移的具体机制

v2 使用强透视俯拍、真实桌面空间、体积光、景深、金属高光、厚纸边、复杂投影和大量随机旋转；物件像真实道具，UI 像一次性布景。标杆的本质则是正交资产板：深蓝平面底、模块化矩形分区、统一浅投影、克制材质、有限角度；低多边形主要存在于照片/插图内容中，不是把整个界面做成写实三维桌面。

## 2. 即使好看也必须废弃的部分

必须废弃：整张摄影桌面背景、巨型倾斜报纸、散落且越界的夹子/灯管/CD、独立票根 CTA、悬空结算纸、靠物理遮挡表达层级、装饰性主导的头版构图。它们可作为氛围概念参考，不能继续裁切或改造成生产 UI；否则文字安全区、状态复用、命中区域和低分辨率适配都会失控。

## 3. 第三版二维骨架

1920×1080 固定三栏：`候选池 320 / 间隔20 / 六版位周刊1040 / 间隔20 / 复核360`，整体居中。三栏职责不可互换：

- 候选池：5–6 张紧凑剪报，只显示缩略图、短标题、状态章；当前稿展开，其他稿折叠。
- 六版位周刊：真实双页但保持正交，六个槽位尺寸与头版/次条/专题/内页层级明确。头版靠图像建立第一视觉，其余槽只保留短标题与占用章。
- 复核区：只保留头版、预计传播、净收益、风险/阻断、唯一主 CTA“签批送印”。

固定六状态：

| 状态 | 必须可见的反馈 |
| --- | --- |
| 未选 | 候选卡正常停放 |
| 已拿起 | 卡抬升，来源位保留 |
| 可投放 | 合法槽描边并显示落点 |
| 已占用 | 槽显示缩略图、短标题、退回把手 |
| 空位 | 明确空槽及代价 |
| 阻断 | 槽与送印同时出现原因标记 |

点击与拖拽共用同一状态机：选稿→选槽/拖入→已占用；点击已占用稿可退回或换稿；任何时刻都能看见“稿从哪里来、准备去哪里、是否已经放下”。

## 4. 标杆的正确转译

应提取“图形语法”，不是复制“办公桌实物”：

- 深海军蓝作为连续平面底；
- 橄榄、钴蓝、芥黄形成一级大色块；
- 文件夹、照片、便签转成扁平矩形组件轮廓；
- 统一 0° 功能面，装饰最多 ±2°；
- 同方向、同深度的短硬投影；
- 图标采用细线地球、眼睛、问号、警告符号；
- 低多边形异常图只进入报道缩略图与头版主图；
- 纸纹只做轻微颗粒，禁止写实污渍、景深和电影灯光。

## 5. 三种生产方式的分工

- 整屏生图：只探索氛围和面积关系，标注“概念稿”，不得验证功能、不得直接落地。
- 组件生图：只产无文字、正交、透明背景的文件夹、纸框、缩略图、章、夹具等资产，并冻结可写区/禁入区。
- 确定性拼装：Godot/HTML 承担所有文字、尺寸、六状态、交互、命中区和响应式验收；这是唯一生产路径。

## 6. 第三版开始前 Hard Gate

以下任一项未通过，禁止再生整屏效果图：

1. 先交黑白 1920×1080 二维骨架，不含材质和氛围装饰。
2. 候选→放置→退换→复核→送印五步可连续演示。
3. 六状态在同一套组件上完整定义，点击与拖拽结果一致。
4. 320/1040/360 三栏及六槽边界冻结，不允许生图改布局。
5. 默认态可见文字只保留决策必需项；标题溢出策略已确定。
6. 标杆对照必须通过：无强透视、无写实桌景、无体积光、功能面正交、低多边形仅用于报道图。
7. 黑白骨架先由 UX 验证功能，再进入组件资产风格化；整屏氛围稿不得作为通过依据。

给 UX 老哥的交接结论：下一轮先审状态链和三栏骨架，不审美术完成度；骨架通过后再审组件资产是否破坏可写区与操作反馈。
