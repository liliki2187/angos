# 发刊编辑钴蓝风格资产化桥接 Brief

## 目标

把用户偏好的方案 1 钴蓝配色转为可拆图、可复用、可由 Godot 原生控件拼装的美术资源，同时保持 v6 与现有 UI 合同的正交尺寸、槽位、命中框、滚动和状态逻辑。

## 真值分工

- 方案 1 风格稿：只负责钴蓝配色、暖纸、金属夹、胶带、切角、层叠与印务设备语言。
- v6 / `design/ui-contracts/weekly-editorial/`：负责所有尺寸、坐标、内容槽、命中区、状态数量和交互边界。
- 正式报道图与中文：继续由运行时动态回填，不烘焙进美术底图。

整张生成图不得直接裁成运行时 UI。生产资产必须在 exact-size 正交画布上重新绘制或重构。

## 斜件处理规则

- 功能节点始终是 `0°` 的矩形 `Control / Button`。
- 斜边、切角和不规则轮廓通过矩形透明 PNG 内的 alpha 轮廓实现。
- 夹子、胶带、斜签和探出纸角是独立 overlay，`mouse_filter=IGNORE`。
- 需要越过功能矩形时，用同父节点 sibling overlay 和显式 overscan；不扩大点击区，不推开邻接布局。
- 有文字的标签必须另设水平 `content_rect`，文字和按钮根节点不旋转。

## Godot 拼装层级

1. `Z10`：固定底图——分拣架、左右纸壳、签发板。
2. `Z20`：动态内容——标题、图片、ID、meta、证据项和数值。
3. `Z30`：状态层——合法、悬停、选中、禁用、阻断。
4. `Z40`：真实交互——Button、拖拽热区、ScrollContainer。
5. `Z50`：无输入装饰——夹子、胶带、斜签、螺钉。

## 资产类型

- 整块固定透明 PNG：左分拣架外壳、左右页纸壳、右签发板外壳。
- 9-slice / `StyleBoxTexture`：候选卡状态框、版位状态框、证据纸载体、硬阻断、CTA 状态皮肤。
- 透明 overlay：夹子、胶带、斜签、选中稿外伸、纸角和局部状态角标。
- Godot 原生控件：全部文字、报道图、缩略图、按钮、滚动、筛选 / 排序、焦点和状态逻辑。

## 首个 exact-size Vertical Slice

先做 `main_head_slot 442×374`，2×源画布为 `884×748`：

- 标题：`[16,14,410,68]`
- 横图：`[16,92,410,218]`
- meta：`[16,318,360,42]`
- 唯一局部换稿：`[390,322,44,44]`

首轮验证 `idle / legal / hover / slot_focused + replace` 四种关键状态；之后补齐合同七态。通过标准是所有状态共用同一矩形根节点，标题、图片和按钮零漂移，斜轮廓无透明洞、接缝、点击穿透或错误热区。

通过后按顺序推进：

`candidate_card 288×92 → secondary_head_slot 442×342 → signoff_panel 360×920 → 两页纸壳与左分拣架整屏拼装`。

## 分层 PSD 与导入

- 使用 2× exact-size 分层 PSD 作为可编辑源稿；动态内容槽只保留参考辅助线，不导出。
- 用 `python scripts/import/build_psd_ui_bundle.py <psd_path>` 生成图层 PNG、扁平预览、`manifest.json` 和 `Control + TextureRect` 脚手架。
- 导入场景只作为美术布局基线；正式接入时必须把动态层替换 / 绑定到原生 Godot 控件，不能把栅格脚手架误称为完成的语义 UI。

## 当前需先处理的合同差异

`candidate_card.json` 的单卡尺寸 `288×92` 可继续使用，但 `positions` 仍只列 6 个位置；v6 的正式结构要求 8 张常显，实际排列为 92 高加 8 间距。不得按旧位置数组烘焙六槽分拣架。主头版切片不受此差异影响；在制作左分拣架前，需单独同步候选卡位置合同或实现。

## 当前边界

本 Brief 只定义资产化桥接方法。用户确认首个切片方向前，不批量拆件、不改 Godot 正式界面、不升级组件合同或 GDD。
