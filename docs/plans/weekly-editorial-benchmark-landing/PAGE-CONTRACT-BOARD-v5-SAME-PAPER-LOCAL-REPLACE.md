## 3. 局部换稿状态合同

| 状态 | 进入方式 | 局部换稿按钮数 | 数据变化 |
| --- | --- | ---: | --- |
| `idle` | 进入页面、完成或取消操作 | 0 | 否 |
| `slot_focused` | 点击一个占用版位 | 1 | 否 |
| `replace_armed` | 未选来源时点击“换稿” | 0 | 否 |
| `replace_pending` | 已选候选后点击占用版位 | 1 | 否 |
| `dragging` | 从候选或真实版位开始拖拽 | 0 | 否 |
| `drag_hover` | 拖拽进入合法目标 | 0 | 否 |
| `confirmation_frozen` | 打开发刊确认 | 0 | 否 |

唯一按钮文案为“换稿”，使用版位右下 `44×44` 动作位。点击另一个占用版位时按钮迁移；点击空白、按 `Esc`、开始拖拽、完成操作或进入确认时全部临时状态清除。

## 4. 拖拽与原子事务

| 来源 | 目标 | 结果 |
| --- | --- | --- |
| 候选稿 C | 空槽 B | C 放入 B |
| 候选稿 C | 占用槽 B（原稿 X） | C 替换 X，X 回候选 |
| 占用槽 A 的 C | 空槽 B | C 从 A 移到 B，A 变空 |
| 占用槽 A 的 C | 占用槽 B 的 X | A / B 原子交换 |
| 占用槽 A 的 C | 候选池 | C 回候选，A 变空 |
| 任意来源 | 原位置或非法区域 | no-op |

点击与拖拽必须共用同一个来源—目标事务。每篇报道在六个版位中最多出现一次；任何 drop 提交前不得提前清空来源。

## 5. 拖拽动态层

- 拖拽开始后所有局部换稿按钮立即隐藏。
- 合法目标只显示 `1px rgba(126,138,72,0.55)` 非文字边线。
- 当前 hover 目标使用 `3px #D3B37C` 外线与内缩 `1px #7E8A48` 内线。
- 来源槽只保留低权重钴蓝来源线；图片、标题和 Meta 始终全亮。
- 槽内稿拖向候选池时，只加强候选池外框；不增加常驻“移出”说明。
- `StatusBadge` 与 `ReturnToCandidates` 节点已退出当前实现。

- 默认换稿按钮数 `0`；点击占用槽后 `1`；拖拽 / 确认态 `0`；任意时刻 `<=1`。

- 双版在全部状态中保持两张 `490×800` 页面同屏，不恢复单版聚焦。
