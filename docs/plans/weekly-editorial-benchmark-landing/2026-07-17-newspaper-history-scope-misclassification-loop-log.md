# 报刊界面历史索引范围误判 Loop Log（2026-07-17）

## 决策条

结论：上一版历史索引把“编辑部工作空间”误归为“报刊界面”，并因只按 `weekly-editorial` 等近邻目录名筛选而漏掉 `report-board / report-reorg`、早期 `paper-editorial` 和 2026-07-14 两张整屏过程稿；原索引降级为错误审计证据，立即返工。

影响：上一版不能回答“真正的报刊界面以前长什么样”，也不能用于判断当前结构是否继承了既有报纸主体、候选池、签批纸和送印动作。

下一步：以“画面主体是否承担报纸组版、校样、版位编辑、签批或送印”为准重建索引；先从源码入口、Git 路径、截图目录和生成稿四路取并集，再做人工分类和代表页汇总。

## 触发与归因

- 触发来源：用户截图纠偏。
- 原始问题：用户指出编辑部大厅不是报刊界面，而且真正的已落地功能页与过程稿没有找全。
- 失败归因：对象身份、证据检索和产物分类三重失败。
  - 对象身份：把上层“编辑部工作空间”当成下层“报刊组版界面”。
  - 证据检索：只依赖截图目录名，没有从 HTML/Godot 入口、源码引用、Git 历史和生成稿反查。
  - 产物分类：没有区分界面主体、相邻结果页、单体资产与视觉参考。
- 复发判定：命中 F1“验证等级/产物类型冒充”与 F4“只修点名局部不扫同类”。F1 已在 gate 层，F4 本次为再次复发。
- 本轮处理：返工；旧索引显式标记为已替代，不删除审计证据。
- 沉淀判断：Loop Log + 复用现有 F1/F4 防线；不另造重复规则。

## 复发保护

同类“把历史页面都找出来”任务，开工与交付前必须同时检查：

1. 先写对象定义和排除项，不能以目录关键词代替对象判断。
2. 取证必须覆盖当前文件、截图目录、HTML/Godot 入口、生成稿和 Git 文件历史。
3. 每张候选图至少归入：运行页、功能原型、过程稿、组件资产、相邻页、排除项之一。
4. 汇总页只展示运行页、功能原型和过程稿；相邻页与排除项留在机器清单中。
5. 反向检查：如果删掉报纸主体后页面职责仍成立，它就不是报刊界面主线。
