# 发刊右页普通报道 folio 空轨误判 Loop Log

## 结论

中央双版结构稿 v2 的右页普通报道存在无效空洞：`213px` 宽版位中的 `160×160` 图片从 `x=53` 起排，左侧约四分之一宽度只放置竖线和两位 folio。此前全区域 PASS 撤回，修复前不得冻结。

## 影响

- 右页普通报道的信息密度明显低于程序版。
- 标题、图片与 meta 分别落在不同横轴，削弱同一报道的图文耦合。
- 若直接进入美术包装，空洞会被材质和装饰掩盖，后续拆图与运行时实现会固化错误骨架。

## 触发与根因

- **触发**：2026-07-22 用户将 v2 与原程序版并排后指出图片左侧空间过大。
- **根因**：为了让右页普通报道与左页形成非同构节奏，设计时把 folio 侧轨扩至 `53px`，却没有检查该侧轨的信息承载量；UI / UX 复核只验证了正方形图片合同、溢出和模板差异，没有验证“留白是否有出版价值”。

## 唯一修正

- 保持普通报道图片合同为 `160×160`，不改成长方形。
- 右页图片由相对 `x=53` 移至 `x=26`；folio 轨压缩为 `26px`。
- 删除 `160px` 全高竖线，改为 `32px` 高短规则；标题和 meta 保持原宽度与位置。
- 右页仍采用“图片先行 → 标题 → meta”，左页仍采用“标题先行 → 图片 → meta”，不靠无效空轨制造差异。

## 防复发

已向 `editorial_media_identity` Gate 增加“编辑留白有效性”检查：低信息 folio / 装饰侧轨占单篇报道宽度 `20%` 以上即阻断，并要求与上一可读结构并排检查。
