# 发刊编辑审阅信息过载 Loop Log

## 用户看到的问题

副头版横图 v3 的实际改动只需要一张主状态图、一段动态和少量改动说明，但最终回复同时展开了完整 UX 诊断、UI 几何交接、验证细节和文件记录，导致真正需要用户判断的画面被过程信息淹没。

## 原因

父级把“证据必须可追溯”和“所有证据都应展示给用户”混为一件事。内部 agent 原文、像素坐标和完整审计适合落盘或按需展开，不适合成为每次增量审阅的默认正文。

## 修正后的审阅顺序

1. 简短说明结果。
2. 展示足以让差异被看清的例图或必要动态。
3. 只说明真实影响本次审阅的改动。
4. 只有存在真实分歧时才给清楚可比的方案，并明确需要用户拍板的事项。
5. 只列会影响视觉判断、方案选择、风险或后续成本的问题与建议。

2026-07-21 用户二次修订：以上各项不设机械条数上限。高价值信息可以多给，低价值小问题不得为了凑结构而上推给用户。

## 默认隐藏内容

- subagent 完整原文；
- 像素坐标与 CSS 交接表；
- audit、console、状态矩阵和测试命令；
- manifest、Router / Gate 与内部复盘；
- 没有变化的状态截图。

这些内容继续保存并保持可追溯；只有出现失败、阻断、agent 冲突、会改变用户判断，或用户主动要求时才展开。
