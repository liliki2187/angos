# Loop Log：副头版异色与全局替换控件破坏杂志统一感

结论：返工已完成并形成新证据；A02 报道图与资产分层保留，冷钴蓝独立壳和全局 `替换 / 放入` 控件已退出当前实现。

影响：新候选已满足同纸色、默认 0 / 点击 1 / 拖拽 0 和原子事务的自动门槛；仍暂停 B 级专题 / 内页图扩产，等待用户复核真实画面。

下一步：用户复核 `docs/screenshots/2026-07-15-weekly-editorial-same-paper-local-replace/` 的三态截图与动态 WebP；通过后再决定恢复 B 级扩产。

## 1. 触发反馈

2026-07-15，用户复核副头版 A 级真实 Godot 截图后明确指出：

1. 主头版与副头版不应使用两种页面底色；它们属于同一期杂志，异色页壳破坏统一观感、代入感和印刷物身份。
2. 每个版块上的替换按钮不应同时常驻；应保留拖拽决定稿件去留，以及点击某个版块后才局部出现替换按钮的逻辑。

## 2. 本轮错因

### 2.1 把资源等级错误映射成页面底色

父级把“主头版 S 级 / 副头版 A 级”的层级关系直接翻译成“暖纸主版 / 冷钴蓝副版”。这能在截图里形成清晰焦点，却把一本杂志拆成两套界面皮肤。正确的层级应由标题字号、图像面积、构图冲击力、留白和边线重量承担，而不是改变整张页面的基础纸色。

### 2.2 把可发现性错误映射成全局动作控件

UX 修正了“退回与替换争抢同一位置”，但父级随后让所有合法版位同时显示 `来源 / 放入 / 替换` 文本徽记。它虽然可读，却让编辑页面重新像工具后台，并把本应是局部、临时的替换动作扩散到整本杂志。

### 2.3 验证目标选错

35/35 审计只证明“按钮按当前设计可用”，没有验证“这些按钮是否应该同时出现”。后续交互审计必须加入否定断言：默认态和拖拽态不得出现多枚替换按钮；只有点击选中的单个版块可以显示一个替换动作。

## 3. 修订合同

### 3.1 杂志统一纸面

- 主头版与副头版必须共享同一基础纸色、纸张材质和印刷边线体系。
- 副头版不得再使用整块钴蓝页壳作为身份区分。
- 主 / 副层级改由标题权重、照片高度、构图对比、栏线和留白承担。
- A02 报道图可保留；报道图自身的夜景冷色不等于页面壳改成另一套底色。

### 3.2 替换交互局部化

- 默认浏览态：所有版块都不显示 `替换` 按钮。
- 拖拽态：只显示必要的落点边线 / 插入位置，不在所有目标上铺文字按钮。
- 点击某个已占用版块：只让该版块进入局部选中态，并在该版块出现唯一的 `替换` 按钮。
- 点击空白、按 `Esc`、开始拖拽或完成替换后，局部按钮消失。
- 同一时刻最多存在一个替换按钮；不得恢复六版位同时出现 `替换 / 放入` 徽记的表现。

## 4. 证据与返工边界

- 可保留：A02 低多边形报道图、壳 / 图 / 文字 / 状态分层、合同 rect、fallback 与文章 ID 映射、双版常显几何。
- 必须返工：副头版冷钴蓝壳、所有目标同时出现的状态徽记、以全局按钮证明落点可发现性的交互测试。
- 当前代码仍保留被否决表现；在完成 UI / UX 双复核和实现前，文档与代码存在显式差异，以本 Loop Log 与 A214 为目标真源。

## 5. 重新放行条件

1. 主 / 副版同纸色整屏截图能首先读作同一期杂志。
2. 默认态没有任何常驻替换按钮。
3. 拖拽时落点清楚，但没有六个文本动作同时出现。
4. 点击一个版块后只出现一个局部替换按钮。
5. 新自动审计加入“同时可见替换按钮数 `<= 1`”和“默认态为 `0`”断言。
6. 用户复核真实截图与动态演示后，再决定是否恢复副头版 A 级放行和 B 级扩产。
