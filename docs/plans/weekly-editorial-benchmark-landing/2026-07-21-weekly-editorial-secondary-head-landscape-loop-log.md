# 发刊副头版横图纠偏 Loop Log

## 触发

用户审阅正式视觉包装候选 v2 后指出：副头版使用方图时，右侧与下部形成大片无法自然填充的空白，版面看起来像未完成模板。

## 本次误判

上一轮把“非主头版全部方形”当成图片两规格合同的最直接表达，但只验证了图片框比例与字段不虚构，没有把副头版作为 `442×342` 的完整信息容器检查实际占用率、视觉密度与层级职责。

这导致合同纯度优先于成稿可读性：虽然没有新增第三种图片比例，却让副头版的图、标题、meta 和留白分裂为互不支撑的区域。

## 修正

- 仍保留 `square + headliner_landscape` 两种资产规格。
- 将消费规则从“只有主头版用横图”改为“主、副头版共同用同源横图；候选和普通位用方图”。
- 主头版 `410×219`，副头版 `375×200`，用面积差保持主副层级。
- 副头版标题与 meta 移至横图下方；换稿按钮固定在右扩展翼 action-safe zone。
- 不新增摘要、导语或伪数据填空。

## 后续防错

今后冻结版位图片合同时，除了检查比例数量和跨槽位身份一致性，还必须同时检查：

1. 整个版位的有效占用率，而不是只看图片 rect；
2. 图片、标题、meta 是否形成连续信息簇；
3. 主次版位的图片面积差是否足以表达层级；
4. 局部动作按钮是否落在明确的非主体安全区；
5. 无摘要字段时是否仍能形成完整成稿，而不是靠空白掩盖结构缺口。

## 验收附带发现

在 v3 完整交互回归中发现，继承自 v4 的“清空双版”路径会在右栏读取不存在的头版标题。v3 已增加“尚未设置头版”安全显示，并验证清空后所有版位为 0、主 / 副头版仍标记横图格式、控制台错误与警告为 0。该修复只落在 HTML 候选，没有扩张到 Godot 或规则真源。
