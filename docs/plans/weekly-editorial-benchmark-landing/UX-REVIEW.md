# 发刊前编辑 / 报刊版面界面 UX 诊断报告

## 一、诊断基础

**现状产物类型：** `runtime_state_preview`
**下一阶段产物类型：** `filled_state_text_mock`
**界面类型：** 排版 / 创作台 + 不可逆签批面板
**优先评估：** 排版映射、决策信息可达性、送印错误预防
**诊断依据：** 1920×1080 当前真实运行截图、Godot 实现、两份发刊 GDD、两张 clean low-poly weekly 标杆和历史稳定功能版截图。
**长尾 KB：** 未触发；这是单界面、非付费任务，主 spec 已足够。

### 页面职责

这页唯一职责应是：

> 主编把候选报道安排进本期周刊的不同版位，确认头版立场、传播预期和公开风险，然后签批送印。

它不是后台数据看板，也不是结算结果页。结算结果属于下一阶段；本页只展示足以改变“排哪篇、放哪里、是否送印”决策的预测信息。

### 目标对齐

- **Business Goal：** 冻结 `slot_assignment / published_issue / settlement_preview`，让排版取舍真正影响传播和后续世界反馈。
- **User Goal：** 在候选报道、版位价值和送印后果之间做取舍，形成一期有明确头版立场的周刊。

### 当前状态还原

截图中：

- 候选报道共 6 篇，已有 5 篇入版。
- 本期 6 个版位已填 5 个，`内页 B` 为空。
- 当前选中候选为“街区猫群一致拒绝经过蓝色电话亭”。
- 右栏显示需求、销量、收入、利润、下周订阅等预估，但同时暴露大量开发字段和乘数。
- `结算本期` 当前可点击。
- 代码中的 `_settle_issue()` 会直接依次调用 `publish_issue()` 和 `settle_published_issue()`，没有 `pre_publish_check`、二次确认或运行时可见的发刊有效性阻断。

这与 GDD 有一处必须明确处理的出入：GDD 定义了 `required_slots_filled / blocked_task_not_violated` 和 `pre_publish_check`，当前实现没有对应拦截。UI Designer 不应自行猜测哪些版位必填；需要产品 / 实现先确定真实规则。

### 当前操作链

① 浏览候选稿
→ ② 点击一篇候选稿
→ ③ 横跨到中央，逐项阅读 6 个版位名称、权重和当前内容
→ ④ 点击某一版位放稿
→ ⑤ 页面整体重建，确认稿件是否进入目标版位
→ ⑥ 横跨到右栏，从开发字段中推断传播、收入和风险变化
→ ⑦ 重复 ②—⑥
→ ⑧ 点击 `结算本期`
→ ⑨ 直接发布并进入结算结果

### 信息依赖断裂点

- **步骤③：候选报道 vs 目标版位**
  候选卡中心约在 `x≈330`，版位中心约在 `x≈980`，距离约 650px；两者之间没有连线、浮动稿件、选中摘要或局部落位预览。需要同时注视，构成断裂风险。

- **步骤⑥：本期版面 vs 预估后果**
  版位中心约在 `x≈980`，预估中心约在 `x≈1600`，距离约 620px。右栏又使用 `mQuality / comboRaw / mBias` 等内部术语，玩家不仅要移动视线，还要翻译算法。

- **步骤⑧：当前问题 vs 不可逆送印动作**
  “本期头版是谁、是否空版、是否冲突、预计扩散 / 收益、送印是否有效”没有在 CTA 周围形成一次完整复核。按钮只写 `结算本期`，无法表达它会先发布再结算。

## 二、7 域冲突扫描

已逐项对照附录 A 的 20 类冲突和附录 C 的案例；A-15～A-18 不适用于本单机界面，A-19 当前未触发，A-20 需在后续真实字体和状态色阶段检查。

- **数值域：** 截图中 `已填 5/6` 与中央 5 个已占版位、1 个空位一致，暂未发现明确算术矛盾。`需求 10418 / 销量 4200 / 印量 4200` 的关系表面成立，但“需求”的产品含义不清。
- **时间域：** 顶部仍显示 `剩余 7/7 天`，当前已经进入编辑阶段。是否允许探索零耗时获得 4 条素材需确认；现有证据不足，暂不判冲突。
- **术语域：** 页面职责是发刊，GDD 状态是 `publish_commit`，实现按钮却叫 `结算本期`。它把“不可逆发布”说成“查看 / 计算结算”，属于 A-7 术语不一致与 A-13 可逆暗示冲突，参考 case C-13-1。
- **状态域：** 只要存在当前选中稿件，代码会把所有版位的 `selected` 同时设为 `true`；视觉上所有槽都出现相近金色边框。玩家无法区分“这是可放置目标”与“这是已选中版位”，属于 A-3 条件状态矛盾。
- **层级域：** 右栏内部公式和顶部宏观值占据大量高权重面积，真正的报刊对象、头版决定和签批 CTA 反而较弱，属于 A-4 层级与内容矛盾。
- **操作范围域：** `清空版面` 的范围准确，但会一次删除全部排版；`结算本期` 实际范围包含“发布 + 结算 + 阶段切换”，文案明显小于实际作用范围，属于 A-11 / A-13。
- **空间方向域：** 提示文案写“再点右侧版位”，实际版位在中央；更深层的问题是 6 个纵向列表项并没有建立“头版 / 次条 / 专题 / 内页”的空间映射。

## 三、容器和视觉层级审计

- **边界：成立但角色不成立。** 三块面板边界清楚，却使用同一种后台面板语法；看不出左边是稿件剪报、中间是正在排的周刊、右边是签批纸。
- **厚度：不成立。** 主要依赖单层描边和同色底，没有纸张叠层、书脊、夹板、内高光或职业物件厚度，读成网页 / 调试面板。
- **金字塔：不成立。** 当前最高权重接近页面标题、黄色版位框和密集白字；主 CTA 只有 160×42，既不像送印动作，也不是视线终点。
- **节奏：不成立。** 左中两栏都是等高卡片流水，右栏从上到下连续堆字段；缺少“头版定稿 → 收益摘要 → 风险 → 批注 → 送印”的节奏。

## 四、问题诊断

### 🔴 P0-1｜送印语义隐身

**断裂点定位：** 操作链第⑧步，玩家准备完成本期不可逆发布时。

**现象：** 5/6 版位状态下，`结算本期` 仍直接可点；按钮没有说明会发布，代码没有预检、确认或阻断，点击后直接发布并结算。

**破坏力：** 表面上这是一个结算按钮，本质上却是不可逆送印开关。按钮语言越像普通计算，玩家越不会进行最后复核；一旦误点，结果不是“少看一眼数据”，而是本期版面被冻结、世界后果开始结算。Nielsen #5 要求不可逆操作前明确展示作用范围、关键后果和确认；当前界面三项都缺失。

**改进：**

```text
改前
[清空版面] [结算本期]

改后
[清空当前排版]                  ╔════════════╗
                                ║  签批送印  ║
签批纸：头版 / 空版 / 冲突 /    ║ 本期将冻结 ║
预计扩散 / 收益 / 阻断原因      ╚════════════╝
                                二次确认态
```

- 主 CTA 改为 `签批送印`，尺寸建议不小于 240×64。
- 第一次点击进入就地确认态，明确“本期版面将冻结并进入发刊结算”。
- 如果 5/6 允许发刊，签批纸必须显示空版代价后仍允许确认。
- 如果命中 `required_slots_filled` 或势力硬禁令，CTA 必须禁用并在按钮旁显示唯一阻断原因。
- `清空当前排版` 与 CTA 至少分隔 24px，并采用低权重纸签，不共用同一动作托盘。

**注意力预算：**

- 【加】签批复核摘要、明确 CTA、一次确认态。
- 【减/压缩】删除右栏开发乘数、重复“已填 / 空位”流水，把空间交给复核信息。

### 🔴 P0-2｜三段式决策断链

**断裂点定位：** 操作链第③和第⑥步，玩家判断“这篇应放哪里、这样排值不值得”时。

**现象：** 报道、版位、后果被拆成跨越约 650px + 620px 的三块；没有选中报道摘要、位置映射、落位后果或同色联动。右栏又要求玩家理解 9 个乘数与多个内部计数。

**破坏力：** 排版游戏的前提是玩家能把“内容—位置—后果”视为一个决定。三者一旦分裂，效果不是稍慢，而是反转：玩家不再像主编排版，只能像 QA 在三个数据表之间来回查值。玩家不是不想权衡，而是界面把一次编辑判断变成了约 3 次长距离眼动、若干术语翻译和反复试放。

**改进：**

```text
┌候选剪报┐  →  ╔本期周刊 / 真实版位╦签批纸╗
│选中稿件│     ║[头版头条]           ║预计扩散║
│标题/取向│     ║[头版次条][专题]     ║净收益  ║
│有效传播│     ║[专题][内页][内页]   ║风险/冲突║
└────────┘     ╚════════════════════╩签批送印╝
                  ↑ 当前可放槽同色提示
```

- 选稿后，在周刊顶部出现单一“当前拿起的剪报”短条。
- 可放置版位使用同一强调色，但状态命名应是 `drop_target / available`，不能伪装成 `selected`。
- 落位后，稿件在周刊中成为真实标题 / 图片 / 摘要；右侧只显示玩家能判断的“预计扩散、预计售出、净收益、公开冲突、同题疲劳、空版代价”。
- 调试公式移到开发开关或 tooltip，不进入默认玩家视图。

**注意力预算：**

- 【加】选中稿件短条、位置映射、签批摘要。
- 【减/压缩】移除等权重的 `mQuality / mCombo / mDiversity...` 和候选卡内的原始英文调试字段。

### 🟡 P1-1｜版面被压成列表

**断裂点定位：** 操作链第③步，玩家比较不同版位角色时。

**现象：** 头版头条、头版次条、重点专题、内页全部是同宽同高纵向按钮；差异主要靠 `x1.00 / x0.70 / x0.45` 文本。

**破坏力：** 直接操纵原则要求编辑 / 创作类界面把结果空间本身变成操作面。当前玩家看到的是六行倍率，不是一期周刊；头版价值只能靠读数字记忆，GDD 强调的“版位是不同角色”没有进入视觉。

**改进：**

- 【加】中央改为真正的双页 / 跨页周刊对象；头版头条面积最大，次条和专题次之，内页最小。
- 【减/压缩】删除六个同构列表按钮和重复的版位说明句。
- 版位倍率不作为主标签，可翻译为 `最高曝光 / 高曝光 / 专题 / 内页`；精确倍率进入 hover 或详情。
- 历史稳定功能版的“左候选剪报 + 中央双页周刊 + 右签批”职责可保留，但必须按当前 6 版位重新设计，不能沿用旧的 3/3 假结构。

### 🟡 P1-2｜选中态污染与稿件锁死

**断裂点定位：** 操作链第②—⑤步，玩家选择、落位和调整已排稿件时。

**现象：**

- 选中一篇稿后，所有槽位都被设置为 `selected`。
- 已入版稿件在候选区直接 disabled，却没有高权重标出“已入版 · 具体版位”。
- 已入版稿件不能直接重新选中移动；玩家需要覆盖、再找回，或清空全部版面。

**破坏力：** 前注意加工要求状态在阅读前就可辨。当前金框同时承担“当前选中”“可投放目标”“已占版位”多种含义；全部高亮等于没有高亮。已排稿件又从可编辑对象变成灰色死项，把本应可反复调整的排版变成绕路操作。

**改进：**

- 【加】状态矩阵：`candidate / lifted / placed / placed-located / drop-target / occupied / warning`，至少用形状、章签、明度三项区分。
- 【减/压缩】取消“所有槽统一 selected”的状态复用。
- 已入版候选显示 `已入版 · 头版次条`，点击应至少定位对应版位；理想方案允许两次操作内移动版位。
- 若本轮不实现拖拽，仍保留“点稿 → 点新槽”的点击映射；不要为了拟物感强制新增拖拽机制。

### 🟡 P1-3｜后果预览开发态

**断裂点定位：** 操作链第⑥步，玩家判断是否继续调整排版时。

**现象：** `totalBaseValue / uniqueTags / comboRaw / linkedTags / negPenalty / mQuality...` 与最终销量、利润并列展示，信息组超过 12 个且层级扁平。

**破坏力：** Miller 原则要求复杂信息先按决策用途分组。当前右栏要求玩家先理解算法，再理解结果；算法解释占据的注意力反而超过结果本身。

**改进：**

- 【加】四组玩家语言：
  1. `头版定稿`
  2. `预计传播与售出`
  3. `预计净收益 / 下周订阅`
  4. `同题疲劳 / 公开冲突 / 空版 / 势力禁令`
- 【减/压缩】内部乘数和计数默认全部移除。
- `三轴占比` 翻译成一句本期倾向，例如“公共事务为主 · 大众关注为辅 · 轻内容不足”；细分条按需展开。
- 数字层级最多保留 3 个第一梯队数值，其余为次级摘要。

### 🟡 P1-4｜全清空无恢复

**断裂点定位：** 操作链调整阶段，玩家想撤销部分排版时。

**现象：** `清空版面` 是唯一明确移除路线，点击后立即清除全部 6 个版位，没有确认、撤销或局部退稿。

**破坏力：** 它虽然可通过重新排版恢复，但会抹掉本期全部选择，操作成本高。按钮又紧邻送印动作，容易造成“想调整一篇，先毁掉整期”的效率损失。

**改进：**

- 【加】版位局部 `退稿 / 换稿` 入口；全清空后提供 5 秒撤销，或在已填版位时确认。
- 【减/压缩】把全清空从主动作行移到周刊对象左下的低权重工具区。
- 历史版的 `清空当前排版` 语义可保留，但不能继续作为移动稿件的主要办法。

### 🟢 P2-1｜正式文书混入开发词

**现象：** `Gossip / Humor / Gold / base`、变量名和倍率直接进入正式页面，中文 / 英文 / 代码命名混杂。

**改进方向：** 候选剪报只保留玩家语言：报道类型、公开取向、主话题、有效传播；英文枚举只留开发模式。正式周刊基础层使用清楚正体，个人批注只作为独立便签层。

### 🟢 P2-2｜落位与签批缺少职业动作反馈

**现象：** 页面主要通过瞬时重建改变文字；没有剪报落入版位、版位压印、签批盖章或送印收束。

**改进方向：** 后续 runtime 可使用 150—250ms 的纸片位移 / 压入反馈；签批确认使用 250—350ms 印章下压，送印结果至少保持 1.5 秒可见。动效不能替代状态更新，且正式交付必须提供真实 GIF / 视频。

## 五、动态行为审计

- 当用户点击候选稿后 → 预期应看见“当前拿起哪篇稿、哪些槽可放” → 当前代码会把所有槽统一设为 selected → 导致目标状态与选中状态混为一谈。
- 当用户点击版位后 → 预期应看见稿件从候选位置进入具体报刊槽，并就地反馈预估变化 → 当前表现是整体列表重建、选中清零 → 导致来源—去向关联丢失。
- 当用户想把已入版稿件移动到另一槽位时 → 预期应直接选中并移动 → 当前稿件 disabled → 需要覆盖或全清，形成操作绕路。
- 当用户点击清空版面后 → 预期应有确认或撤销 → 当前立即清空 → 导致多轮排版被一次点击抹掉。
- 当用户点击 `结算本期` 后 → 预期应进入 `pre_publish_check`，确认头版、空版、风险和不可逆性 → 当前直接发布并结算 → 导致送印前决策链完全消失。
- **需确认：** 实际运行时 hover、键盘焦点、按钮音效是否有额外反馈；现有截图与代码不足以证明。

## 六、资产化与视觉安全区约束

当前页面主要是 Godot 原生面板，尚未出现 bitmap 拼装问题；因此不能把现状问题误报成资产接缝缺陷。进入 `filled_state_text_mock` 和后续组件资产化时，必须新增以下合同：

- 报刊中缝、装订、纸边、夹子、折角、贴纸、印章、低多边形主图为 `no_text_rects`。
- 头版标题、摘要、版位名、图片窗、签批字段、CTA 文案各自拥有独立 `carrier_rect / inner_rect`，不能共用万能文本框。
- 所有承载动态文字的正面必须 0° 正交；斜纸片只作 no-text 装饰。
- 周刊图像层可以烘焙，但报道标题、期号、版位名、公开取向、传播预估、冲突、按钮文案不能烘焙。
- 填字稿只用于目标图文验收，不能切图、进 atlas 或作为 runtime 底图。
- 运行时状态至少覆盖：空态、1/3 中间态、5/6、满版、选稿、落位目标、冲突、硬阻断、确认送印。
- 资产拼装后补跑 `card_body_opacity_probe / chroma_residue_scan / composite_cleanliness` 等完整性 gate，检查重复印章、接缝、透明洞和旧图泄漏。

## 七、历史稳定功能版的继承边界

### 可以保留的语义

- 顶部轻量阶段感：写成报道 → 定主口径 / 排版 → 发刊回响。
- 左侧候选剪报、中央可见成刊、右侧签批纸三者的职责分工。
- 中央双页周刊作为页面主物件。
- 右侧集中呈现头版定稿、预计传播、冲突和送印 CTA。
- `送印后不可撤` 作为一次明确确认语义，而不是默认按钮名称。
- 候选稿件具有“拿起、放入、已入版”的位置关系。

### 不可带回的内容

- 旧版青色霓虹、终端网格、重像素 / 重半调视觉；本轮视觉真源是两张 clean low-poly benchmark。
- `ISSUE / LAYOUT / PRESS` 与右栏重复表达相同状态。
- 三枚以上签批章、重复不可撤提示和重复“待送印”标签。
- 旧版 3/3 版位结构；当前真实结构是 6 个不同角色版位。
- 烘焙死的报道标题、期号、数值、按钮和签批状态。
- 开发字段、假比例、占位图表和不可验证预测。
- 把历史截图当作视觉真源；它只证明职责和操作关系。

## 八、双版本建议

| 维度 | 方案 A：最小修正 | 方案 B：理想重构 |
|---|---|---|
| 改动范围 | 保留三栏和现有 ActionItem；修 CTA、确认、状态名、玩家语言预览、局部退稿 | 左候选剪报架 + 中央真实双页周刊 + 右签批纸，建立完整资产化组件系统 |
| 保留 | 当前 Godot 信号、两步点击映射、数据结构 | 当前规则、6 个版位、候选池、清空和结算能力；继承历史版职责 |
| 牺牲 | 仍然不像真正排报，只是可用性止血 | 需要新 scene / 组件合同 / asset atlas / 状态矩阵 |
| 成本 | 低—中；主要是 payload 和现有场景重排 | 中—高；需合同板、vertical slice、无字组件、回填和 runtime 绑定 |
| 改善 | 消除误送印和开发公式黑箱 | 同时解决职业幻想、版位映射、信息链和 clean-lowpoly 视觉 |
| 风险 | 视觉上仍可能被读成后台三栏 | 6 个槽在 1920×1080 中可能密度过高，必须先用真实中文 filled mock 压测 |
| frozen 合同 | 未发现现有 editorial UI 几何合同；不涉及升版 | 先建立 v0.1 合同，用户确认后冻结；后续再改几何需升版并重跑整屏回填 |

**明确推荐方案 B。** 用户当前目标就是报道填入报刊界面的风格稿并进入资产化链路，方案 A 只能止住 P0，无法让页面第一眼成为“主编在排一期周刊”。

## 九、filled-state text mock 必须同屏可见的事实

1. 当前期号 / 周次。
2. 当前拿起的候选稿件。
3. 每篇稿件的报道类型、公开取向、主话题、有效传播值。
4. 6 个版位的角色差异；头版必须显著大于内页。
5. 已入版稿件与其版位的一一对应。
6. 当前头版定稿。
7. 空版数量及真实代价。
8. 同题疲劳和公开取向冲突；只在实际命中时出现。
9. 势力硬禁令或其它发刊阻断。
10. 预计扩散 / 售出、净收益、下周订阅三个核心结果层。
11. 唯一主 CTA `签批送印` 及不可逆确认语义。

不应默认同屏出现：全部内部乘数、原始枚举名、调试计数、公式分解、重复阶段状态、重复警告章。

## 十、给 UI Designer 的硬约束

- 页面第一眼必须读成“主编正在把报道排进本期周刊并签批送印”，不能读成三栏后台、KPI 面板或旧档案表格。
- 桌面 1920×1080；不做移动端方案。
- 保留当前机制：选候选稿 → 指定版位 → 清空 → 发刊；不自行新增路线规划、证据墙、广告版等不存在功能。
- 点击映射可以继续使用，不强制拖拽；若展示拖拽，必须同时保留点击可达。
- 中央报刊必须是最大主物件，建议占主要工作区宽度 52% 以上。
- 6 个版位必须用面积和位置体现角色差异，不能只靠倍率文字。
- 右栏只做完整复核和 CTA，不承载开发公式。
- CTA 固定在右下视线终点，和清空动作分离。
- 候选、落位目标、已入版、冲突、阻断不得只靠颜色区分。
- 采用两张 clean-lowpoly benchmark 的深海军蓝主场、暖灰 / 象牙纸、橄榄、芥黄、钴蓝、低饱和锈红和大块低多边形异常图；禁止泛黄旧纸、脏污、写实摄影噪声、旧档案气质、细密三角网和 SaaS 白卡。
- 正式文书基底用正体字；个人批注必须是独立贴上的便签；贴纸必须有独立模切边和附着关系。
- `filled_state_text_mock` 使用真实中文和当前报道内容，但所有动态文字都只是目标层，不能作为生产底图。
- 必须附元素对照表和文字安全区表，明确 `visible_color_module_rects → carrier_rects → inner_rects → glyph bbox`。
- mock 阶段不能声称 runtime hover、pressed、拖拽、确认和动效已经实现。

## 十一、待确认项

1. GDD 中 `required_slots_filled` 的真实定义是什么：仅头版必填、最少 N 个版位、还是 6 个全填？当前代码无任何发刊有效性阻断。
2. 空版是否允许送印；如果允许，真实损失需要由哪个 `settlement_preview` 字段提供？
3. 势力硬禁令当前是否已经有可读取字段，还是本期先只预留签批纸槽位？
4. `同题疲劳 / public_stance / stance_clash` 当前 runtime article 数据是否已接入；若尚未接入，filled mock 可以按 GDD 展示目标，但必须标注“目标字段，待实现”。
5. 已入版稿件是否允许直接换位 / 退稿；当前实现实际上只能绕路或全清。
6. 主图是每篇稿件独立动态报道图，还是首轮仅头版 / 专题拥有主图？这决定图像资产量和 6 槽密度。

## 十二、验收测试问题

- 陌生人看改进后静态截图 5 秒，能否说出“我在排一期周刊，头版是谁，还有一处空版，右边可以送印”？
- 指定任务“把 M330 稿件移到头版头条”，是否能在两次清晰操作内完成？
- 已入版稿件能否在不清空整期的情况下移动或退回候选？
- 选稿后，玩家能否不用读说明就识别当前稿件和可放槽？
- 5/6 版面时，玩家能否准确回答“能不能送印、会损失什么”？
- 命中同题疲劳或公开冲突时，风险是否只出现一处主承载位，并靠近送印判断？
- 最长中文标题、两位数期号、两位数计数、空态 / 5/6 / 满态是否都不压中缝、夹子、纸边和图片窗？
- `default / hover / selected / placed / blocked / warning / confirm` 是否同时通过状态与视觉安全区？
- 点击送印后是否先进入可读确认态，而不是直接跳结算？
- runtime 落地后在 1920×1080、1600×900、1366×768 三个桌面 16:9 视口中，中央周刊是否仍保持主物件地位？

## 十三、Top 3 ROI

1. **建立“签批送印”预检与确认** — 直接消除不可逆误发和 GDD / 实现缺口，成本相对最低。
2. **中央改为真实 6 版位周刊对象** — 一次解决头版权重、空间映射和主编职业幻想，是本轮风格稿的核心。
3. **把右栏公式翻译为收益 / 风险 / 倾向** — 不改结算机制即可大幅缩短排版判断链。

**时间线：**

- **立即：** 明确发刊有效性规则；UI Designer 产出 `filled_state_text_mock` 和元素 / 安全区表。
- **短期：** 用户确认整屏职责和 6 槽容量后，建立组件合同板并做一个版位类的 vertical slice。
- **中期：** 扩无字组件、状态 atlas、Godot 动态绑定、多状态截图和送印动效验收。
