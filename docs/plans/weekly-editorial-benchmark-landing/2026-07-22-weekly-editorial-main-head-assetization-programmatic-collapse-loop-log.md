# 发刊主头版资产化“生图退化为程序线框”偏差 Loop Log

## 结论

主头版钴蓝资产化预演 v1 被用户否决。它虽然通过尺寸、坐标和状态审计，但最终可见造型主要由脚本重新绘制的矩形、直线、角标和色条构成；真实生图只剩纸纹，因此再次退化为程序 UI。该预演只能保留为失败证据，不得推广到候选卡或正式 Godot 界面。

## 影响

- 撤销此前 UI / UX 对该预演的视觉放行；它们只证明了几何和状态没有漂移，不能证明美术成立。
- 方案 1 的钴蓝配色偏好、现有 `main_head_slot 442×374` 几何合同继续有效；本次被否决的是资产生成与拆分方法。
- `candidate_card` 扩产暂停。正式 Godot 发刊界面、组件合同、GDD 和正式资产 manifest 继续不动。

## 这次错在

1. 生图 prompt 以旧程序空壳为主要编辑目标，并把任务限制为暖纸、钴蓝线和少量色标，生成源本身已经是“空白 UI 模板”，没有继承标杆中的杂志实物、自然纸边、照片压角和编辑排版节奏。
2. `build_weekly_editorial_main_head_cobalt_v1.py` 并非只做裁切与拆层：它截取并拉伸纸纹、把生图源模糊到低透明度，再用 `ImageDraw` 重画边框、角括号、色条、状态框和按钮皮肤。最终风格由代码决定，生图没有承担美术造型。
3. 固定橄榄色条位于 2× 画布 `y=44–54`，折算运行时为 `y=22–27`，直接侵入 eyebrow 的 `y=14–37`，造成用户截图中的文字与图形叠化。
4. 自动审计只比较 Control 矩形和按钮数量，没有检查固定装饰的非透明像素是否进入动态文字安全区；缩小后的状态总览也掩盖了 1× 叠化。
5. 父级把“坐标能放回原位”误判成“美术已经成功转译”，重复了此前已经记录过的“程序换肤”错误。

## 正确的下一轮方法

1. 先制作完整 `visual master`，不先拆层：在最终 `884×748` 的 2× 画布上，保留合同中的标题、横图、meta 和按钮安全区，以用户给出的杂志标杆为美术第一真值，生成完整的纸件外观。
2. 先把动态中文和真实报道图叠到母件上，向用户展示 1:1 局部和 1920×1080 整屏；通过“与标杆同族、文字不叠化、放回整屏仍成立”三个 Gate 后，才允许拆件。
3. 由已通过的母件反向拆出纸面、固定印刷物、照片槽压边和状态纹理；缺失区域通过透明蒙版或局部修补恢复。脚本只允许裁切、缩放、蒙版、alpha 分离、拼接和检测，不得重新设计可见边框、色条、角标或按钮外形。
4. Godot 继续负责动态文字、报道图、状态显隐、命中和动画；程序线框只可用于调试证据，不可进入最终美术层。

## 新增硬检查

- 固定装饰层与 eyebrow、headline、meta、按钮文字安全区的非透明像素交集必须为零；底纸层单独豁免。
- 必须提供 1:1 局部截图，不能只用缩小总览验收文字与装饰关系。
- 必须并排展示母件与美术标杆，完成去字缩小五秒同族检查；几何审计不能替代美术 Gate。
- 交付清单必须区分“来自真实生图的可见美术”和“程序仅做的蒙版 / 检测”，不得把程序重画描述为拆分。
