# 发刊包装 Mock 候选容量断链 Loop Log

## 三行决策条

- **结论**：`weekly-editorial-packaging-mock-v1` 因候选池容量与操作链不成立而否决 / 降级；它只能作为视觉包装探索与偏差证据，不能继续充当结构真源。
- **影响**：上一稿的单张 `280×264` 大候选卡、双 CTA 和 5/6 展示态全部撤回。中央报刊气氛与右栏物件想法也不因局部可看而自动获批，正式包装必须重新依附本轮功能结构。
- **下一步**：先由用户审核 `8` 篇候选、`6` 张 `288×92` 常显、`2` 张滚动访问、`3/6` 版位与单一禁用签批 CTA 的黑色结构稿；获批后才进入视觉包装，不直接改 Godot。

## 触发

2026-07-17 用户检查包装稿左侧候选区后明确指出：报道数量很多，不可能全部使用接近正方形的大卡；要求基于已确定组件，先输出一版功能合理的黑色结构稿。

## 错误表现

1. 已冻结的 `candidate_card v1.2.0` 是 `288×92` 紧凑横卡，上一稿却把候选来源画成单张约 `280×264` 大卡。
2. 页面只证明“一篇被选报道可以被看见”，没有证明多篇候选能在首屏比较、滚动访问、保持位置与维持唯一选中源。
3. 包装稿在真实列表容量尚未通过前就进入文件夹、纸张和签批夹语法，视觉气氛覆盖了基础功能错误。
4. 右栏出现“计算发行预览”与“签批送印”两层 CTA，而当前 `signoff_panel` 合同只允许一个 `primary_cta`；预览待重算应由状态区解释，并直接禁用签批。

## 根因

### 1. 产物阶段误判

在候选池的最小 / 常态 / 压力容量尚未放行前直接制作 `filled_state_text_mock`，把“单篇选中展示态”误当成“候选列表结构已成立”。这是 F1“验证等级冒充”的再次复发。

### 2. 同类组件与容量扫描缺失

虽然仓库已有 `candidate_card.json` 和六张常显坐标，但落稿前没有把同类候选实例真实铺满，也没有检查第七 / 八张的访问方式。只画一个代表卡就认为候选组件成立，同时命中 F4“只修点名局部不扫同类”。

### 3. 合同读取没有绑定放行动作

已读到三栏与双版结构，却没有把 `candidate_card 288×92`、候选总数、滚动视口和 `signoff_panel` 单 CTA 设为包装稿的前置阻断项。合同存在，但没有进入截图 gate。

## 当轮修正

- 先由 UX 老哥回归真实候选容量与来源—目标—回流链，再由 UI Designer 冻结精确桌面坐标。
- 新建 `structure_wireframe`：工作区 `1760×920`，三列 `320 / 1040 / 360`，间距 `20`。
- 左栏常态展示候选 `8` 篇；首屏完整显示六张 `288×92` 横卡，卡七 / 八完全位于滚动区外，不露半卡。
- 唯一 selected 维持原尺寸与原位置，只增加双线框、左括号和“已选稿”状态槽。
- 中央保留双版六槽，展示 `3/6` 占用、三个空位与一个非文字双边线合法目标。
- 右栏只保留一枚禁用的“签批送印”；`发行预览：待重算`、`空位 3` 与`送印状态：阻断`共同解释禁用原因。
- 生成确定性 `1920×1080` 灰度结构板及 `audit.json`；结构审计全部通过。HTML 交互稿已落盘，但本轮不把未完成浏览器运行验证的交互声称为通过。

## 防复发升级

- **错误家族**：主命中 F1，次命中 F4；更新全局错误家族索引的已知复发次数与案例。
- **包装前容量 Gate**：列表 / 网格类组件在视觉包装前必须实铺 `min / default / max`，至少提供总数、首屏完整可见数、隐藏项可达方式与选中稳定性；只画一个代表实例不得放行。
- **类合同 Gate**：包装稿前必须读取并逐项绑定本页涉及的 class contract；尺寸、状态、CTA 数量任一冲突都回退到 `structure_wireframe`。
- **截图审计**：候选卡数量、尺寸、首屏完整卡数量、第七卡首屏不可见、selected 零位移、版位占用数与 CTA 数量进入确定性审计。
- **沉淀位置**：本次属于已有 F1 / F4 家族在发刊资产线的实例，不新增另一套全局口号；修正写入本 Loop Log、包装稿 README、状态页与错误家族索引。
