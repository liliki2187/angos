# 落地 Brief：危险任务「暴露」副轴（多轴读数首版）

> 交接用实现说明，可直接交给执行 AI。设计决策已登记：`docs/design-decisions/core-mechanics.md` A195。
> 与《判定弹窗重投 + 复核点》brief（`docs/plans/dice-reroll-review-points/落地brief-2026-07-14.md`）相互独立，可先后或同时实现；若重投已落地，暴露预览会随重投后的重新渲染自动更新，无需额外适配。
> 本文分「已实测事实」（已读代码核实）与「待验证假设」（执行方开工先自查）。

## 1. 目标

给带危险标识的任务加一条副轴「暴露」，让结果从「过 / 不过」变成「过了，但有没有留下尾巴」：

- **产生**：判定最终停骰状态中，职员骰的「无效面」（空面，或属性不在本任务需求里）**每 2 个 → 本次暴露 +1**。包装：现场停留太久、问错了人、留下了痕迹。
- **积累**：暴露按区域、按周累计。
- **回响**：某区域本周暴露累计达到阈值（首版 2 点），下周编辑部简报出现一条对应文本反馈（「有人在打听你们的记者」类钩子）。**前期只到文本为止，无数值惩罚。**
- **干净奖励**：无暴露且超额达标（总有效点 ≥ 目标 +2）→ 附赠一条 Tier 2 线索「干净利落的独家」。

## 2. 硬约束（仓库协作规则，必须遵守）

1. 只做局部嵌入：不重排判定弹窗、结算页、简报页布局。
2. **首版只在 `m.riskTier === "high"` 且非黑骰的任务上启用**；普通低压任务、黑骰任务、线索调查一律不启用（普通任务保持干净是设计边界，不是遗漏）。
3. 不做数值惩罚：暴露不扣宏观属性、不加对手、不改成功率；回响只是简报文本。
4. 机制必须在决策现场可见（判定弹窗内），不能只出现在结算文字里。
5. 交付附 1–3 张真实浏览器截图（决策现场预览 / 结算行 / 下周简报回响三个状态）。
6. 不改 `world-mysteries-full-chain.html` 里 `data-obsolete-inline-script` 的废弃内联脚本副本；改完把底部 `<script src>` 版本号更新为 `?v=20260714-exposure-axis-v1`。

## 5. 待验证假设

- 行号漂移：按函数名 / 字符串搜索定位。
- `m.regionId` 在所有走 `runMission` 的危险任务上存在（队列任务 `rec.regionId` 有先例）；若个别任务缺失，暴露累计落到 `"unknown"` 桶并跳过回响。

## 6. 实现步骤

### 6.1 常量与状态

```js
const EXPOSURE_INVALID_FACES_PER_POINT = 2;   // 每 2 个无效面 → 暴露 +1
const EXPOSURE_ECHO_THRESHOLD = 2;            // 周内区域暴露 ≥2 → 下周简报回响
// state 新增：
regionExposure: {},        // { regionId: number } 本周累计
exposureEchoes: [],        // 下周简报要显示的回响 [{ regionId, regionName, amount, text }]
```

`nextWeek()` 内（在其它周重置附近）：**先结算回响，再清零**：

```js
state.exposureEchoes = Object.entries(state.regionExposure || {})
  .filter(([, n]) => n >= EXPOSURE_ECHO_THRESHOLD)
  .map(([regionId, n]) => {
    const region = REGIONS.find((x) => x.id === regionId);
    return { regionId, regionName: region ? region.name : "未知区域", amount: n, text: pickExposureEchoText(region ? region.name : "某地", n) };
  });
state.regionExposure = {};
```

### 6.2 核心函数

```js
function missionHasExposureAxis(m) {
  return !!m && m.riskTier === "high" && !m.isBlackDiceTask;
}

// 数最终停骰状态里职员骰的无效面（与是否计入无关）
function countInvalidStaffFaces(mission, rolls) {
  const need = (mission && mission.need) || {};
  return (rolls || []).filter((r) => {
    if (r.kind !== "staff" && r.kind !== "tempStaff") return false; // 道具骰、黑骰不算
    const f = r.face || {};
    if (f.blank) return true;
    return !(f.attr && need[f.attr] != null);
  }).length;
}

function exposureFromRolls(mission, rolls) {
  if (!missionHasExposureAxis(mission)) return 0;
  return Math.floor(countInvalidStaffFaces(mission, rolls) / EXPOSURE_INVALID_FACES_PER_POINT);
}

function pickExposureEchoText(regionName, amount) {
  const pool = [
    `${regionName}的线人来电：最近有人在打听你们记者的行踪。`,
    `${regionName}方向传来消息：上周的走访被人记了下来。`,
    `一封没有署名的信提到，${regionName}那边「有人对你们很好奇」。`,
  ];
  return pool[Math.floor(Math.random() * pool.length)];
}
```

### 6.3 结算挂接（`runMission` 内，角色骰分支）

在 `check = { characterDice: true, ... }` 之后、`applyStandardOutcome` 调用之前插入：

```js
const exposureGained = exposureFromRolls(m, rolls);
if (exposureGained > 0) {
  state.regionExposure[m.regionId || "unknown"] = (state.regionExposure[m.regionId || "unknown"] || 0) + exposureGained;
  lines.push(`暴露 +${exposureGained}：现场留下了痕迹，有人注意到了你们的走访。`);
  log(`暴露 +${exposureGained}（${m.name}）`);
}
```

干净超额奖励（同处，仅暴露副轴任务）：

```js
if (missionHasExposureAxis(m) && diceSelection.success && exposureGained === 0) {
  const total = contributionTotalForNeed(m.need || {}, diceSelection.sum || {});
  if (total >= needTargetValue(m.need || {}) + 2) {
    lines.push("干净利落：无人察觉的超额收获。");
    addMissionClue(m, "干净利落的独家", 2, rewards, "无暴露超额达标：附赠线索（Tier 2）", tier);
  }
}
```

注意：`mapHighRiskTier` / `applyHighRiskOutcome` / `applyStandardOutcome` 本体一律不改。

### 6.4 决策现场预览（判定弹窗）

新增 helper，插入 `showDiceSelectionPopup` 的 `render()` 内 aside 栈（`diceSubmitPreviewHtml` 之前），仅 `missionHasExposureAxis(mission)` 且 `stage === "select"` 时渲染：

```js
function exposurePreviewHtml(mission, rolls) {
  const invalid = countInvalidStaffFaces(mission, rolls);
  const gain = Math.floor(invalid / EXPOSURE_INVALID_FACES_PER_POINT);
  return `<section class="dice-exposure-preview" aria-label="暴露压力">
    <strong>暴露压力</strong>
    <div>本任务会留下痕迹：最终无效面每 ${EXPOSURE_INVALID_FACES_PER_POINT} 个 → 暴露 +1。</div>
    <div>当前无效面 <b>${invalid}</b> 个${gain > 0 ? ` · 提交后暴露 <b>+${gain}</b>` : " · 目前不会暴露"}</div>
  </section>`;
}
```

每次 `render()` 重算（若重投功能已上线，重投后数字自动刷新）。

## 7. 调参旋钮（首版值，均可后续调整）

| 参数 | 首版 | 说明 |
|------|------|------|
| 无效面 → 暴露换算 | 2:1 | 3 人队最多 3 无效面 → 单次最多暴露 1 |
| 周回响阈值 | 2 | 定 3 的话首周几乎触发不了，违背「首区就能感知」原则 |
| 干净超额线 | 目标 +2 | 与黑骰大成功口径一致 |
| 适用范围 | 仅 `riskTier === "high"` | 验证成立后再谈类型包扩展 |

## 8. 不要做

- 不给普通任务、黑骰任务、线索调查挂暴露。
- 不做污染 / 损耗等其它副轴。
- 不做暴露的数值惩罚、对手压力加成、任务关闭。
- 不改 `mapHighRiskTier` 五档映射与各 outcome 函数本体。
- 不做常驻「暴露值」统计面板（回响保持现场化文本）。

## 9. 验收清单

流程：打开 demo → 派 3 人做任一危险任务（`riskTier === "high"`，地图上带「!」/「危险」徽标）→ 判定 → 跨周。

1. 危险任务判定弹窗停骰后，右侧出现「暴露压力」预览，无效面数量与骰面实况一致。
2. 非危险任务、黑骰任务弹窗**没有**该预览。
3. 最终 2 个无效面 → 结算页出现「暴露 +1」行；1 个无效面 → 不出现。
4. 无暴露且总有效点 ≥ 目标 +2 → 结算多一条「干净利落的独家」Tier 2 线索。
5. 同区域本周暴露累计 ≥2 → 点「进入下一周」后，简报页出现一条回响文本；未达阈值不出现。
6. 跨周后 `state.regionExposure` 清零，回响文本只在新一周简报出现一次。
7. 宏观五维属性、成功率、任务开闭均不受暴露影响（对照改动前后同一任务）。
8. 截图 1–3 张：弹窗暴露预览 / 结算暴露行 / 下周简报回响。
