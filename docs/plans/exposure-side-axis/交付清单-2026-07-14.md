# 危险任务「暴露」副轴交付清单

## 决策条

- **结论**：HTML 全链原型中的危险任务「暴露」副轴已通过本轮运行验收，可以进入玩家共同评测与参数试玩。
- **影响**：已验证停骰预览、重投刷新、独立结算、零暴露超额奖励、区域周累计、下周文本回声及排除边界；不能据此声称 `2:1 / 阈值 2 / 目标 +2` 已完成平衡，也不代表 Godot 已同步。
- **下一步**：用当前试行参数连续玩若干危险任务，重点判断它是否让“选骰 / 重投”多出真实取舍，再决定保留、改数或撤回。

## 详情

- **一句话结论**：本轮把 A195 落成可运行的 HTML 副轴闭环，玩家在提交前就能读到“本次是否留痕”和“是否满足干净奖励”；下一步应评测玩法感受，不应继续添加第三条副轴。
- **我实际做了什么**：危险标识、非黑骰且非线索调查的角色骰判定会读取最终停骰无效面；每 2 个无效面产生暴露 +1。判定右栏加入紧凑暴露卡，重投 720ms 内隐藏旧值；结果页加入互斥短回执；零暴露且有效点达到目标 +2 时附赠 Tier 2 线索；有效区域按周累计达到 2 后，下周简报显示带来源的现场化回声并清空累计。同步事件检定 GDD、A195 和归档总集。
- **现在卡在哪里**：无工程阻断；只剩副轴是否真正改善决策密度、参数是否合适、回声是否值得进一步产生系统后果，需要玩家试玩判断。
- **为什么不能跳过**：确定性调试路径能证明状态机与 UI 正确，但不能证明玩家是否会为了少 1 点暴露而放弃高点骰、是否会觉得奖励值得、周回声能否形成记忆。
- **下一步怎么验证**：至少覆盖 0、1、2–3、4 个无效面的危险任务；记录提交前是否理解暴露与计入无关、是否使用重投清掉暴露、是否为 Tier 2 奖励继续优化，以及下周回声是否被记住。
- **本轮不要做**：不要把三项试行值写成永久定值；不要给回声追加宏观惩罚；不要把暴露扩到普通任务、黑骰或线索调查；不要立即叠加污染 / 损耗等第三条副轴。

## 路由记录

- **任务一句话**：按已采纳 A195，在现有全链 HTML 判定弹窗中落地危险任务暴露预览、结算与跨周回声。
- **任务类型**：玩法、UI、状态逻辑、代码、GDD。
- **风险等级**：`risky`。
- **当前阶段**：运行实现与共同评测前验收。
- **目标载体**：桌面 16:9 HTML 全链原型、GDD、决策记录、截图与 WebM。
- **本轮交付物类型**：`implementation`、`delivery_manifest`、`screenshot`、`video`。
- **被路由对象类型**：`runtime_state_preview`。
- **本轮只验证**：暴露副轴能否在决策现场被理解，是否只依赖最终停骰，重投时是否刷新，结算与周回声是否闭环，是否不污染原成败与宏观数值。
- **本轮不做**：竞品研究续篇、Godot 实现、数值定案、暴露惩罚、常驻统计面板、新美术资产或全局 UI 重做。
- **本轮必读真源**：五份顶层 GDD、`design/gdd/event-check-resolution.md`、A195、协作与 UI 指南、workflow harness、截图指引、原落地 brief。
- **必调 agent**：改进现有 UI，先由 `ux_laoge` 诊断，再由 `ui_designer` 给紧凑落地规格；两者均已完成只读互审。
- **明确不调的 agent 与原因**：未调用冷备 `game_numerical` 与 `game_logic_check`，因为本轮按已采纳试行参数实现，不做平衡定案或正式防爆审查；已向用户提示共同评测阶段命中两者的解冻条件。未调用美术 agent，因为没有新增美术资产、视觉风格稿或真源候选。
- **停止条件**：只要出现线索调查 / 黑骰误挂副轴、重投仍显示旧暴露、计入选择改变暴露、区域累计直接展示、回声改宏观数值、未登记区域生成虚假回声、桌面弹窗溢出或 GDD 与实现不一致，即停止交付并返工。

- **产物类型**：`runtime_state_preview`。
- **风险等级**：`risky`。
- **它能证明**：在真实全链页面中，3 个无效员工骰会预览暴露 +1；重投期间旧无效面、旧暴露与旧奖励进度隐藏；重投成 0 无效面并计入 6 点后会预告并发放 Tier 2「干净利落的独家」；区域累计 2 会生成一次带纽约市来源的下周文本回声并清空，累计 1 不生成；副轴应用前后宏观数值不变。
