# Loop Log：把世界地图地区入口误套为区域地图固定热点

## 决策条

- **结论**：此前“五个固定热点”功能前提错误；世界地图按地区选择，区域地图应按事件坐标动态显示 `0–N` 个图钉，同一区域允许多个标记。
- **影响**：基于旧五热点对第三张地图做的安全区清障失去功能必要性；原始第三案恢复为美术方向真值，v2 / v3 不进入资产链。
- **下一步**：本轮只修正文档口径并标记实现出入；后续真正重构区域地图时，再把固定 hotspot 数组替换为事件节点数据、碰撞避让、标签翻转与多节点聚合。

## 原始问题

父级把 `region_task_asset_manifest.json` 中 northwest / central / east / southwest / southeast 五个旧热点当作冻结需求，并要求地图美术为这些位置预留空区。用户指出：世界地图确实是一地区一入口，但进入区域后，事件可以发生在地图任意地点，同一地理版块也可同时存在多个事件；实际交互对象应是动态事件图钉，而非五个版块中心。

## 失败归因

- **层级混淆**：把世界地图的 `region-centric` 选择模型下沉为区域地图的 `event-centric` 节点模型。
- **真源优先级误判**：现行 GDD 已写明区域任务点需碰撞避让、不能只依赖固定坐标；父级却把旧资产 manifest 当成更高优先级真源，未先检查功能语义。
- **错误下游化**：UI / UX 与生图流程都在优化五点安全区，但优化的是错误前提，继而造成边框删除和整图重采样等无效返工。

## 当前处理

1. A204 正式区分世界地图与区域地图交互主语。
2. A200 撤回“五个固定热点通过后才能接入”的条件；第三张原图恢复为当前美术真值。
3. A203 连续边框规则保留，但不再要求为旧热点改道。
4. `design/gdd/exploration-and-node-dispatch.md` 与 legacy 总集同步动态 `0–N` 节点、同区多标记和碰撞避让口径。
5. 本轮不修改 manifest、Godot 或 HTML；明确保留“文档 / 实现不一致”提醒，等待正式实现任务再升合同版本与补运行时验收。

## 复发保护

- 地图需求必须先回答点击主语：世界层点击地区，区域层点击事件，派遣层点击员工与签批动作。
- 看到固定坐标 / hotspot 数组时，先判断它是内容数据、布局默认值还是旧实现夹具，不得直接反推成玩法规则。
- 区域地图验收用 `0 / 1 / 多节点 / 同区密集节点` 四种状态，不再用“五个固定点都空出来”作为底图 Gate。

## 沉淀

- **触发来源**：用户功能纠错。
- **失败类型**：交互层级与数据模型误判；旧实现夹具冒充功能真源。
- **本轮处理**：撤回错误前提、停止无效美术修正、同步 GDD / 采纳记录、保留实现出入提醒。
- **状态**：已完成文档纠偏；实现尚未修改。
