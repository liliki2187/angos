## 直接原因

合成脚本为了纠正生图模型的坐标漂移，先贴入了包含内部纸件的完整大区，又把内部 carrier 分别贴了一次：

- 左栏：完整 folder 位于 `build_region_task_surrounding_ui_visual_target_v1.py:74`，header / 两张任务卡 / footer 又在 `:75-80` 重复贴入；
- 右 dossier：完整 dossier 位于 `:83`，header / summary / metadata / risk / CTA 又在 `:84-88` 重复贴入；
- 底栏：完整行动带位于 `:91`，推进票与长回条又在 `:94-95` 重复贴入。

因此出现了双层纸檐、重复底边、背板再套背板和 CTA 托板，并非单纯线条稍多。

## 三处 P1

1. 左栏从 outer folder、header 背纸、任务卡背衬、任务卡正面到图标纸槽形成多级套娃；同级任务纸条被再次包装。
2. 底栏由 outer band 包 inner receipt，左 action 再成为完整内票，中央与右侧继续叠加端帽和内外框。
3. dossier 已有 olive backing 与 warm page，metadata、risk、CTA 又各自成为多层独立纸件；只读信息与可操作对象因此同构。

## 为什么上一轮 GO 失守

- 窄回归只复验了文字安全区、建议完整性和 CTA 权重，却错误地把“原问题关闭”外推为“整张视觉目标通过”。
- 25% 检查只证明了大区综合色彩与决策链成立，无法证明 100% 下的纸层克制。
- 三方都把“材质统一、carrier 清楚”误判为“嵌套合理”，没有统计主轮廓数、最大物理嵌套层数与平行边频率。

## 后续硬 Gate

1. 每个语义层最多一道闭合轮廓。
2. 每个大区只有一个主轮廓；嵌套物理纸层最多两层。
3. 同级任务 slip 可以并列，但每张只允许一个外缘；selected 只能增加类型色脊或单层局部后衬。
4. header、metadata、risk、schedule 等只读 carrier 默认使用留白、印刷色带或单条规则线，不新增完整四边纸件。
5. CTA 静态态只允许一层动作纸件；focus / pressed 轮廓只在对应运行状态出现。
6. 100% 局部中不得连续出现三道平行边；视觉目标升格前必须同时检查 100% 局部与 25% 整屏。
7. 窄回归只能关闭指定问题，不能自动授予整屏 GO；整屏 GO 必须重新执行完整结构审计。

## 下一步边界

用户若要求继续，只做一轮同路线定向减层：优先级为右 dossier → 左任务卡 → 底部长票。保留地图、配色、文字系统与大区布局；不重开 A / B / C，不改 Godot，不拆生产组件。
