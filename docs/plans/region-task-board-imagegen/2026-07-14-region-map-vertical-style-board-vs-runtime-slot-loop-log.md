# Loop Log：竖版三案风格板未对齐真实地图槽

## 决策条

- **结论**：当前三张竖向地图只能保留为块面塑造语言比较板，不能直接作为地区任务台的地图底图或生产候选。
- **影响**：竖版比例会在真实中央地图槽中产生约四成横向空置或纵向裁切，并压缩五热点与短签避让空间；烘焙地名、白路线和节点也会与运行时状态层冲突。
- **下一步**：不推翻已确认的美术方向；A / B / C 分别按原生 `960×742`、无字、无 pin 输出，比较板只做 contact sheet，不从比较板反向裁图。

## 详情

- **一句话结论**：我先按“同屏三案看得清”选择了竖条拼版，却没有先套地区任务台真实地图资产合同，导致比较构图与运行时承载比例脱节。
- **当前产物类型**：`style_board / shaping exploration`，能比较地形大面、剪纸层次和地标节奏，不能证明 `rt_map_base_clean` 已可落地。
- **实际合同**：独立地图底图为 `960×742`（约 `1.29:1` 横版）；`760×760` 仅是现有 v3 整屏视觉锁定图上的透明热点层，不是新地图资产的尺寸授权。
- **当前三案**：内部地图约为 `0.78–0.81:1` 竖版。等高放入 `960×742` 后只剩约 `580–601px` 有效宽度，约 `37%–40%` 槽宽空置；铺满宽度则必须裁掉约 `37%–40%` 的纵向内容。
- **交互后果**：现行五热点按三列两层横向分布，pin 为 `64×64`、热区为 `64×86`，短签为 `200×72`。竖版会把东西向空间压成上下串列，短签更易碰左右边界或侵入左右栏。
- **动态层冲突**：候选图中的地区名、粗白路线和白色节点已形成可操作暗示；正式底图合同要求无文字、无 pin、无节点、无任务牌，正式路线、高亮、pin 与短签必须由独立 atlas / runtime 层承担。
- **本轮处理**：当前图降级为风格语言板；不进入 atlas、manifest 或 Godot 回填。

## 后续生成约束

1. A / B / C 每案先独立生成 `960×742` 原生源图，再额外制作比较 contact sheet。
2. 五个既有热点坐标保持不变；每个 anchor 周围至少保留约 `112×112` 安静区，并在一侧预留约 `220×88` 低细节短签走廊。
3. `rt_map_base_clean` 只保留概括陆水关系、大地形面与低权重非交互纹理；无文字、无 pin、无节点、无任务牌。
4. `rt_map_route_layer` 与底图 `1:1` 对齐，正式路线 / 高亮路线独立承载；pin 与短签继续由现有 atlas / runtime 层承担。
5. A 的地形大面和 C 的地标节奏可继承；B 的纸层高差必须降权，避免边缘被误读为可点击区域或遮挡层。
6. 这套修正不更改 frozen manifest；若要改成竖版 / 方形地图槽或重排五热点，必须升合同版本并重跑整屏回填与状态测试。
