# Loop Log：地图比例锁定通过，但中央主舞台余高没有职责归属

## 决策条

- **结论**：当前区域事件选择界面 v2 降级为带 P1 版式缺口的 `filled_state_visual_mock`；地图比例和事件坐标语言可保留，但整屏版式不能按现稿继续资产化。
- **影响**：地图自身虽以 `960×742` 正确回填，中央槽底部仍留下约百像素无标题、无边界转换、无功能的深蓝空带，使地图从空间主语退化成嵌入式插图，并让玩家误以为这里漏了 footer 或状态栏。
- **下一步**：保留第三张地图和现有事件 pin；新版只重排中央地图板与真实底部日程条，不拉伸、不裁切、不补绘地图，也不重生左右两栏。

## 详情

- **触发来源**：用户复核截图时指出“中间地图部分上下缺一块”，并询问此前界面如何处理。
- **原始问题**：上一轮只检查了已选地图是否按 `960×742` 原比例回填，却没有检查“地图板之外的剩余纵向空间由谁承担”。交付清单因此错误声称“地图、索引、dossier 与 CTA 的整屏权重可以成立”。
- **失败归因**：可读性 / 容器职责 / 交付放行误判。几何像素正确不等于主舞台版式成立；`contain` 式放入较高容器后出现的空带必须有真实模块归属，不能作为无定义负空间交付。
- **旧稿证据**：`docs/screenshots/2026-06-18-region-task-v3-6-separated-advance/01-region-task-v3-6-separated-advance.png` 中，地图填满自己的地图框，剩余高度由独立底部全局日程条承担；`docs/plans/region-task-board-assetized-production-spec.md` 第 73、84、353、397 行同样要求区域任务台保留底部日程条与独立“推进一天”，且与右侧任务 CTA 分离。
- **当前产物处理**：地图原图、事件 pin 语言、左索引与右详情的方向继续保留；整屏 v2 不再作为下一步资产化依据，必须先做版式修正版。
- **复发判定**：命中 F1「验证等级冒充」的相邻化身——局部比例 Gate 通过被误当成整屏权重成立；现有 manifest 文本检查无法替代主舞台职责的肉眼反向读法。
- **沉淀判断**：本次先更新原交付清单并登记本 Loop Log；不新开 GDD 规则，不重复写入 UI 指南。若同类“主舞台空带无归属”再次出现，再升级为独立家族或机器可读的整屏容器职责 Gate。

## 防复发检查

后续地图类整屏稿交付前，除检查地图源比例外，还必须回答：

1. 地图是否填满被命名为“地图板”的容器，只保留有意的框边 / 纸边；
2. 地图板外的每一块大面积留白是否有明确模块名称、功能和边界转换；
3. 若存在底部日程条、回执或图例，是否来自现行 GDD / UI 合同，而不是为了填洞临时发明；
4. 地图、底部全局动作与右侧任务 CTA 是否保持清晰空间分离；
5. 整屏反向读法是否仍会把地图看成“插图”或把空带看成“漏资源”。
