# 区域任务组件母版“只贴图、无说明”交付误判 Loop Log

> 日期：2026-07-17
> 触发：用户复核母版 v3 后询问“这是几版让我选吗”，并明确要求下次不要只贴图，要给必要介绍和文本。

## 结论

母版内容本身是三版选型板，但交付消息只展示图片，没有说明左 / 中 / 右的方案映射、推荐项、当前 Gate 与用户需要作出的决策，导致“无字资产”被错误扩张成“无字交付”。该交付不合格。

## 影响

- 用户无法在第一眼确认图片是单方案元素板还是三方案选型板。
- A / B / C 的控制变量、UI / UX 基于 25% 实证改荐 C 的结论，以及“尚非生产资产”的边界全部丢失。
- 用户需要主动追问本应由交付消息承担的最基本上下文。

## 根因

1. 把“母版图片内部不烘焙文字”误当成“对话交付不得附文字”。
2. 只检查了图像产物是否落盘，没有检查用户是否能理解产物用途和下一步决策。
3. 最终回复缺少选型交付的最小四项：用途、方案映射、推荐与理由、当前放行边界。

## 修正规则

后续任何候选图、母版、风格稿或 A/B/C 选型图，即使图片本体必须无字，交付消息也必须至少说明：

1. 这张图是什么、包含几版；
2. 左 / 中 / 右或上 / 下分别对应什么；
3. 当前推荐哪版及一条核心理由；
4. 本次让用户确认什么，以及确认前哪些动作仍冻结。

图片负责视觉证据，文字负责决策上下文；二者不得互相替代。只有用户在当前回合明确要求“只发图”时才可省略介绍。

## 本次补正

- 明确 v3 为三版选型母版：左 A 侧脊、中 B 错层、右 C 切角。
- 明确 UI / UX 的当前推荐为 C，并建议吸收 B 的安静内容面与 A 的单侧纸脊。
- 明确当前仍处于 `pending_user_variant_selection`，未获选择前不裁正式 alpha、不替换 Godot、不解锁 event card。

## 状态

规则已同步至资产化 UI 生产链、设计采纳记录与区域任务生图线 STATUS；本 Loop 关闭。
