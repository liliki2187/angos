# Loop Log：区域任务台组件裁切清单必须先于组件生图

> 日期：2026-07-16
> 触发：用户再次强调必须提前评估可裁切性，并要求每个需要裁切的功能组件都先确定，避免为了整屏美观生成无法干净裁切的组件。

## 本次错因

2026-07-15 的落地前报告已经禁止整屏裁切，但仍停留在“约 8 类无字外壳”和宽泛组件表：

- 没有为每个正式 class 分配唯一 `asset_id`；
- 没有统一登记 alpha padding、外投影所有权、母版数、frame roster 与状态派生；
- “固定透明母版、矩形 NinePatch、不透明底图、程序组件”仍混在同一张表里；
- 因此流程虽然口头上知道不能直接挖图，却仍可能在下一轮 prompt 中重新追求整屏完成度，之后再被迫手抠。

这不是新风格问题，而是既有资产化规则在页面级证据上没有闭合，命中已知的“整屏图先于组件合同”“视觉完成度替代生产资格”和“验证阶段误标”错误家族。

## 本轮纠正

1. E2 明确降级为 `filled_state_text_mock`；正式直接裁切数冻结为 0。
2. 新增 `component_cutout_inventory_v1.json`，登记全部 18 个 class。
3. 9 类固定透明母版只接受单件、无字、自带干净 alpha 的源；无 alpha 直接退回，不以复杂手抠补救。
4. 6 类规则矩形改走 NinePatch，2 类走不透明复用 / 平铺，cluster 走程序，不再把所有美术效果都转成裁切任务。
5. 所有互动阴影、pressed 位移、状态色、文字和 glyph 的所有权回到 Godot；位图不再焊死交互反馈。
6. 第一轮只允许 pin + 短签纵向切片，未通过 alpha、缩小、anchor、状态和回插证据时不扩产。

## Gate 增量

全局 `assetized-ui-production-chain.md` 和 workflow gate 已经要求 class 清单、文字 / 几何合同、纵向切片和回插证据，本轮不再添加重复的全局规则。页面级新增的强制证据是：

- 任何 prompt / 资产文件必须引用 inventory 中的 `asset_id`；
- 未登记 class、未冻结生产路线或 `production_authorized=false` 的资产不得生成；
- 每个生成资产必须逐项满足自身 alpha / padding / shadow / baked-content 合同；
- 整屏效果稿永远不能反向取得组件源资格。

## 回归判定

以下任一情况出现即视为同类错误复发并停止扩产：

- 从 E2 或其它整屏图直接抠任务卡、dossier、CTA、pin 或日程票据；
- 用“后面再清字 / 清阴影 / 补边”接受被污染的母版；
- 为不同状态分别生图导致轮廓或 anchor 变化；
- 为了保留漂亮装饰，让夹子、胶带、折角、印章或外投影侵入动态文字区；
- 未经过单类 Godot 回插就开始同类批量生产。
