# 区域任务短签预检图缺少拆分审阅价值 Loop Log

> 日期：2026-07-21  
> 触发：用户指出“输出这个没有审阅价值，希望看到比如如何拆图”

## 误判

父级把用户的“继续”解释为先做精确运行比例与真实中文回填板。该图能够验证缩小可读性，但没有把背板、图钉壳、类型色附件、图标、短签底、端帽和动态文字逐层摊开，因此没有直接回答“这套美术如何拆图、哪些层能独立落地”。

## 根因

- 把“运行比例验证”放在了“资产分层证据”之前。
- 只说明了拆分表，没有把实际透明资源做成可视化爆炸图。
- 将开发侧有用的 preflight 误当成用户侧首要审核产物。

## 纠正

1. 原 4×2 回填板降级为内部 `runtime_scale_secondary_evidence`，不再作为本轮主审图。
2. 新增实际透明层爆炸图，逐项展示源文件、源尺寸、运行尺寸、z-order 和最终组合。
3. 同时导出四类 selected backplate、pin type accent、label type accent 的独立 frame，避免只展示 atlas 条带。
4. 动态标题 / meta 明确标为程序层，不进入 PNG。

## 后续防错规则

当用户问“是否方便拆分 / 如何拆图 / 怎么落地”时，首要证据必须是实际 layer exploded sheet 与 alpha frame inventory；运行比例、文字回填和整屏截图只能作为第二层证据，不能替代拆分图。

## 二次反馈：拆开后暴露为不可冻结结构

用户继续指出：拆图一摊开就能看出，当前微型色片难以实现效果稿中的小纸沿、压合和装饰细节，动态文字也与框体明显不适配。

进一步核查确认问题不在展示方式，而在资产结构：

- `pin_type_accent` 与 `label_type_accent` 并非独立美术生成件，而是脚本按旧资源的颜色距离提取后换色，仍属于程序派生。
- 选中背板来自一次独立生图，图钉壳、短签底和图标来自旧 v3 资源；它们没有在同一美术源中共同确定接触边、纸沿和阴影。
- 短签 `200×72` 的真实不透明范围约为 `x=6..194、y=11..61`，合同文字区却为 `x=14..180、y=8..64`；上下各越出纸面约 3px，右端色帽从约 `x=175` 开始，与文字区重叠约 5px。
- 效果稿中的 assigned / urgent / locked 小纸签与 hover / focus 印刷弧没有对应美术资源，当前 Godot 仍以 `Polygon2D` / `Line2D` 生成，未解决用户最初指出的粗糙来源。
- 左右翻签没有统一的端帽与连接件语义；预检脚本镜像标签，而生产代码只平移同一资源，两者不是同一实现。

因此 `layer_exploded_v1` 判为 `split_strategy_rejected`，不得作为 v3 冻结依据。下一轮必须先从最终 1× 尺寸与真实中文样本反推组合件边界和文字安全区，再决定需要烘焙的宏观组合件；不得继续把效果稿拆成不可辨认的微型色片。

## 纠正结果

后续 `macro_component_preflight_v2` 已落实上述防错规则：

- default pin、selected pin 分别作为完整组合件，背板、前壳、连接肩和类型尖端不再微拆。
- 左右 label 分别生成，纸面与远端类型帽烘焙在同一资源中。
- assigned / urgent / locked 使用完整美术小纸签；temp 使用独立生成的沙漏图标，避免与 urgent 混义。
- 文字安全区候选调整为 `[14,12,158,48]`，用真实中文和最长标题在 1×验证。
- selected 最终保持 `64×80` 与 `[4,0]` offset；左挂端帽最终收进 `x=0..13` 禁入区。

UI 与 UX 最终复核均为 `P0=0 / P1=0 / GO`。该结果仅把 v2 升为 `runtime_candidate_pending_user_visual_review`，不绕过用户视觉 Gate，也不自动接入生产。

## 三次反馈：宏观组合件仍丢失一体接合关系

用户把旧效果稿与 v2 的真实 1×读回并排后指出：旧稿中图钉压住名称横条，两个部件形成同一纸件组合；v2 中两者之间仍有明显暗缝。

核查结果：

- 右挂使用 `label_x=78`，图钉 visual 位于 `x=4..68`，约有 10px 暗缝。
- 左挂使用旧 anchor `-208`，换算到预检画布后 label 止于约 `x=200`、图钉从约 `x=212` 开始，约有 12px 暗缝。
- 预检脚本的合成顺序为 label 后方、pin 前方，方向正确；生产 Godot 则 `_caption_panel.z_index=4`、`_pin_shell.z_index=1`，若只平移会反向覆盖。

此前 UI / UX GO 未把“部件各自成立”和“组合接合成立”分开验收，是新的阶段误判。当前 GO 撤回，`pin_label_connection_p1_reopened`。下一轮只允许通过负间距重叠、正确 z-order 与必要的接合肩形复原旧稿的一体关系；禁止再加程序色块或重开整体美术路线。

## 定向修正结果：逻辑锚点不动，接合关系烘焙进 compound

用户明确要求继续后，本轮没有采用“直接移动 label anchor”的快捷方案，因为这会违反此前已经通过的锚点、dense、cluster 与 clamp 合同。父级合并 UI / UX / 美术意见后，采用以下窄范围处理：

- 真实生图只负责锁定“横条从 pin 下方穿入、pin 前壳压住横条”的完整纸件关系；不生成文字、图标或第三块连接补丁。
- 既有四类 pin / label 通过九宫格只延展横条中央空白纸面，烘焙为整体 compound background；左右端帽、pin、selected 背板与类型色不拉伸。
- 逻辑 hit `72×80`、anchor `[36,76]`、caption rect `[78,4,200,72] / [-208,4,200,72]`、文字区 `[14,12,158,48]` 和总 footprint 均保持。
- 右挂形成 12px underlap，左挂形成 10px underlap；16 个候选 frame 在 `alpha > 24` 下均只有一个主要连通体。
- 美术指导、UI Designer 与 UX 老哥对真实 1×证据均判定 PASS / GO；保留的上下短凹口属于裁纸接合肩，不再继续加阴影或重画。

当前仍是 `visual_candidate_pending_user_review`：没有替换 Godot，也没有把静态接合 PASS 扩写为 dense / cluster / clamp / 动态合同已经回归通过。

## 第四次用户反馈：alpha 连通不等于美术一体

用户在放大接合局部后明确否决 v3：“这个结合太简陋了”。红框证据显示：

- pin 面向横条的一侧仍保留完整外边线；
- selected 背板在接合处形成一条直立绿色板块；
- label 近 pin 一端仍保留完整切角和外框；
- 三套轮廓相撞后留下上下凹口与明显竖向拼缝。

因此，v3 虽然在 `alpha > 24` 下成为单一连通体，也消除了贯穿地图底色，但仍然只是“两个完整组件 overlap”，没有共享外轮廓、共享肩或共同纸层。此前父级和三方复核把技术连通性当成美术一体，是新的证据与阶段误判；PASS / GO 全部撤回。

下一轮禁止继续调 underlap、加阴影、加 mask 或补程序连接片。正确方向是先把可见底图重新定义为一次画成的完整 compound：pin 与横条共用一套外轮廓，接合侧删除双方完整边框，只保留必要的低权重内部压线；selected 背板应包住 pin 与横条起始段，而不是形成独立竖板。逻辑 hit、anchor、caption rect、动态文字 / 图标 / 状态签、dense、cluster 与 clamp 继续保持独立且不变。

## 第五次用户反馈：结构示意不能替代真实美术组合证据

用户确认拆分 / 拼装结构“问题不大”，但明确指出无法从示意图判断实际制作出的美术资源组合后效果。该反馈关闭的是结构理解，不是视觉 Gate。

下一步不得全面铺开 16 帧，也不得再交另一张流程结构板。只制作一例 `常驻任务｜selected｜右挂`：先生成真正共享外轮廓的无字 compound 美术，再裁透明候选，在测试专用 Godot 场景中叠加现有 kind icon、真实中文标题和 meta。交付只给同一候选的 4×透明 / 接合局部与真实 1×地图落位图；生产组件、正式合同、左挂与其他类型继续冻结。

## 单例真实证据结果

已按上述复发保护完成 `常驻任务｜selected｜右挂` 一例：可见底板来自一次真实生图的完整 compound，不再由完整 pin / label overlap；程序只做色键转透明、中央无字纸面的三切片延展、尺寸归一和 QA 排版。测试专用 Godot 场景按旧 footprint 叠加既有 kind icon、真实中文标题 / meta 后输出 1920×1080 截图，生产实现、正式合同和其余 15 个方向 / 类型 / 状态仍未修改。

本次证据只关闭“没有真实资源组合图可审”的阻断，不自动关闭美术 Gate。是否冻结 v4 母结构必须由用户看过共享肩、selected 后衬和 1×文字融合后决定。

## 状态链落地前自检：旧 pin-only 不能继续复用

用户要求继续验证选中 / 非选中状态后，父级在进入动图前并排检查旧生产 pin-only 与 v4 compound，发现二者在头宽、肩位、尖端斜率和内框比例上明显不同。若按最初设想直接复用旧 pin，idle → hover crossfade 会形成双头和尖端分叉。这属于交付前发现的资产谱系不一致，未进入生产或用户交付。

处理方式改为从已通过的 default compound 做一次真实生图定向编辑：只删除横条并补最短右闭合边，得到同谱系 idle pin-only；程序不补造型。随后用 Godot 原生 1×逐帧验证闭合边被横条覆盖、anchor 不动、文字不重排。复发保护：任何 compound 状态链都必须同时验证它的 idle head，不得因为 hit / anchor 相同就默认旧 pin 美术可复用。

## 原生 1×状态证据：结构通过不等于状态差异通过

58 帧动图证明 idle → hover → selected 的位置、文字和持续性正确，但也暴露了静态资产板无法可靠判断的问题：hover 与 selected 同时展开相同短签时，selected 只增加约 1–2px 的橄榄后衬；在相近色地图陆地区域，点击后的即时反馈很弱。美术认为它刚到最低冻结线，UI / UX 则均判 P1 / NO-GO。

父级采用保守裁决：compound 结构继续 GO，完整三态状态链不冻结。复发保护：状态美术不能只验“有无差分像素”或依赖状态说明文字；必须在去掉审计标签的原生 1×同位置截图 / 动图中，让玩家第一眼区分 hover 与 selected。用户授权前不得为了通过 Gate 擅自加粗后衬。

## 第六次用户反馈：selected 弱、闭合内圈在 1×下不稳定

用户查看真实运行局部后明确指出：当前 selected 效果仍不够明显；pin 头周围的闭合黑线若隐若现，观感不好。问题不是 compound 接合或文字，而是两项原生 1×状态美术失效：约 `1–2px` 后衬不足以承担选中反馈，细闭合线缩放后成为断续噪点。

本轮只做 v4b 定向修正：三态统一删除闭合黑色内圈，不用更淡 / 更粗的线、局部 C 形线、发光或程序描边补回；selected 只把左上、左侧、左下的常驻橄榄后纸加强到约 `3–4px`，不进入接合肩、横条与右端帽。一体轮廓、共享肩、动态图标 / 文字、hit、anchor、caption rect 和状态时序全部保持。

Godot 4.6.3 的 1920×1080 三态同屏与 58 帧动图证明：selected 能不依赖审计文字与 hover 第一眼区分，移出后持续；内圈在所有过渡帧均无残影，icon / anchor / 文字不跳。美术、UI、UX 最终复核均为 `P0=0 / P1=0 / P2=0 / GO`。复发保护：任何运行尺寸细内圈必须以原生 1×连续性为准；若不能稳定成线，应删除并把识别职责交给外轮廓和图标，不得保留“理论存在、肉眼断续”的装饰。

## 第七次用户反馈：删除坏线不等于允许图标区完全无框

用户复核 v4b 无内框 idle pin 后明确指出：如果图标周围没有线框，设计不成立，因为会显得太空；要求提供多个优化方案。该反馈否决的是“完全删除图标容器”的解决方式，不撤销“旧 1×细闭合线不能保留”的结论。

本轮把问题重述为：需要一个稳定的美术图标座，而不是在“断续细线”和“完全无框”之间二选一。真实生图制作 A 下开口切角框、B 闭合八边纸槽、C 微差色切角纸窗，并把同一 runtime icon 装回 `64×80` 原生 1×和 Godot 地图。A 在高噪声树林背景仍能托住图标且不复制外轮廓；B 形成徽章 / 盾牌套娃；C 在 1×下再次接近消失。

复发保护：以后删除不稳定装饰时，必须先确认它是否还承担分组、承托或层次职责；若承担，删除后必须用能够在原生 1×稳定成立的美术结构接替，不能把“去噪”执行成“去掉必要层级”。

## 第八次用户裁决：开口框的理论完整性不等于视觉完成感

用户在三案中选择 B，并明确指出 A 的方框下半截缺失、只有三边，看起来像未完成。此前三方把“底部开口能避免双框、导向 pin 尖端”作为 A 的优势，但没有充分考虑玩家对“框”这一原型的完整闭合预期；设计解释不能覆盖第一眼的未完成感。

父级不再要求用户接受 A 的内部逻辑，也不通过补短线继续修 A。B 闭合八边纸槽成为当前视觉真值，并只同步到常驻右挂三态测试资源。复发保护：当用户明确要求“框、环、底板、容器”等完整物件原型时，除非视觉证据已证明开口是明确的功能结构，否则不得用理论上的方向性或减重理由替代完整感。

## 第九次用户反馈：结构完整通过不等于 selected 强度通过

用户查看 B 三态真实运行后认为 selected 仍“差一点”，提出选中后多边形闭合框也变色。该反馈不撤销 B 的完整闭合拓扑、compound、锚点或现有 `3–4px` 橄榄后纸；它重开的是 hover 与 selected 的即时差异强度。

复核确认当前外背属于外轮廓通道，但面积有限且会与地图颜色接近；B 内框又始终保持中性，因此 selected 缺少第二个稳定的内部通道。候选应优先复用已有 B 框，不新增构件：selected 时只把闭合框从中性纸灰切换为任务类型色，线宽、alpha 边界、图标、内纸面与外背全部不变。

## 第十次收口：局部 image edit 不能直接拥有几何真值

用户采用类型色内框推荐方案后，本轮只制作常驻任务右挂单例。两次内置 imagegen 编辑在视觉上都正确生成了橄榄闭合框，但画布分别从 `1816×866` 漂移为 `1818×865` 与 `1815×866`。如果直接缩放、裁切或进入三段拉伸，1–2px 漂移会在 1×下重新制造双线、厚度变化、共享肩错位或 selected 过渡残边。

本轮没有把第二张“看起来正确”的图直接判为可拆资源。处理边界改为：

1. 原 B 中性 compound 继续拥有画布、轮廓、闭合框覆盖范围、alpha、锚点与三段拉伸几何；
2. imagegen 结果只拥有橄榄油墨、纸面纹理与印刷质感；
3. 构建脚本把生成内容限制在原 B 闭合框覆盖范围内，框外逐像素保留原资源；
4. default / selected 前层 alpha 必须逐像素一致，运行时用互补 alpha 交叉淡变；
5. 只有 Godot 原生 1×静态图与动图无双线、增粗、闪烁和残灰，才可交给用户判断。

结果见 `2026-07-21-region-task-selected-type-frame-v6-delivery-manifest.md`。该约束只解决生成编辑的几何漂移，不授权程序重新设计美术框、扩大背纸或批量生产其他类型。

生成后美术复核还发现，原始橄榄框中位色约为 `[145,154,65]`，比合同 `#7F8A47` 更亮、更黄。该稿未直接交用户；只在既有 B 框遮罩内校准色号并重跑 Godot，最终中位色为 `[127,138,71]`。这次说明“生成模型做了正确对象”仍不等于“通过色彩合同”，后续四类型派生必须同时检查结构 mask 与代表色中位数。

复发保护：状态链验收不仅检查动画、持续性和结构是否正确，还要检查同位展开的 hover / selected 是否存在两个互补且不冲突的持久通道。若主通道面积受限，优先复用既有美术结构的颜色状态，不先扩大轮廓或增加新装饰。
