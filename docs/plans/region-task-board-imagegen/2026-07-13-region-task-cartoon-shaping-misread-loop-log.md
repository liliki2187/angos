# Loop Log：把卡通塑造误读成卡通题材元素

## 决策条

- **结论**：连续两版的核心错误是没有拆开“塑造抽象度”与“题材符号强度”。
- **影响**：v1 用怪物表情和拟人贴纸冒充卡通画法；v2 删除这些元素时又恢复细碎多边形与摄影细节，并把黑色幽默一起删掉，形成两端摆动。
- **下一步**：固定为“高塑造抽象度 + 中等符号化黑色幽默 + 低拟人萌化 + 低摄影写实”，先用对象级块面预算验证，再生下一版。

## 标杆复盘

- 海怪、金字塔、石像头像和人物剪影是**主造型锚点**：少面、大轮廓、离散明暗，删除真实材质和结构零件。
- `SCENE MOOD / PHOTO & SNAPSHOT` 中部分较细图像是**辅助氛围层**，不能平均成所有任务插图的生产颗粒度。
- 问号警示牌、眼形章、手绘便签、荒诞分类标签是**符号化黑色幽默层**；它们不是表情包，但也不能被通用信号 / 导航 icon 取代。

## 两版错误

- **v1**：底层塑造尚有大块面，但怪物、独眼、笑脸影子、张嘴报纸和问号手过量，题材元素抢走主画风。
- **v2**：飞碟出现面板、高光和真实空气感，列车逐窗、塔架完整、建筑逐格窗，天空和地面铺满细小三角；这是“照片转 low-poly”，不是标杆式重塑。符号区又变成通用分类 icon，黑色幽默消失。

## 防复发

- 每次 prompt 分两段写：先锁对象块面预算与删细节清单，再写符号笑点；不得只写 `cartoon` 或只写题材名词。
- 先遮掉符号验底图塑造，再遮掉底图验符号语义；任一层单独不成立都不放行。
- 任一主体出现均匀细三角、镜面高光、完整零件或逐窗细节，直接判写实回弹。
- 任一符号区只剩通用软件 icon、没有荒诞分类与冷面语义，直接判黑色幽默丢失。
