# 区域任务台底板印刷与 dossier 分区坍塌 Loop Log

> 日期：2026-07-22  
> 触发：用户指出左栏 `ISSUE INDEX / ISSUE 002 / NORTH SHORE DESK` 被误做成无意义固定内容；同时指出右 dossier 虽有字段，但摘要、执行条件、风险、依据与建议没有形成不同分区。

## 这次错在

1. 图文一体风格稿为了让所有真实文字进入画面，把本应属于深青文件夹底层的低对比印刷提升到暖白功能纸面，导致它看起来像一块独立内容或第三条任务。
2. 前一轮为关闭“卡片套娃”而强调连续纸面，但把“减少封闭容器”错误执行成“取消语义分区”，摘要、metadata、风险与建议只剩位置差和细线差。
3. 正式 dossier 合同与当前实现复用同一个 `rt_dossier_section_plate` 承载 metadata 和 risk；代码虽然有不同 rect，视觉角色却来自同一中性 NinePatch，天然容易读成同一类信息框。

## 修正

- 左栏把期号印刷恢复为任务纸条下方的深青底板层；条目少时露出，条目多时自然遮住，永不计入任务条目、功能模块或空状态。
- 右 dossier 保持一张连续主纸，但明确四段语义：页眉 / 摘要、青色执行条件全宽带、锈红风险决策区、底部橄榄签批 CTA。
- 风险区内部按“等级 → 依据 → 建议”分行和分距，不再合并成一个段落。
- 用同一张局部板同时展示左栏少条 / 满条两态，避免只看单态而无法证明底板遮盖关系。

## 防复发规则

1. 生图前先把所有文字分类为：运行功能文本、背景印刷、状态标记、审阅标注。背景印刷不得进入功能 carrier 或占用内容高度。
2. “不套娃”不等于“无分区”。只读信息优先通过全宽色带、侧签、折线、纸面明度和留白分区；只有 CTA 使用完整封闭动作载体。
3. 两个语义角色若需要一眼区分，不得仅复用同一中性资产再改标题颜色；必须在整件 visual master 中验证角色差异，再决定是否拆分资产类。
4. 可变条目列表必须至少提供“条目不足 / 条目充足”双态，证明空闲底板、遮盖、滚动与 footer 的关系。

## 当前边界

本轮只生成局部美术实验板并完成 UI / UX 复核；没有修改 Godot、正式 dossier 合同、component inventory、manifest、pin v7、地图、event card 或 CTA 交互。
