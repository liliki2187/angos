## 它能证明什么

- 地图可以完整填满地图板，不再产生无职责的上下空带。
- 底部剩余高度可以由真实的全局日程模块承担。
- 全局时间推进与任务级派遣入口可以形成两条独立操作链。
- 左下时间闸门可以在不改五个大区矩形的前提下，与事件索引尾部保持结构分隔。
- 右侧原有无职责空白可以转为 7–8 行任务介绍容量，同时保留 meta、风险与 CTA 的稳定可见性。
- 地图仍是全屏最大的单一功能模块。

## 它不能证明什么

- 不能证明 clean low-poly weekly 的色彩、纸张、符号与美术质感。
- 不能证明运行时事件 `0–N`、hover、聚合、标签避让与确认态。
- 不能证明第一击原位展开 `确认推进到第 N 天` 的动态交互；本稿只冻结默认态位置与层级。
- 不能直接作为 Godot 布局、PNG 切图、atlas 或生产资产。
- 图中的尺寸标注、`动态图钉层` 等文字是交接说明，不是玩家界面文案。

## Gate 结果

- UI Designer：通过；推荐 `1040×804` 地图板 + `140px` 底部日程条。
- UX 老哥：`P0=0 / P1=0`；上一轮四个 P1 在结构层解决。
- P2：正式视觉中必须继续区分“日程闸门”与“签批动作”的材质 / 色彩 / 按压语法；删除开发标注。
- 实际渲染：Edge `1920×1080` 无头截图成功。
- 肉眼检查：地图、左索引、右 dossier、底部日程条均完整可见，没有裁切或裸空带。
- 左下局部检查：时间闸门包含独立日期窗和“全局日程”归属标识，处于日程条内部且与上方事件索引相隔 `16px`，没有读成列表末项。
- 摘要局部检查：8 条占位线完整，三块间距仍为 `16px`，无滚动条或溢出；CTA 坐标与尺寸未变，风险块到 CTA 的呼吸区约 `45px`。
