## 回答的问题

用户担心：如果先拆功能再生图，是否会变成程序化出图，或者和整屏风格稿差距过大。

v3c 的结论是：**拆功能本身不会导致程序化，前提是组件不零散生成，而是先用同屏组件板锁定统一风格。** 这张组件板保持了 v3b 的深海军蓝、干净象牙纸、红橙签批、青色支援、半调和像素印刷关系；相比直接程序画矩形，它仍是同一套 Angus 美术语言。

## 比 v3b 的改进

- 假字横条大幅减少，组件内容区更接近“空白可写区”。
- CTA 从 3D 旋钮 / 旧机器按钮改为扁平红橙签批压板方向。
- 左任务纸、右复核纸、员工卡、支援槽、顶部 HUD 和状态章处在同一张画布上，材质和阴影更统一。
- 纸面比 v2 / v3b 更少旧档案气，脏旧破败风险下降。

## 仍不能直接落地的原因

- 这仍是整张组件板，不是透明 PNG / atlas；每个组件还要单独重出或裁切后验边缘。
- 部分纸叠、夹具、图标仍偏装饰，需要在单组件版本里进一步退到 `no_text_rects`。
- 顶部 HUD 仍要继续压成“印刷系统短条 / 信号条”，避免变成通用资源栏。
- CTA 状态只是视觉方向，不代表 default / hover / pressed / disabled / loading / stamped 的精确 atlas 帧。
- 还没有把组件放回 1920x1080 实际界面做多状态回拼验收。

## 下一步规则

1. 使用 v3c 作为单组件生图的风格参考，而不是从空 prompt 重新生成。
2. 每次只生产同类组件 atlas，例如先做 `ds_cta_signoff_atlas` 或 `ds_staff_card_atlas`。
3. 单组件 prompt 必须同时引用 v3b 整屏因果链和 v3c 组件材质。
4. 生成后立刻回拼到 v3b / manifest 坐标，检查中文长文本、状态帧和整体风格。
5. 如果回拼后像程序贴片、网页卡片或另一套风格，直接退回组件 prompt，不进入 Godot。
