# 任务派遣 / 签批外勤界面：恢复中央决策密度结构稿 V4

日期：2026-06-22

定位：V4 是对 V3 “过度合并导致中央空心化”的修正版结构稿。V3 不再作为推荐结构基准，只作为过度合并反例。

2026-06-22 追加修订：V4 只保留“中央不能空心化”的正确教训；其中“队伍覆盖关系 / 覆盖矩阵”的独立模块语法已降级为误读案例。后续结构基准改用 V5：不新增第五功能，只放大人员空槽、当前角色、随队器材和需求覆盖四个原有功能区。

## 用户强反馈

V3 把“需求覆盖与补强”全部移到右侧后，中央黄金区只剩地图底板和少量路线标签，变成空心主舞台。用户明确指出这是离谱、业余的方案，要求后续不要再交付未经自检的类似结构。

## V4 修正

- 中央恢复“队伍覆盖关系”主决策层，而不是只留空地图。
- 中央必须同时保留：
  - 已选员工队列与空槽
  - 随队器材与补位效果
  - 洞察 / 人脉覆盖轨道
  - 贡献来源 token
  - 补强投影
  - 风险因果
- 右侧只做复核与收据：
  - 可签批状态
  - 达标率 / 有效点 / 硬需求 / 耗时
  - 提交摘要
  - 主 CTA

## V3 失败模式

- 只解决了“右侧重复”，却没有保护 V2 已经成立的中央复核闭环。
- 删除中央解释块后没有回收容器，也没有补入等价主决策内容。
- 右侧越权承载了玩家做选择所需的信息，中央只剩装饰性地图。
- “覆盖依据见右侧票据”属于布局解释文案，说明信息关系没有被界面自身表达出来。

## 交付前自检 Gate

1. **中央单独裁切测试**：遮住右侧，只看中央 5 秒，必须能回答“谁去、带什么、补了什么、为什么可签”。答不出，不得交付。
2. **空心率测试**：中央主舞台不得出现大面积无功能空白；地图空白必须被路线、队伍、器材、覆盖轨道或风险/补强关系解释。
3. **右栏越权测试**：右侧只能做最终复核与 CTA，不得成为唯一解释“为什么可执行”的位置。
4. **删除回收测试**：从中央删掉一块信息后，必须用新的主信息填回，或收缩容器；不能留下同等面积空洞。
5. **旧版优点保护**：返工前列出上一版已经成立的优点；新稿不能修掉 A 却破坏 B。
6. **禁止转场补丁文案**：不要用“见右侧 / 见下方”解释布局关系；真正的 UI 应让关系就地可见。

## 后续基准

派遣签批台结构后续不再以 V4 的覆盖矩阵语法为推荐基准。V4 仅作为“修复中央空心化”的过渡稿保留；下一轮以 V5 为当前推荐结构基准：中央是原四区放大的签批前工作台，右侧是复核票据，底部是可选资源抽屉，左侧是任务卷宗。
