# 任务派遣 / 签批外勤界面：原四区放大结构稿 V5

日期：2026-06-22

定位：V5 是对 V4 “需求覆盖被包装成独立覆盖矩阵”的回正稿。它不新增第五功能，只把派遣签批台原有四区放回中央主舞台并给足表现空间。

2026-06-23 追加修订：V5 只保留“不要把需求覆盖包装成覆盖矩阵”的正确教训；其中中央底部整块“需求核对”横向面板仍然过重，已被用户、UX 老哥与 SIA 判定为后台表格化 / 重复复核风险。后续 V6 结构基准应把完整复核摘要合并进右侧票据，中央空间优先还给已选人员席位、候选人员抽屉、随队器材托盘和有任务痕迹的拟物工作台。

## 用户反馈

用户指出 V4 中央像是额外加了一个功能，质疑为什么不能把原有功能给更多空间和表现空间。随后 UX 老哥、UI Designer 与系统架构子 agent 复审结论一致：V4 的“队伍覆盖关系 / 覆盖矩阵”本质应是原有“需求覆盖信息”的表现增强，但独立标题、边框、矩阵语法和连线让它看起来像新增玩法系统。

## V5 修正

中央主舞台改为“外勤签批工作台”，只承载原四区：

1. **任务人员空槽**：保留 4/5 队伍容量与可补 1 人空槽。
2. **当前角色列表**：已选角色以席位卡呈现，卡内直接显示本任务贡献。
3. **辅助骰位 / 随队道具**：器材作为本次队伍的一部分，位于队伍席位下方，明确 `1/1`、效果和“不占人员槽”。
4. **需求覆盖信息**：改为“需求核对”，逐行显示需求项、当前值、来源、覆盖状态和关键结果；不再命名为覆盖矩阵或队伍关系系统。

右侧签批票据只保留最终复核：

- 可签批状态
- 耗时 / 本周变化 / 队伍摘要
- 覆盖已核对
- 风险确认
- 主 CTA

## V4 降级范围

V4 仍保留一个正确教训：中央不能空心化。但 V4 的“队伍覆盖关系 / 覆盖矩阵”语法不再作为推荐结构。后续若需要展示来源关系，应贴回角色卡、器材槽和需求核对行，而不是另起独立系统面板。

## 交付前自检 Gate

1. **四区归属检查**：中央每个块必须归属到人员空槽、当前角色、随队器材、需求覆盖四区之一。
2. **第五功能误读检查**：截图第一眼不得像新增覆盖矩阵、关系网络、协同算法或队伍关系系统。
3. **中央单独裁切测试**：遮住右侧，只看中央 5 秒，必须能回答“谁去、带什么、补了什么、为什么可签”。
4. **右侧越权测试**：右侧只能复述最终摘要和 CTA，不能成为唯一解释签批依据的位置。
5. **表达增强检查**：增加一个表达层时，必须同步删减旧表达或把信息贴回原功能区；不能只加框、加线、加说明。

## 后续基准

派遣签批台下一轮结构稿、真实内容风格稿和资产化 UI 链路不再以 V5 的中央横向“需求核对”面板为基准。V5 保留为“原四区回正但复核面板仍过重”的过渡稿；V6 应转向“外勤签派现场 + 右侧票据复核”：中央展示任务短条、人员席位、候选抽屉、随队器材和拟物桌面空间，右侧票据承载完整复核摘要与 CTA。
