## 本轮判断

用户指出 V2 中央的“需求覆盖与补强”仍然可能合并到右侧。判断结果：可以合并，而且更干净。

原因：

- 这块内容主要是解释“为什么可签批”，天然属于签批票据的依据区。
- 中央黄金区应优先展示派遣舞台：地图、路线、图钉、已选队伍、随队器材。
- 右侧票据已经承载签批结论，把覆盖来源放进去能避免中央与右侧再次分裂。

## V3 改法

- 中央删除大段“需求覆盖与补强”文字板。
- 中央只保留：
  - 已选成员队列
  - 空槽
  - 随队器材条
  - 地图纸面
  - 路线标签：洞察路线 2/2、人脉路线 2/2、M330 外勤路径
  - 轻量提示：覆盖依据见右侧票据
- 右侧票据合并：
  - 签批状态：可签批
  - 签批依据 2×2：达标率、有效点、硬需求、耗时
  - 覆盖来源：洞察、人脉、补强
  - 提交摘要：本周 7→5、队伍 4/5 + 器材 1
  - CTA：盖章派遣 · 2天

## 信息边界

- 中央回答：派谁、带什么、走哪条线。
- 右侧回答：为什么可签、按下去消耗什么。
- 底部回答：还能换谁、还能带什么。
- 左侧回答：任务为什么存在、要求是什么。

## 后续原则

- 中央不再放大段文字说明板。
- 中央可以保留短路线标签、图钉、连线、状态小标，但不承担复核清单。
- 覆盖来源、补强建议、达标率、有效点、硬需求、耗时统一进入右侧票据。

## 2026-06-22 修订：V3 已降级为反例

用户随后明确指出：V3 把中央“需求覆盖与补强”移到右侧后，中央黄金区几乎空出来，属于离谱、业余的方案，不应作为推荐结构继续推进。

复审结论：

- V3 解决了右侧重复问题，但破坏了中央主舞台的信息密度。
- 中央只剩地图底板、路线标签和“覆盖依据见右侧票据”的转场说明，无法独立完成派遣决策判断。
- 右侧越权成为“为什么可签”的唯一解释位置。

因此 V3 仅保留为“过度合并 / 空心主舞台”反例。后续以 V4 为推荐结构基准。
