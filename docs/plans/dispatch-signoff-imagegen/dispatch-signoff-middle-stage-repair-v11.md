# 任务派遣 / 签批外勤界面：V11 中间主舞台修正方案

状态：`middle-stage-structure-plan`。本方案保留左右两边栏目与底部候选抽屉，只针对中间空白和主舞台弱的问题提出结构修改；不是真实内容风格稿、no-text 生产母版、atlas 来源或 Godot 落地稿。

## 保留项

- 左侧任务卷宗：任务名、地点 / 调查类型、任务简报、外勤目的、风险叙事。
- 右侧签批票据：完整复核、耗时、本周变化、队伍摘要、盖章 CTA。
- 底部候选抽屉：候选员工与可选器材供应层；已选角色从候选池移出。

## 中间区目标

中间不再试图填一张新表，也不新增路线、覆盖矩阵或骰池纸。它只做一件事：

> 把“本次队伍已经被压到 M330 案卷上，随队器材已夹入，等待右侧盖章”的派遣现场做清楚。

## 空白的填补方式

1. **放大已选角色卡**：中间优先给已选队伍更大的卡片和头像，不再用小状态块填空。
2. **让卡片“压在案卷上”**：角色卡底部轻微压住案卷底板，卡与任务短条之间用弱红青引线表达归属，不表示可操作路线。
3. **器材嵌入队伍而非单独一行**：随队器材做成案卷底板下沿的夹条 / 附件条，视觉上属于本次队伍。
4. **空槽做成弱邀请位**：空槽是 `可选增援席`，不是强制缺口；避免和右侧“可签批”矛盾。
5. **保留拟物负空间**：案卷底板中央可以留 20-30% 干净纸层 / 桌垫纹理 / 半调，不需要功能块填满。

## 不放进中间的内容

- 完整达标率、缺口、耗时、本周变化：留在右侧票据。
- 中央骰池表、骰面矩阵、覆盖来源表：集成在角色卡 / 器材卡或 hover。
- 路线规划、站点选择、队伍关系、覆盖矩阵：游戏内无此功能，不进入中间。
- `可签 / 待盖章 / 压力 +2` 等重复状态块：右侧已有，不在中间重复。
