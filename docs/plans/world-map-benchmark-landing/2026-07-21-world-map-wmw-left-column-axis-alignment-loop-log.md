# WMW 左栏共轴错位误交付 Loop Log

## 触发

2026-07-21 用户查看完整整屏 v0.2 后指出：三张地区卡与左下日程器没有对齐，并明确要求以后不要再交付这种明显错误的界面。

## 结论

用户判断成立，v0.2 的 UI / UX PASS 撤回。该问题不是观感分歧，而是基础几何错误：三张地区卡为 `[66,y,306,240]`，日程器为 `[36,810,342,246]`，左边相差 30px、右边相差 6px，既不同轴也不同宽。

## 根因

- 父级机械保留了 v5.1 的历史 rect，没有在视觉资产化阶段重新检查同栏共轴关系。
- 几何审计只验证各 rect 存在、文字安全区和三栏闭合，没有建立 sibling shared-edge / equal-width 断言。
- UI Designer 与 UX 老哥复核聚焦双 carrier 清除、动作层级和整屏阅读链，未把同栏外边界共轴作为交付前硬闸门。
- 用户在正常观看比例下即可发现的问题，被错误留给用户承担终审。

## 修正

1. 日程器外框改为 `[66,810,306,246]`，与三张地区卡左右边完全一致。
2. 日期头、动作区、图标井、文字区和后果区按新宽度原位缩排；不得删除当前日、剩余日、推进动作、后果预览、到期信息或归零去向。
3. 中央与右栏保持像素不变。
4. v0.2 保留为失败证据；修正版使用 v0.3 文件名。

## 新增硬 Gate

- `left_column_outer_axis_alignment`：四个左栏模块 `x` 必须一致。
- `left_column_outer_width_alignment`：四个左栏模块 `w` 必须一致。
- `left_column_inner_axis_alignment`：卡内照片 / footer 与日程内部主 carrier 的左右边必须共享同一内缩轴。
- `center_right_zero_diff_from_v0_2`：修正范围外差异像素必须为 0。
- 交付前内部以 100% 整屏和左栏 200% crop 双重目检；用户只看通过后的完整整屏。

## 范围

- 不重谈三栏职责，不移动三张地区卡。
- 不修改中央地图或右侧档案。
- 不调用 imagegen，不改 Godot、正式合同、compact A5.1 或 B2.12。

## 纠偏结果

v0.3 已把四个左栏外壳统一为 `x=66,w=306,right=372,center=219`，三段垂直间距均为 18px。内部 alignment QA 以 200% 检查左右边、中心轴和水平分隔；程序同时断言 child containment、文字安全区、卡片区 0 diff 与中央 / 右栏 0 diff。UI Designer 与 UX 老哥最终复核均为 `PASS，P0=0 / P1=0 / P2=0`。当前等待用户复核完整整屏 v0.3。
