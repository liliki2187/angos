## UX 老哥诊断原文

### 总结论

三栏职责已经成立，当前问题不是“缺功能”，而是信息量与容器量严重失配。应保留组件身份，压缩低信息区域，把空间还给地图；不要继续用大纸张和大文件袋填满整屏。

玩家动作链保持：

`查看周次与当前日 → 扫描左卡与地图 → 选择地区 → 读取右侧地区档案 → 按需展开任务情报 → 在进入地区与推进日之间做作用域不同的决策 → 执行 → 世界状态刷新`

- `进入地区任务台` 是当前选区跨页面主操作，留在 A5.1。
- `推进到下一天` 是全局周程操作，留在左下并原位确认。
- 红线预警 / 深链动向只提供被动世界状态，不承担选择、确认或跳转，不应获得接近主操作面板的体量。

### P0 / P1 / P2

**P0：0。** 当前问题降低层级清晰度，但不阻断选区、进入地区或推进日，不应误升。

**P1-1 回执冒充决策卡**：两张 369×207 只读纸件只有标题、短状态和七格进度，却获得接近任务卡的视觉重量。应新建 450×90 `bottom_receipt_strip`，保留红 / 青身份、标题、状态和刻度，删除脚注和大留白。旧 `bottom_receipt_card v0.8.5` frozen 类不得直接拉扁。

**P1-2 空档案尾制造虚假续篇**：CTA 下方 75px 背页 + 156px 文件袋正面共 231px，零信息、零命中，却暗示下一页、抽屉或隐藏操作。只保留约 62px 浅袋口；其余恢复无框宿主背景。

**P1-3 次级周程动作体量接近主操作**：246px 日程器和 100px 级按钮偏厚。建议压至 182px、默认按钮 66px，确认状态复用同一矩形；语义仍包括当前日、剩余日、原位确认和后果预览。

**P2**：回执的大书签、纸边、脚注和七格同时存在，装饰超过信息；右侧多层背页、侧签和厚袋口比任务情报 disclosure 更醒目。

- 不为了齐底重新把右侧文件袋拉满到 `y=1056`。

## UI Designer 出稿正文

### 元素表与冻结边界

- 三栏逻辑区继续是 342 / 972 / 480，24px 栏距；逻辑区不等于产品全高边框。
- 三张 B2.12 与内部照片 / 标题 / 状态章坐标全部不动。
- A5.1 `[1398,45,480,780]` 及照片、正文、disclosure、CTA 坐标全部不动。
- 中央回执改为独立新类 `bottom_receipt_strip`，不是对旧票据卡缩放。
- 右下只有 62px 浅袋口，之后不画边框、文字或命中区。

### Z-order 与安全区

- 背景 → 逻辑辅助线 → 地图 → 日程器 / 回执 / 浅袋口 → B2.12 / A5.1 → 文本 → 交互 → selected / focus → 日程 confirming。
- 回执色条、图标和刻度为禁入区；标题与当前值最多两行层级，实际各单行。
- 浅袋口整块 `no_text / no_hit`；其下整块 `no_text / no_hit / no_frame`。
- 顶部不重复 `DAYS LEFT`；剩余天数只归左下日程器。
- A5.1 CTA 固定“进入地区任务台”，不得追加地区名。

## 父级合并与分歧

UX 与 UI 对地图、紧凑回执、A5.1 frozen 和 62px 袋口完全一致。

唯一位置分歧是紧凑日程器：一个 UI 草案将 182px 日程器下移到 `y=874`，UX 保持既有锚点 `y=810`。本轮可见结构稿采用 `[36,810,342,182]`：它不在第三张卡底部 `y=792` 与日程器之间制造 82px 空洞；日程器下方保留 64px 无框呼吸区。该选择只用于待评审 structure wireframe，用户确认前不改 runtime。

## 双审结论

`P0=0`。结构方向可进入用户裁决：弱信息已降为窄条、地图重获主舞台、右下不再是假面板、两类核心冻结组件未动。尚不得进入合同升级、生图或 runtime。
