# 世界地图真实内容目标图前置 Loop Log

## 结论

- **错在阶段顺序**：在用户只确认风格稿“差不多”后，父级直接进入组件合同与 Godot 纵切片规格，没有先交付一张真实内容、真实中文、真实状态的完整界面目标图。
- **影响**：即使组件拆分方法正确，也会提前固化尚未经过用户整屏审阅的信息密度、三栏视觉权重、文字融入、状态距离和趣味剂量；后续返工会扩散到切图、atlas、合同和代码。
- **纠正**：暂停组件生产与 Godot 接入；先制作 `1920×1080 filled-state visual target`，由用户确认实际玩家界面长相后再反推资产与实现。

## 误判来源

1. 把“风格板方向接近成立”误当成“真实界面目标已经成立”。
2. 过早关注资产分层、hit rect 和合同安全区，忽略用户首先需要判断完整玩家观感。
3. 当前 Godot 截图虽然是真实功能态，但视觉仍属于旧组件，不能代替新方向的真实内容目标图。
4. 世界地图 A 虽然完整，但包含生图英文 / 假信息与非正式交互物件，也不能直接作为真实内容界面。

## 正确阶段链

```text
风格板方向确认
  → 真实内容 filled-state visual target
  → 用户整屏裁决
  → 无字组件 / 状态 atlas / safe rect
  → Godot 单状态纵切片
  → 多状态与动态证据
```

## 本轮目标图合同

- 画布：桌面 `1920×1080`。
- 布局：严格沿用世界地图黑白功能稿的三栏责任区。
- 风格：世界地图 A「夜班石板蓝」与两张 clean-lowpoly benchmark。
- 内容：只使用当前正式 `WeeklyRunContent` / `WeeklyRunGame` payload。
- 状态：北美禁区带 selected、红线升温、可进入、任务情报 collapsed。
- 文字：真实中文；不使用 lorem、乱码、生图伪英文和不可解释数字。
- 行为边界：画面中的按钮感只属于地区卡、地图 pin、任务情报 disclosure 与唯一 CTA；`DAY 1` 机器与装饰贴纸不表现为可点击。
- 产物身份：`filled_state_visual_target / pending_user_visual_decision`，不是 production asset、atlas 或 runtime screenshot。

## 重新进入实现的 Gate

用户能从整屏目标图在 5 秒内指出：

1. 当前选择了哪个地区；
2. 当前为何紧急或异常；
3. 哪些地区锁定以及大致缺口；
4. 下一步唯一主动作是什么；
5. 画面是否像成年怪新闻编辑部，而不是旅行社、军事情报台或 SaaS 后台。

只有用户确认完整目标图后，才恢复 `2026-08-03-world-map-a-runtime-landing-implementation-brief.md` 中的组件生产与 Godot 纵切片。

## 2026-08-03 第二次误判：把功能责任区误当成视觉母体

- **用户反馈**：首张真实内容目标稿“和原来的界面那么像，反而和刚刚做的风格稿不像”。
- **结论**：反馈成立。首稿以黑白功能稿 / 旧运行界面的规整三栏、浅色矩形地图、中央下详情卡、表单式右案卷和外置 CTA 为骨架，只迁移了 A 的夜蓝、暖纸、照片和夹子，实际是旧 UI 的高质量换皮。
- **根因**：prompt 与 UI brief 使用了“严格三栏”“精确坐标”“正交字段载体”等过强布局约束；联合参考中又把功能稿与旧 runtime 放在和 A 风格稿近似的视觉权重，导致生图优先服从旧容器，而不是 A 的构图主语。
- **放大错误**：为避免中文乱码而预留大量矩形空白字段，并用程序回填状态框，进一步强化了后台表单感；同一雷达照片在左卡、中央详情、右案卷重复三次，也压低了 A 稿原本的拼贴变化与趣味。
- **处置**：首稿降级为 `functional-content-fill-reference / style-translation-deviation`，不得拆组件、接 Godot 或升格为 A 风格标杆。

### 修正后的继承优先级

```text
功能真值：决定必须出现什么、哪些状态可操作
世界地图 A：决定整屏构图、视觉主语、物件关系与情绪
黑白功能稿：只用于检查是否漏功能，不再约束精确几何
旧 runtime：只用于核对 payload 与交互边界，不进入美术参考权重
```

必须恢复 A 的深蓝异常地图墙、左上刊头与错层地区索引、撕纸 / 眼睛 pin、右侧连续新闻纸堆、dossier 内行动票、小型 DAY 与暗色负空间。必须删除首稿的巨型中央下详情卡、浅米白地图纸、普通定位针、表单字段框、外置巨型 CTA 和重复三次的同一大照片。

### v2 候选执行状态

- 已按修正继承优先级生成 v2：生图视觉输入只使用世界地图 A 与两张 clean-low-poly-weekly 标杆，不再输入黑白功能稿和旧 runtime。
- 当前候选恢复 A 母体构图并装入真实中文与真实状态；产物身份仍为 `pending_user_visual_decision`，在用户确认前不得升格。
- v1 已在自身交付清单中标注为偏差案例；v2 通过父级 25% 层级检查，但用户裁决仍是下一 Gate。

## 2026-08-03 第三次误判：把 A 完整构图当成不可变模板

- **用户反馈**：v2“只是生硬地进行了一些拼贴，没有重新设计并和真实 UI 结合”。
- **结论**：反馈成立。v2 修复了 v1 的旧 UI 骨架问题，却把世界地图 A 的完成插画逐件复制，再用米白文字贴片覆盖动态地区名、状态、正文和任务情报；它接近 A 的氛围，但没有长成可复用、可扩展、可学习的真实功能组件。
- **根因**：上轮把“世界地图 A 是视觉母体”误写成“A 是不可变构图母体”。这让功能只能寄生于参考图已有空位，未重新设计动态文字槽、统一 hit rect、状态矩阵、hover / focus / selected 反馈和内容容量。
- **P0**：地区选择器没有唯一视觉边界。左卡与地图节点都由多个具有独立可点感的碎片组成，且两处不共用 selected / warning / locked 语法。
- **处置**：v2 降级为 `a-mood-close / integrated-component-failure`；停止继续整屏生图与文字覆盖。

### 第三条路线

```text
真实操作链与信息层级
  → 新 integrated layout
  → RegionIndexCard / MapRegionBeacon / SelectedRegionDossier / ReadOnlyTimeStrip 结构设计
  → 动态字段槽、hit rect、状态矩阵与装饰边界
  → 使用 A 的视觉语法生成无字组件壳
  → 原生文字与状态装配
  → 完整真实内容 filled-state 目标稿
  → 用户裁决
  → Godot 单状态纵切片
```

此前“真实内容整屏必须先于生产资产和 Godot”的规则继续有效，但整屏生图前必须先完成行为组件与动态内容结构设计；不能再把完成插画当作 UI 布局合同。

## 2026-08-04 第四次误判：把夹层空洞当呼吸区，把同算法复绘当一图复用

- **结论**：v3 的不对称三责任区方向继续保留，但 v3 终审 `P0/P1/P2=0` 撤回。左索引结束于 `y824`、DAY 固定在 `y930`，两个同宽模块之间形成 `106px` 无职责夹层；它会被反向读成缺失的第四地区卡或未加载模块。当前处理为增量返工，不推翻中央地图或右 dossier。
- **影响**：若继续按 v3 几何制作正式壳，空洞会被资产化为永久布局；若用第四卡、日志或教程填补，则会制造世界层不存在的功能。与此同时，左卡 `126×96` 与右图 `420×236` 只共享绘制算法与 variant 名称，不共享同一位图资源，左右对象连续性会在正式出图后继续漂移。
- **失败归因**：命中 F1“验证等级冒充”家族。父级与终审只检查了地图净区、操作链和信息边界，没有对所有相邻同宽模块做夹层空洞检查；图片侧又把“同一脚本按归一化坐标重绘”误报为“同一美术资源复用”。
- **本轮处理**：DAY 上移到 `y840`，与 RegionIndex 固定 `16px` 间距；不新增内容。每个地区改为唯一 `1104×704 / 69:44` canonical texture，左卡 `138×88`、右 dossier `414×264`，完整画幅严格 `3×` 等比显示；状态由运行时叠层表达。
- **复发保护**：`test_world_map_integrated_prototype.gd` 新增 DAY rect、source size、左右 display size 与 `resource_path` 相等断言；截图交付追加左缩略图三倍放大与右图并排证据。下次任何“一图两用”声明必须同时给出资源身份与画幅证据，不能只给视觉近似或共享算法。
- **沉淀判断**：用户裁决写入 A281；不新增平行规则，复用 A201 的 `69:44` 与 A229 的栏位职责闭合，并把本次廉价可判定条件升级为原型测试断言。

## 2026-08-05 第五次误判：只消灭局部夹层，却没有复核整栏是否真正闭合

- **触发来源**：父级自检失败。用户要求重新发出此前冻结的 V5.1 结构稿并与 v4 比较后，父级发现 v4 虽把 `RegionIndex → DAY` 间距从 `106px` 收到 `16px`，但 DAY 在 `y926` 结束、地图在 `y854` 结束，大片无职责暗色仍留在两者下方。
