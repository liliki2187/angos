# Schedule ContactDecor 语义失败复盘

## 触发

2026-09-04，Schedule V2 为解决旧稿中的孤立 C 形金属弧与白纸浮空感，引入一枚完整 binder clip，并将其拆成位于 FrontCarrier 之上的 `ContactDecor`。用户看到实际成图后直接询问“这个小夹子是干嘛用的”。

## 错误判断

内部复审一度把“夹子完整、无文字遮挡、NO-HIT”当作视觉问题已经关闭，但忽略了更高优先级的语义门禁：玩家不应为一个无功能装饰停下来理解它。夹子位于左侧中段且靠近“当前版本不可操作”，即使几何安全，也会被误读为行首状态图标或控件提示。

## 根因

- 把物理完整性当成了语义清晰度；“完整 binder clip”并不等于“自然的夹持位置”。
- 为解决纸层接触关系，过早新增了一个独立注意力物件，而没有先验证纯纸层遮挡是否已经足够。
- 静态审查只检查遮挡、热区和层级，没有把“需要解释的装饰”列为 NO-HIT 组件的失败条件。

## 修正

- V2 保留为局部诊断样本，不进入用户视觉目标或运行时。
- V3 彻底删除 `ContactDecor`、夹子 alpha 与所有替代小图标，不用回形针、胶带、图章或日历符号补位。
- 纸层关系只由不等宽露边建立：石板蓝背纸运行时左 8px、上 2px、下 4px，右侧 0；底边末端允许一段 `18×4px` 的低饱和灰橄榄纸边。
- FrontCarrier、四条动态文字、`372×246` 根矩形、底部留白、0° 与 NO-HIT 合同保持不变。

## 新防线

对所有被动、NO-HIT 的编辑部纸件，新增视觉语义检查：

1. 装饰物若让用户询问“这是干嘛的”，直接判为 P1 语义失败，不能以“不遮字、无热区”降级处理。
2. 先用承纸、露边、遮挡和局部接触阴影解决拟物关系；只有具备自然物理位置且不产生功能联想时，才允许独立夹具。
3. 删除失败装饰时不得立即换成另一枚小图标，必须先验证无装饰版本。
4. 用户真实第一眼反馈优先于内部静态推断；旧复审结论随之撤回并重跑。
