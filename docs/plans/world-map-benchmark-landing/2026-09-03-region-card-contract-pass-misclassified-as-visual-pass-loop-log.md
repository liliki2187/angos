# RegionCard「合同通过」误判为「视觉通过」复盘

- 日期：2026-09-03
- 触发反馈：用户指出三张地区卡仍有明显拼凑感，要求先由助手自行定位。
- 影响范围：世界地图左栏 `RegionCard`；不扩展到 Godot、atlas、manifest 或 `WeeklyRunGame`。

## 结论

上一轮 `41/41` 只能证明三地区的编号、标题、状态和共享 `69:44` 图片母图绑定正确，不能证明玩家可见的 RegionCard 视觉整合已经通过。原“视觉通过”判断撤回：内容身份合同保留 PASS，RegionCard 视觉整合改为 FAIL。

## 错误发生在哪里

1. 把机器可验证的内容一致性当成了美术完成度证据。
2. 只检查了外轮廓和图文对应，没有检查 FrontCarrier 内部是否存在透明断层、双重底边和互不服从的材质。
3. 用局部状态可辨认替代了整件物件是否成立的判断。
4. 没有在关掉调试框后，以 A291 左栏的“单张连续地区简报”原型做第一眼对照。

## 已确认的结构性问题

- 顶部标题条、照片白相框和右侧白纸块像三个独立组件。
- 照片右缘存在内部低透明竖带，落在深底上形成黑缝。
- 照片纸和右侧白纸各自拥有底边、阴影与材质，产生双层拼贴。
- 右侧区域大面积空白并带孤立锁图标，像漏填表单。
- `selected` 的完整钴蓝框像调试 focus，而不是编辑部纸件状态。
- `locked` 同时使用状态文字、角括号和悬浮锁，信息重复且像额外控件。
- 三卡共用同一 FrontCarrier，因此这是组件类别问题，不是东亚卡个例。

## 新的防复发闸门

后续审计必须分开记录：

1. 内容身份合同：编号、标题、状态、图片归属与母图复用。
2. 机器几何合同：尺寸、slot、alpha、hit、缩放和裁切。
3. 玩家可见视觉整合：是否首先读成一个完整物件，而非多个控件拼装。

只有前两项通过时不得写“视觉通过”。视觉整合还必须满足：

- 关闭调试框后，100% 比例第一眼是一份完整地区简报。
- FrontCarrier 内部不得有落到底色上的透明竖缝。
- 照片必须嵌入同一纸件，不能再出现“卡中卡”。
- 右侧留白必须是完成构图的留白，不能像漏填字段。
- selected / warning / locked 各只有一条清楚且不互相抢占的视觉通道。
- 与 A291 直接并排通过物件原型、色彩节拍和编辑部气质复审。

## 当前处置

- 保留三地区内容绑定和 `41/41` 机器结果，限定其证明范围。
- RegionCard 当前视觉候选降级为诊断样本，不得进入 Godot 或资产化链条。
- 下一轮只重构 RegionCard 整件壳体；冻结运行时几何、动态文字槽、图片比例、状态语义和 hit 合同。
- 优先验证“连续地区简报纸”；并行保留“编辑接触印样卡”作为更大胆的编辑部方向。
