# Loop Log：世界地图 BackDecor 夹具两次画法偏移

> 日期：2026-08-07  
> 触发：父级自检发现首张长尾夹滑向写实产品渲染，第二张纠偏又滑向极简矢量符号；两张都未进入合成候选。

## 结论

长尾夹既是编辑部拟物轴的一部分，也必须服从 clean low-poly weekly 的图形化块面语言。只写“真实可辨、黑化钢、低多边形”会被模型解释为带连续高光的产品渲染；只写“4–6 个平面、无渐变”又会把物件压成软件图标。正确口径是：保留可信的紧凑夹具比例和可操作物件身份，但用中等数量的离散哑光块面、轻纸齿和简化机械关系重建。

## 偏差案例

- `rejected-03-binder-clip-too-photoreal.png`：连续金属高光、圆管手柄和产品摄影体积感过强。
- `rejected-03b-binder-clip-too-flat.png`：手柄过高、块面过少、轮廓像通用矢量图标，缺少编辑桌物件身份。
- `03-binder-clip-chromakey.png`：第三轮以紧凑比例、5–8 个中等大块面、离散明度阶和轻材质颗粒取得折中，进入透明化和回填预览。

## 原因

1. 首轮提示词同时使用“recognizable / practical / steel”与“low-poly”，但没有明确禁止连续高光、圆管和产品摄影光，模型优先保证了物件真实感。
2. 第二轮把禁止项推得过满，要求硬边和极少色面，却没有保留“真实编辑部工作物件”的最低结构信息，模型退化为极简 pictogram。
3. 夹具最终显示只有约 `56×44`，不能以大图局部材质细节判断；必须同时检查源图画法和运行时尺度剪影。

## 防复发规则

- 物件型 BackDecor 的提示词同时锁三条：`believable compact ratio`、`5–8 medium-large matte facets`、`no product photography / no vector pictogram`。
- 先以源图检查材质漂移，再以运行时尺寸检查是否仍像真实工作物件；任一失败都不得以“缩小后看不出来”为理由放行。
- 不用程序重画夹具；程序只负责色键转透明、等比下采样、定位和遮挡 QA。
- 失败候选留在交付目录并显式加 `rejected`，避免后续误采为资产真源。

## 影响范围

本次只改变 BackDecor 夹具源图，不改变 Dossier、Schedule、CTA、文字槽、图片槽、状态事实、热区或 Godot 行为。第三轮仍待 UI / UX 与用户视觉裁决，不因机器 Gate 通过自动升格生产资产。
