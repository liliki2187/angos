# WMW A263 文字载体与语义间距假通过 Loop Log

> **结论**：A263 v0.1 的“最终双审 PASS”撤回；当前稿降级为 `user_visual_review_failed_rework_required`，不可继续作为用户确认主图。
> **影响**：方案 1 的配色、图片、三栏、材料方向和双态数据语义仍有效，但第三卡状态载体、日程状态/动作分组、右栏正文/任务章节均需局部返工。
> **下一步**：先修真实 carrier 模型、语义间距审计与独立 100% 局部裁切，再生成 v0.2；不重做整页，不改 Godot、runtime、atlas 或正式合同。

## 触发来源

2026-07-22 用户在最终交付图中圈出三处明显问题，并追问为什么父级与双 agent 都没有发现：

1. 第三张左卡的标题补纸、照片与“锁定”状态签错层；
2. 左下日程的“当前第 1 天 / 剩余 7 天”与推进主动作挨得过近；
3. 右栏正文、任务情报标题、统计与第一任务行拥挤。

## 原始问题与分级

UX 老哥与 UI Designer 重新从最终 PNG 做独立局部复核后均撤回原 PASS。当前统一分级：`P0=0 / P1=3`。

### P1-1：第三卡载体错层

- 程序把另一卡的纸面补片贴到 `[49,744,265,52]`；
- 标题 safe rect 为 `[64,754,232,32]`；
- 状态 safe rect 为 `[323,754,84,30]`；
- 但原图真实灰靛状态签并不占据作者声明的状态框，`锁定`文字落在照片/拼接层上。

因此 `text bbox ⊆ safe rect` 虽为真，`text bbox ⊆ visible state carrier` 为假。

### P1-2：日程状态与动作分组失败

日期补片延伸至 y=864，日期文字实际到 y=861/862，动作标题从 y=872 开始。字形 bbox 没有相交，但日期和动作仍共享/贴住同一橄榄动作载体，导致“当前状态”像按钮标题的一部分。

### P1-3：右栏语义组实际拥挤

- 正文第二行 safe rect：y=512–534；
- `任务情报` safe rect：y=527–555；
- 两个作者声明的安全框重叠 7px；
- 正文实际 bbox 到 y=529，章节标题从 y=533 开始，只有 4px；
- 章节标题 bbox 到 y=552，首任务载体从 y=556 开始，也只有 4px。

审计缺少 pairwise overlap 与最小语义间距检查，所以逐项 `passed=true` 仍能放行整体失败。

## 失败归因

### 1. F1 验证等级冒充复发

父级把以下工程事实错误升级成视觉通过：

- 38 条文字各自落在作者定义的 safe rect；
- 允许修改区外像素为 0；
- 默认态与确认态只在日程区域变化。

这些只能证明“修改受控、文字未超作者框、双态差分受控”，不能证明作者框属于真实载体、补片层级正确、语义组有呼吸或局部完成度成立。F1 已知复发计数更新为 `≥25`。

### 2. F4 只修点名局部不扫邻域复发

上一轮只复核了“任务情报由 12px 升为 18px”和“状态文字变深墨”，没有检查修改点上下至少 100px 的邻域；增大标题反而把它与正文和首任务进一步挤紧。F4 已知复发计数更新为 `≥8`。

### 3. 双审证据不独立

父级、UX 与 UI Designer 都读取同一个生成侧 audit，并主要看缩小整屏。复核者没有独立重建 `carrier_rect`、没有从最终 PNG 固定裁出高风险接缝，也没有单独计算元素间距。因此这是三个角色共享一个盲区，不是三条独立证据链。

### 4. 既有硬规则没有进入放行动作

`ui-interaction-guidelines.md` 已明确要求视觉载体、100% 局部裁切、底部末卡优先检查；`workflow-gates.yml` 也已有 `text_carrier_capacity`。本轮不是缺规则，而是没有执行 gate，并让自画 safe rect 自证正确。

## 当前处理

- A263 方案 1 的材料方向继续保留；不重谈三栏和整页布局。
- v0.1 默认态、确认态和双态板保留为失败证据与修复输入。
- 撤销 `dual_reviewed_pending_user_visual_confirmation`、`P1=0` 和“无需返工”的声明。
- audit 状态改为 `user_visual_review_failed_rework_required`，并显式记录三个 P1、错误 safe rect 交集和未通过的视觉 carrier 断言。
- 本轮不修改 Godot、runtime、atlas、正式合同、frozen compact A5.1、B2.12 或 GDD。

## 复发保护

`text_carrier_capacity` gate 增补以下放行项：

1. 每个文字字段登记 `owner_carrier_id` 与 `semantic_group_id`；
2. 独立检测 safe rect 两两交集与角色级最小语义间距；
3. 状态文字中心必须落在真实可见状态签内；
4. 文字、补片或字号修改后必须检查上下左右 100px 邻域；
5. 必须由复核者从最终 PNG 独立裁出 100% 局部图，不采信生成脚本自己的 PASS 结论。

A263 后续 v0.2 的固定三联裁切为：

- 第三卡标题 / 状态 / 照片交界；
- 日程日期 / 动作 / 后果；
- 右栏正文 / 任务标题 / 首任务行。

只有整屏和三联局部同时通过，才允许重新进入用户视觉确认。

## v0.2 纠偏结果

v0.2 已按本日志的复发保护执行：第三卡使用完整 footer / 状态签局部素材，不再保留旧残签；日程日期与动作成为独立 carrier；右栏重排后正文到任务标题、标题到首任务均为 10px。相对 v0.1 的三个批准 ROI 外变化为 0。UX 与 UI Designer 均先独立查看最终 1920 PNG、100%局部和200% QA板，再读取 audit；终审均为 PASS、P0/P1=0。当前恢复为 `dual_reviewed_pending_user_visual_confirmation`，等待用户整屏视觉裁决。

## 沉淀判断

本次不是新错误家族，命中既有 F1 与 F4；不再新增重复 onboarding 规则。按二次复发升级律，直接扩展现有 `workflow-gates.yml -> text_carrier_capacity`，并把本次三处作为 A263 的固定失败回归样本。
