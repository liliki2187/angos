# Loop Log：右 dossier A5 容量模型误判与左抽屉方向撤回

> **结论**：A5 将纸面下半部误建模为不可复用的独立槽，因而得出“卡内没有任务列表余量”的错误结论，并制作了左锚抽屉。用户用原始风格稿证明同一区域本可容纳多行内容；左抽屉候选现已撤回。
> **影响**：A5 的连续正文 carrier、合并摘要、正式字段与 collapsed 运行证据继续有效；所有左抽屉 expanded 截图和动图只保留为被否决的历史证据，不能再用于宣称交互通过。
> **下一步**：先比较固定高度原位切换与常驻两条预览；用户选定前不实现 A5.1、不修改 frozen 几何。推荐原位切换：展开态显示 2 条只读任务和“另有 N 条”，照片与橄榄主 CTA 零位移。

## 触发与归因

- **触发来源**：用户把原始红框信息区与 A5 左抽屉运行图并排复审，指出原图下半部足以承载多行任务。
- **直接错误**：只检查 `mission_intel_button` 单槽和 CTA 下方余量，没有把 `region_body=[22,288,276,90]` 与 disclosure 周边视为可按状态复用的连续信息区。
- **判断偏差**：把“默认态要显示地区描述”误等同于“展开态仍必须完整保留同一段描述”，于是过早引入外部空间，而没有先比较内容原位替换。
- **证据缺口**：A5 展开前没有提交卡内容量预算和原位方案对照；动态证据只证明抽屉能运行，没有证明抽屉是正确的信息架构。
- **复发家族**：与此前“按槽位字面执行、忽略结构意图”的错误同源。几何 gate、非遮挡和可运行都不能替代承载方式是否合理的 UX 判断。

## 固化检查

1. 固定卡片新增 popover / drawer 前，必须先计算相邻内容槽的联合高度，并分别列出 collapsed / expanded 的文字与行数预算。
2. 至少提交一个不移动图片、不移动主 CTA、不改变卡片总高的原位方案；只有它无法满足最小信息量时，外部层才进入比较。
3. 只读任务预览默认最多 2 条，并用“另有 N 条”说明剩余数量；不得硬塞第 3 条、设置内嵌滚动或把预览行画成并列按钮。
4. 运行截图的“能展开、无遮挡、可关闭”只构成交互实现证据；是否符合玩家预期必须另做内容容量与层级复审。
