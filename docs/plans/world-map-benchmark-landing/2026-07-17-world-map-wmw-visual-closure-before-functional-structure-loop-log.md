# WMW 先做视觉闭合、后补功能结构的误判 Loop Log

## 三行决策条

- **结论**：上一张概念图只保留三栏大组合参考，内部功能与尺寸全部撤回；它不是可继续细化的正确结构稿。
- **影响**：若继续沿上一张图补美术，会把漏掉的推进日、重复 / 空白中下卡、错误展开态和漂移几何一并固化，最终仍然无法落 runtime。
- **下一步**：以本轮精确黑白结构稿为唯一布局真源生成新 mock；推进日运行命令另立实现任务，未完成前不声称功能已可用。

## 触发

2026-07-17 用户在上一张整屏概念图上明确反馈：大模块组合可以，但很多功能、位置和大小有问题；左下日期本应提供推进到下一天，并要求先总结、再给黑白结构稿、最后按结构稿生成。

## 错误表现

1. 左下被画成只读日期卡，直接漏掉 A99 / A110 已采纳的推进日入口。
2. 推进日没有首次点击确认和后果预览，无法表达剩余天数、截止日与到期任务变化。
3. 中下两张大型纸卡没有真实决策价值，用空白和泛化状态代替功能。
4. A5.1 默认展开任务列表，破坏“先读地区、按需展开”的默认动作链。
5. 顶部和左下同时显示剩余天数，形成同一事实双主人。
6. B2.12、双回执与 A5.1 的尺寸没有按 1920×1080 frozen 比例复原；右侧档案尾又显得像第二功能面板。
7. 前一轮把“四角视觉闭合”放在“完整功能盘点”之前，得到的是闭合但职责错误的页面。

## 根因

### 1. 已采纳决策漏读

上一轮只沿 A226 的最新文字继续，未回读 A99 / A110，错误地把“没有伪功能”收缩成“左下只读周程”。用户指出推进日后重新交叉检索，确认本次不是新增机制，而是此前已采纳交互被漏掉。

### 2. 产物阶段误判

在没有精确功能结构稿的情况下直接进入 `filled_state_text_mock`，让生图模型自行推断容器内容。模型可以给出大致三栏气氛，但不能替代真实功能清单、状态机和 frozen 坐标。

### 3. 视觉闭合 Gate 覆盖过窄

A226 新增了四角闭合检查，却没有把“闭合物件是否对应真实职责”作为前置条件。于是左下、中下、右下都有东西，但这些东西不一定是正确的东西。

### 4. 评审对象不完整

此前 UX / UI 评审围绕“如何填补空角”展开，没有先得到完整操作链与运行命令盘点，导致评审 prompt 自带“只读周程”假设。

## 修正

- 先由 UX 老哥给出完整动作链和 P0/P1/P2，再由 UI Designer 锁定 1920×1080 坐标。
- 左下从只读周程改为独立全局日程器；推进日采用首次点击确认，且明确预览后果。
- 中下删掉当前选区摘要和“世界状态已同步”，只保留真实世界回执。
- A5.1 默认收起，进入地区任务台仍为唯一最强 CTA、进入不耗天。
- 顶部只显示 `ISSUE 001 / WEEK 01`，剩余天数由左下唯一拥有。
- 先生成确定性 `structure_wireframe`，尺寸审计通过后才允许真实 imagegen。
- 上一张概念图降级为 `composition_reference_only`，只允许参考三栏组合和组件身份。
