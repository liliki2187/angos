# WMW 程序粗装误当整屏美术候选 Loop Log

## 触发

2026-07-21 用户复核 v0.3 后指出：虽然左栏共轴问题已经修正，但当前界面的美观程度仍明显弱于美术标杆图；按钮与组件构成粗糙，左栏外侧留白也比标杆更大，并询问下一步是否应按当前功能 / 尺寸布局、结合美术标杆重新生成完整效果图。

## 结论

用户判断成立。v0.3 的有效身份应降级为 `functional_geometry_filled_state_evidence`：它证明三栏职责、真实内容容量、共轴、文字安全区与无路线边界，但不能继续承担正式美术风格候选。下一有效视觉产物应是以当前功能骨架为输入、以 clean-low-poly weekly 标杆为美术真源的完整整屏 art pass。

## 错误

- 为清理 placeholder、修复共轴与保证文字安全，父级使用大面积纯色矩形、统一 1px 描边和简单状态块覆盖生成源，导致材质、切角、按钮轮廓、状态层级和纸面结构被压平。
- 机器 Gate 能证明“没有越界 / 没有错位”，不能证明按钮和组件已经达到标杆图的美术完成度。
- v0.3 四个左栏外壳虽精确共轴，但 `x=66` 使屏幕左侧外留白显著大于标杆图的视觉重量；该参数尚未经过整屏美术阶段的最终裁决。
- 此前把 UI / UX 的功能与几何 PASS 继续表述成“等待用户风格采纳”，再次混淆了技术合格与美术合格。

## 下一阶段约束

1. 保留 v0.3 的功能职责、内容容量、组件纵向顺序和真实文字；不得恢复错误功能或伪控件。
2. 左栏外边距 / 可见宽度在生图前单独收敛，不能把 `x=66` 当作不可修订的美术真源。
3. 下一张必须是真实 imagegen 参与的完整 1920×1080 整屏 art pass，不再用程序色块冒充美术完成度。
4. imagegen 负责卡框、按钮轮廓、纸面、切角、材质、阴影与整屏统一气质；程序只负责精确 rect、真实中文、状态语义、文字安全区和清除假字 / 假控件。
5. 不再整块覆盖生成后的按钮与功能 carrier；需要文字安静区时，使用与生成材质一致的无字 clean layer / mask。
6. 用户仍只看一张完整玩家视图，并被明确告知其用途、为何现在审阅、需要判断什么。
