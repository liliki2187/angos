结论：用户判断成立。v4 的深色地图、综合色灰桥和离散亮岛关系继续保留，但右侧 Dossier 的载体身份失败；它只能作为 `dark-map-and-lit-islands / corporate-report-component diagnostic`，不能成为下一张完整视觉目标。

影响：问题不是少几张便签或多几条批注，而是标题、状态、照片、Disclosure、四列记录和 CTA 被一张完整白表单统一收编。该结构先读成企业审批 / 工单 / SCP 档案，压过“正在形成的怪新闻主稿”。

下一步：冻结 Dossier 外矩形、钴蓝母夹、同源 `69:44` 新闻图、Disclosure、CTA 和 hit rect；整体重写内部物件为标题纸、照片校样、编辑说明短签、资料索引和行动签。本轮先确认方向，不继续生图。

## 触发

2026-08-19，用户把两张正式 benchmark 的文件夹 / 文书局部与 v4 右侧 Dossier 并排，明确指出标杆虽然有办公属性，但远未达到严肃办公与官僚主义的程度，整体仍是编辑部感觉；v4 则是纯公司报表。

## 误判归因

- 命中 F7：以结构闭合、字段完整、统一线框和完整表格制造组件完成度。
- 命中 F8：没有先判断标题纸、照片校样、索引和行动签分别由谁在什么编辑阶段产生，直接把它们当成同一行政表单的字段。
- 上轮虽然已把右栏机构表格列为 P1，却把它当作局部语义残留，没有识别它其实控制了整个 Dossier 的物件身份。

## 标杆证据

- 文件夹只提供综合色母轮廓和局部露边，不完整包围全部内容。
- 标题、照片、便签、索引和状态往往分属不同纸件。
- 夹子、胶带和压叠说明“仍在加工”，不是说明“这是一份档案”。
- 表格与编号只在边缘收束，不成为第一阅读层。
- 完成度集中在大形、少量综合色块和接触关系，而不是完整字段与微型线框。

## 当前失败信号

- 四面闭合的亮白长表单承担全部功能。
- `STATUS ACTIVE` 建立企业 / 工单状态语言。
- Disclosure 使用四行等高、多列对齐、人员 / 部门 / 日期式台账。
- CTA 读成标准企业门户按钮。
- 标题、标签、表格与按钮都由同一套企业化大写无衬线语气发声。
- `+` 与已展开四行内容同时出现，状态自相矛盾。
