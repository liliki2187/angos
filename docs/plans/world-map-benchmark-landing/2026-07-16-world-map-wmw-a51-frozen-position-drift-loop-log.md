# WMW A5.1 frozen 位置漂移 Loop Log

## 结论

独立 WMW 宿主首轮实现把右栏责任区起点 `[932,16]` 错当成 A5.1 组件起点，把 frozen 位置 `[932,30]` 写成了 `[932,16]`。三区结构与交互测试虽通过，但违反 `right_dossier_page.json` 0.8.8 的 `frozen.positions`，因此首轮 644-650 在修正前不得作为最终证据。

## 根因

- 实现时只核对了右栏宿主矩形，没有在 assembly snapshot 与集成测试中同时断言 A5.1 的 frozen 全局位置。
- 首轮评审输入把错误位置当作既定事实，导致 UX / UI 只能验证相对结构，无法发现合同漂移。
- “宿主边界”和“组件边界”没有在证据清单中分成两个独立 gate。

## 修正

- `RIGHT_RECT` 保持 `[932,16,320,688]`；A5.1 改回 `[932,30,320,520]`。
- 集成测试新增 `dossier_rect=[932,30,320,520]` 断言。
- 运行截图探针同步改为 1920×1080 下的 `[1398,45,480,780]`。
- 644-650 全量重跑；原文件只在同一未交付轮次内覆盖，不新增编号。
- 修正后要求 UX 老哥与 UI Designer 各给一份位置修正附录，确认 14px 顶部内缩未破坏操作链或三栏平衡。

## 防复发

后续整屏装配必须分别记录并断言：

1. `responsibility_rect`：页面职责区；
2. `component_frozen_rect`：组件合同位置；
3. `visible_body_bbox`：实际有色主体；
4. `shadow_bbox`：外部投影。

不得再用责任区起点替代组件合同起点，也不得把父级对齐判断写成子组件 frozen 位置变更。
