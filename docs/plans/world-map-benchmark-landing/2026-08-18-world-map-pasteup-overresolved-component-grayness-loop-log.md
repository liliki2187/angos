## 触发与归因

- **触发来源**：用户对照两张正式 benchmark 的四个文件夹 / 文书裁切，指出标杆更手绘、低多边形、少细节，当前组件太完整、太高完成度、综合色缺灰。
- **原始问题**：父级与 UI Designer 上轮正确识别了 02 的综合色和印刷材料价值，却把“材料身份接近”扩大成“最接近 clean-low-poly weekly”，没有单独检查工作物件的抽象度、可见层数、五金配额、内部细线密度和共同灰底。
- **失败归因**：对象—画法证据不足；既有 `component_render_language_lock` 能拦写实产品渲染、矢量贴纸和细碎新闻图，却没有拦“每个文件夹都把轮廓、背页、五金、边框、状态签、条码和校准线同时做完”的过度精制。
- **复发判定**：命中 F7「符号 / 组件矢量化与过度完成」第 5 次复发；中央地图的密三角伴随命中 F9「低多边形碎片化」第 6 次；同时是 F1“材料改善被扩大为标杆接近”的伴随案例。
- **本轮处理**：降级 + 返工上游 brief；不继续生成。

## 标杆差异

benchmark 的完成度集中在：

- 一个清楚的大轮廓；
- `3–6` 个宽明度 / 综合色块；
- 一处手工切口或偏移；
- 一件足以说明接触关系的夹具；
- 少量粗线印刷 / 手绘信息。

当前 02 的完成度分散在：

- 完整内外双框；
- 多张薄背页和连续侧签；
- 夹子、铆钉、环装、胶带、色样轨同时出现；
- 条码、准星、微型版号、分隔线和注册线同时存在；
- 地图均匀细三角、完整综合色描边和立体厚度同时存在。

结果不是“更高级的粗概括”，而是“精制完成的机构组件”。

## 下一轮减法口径

- 每个主组件只保留 `1` 个主壳、`1` 个内容面和最多 `1` 个状态结构。
- 右稿最多主纸＋一张综合色背纸＋一处统一接触阴影；只保留一枚大夹子。
- 左卡不再逐张增加独立五金；三张共享同一可见层数和轮廓预算。
- 中央 selected 照片的夹子与胶带二选一；地图每个大洲先读 `3–6` 个主要明度面。
- 非功能微元素先删 `40%–60%`；五金与纸层总量先删 `50%–70%`；连续双框、竖向色样轨、准星、条码、微型版号优先删除。
- 综合色共同向一层低彩度冷石板灰靠拢；不是新增灰色组件，也不是叠棕色 / sepia。当前候选的综合色可先试降约 `15%–25%` 彩度，暖白纸可先试降约 `35%–45%` 彩度；这些只作为下一轮视觉假设，须由标杆裁切对照校准，不是生产 token。
