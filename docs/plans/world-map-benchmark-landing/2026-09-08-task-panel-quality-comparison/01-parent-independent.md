# 父级独立分析：任务区组合质量

2026-09-08。此稿先于本轮 subagent 调用保存，后续比较不回改正文。当前任务仅诊断与比较处理方式，不修改 Godot、位图或功能。父级参与了此前实现，因此这是一份先行独立自查，不是无历史偏见的盲测。

## 结论

现状解决了任务可发现性，却把任务做成了一块套在美术稿上的常规列表面板。质量问题主要来自内容节奏与纸件尺度没有一起设计，而非插画清晰度不足。单纯修边或多加贴纸，不能修复这层割裂。

## 证据与判断

1. **任务名和耗时没有成为同一个阅读单位。** 用户截图里每个短标题下方空了一整行，耗时却离下一条标题很近；左侧竖线只包住标题高度，耗时像落在分组之外。代码将任务名固定占 59px、耗时固定从 y=59 开始，即使标题只需一行也预留两行。这是可确认的实现原因。长标题不裁切值得保留，但不该用破坏最常见短标题节奏的方式达成。
2. **密度分配不均：顶部挤、正文散、底部贴边。** 标题签、粗体分类和红色说明连续堆叠；两条任务中间却有大段空白。第二条耗时贴近底框，“可进入调查”又紧挨黄色按钮和外纸底边。几何上没越界，观看时仍像各自放进了槽位。标题、分类、警示也都在争夺先看顺序。
3. **资源被复用了，但形状没有为此用途设计。** 实际代码把同一张 `region-tag.png` 的 329×142 纸面同时九宫格拉成 550×298 正文纸和 556×44 标题条。可见结果是标题条略宽于正文、上沿多重细碎接缝、完整深色框和浅青大空面。这里不是据代码断言所有拉伸都有错，而是素材用途与实图缺陷相互对应：宽块面、明确层叠的纸件，变成了带纸纹的矩形 UI 面板。
4. **字号与文案没有形成编辑节奏。** 标题和分类都偏重，辅助文字与说明较小；“取材提醒：存在限时任务，请进入地区查看具体截止条件”“只读预览”主要在解释系统，实际任务内容反而被拆散。信息不能删掉，但可以把含义写短，并把提示归到它服务的内容旁边；具体新文案需基于真实状态，不能编造截止时间。
5. **局部补功能挤掉了整体的画面重心。** 整屏对照中，右侧照片从 546 缩到 430 宽，换来的是面积较大的任务底板和被固定行高撑出的空白。不能据此断言图片必须恢复旧尺寸，但应该先修阅读结构，再判断任务区实际需要多少面积，而不是继续靠缩图补空间。

## 我的处理方式

先重排“任务内容 + 承载它的一张纸”，再决定是否需要替换纸面资源。

- **改成一张有明确身份的任务便笺。** 保留浅矿物青与新闻暖白的区别；撤掉完整深色框和通栏深色横杠的双重包围。标题可用局部墨青短签，正文纸只在一至两侧露出清楚衬纸；避免再加夹子、杂乱边角或幽默批注去掩盖结构问题。具体形状是待验证提案，不是假称已经做好的美术资源。
- **以任务名为主，类型与耗时贴着它成组。** 类型和耗时可合为紧跟标题的次级行，例如“线索 · 调查 2 天”；取消另立一栏的“线索 + 竖线”。短标题按一行实际排版，长标题自然变两行；先保证组内距离小于组间距离，剩余空间留在组外。整行仍只读，不增加复选框、箭头或按钮底板。
- **只保留两层强弱。** “地区任务 · 4”和任务名为主要阅读文字，分类、耗时和折叠提示为次级文字。限时说明用少量锈红提示并就近关联分类，保留含义，去掉重复的系统解释；折叠后分类及提醒仍可见。
- **把进入按钮及说明当成一个完整收尾。** 蜜黄仍承担主动作；按钮、下方说明和外纸底边之间留出明确距离，不让说明像挤出来的残余。按钮在折叠前后保持稳定。完成任务排版后再以整屏判断是否能适度恢复照片权重，不预先承诺图片可以变大。

## 怎么验证这一处理方式

先做一份带当前真实短标题的右栏整体候选，同步代入两行长标题与折叠状态；至少把新闻图片到进入按钮一起看，不能只审任务局部框。确认常态任务名与耗时归属、辅助文字可读、纸件边缘和整屏色块成立，再迁移运行合同与复跑必要功能检查。若现有纸件无法同时承担细边和宽阅读面，再制作合适的无字资源；不在诊断阶段先开一批生图。

## 此前判断遗漏

此前 57 项运行检查覆盖功能、可见行数和几何边界，未证明正常短内容的排版节奏或素材组合质量。父级此前看到了预留空行但接受了它，未追问组内和组间距离是否倒置；这不是用户标准突变。应修订上一轮“无阻止交付问题”的适用范围：功能证据保留，用户已明确提出视觉质量需要返修。

## 限制与成本

这是基于当前实图、母图、代码和原标杆的诊断，方案尚无新的成品证据。任务区结构调整需要迁移布局及纸件用法，成本高于只改边距；其预期收益是同时修复内容节奏和美术整合。不能仅凭分析文字保证最终好看。
