UX老哥诊断｜世界地图右下任务区

这是运行界面的组合质量问题。玩家要沿“选地区→看新闻与调查机会→判断是否进入→进入后选任务”完成浏览；系统要保留悬疑气氛，同时说明任务分布、风险与进入条件。目前功能关系基本可辨，但新闻、任务和按钮像三套排版临时拼接，缺少一张编辑部来稿应有的整体组织。

实际看过：用户局部原图，默认整屏、长文案、折叠、锁定、开放空态截图，选定三栏候选，两张原标杆的等比查看副本，以及 `region-tag.png`、`action-paper.png`。查阅了 `WeeklyRunWorldMapSoftColumns.gd` 相关布局。未运行交互；本次未触发辅助 KB。已读取 D 盘新版技能及兼容入口，未调用退出活动的旧案例规程。

**观察与原因**

1. **P2：任务区的外壳比内容更抢眼。** 深青横条、浅青大底、闭合细框、任务左竖线、蜜黄按钮连续叠加；正文刚结束，马上进入另一块“应用面板”。选定候选的任务原本延续同一暖白纸面，更像来稿附带的编辑信息。代码确认标题与底板均从同一标签纸局部取样，再分别拉伸和染色。推断：边界和色块主要服务控件分组，没有形成可信的纸件关系；不能仅据此认定纹理失真。原则是让资源表达内容归属，而非每层信息都另造物件。

2. **P2：文字间距服从槽位，不服从句子。** 默认图中任务名称与耗时隔得远，第一条耗时反而靠近下一条标题；长文案图又挤成连续重字。代码确认标题恒占 59 高、耗时固定从 59 开始、每行步长 84。这里的断裂是“任务名—类型—代价”未形成稳定阅读单位，而非字号单纯不够大。左侧类型独占一列，还进一步压缩标题行长。未证明玩家因此作出错误决策，故不升 P1。

3. **P2：右栏空间分配没有共同节奏。** 照片比下方文字明显内缩；短新闻标题后留大空隙，说明文字却紧贴任务头；按钮下的进入说明贴近纸边。折叠只隐藏两条任务，仍保留整块空底，视觉重量几乎不变。代码确认照片、标题、任务底与按钮分别固定定位。推断：各控件分别容纳内容，整栏没有共同决定哪些地方该紧、哪些地方该松。图片复用本身不是问题，也无需另加任务配图救场。

**独立冲突检查**

数值：4 条与预览 2/4 一致；时间：“调查耗时”与“进入不耗天”可区分；术语：“只读预览”修饰信息，但所在整条标题可点击折叠，作用范围略含混；状态：锁定、开放空态、折叠已有区分；层级：重标题条与大片空底放大了任务模块的存在感；操作范围：任务只读、入口统一，代码支持；空间方向：箭头未见矛盾，“下方条件”在锁定图中确实位于下方。无已证实 P0/P1。

**交给 UI Designer 的处理方向**

保守方案：【加】统一右栏阅读边线，让耗时紧跟真实标题高度，把类型并入紧凑元信息；为纸底留足边距。【减/压缩】短标题的预留空行、类型独占列、重复分隔线与标题条重量。优点是改动集中，代价是仍受现有固定分区约束。

结构方案：【加】把“新闻正文→调查摘要→进入”组织成同一张来稿，任务区用轻分隔承接；按实际内容分配行距。【减/压缩】整块浅青嵌套底与重复框线，收起时仅保留分类、提醒和展开入口。代价是需处理折叠后按钮位置是否变化，并核对受影响的运行合同；若触及 frozen 几何字段，需升合同版本。

**Top 3 ROI**

1. 立即可改：任务名与耗时重新成组，收益明确、实现成本低。
2. 立即可做候选：减轻任务外壳，恢复与新闻纸面的关系，质量收益高。
3. 需要产品确认：折叠是否回收空间、按钮是否固定；随后调整整栏节奏。

成品验证应并排比较同尺寸默认与长文案截图，再覆盖折叠、锁定、空态；检查文字是否真正属于纸面、短长内容是否同样从容，并实测标题折叠与入口。这些建议尚未由改进成品或用户测试证明。

待确认：任务分类是否互斥；预览顺序是否有意先展示两条线索；折叠的目的究竟是降低信息量，还是释放版面空间。
