# WMW 功能量与容器体量失配 Loop Log

## 三行决策条

- **结论**：上一版功能结构方向正确，但“形式已确定”被误解为“旧尺寸必须原样复用”，导致简单回执和纯装饰继续占据决策级体量。
- **影响**：地图主舞台被低价值信息挤压，右下无交互区域又被读成第二功能面板；若继续生图，视觉精致只会把错误体量固化。
- **下一步**：新增紧凑回执变体、缩短档案收口、扩大地图；本轮只交付黑白结构稿，等用户裁决后再升合同或生图。

## 触发

2026-07-17 用户查看 A227 的结构稿生成结果后指出：整体大致正确，但很多区域、组件和按钮的尺寸 / 位置仍不合理；双回执功能简单，下方一小条即可；进入地区任务台下方空白区域过大。

## 错误表现

1. 两条只读回执各使用 369×207 大纸，视觉重量接近任务卡。
2. 回执同时使用大书签、两级文字、七格刻度、脚注和大留白，装饰层数超过信息层数。
3. A5.1 下方 75px 后页 + 156px 文件袋正面共 231px，零信息、零命中却像第二功能区。
4. 地图只有 696px 高，反而被弱信息挤占主舞台空间。
5. 结构冻结检查只验证了坐标存在，没有验证“该坐标是否值得这个信息量”。

## 根因

- 把组件身份与组件尺寸绑定：正确保留了“回执”语义，却错误保留了旧 `bottom_receipt_card` 大卡体量。
- 把四角闭合等同于铺满：为了避免右下断尾，用大面积前景档案面一直压到底。
- 信息容量表只问“装不装得下”，没有反向问“是不是装得太空”。
- 黑白结构稿没有在生图前执行信息价值 / 容器体量审计。

## 修正

- 旧 `bottom_receipt_card v0.8.5` 保留，不缩放；世界地图页另建 450×90 `bottom_receipt_strip` 结构候选。
- 两条回执只保留身份色条 / 小图标、标题、单行状态和七日刻度；删除脚注与大纸留白。
- 地图扩大到 924×822；回执压缩释放的高度全部归还地图。
- A5.1 frozen 不动；下方只保留 480×62 浅袋口，`y=887–1056` 恢复无框背景。
- 日程器压至 342×182，但完整保留默认 / 原位确认 / 后果预览。
