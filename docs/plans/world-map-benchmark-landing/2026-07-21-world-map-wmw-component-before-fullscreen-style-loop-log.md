# WMW 在完整风格稿前先做孤立组件的阶段误判 Loop Log

## 结论

本轮错误不在 `schedule_gate` 几何或审计，而在阶段顺序：WMW 尚无一张经过用户认可的完整 1920×1080 美术风格稿，却先让孤立日程器承担“是否符合美术标杆”的视觉裁决。一个 342×246 组件无法证明整屏色彩比例、地图主次、三栏材质统一和整体周刊身份。

## 影响

- 用户即使看到完整组件拆图流程，仍无法判断它放回全屏后是否属于同一套 WMW 美术语言。
- 局部框体可能在技术上完整，却与未来整屏风格产生冲突。
- 若继续扩产，会把尚未确认的局部材料语言扩散到 B2.12、地图和 A5.1，增加返工面。

## 根因

1. 把 A237 的“黑白布局冻结”误当成“整屏美术方向已经冻结”。
2. 把 benchmark board 的局部材质语言误当成可直接下发到单组件的完整整屏样式合同。
3. 资产化 bridge 虽然规定了组件分层，但没有再次检查是否已有通过用户裁决的 `filled-state full-screen visual style mock`。
4. UI / UX 对组件层级、可读性和状态辨识的通过，被错误用作整屏美术裁决入口。

## 修正

1. 当前 `schedule_gate` 有色纵切降级为技术管线证据，不再是视觉候选或风格母本。
2. 立即停止下一组件生产，路线退回完整 1920×1080 真实内容风格稿。
3. 下一稿必须以 v5.1 黑白布局为功能真源、两张 clean-low-poly weekly benchmark board 为美术真源，同屏展示左卡、日程器、中央地图和 A5.1-H。
4. 整屏稿只服务整体风格裁决，不预拆 atlas、不改 Godot、不升正式合同。

## 防复发 Gate

- 没有用户确认的完整整屏 `filled-state visual style mock` 时，任何孤立组件只能标为技术实验或局部构图样本，不能标为正式美术候选。
- 组件生产 Router 必须显式回答“对应整屏风格稿是哪一张、是否已获用户确认”；答案为空或否时禁止批量资产化。
- UI / UX 的局部 PASS 不得替代整屏美术风格 PASS。
- 用户裁决整屏风格前，不要求其判断 alpha、切图、hash、bbox 或 atlas。

## 保留与冻结

- 保留 `schedule_gate` 的 runtime-local 几何、状态机、文字安全区、生产脚本与 QA 作为技术证据。
- 冻结 Godot、正式合同、compact A5.1、B2.12 和整屏结构，不因阶段退回而重新讨论功能布局。
