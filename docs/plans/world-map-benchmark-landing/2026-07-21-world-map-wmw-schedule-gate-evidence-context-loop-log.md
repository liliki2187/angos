# WMW `schedule_gate v0.1` 资产证据上下文缺失 Loop Log

## 结论

首轮证据虽然覆盖真实 imagegen 源、无字母版、状态回填和自动审计，但仍以“若干技术图 + 文件路径”为主要交付单位，没有把完整拆图生产链与用户裁决任务讲清楚。技术证据成立，用户审阅入口不成立。

## 影响

- 用户需要自行猜每张图在生产链中的位置，无法快速判断当前到底完成到了哪里。
- 母版、材料板与状态板的技术身份清楚，但“为什么现在给用户看、需要用户确认什么”没有成为图内第一层信息。
- 若继续沿用该方式，用户会被迫承担几何、hash、bbox 等本应由自动化完成的 QA，同时又缺少观感裁决的明确问题。

## 根因

1. 把自动审计证据与用户裁决材料混为一组。
2. 把“已经覆盖多个阶段”误当作“用户能看懂阶段关系”。
3. 证据板按素材类型分组，而不是按真实生产顺序组织。
4. 最终交付模板没有强制写入“用途 / 当前出示原因 / 需要判断什么”。

## 修正

1. 新增一张完整流水线演示板，顺序展示：原始生成源 → 四角色裁片 → 归一化 → 1368×984 装配 → 456×328 母版 → 342×246 回放 → 状态叠加 → 7 状态输出。
2. 状态复核板顶部增加三段面向用户的说明，不再只显示技术标题。
3. 自动审计继续承担尺寸、alpha、safe rect、颜色和 hash；用户只判断纸材方向、默认 / 危险 / 执行 / 禁用的状态辨识，以及是否允许进入下一单组件。
4. 本轮 delivery manifest 逐图记录 `purpose / why_now / user_judgement`。

## 防复发 Gate

- 可见资产交付若没有完整授权范围的末端结果，不得请求用户裁决。
- 每张用户审阅图缺少用途、出示原因或判断项中的任何一项，Delivery Gate 失败。
- 只给文件列表、尺寸或 QA hash，不算可审阅交付。
- 用户不再需要肉眼判断脚本可验证的像素级事项。

## 范围边界

本次修正只重组证据与讲解，不重开 `schedule_gate` 几何、颜色母版或状态设计，不进入 Godot、正式合同、compact A5.1 或有色整屏。
