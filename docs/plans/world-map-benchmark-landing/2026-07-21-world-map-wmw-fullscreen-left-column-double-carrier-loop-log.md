# WMW 默认态整屏左栏双载体误交付 Loop Log

## 触发

2026-07-21 用户查看完整整屏候选后指出：“这个左边组件怎么乱七八糟的。效果是以图2为准吗”。图 1 是程序装配后的有字整屏，图 2 是 built-in imagegen 生成的无字整屏视觉提案源。

## 结论

用户判断成立。v0.1 左栏不是可接受的最终效果，当前整屏候选撤回 UI / UX 视觉通过口径。左栏的视觉方向应继承图 2 的干净单层卡框与日程色块；图 2 只作视觉材料 / 构造目标，v5.1 继续独占功能、几何、文字与状态真源。

## 这次错在哪里

装配脚本把 imagegen 源中的整张左卡与整块日程直接裁入，其中已经包含占位横条、占位状态块和底板分区；随后程序又叠加真实标题框、状态框、日程头、动作区和后果区，造成：

- 占位横条没有被完全覆盖；
- 标题 carrier 与源图占位 carrier 叠成双层；
- 状态块出现套框与残留底色；
- 日程器出现多层纸条、分隔线与底板残片；
- 三张卡虽几何对齐，但视觉上像不同阶段的素材被强行拼在一起。

根因不是 v5.1 三栏、左卡职责或日程功能，而是错误扩大了 imagegen 源的权限：本应只取照片与材质，却复用了含占位布局的完整组件图。

## 为什么此前 Gate 没拦住

- 44 条文字安全区只证明字没有越界，不证明字下面没有旧占位条。
- 三栏层级与 CTA 权重检查是整屏级检查，没有建立“源占位 carrier 不得进入最终玩家视图”的局部合成闸门。
- UI / UX 最终复核关注地图主场、三栏闭合和动作链，漏掉左栏的双载体与残留横条，因此原 PASS 不能继续成立。

## 修正约束

1. 三张卡只允许从 imagegen 源提取照片内容；不得再粘贴源卡 footer、占位横条或状态块。
2. 卡框、单层纸质 footer、地区标题与状态块由程序按 v5.1 rect 一次性重建。
3. 图 2 的视觉目标是：单一外框、单一照片窗、单一纸质 footer、一个状态块；不得出现 title plate 套 title plate。
4. 日程器不得复用源日程整块；以一层日期头、一层推进动作区、一层后果区重建，保留当前日、剩余日、二次确认入口与后果信息。
5. 新审计必须记录 `left_card_source_role=photo_only`、`left_schedule_source_reuse=false`、`placeholder_carrier_reuse_count=0`。
6. 用户仍只看修正后的完整 1920×1080 玩家视图；局部放大只作内部 QA，不作为孤立审阅任务。

## 范围

- 不重谈三栏结构，不改 v5.1 rect。
- 不重新调用 imagegen。
- 不改 Godot、正式组件合同、compact A5.1 或 B2.12。
- v0.1 PNG 保留为失败证据；新输出使用 v0.2 标识。

## 纠偏结果

v0.2 清除了双 carrier：三卡只复用照片 RGB，日程器不复用任何源 placeholder，`placeholder_carrier_reuse_count=0`；相对 v0.1 的 `x>=402` 差异像素为 0。但用户随后发现 v0.2 日程器与三卡外壳不同轴，因此 v0.2 继续降级为失败证据；共轴问题转入 `2026-07-21-world-map-wmw-left-column-axis-alignment-loop-log.md`，由 v0.3 修正。
