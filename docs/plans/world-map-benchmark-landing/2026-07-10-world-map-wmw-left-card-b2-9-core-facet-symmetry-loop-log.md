# WMW 左卡 B2.9 内芯分面对称性 Loop Log

> 日期：2026-07-10
> 触发：用户复核 519 放大对比后指出，B2.9 虽修复了右侧涂抹，但状态徽章底板的低多边形 X 形分界明显歪斜。
> 结论：B2.9 的无 inpaint 结构修复有效，但内芯纹理构造失败；整体降级为 `visual_fail_badge_core_facet_asymmetry`。

## 一、原始问题

B2.9 为避免修改候选 B approved 外环，只替换了零交集 `CORE_MASK`。这一步正确地消除了 B2.8 的 harmonic inpaint 涂抹，却在 `neutral_core_texture()` 中重新手写了四块低多边形色面。四块色面的外围锚点没有按同一矩形四角顺序成对镜像，导致色面交界形成弯折、偏斜的 X。

## 二、代码证据

B2.8 的对称扇形使用同一矩形四条边，四块都汇聚到 `(332,246)`：

```text
top:    (306,220) -> (358,220) -> center
right:  (358,220) -> (358,272) -> center
bottom: (358,272) -> (306,272) -> center
left:   (306,272) -> (306,220) -> center
```

B2.9 改成了不成对的锚点：

```text
top:    (310,216) -> (354,216) -> center
right:  (354,216) -> (361,269) -> center
bottom: (361,269) -> (310,276) -> center
left:   (310,276) -> (302,224) -> center
```

右块落到右边界中下点，底块又从该点斜跨到底边左点，左块则从底边左点斜跨到左边界上点。它们不是四条对称边，而是沿八角形轮廓错位取点，因此交界线必然弯成歪 X。这个 X 不是状态图标，也不是旧层残留，只是程序色面的明度边界。

## 三、为什么 Gate 没拦住

1. `retired_footprint_texture_continuity` 只证明内芯之外没有涂抹或像素变化，刻意不评价内芯内部造型。
2. `badge_state_color_consistency` 只比较内芯与框带的平均 hue / 明度，不检查分面线方向、镜像关系或中心汇聚。
3. `runtime_icon_shape_completeness` 只检查勾 / 靶心 / 三角 / 锁本身的透明 padding 与完整性。
4. 519 已把歪 X 放大展示出来，但执行方把注意力锁在“右侧涂抹是否消失”，没有对新生成的内芯纹理做独立形状审查。这是人工目检范围锚定导致的假阴性。

## 四、下一轮唯一正确修法

- 保留 B2.9 已验证的外环、右框、照片、地球和运行时图标，禁止再次触碰这些层。
- 内芯分面必须从 `CORE_MASK.getbbox()` 与合同中心参数化生成四个镜像象限，禁止继续手写四组不相关端点。
- 四个象限统一使用同一中心；左 / 右、上 / 下端点必须严格镜像，mask 只负责把矩形扇形裁进八角内芯。
- 新增 `badge_core_facet_symmetry`：检查四条中心分界的端点镜像误差、中心汇聚误差和左右 / 上下色面面积差；程序通过后仍需贴 400% 空底盘对照图。
- 运行时图标叠加后再做 Godot 真实截图；空底盘与最终运行态必须分别目检，不能让图标遮住底纹缺陷。

## 五、宣称修正

- B2.9 的 `retired_footprint_texture_continuity=PASS` 仍是有效的局部结构证据。
- B2.9 整体视觉结论改为 FAIL；526 manifest 仅为程序证据，不能作为生产通过依据。
- 未经下一轮对称内芯修复与用户复核，不得冻结左卡，也不得生产其它 class。

## 六、B2.10 解决回链（2026-07-13）

B2.10 已将共同内芯改为由 `CORE_MASK` bbox 与中心 `(332,246)` 参数化生成。实现先以完整 `CORE_MASK` 清除旧语义，再用 `CORE_MASK ∩ mirror(CORE_MASK)` 作为结构分面区，避免源掩膜自身的单像素不对称污染镜像 gate；剩余非对称边缘只铺状态基色，不承载分面边界。最终端点镜像误差 `0px`、中心汇聚误差 `0px`、左右面积 `876/876px`、面积差 `0`、结构镜像 IoU `1.0`。approved 外环仍保留 `1983/1983px`，内芯外与右侧走廊变化均为 `0px`。
