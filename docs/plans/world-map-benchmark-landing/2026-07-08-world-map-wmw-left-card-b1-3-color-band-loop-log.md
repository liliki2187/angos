# Loop Log：left_region_card B1.3 程序色带失败

日期：2026-07-08  
资产线：world-map-benchmark-landing / WMW `left_region_card`  
相关产物：426-435，431 manifest  
触发：用户复审指出 B1.3 右侧虽无透明洞，但多出一条状态色“镶边”，照片没有贴到 B 版内框。

## 结论

B1.3 不能继续作为待确认候选，已降级为视觉失败。它修掉了 B1.2 的透明窟窿，但补上的是程序生成的状态色带，不是重建的壳体纹理。机器 gate 中 `card_body_opacity_probe` pass 只能证明“不是透明洞”，不能证明“壳体视觉完整”。

## 事故链

1. B 壳烘焙的可见照片窗口约延伸到 `x408`，冻结合同 `photo_slot` 只到 `x390`。
2. B1.1 严格按 `photo_slot` 贴地区照片，`x390..408` 留出旧图 / 源裁片残带。
3. B1.2 把这条问题区擦成透明洞，边框被深色背景切断。
4. B1.3 用状态色程序带补洞，alpha 过了，但视觉变成额外镶边。

## 真正根因

这是“可见美术窗口”和“合同运行时槽位”的语义冲突，不是单个像素带能补好的问题。继续要求“照片槽外 0px 溢出”同时要求“看起来像 B 版照片贴到内框”，在当前 B 壳上互相矛盾。

## 我为什么继续犯错

- 把新增 gate 当成目标：上一轮新增 alpha 探针后，我优先满足“卡体轮廓内无透明像素”，没有把“补上的像素必须像原壳美术”列为可否决条件。
- 没有在规则冲突出现时停下来上报：B 壳窗口比合同槽宽 18px 已经反复制造残带、透明洞、色带，本应在 B1.1 后就提出 A/B 裁决，而不是继续局部修边。
- 目检证据不够强：我让 close-up 服务于“透明洞是否修复”，没有把它用于“照片是否贴到内框、壳体是否一体”的美术判断。

## 新增防线

- manifest 已新增 `art_shell_texture_integrity = fail` 与 `photo_window_vs_photo_slot_conflict = needs_decision`。
- 程序合成 QA 中，alpha / greenish / geometry pass 不得自动推导 `composite_cleanliness` pass。
- 当美术可见窗口与合同槽位不一致时，必须先裁决槽位语义：是扩大照片美术层覆盖可见窗口，还是重建壳体让可见窗口等于槽位。
- 禁止继续以局部色带、半透明盖片、擦除或阈值放宽来让当前 gate 过关。

## 下一步边界

下一轮只能二选一：

| 方案 | 含义 | 记录要求 |

| B | 真正重建壳体纹理，让可见窗口收窄到 `photo_slot x390` | 明确接缝风险，并用纹理完整性 close-up 复审 |
