# WMW 左卡 B2.7 badge 重建 Loop Log

> 日期：2026-07-10  
> 触发：用户在 497 Godot 截图中再次指出 selected 右下 badge 存在明显多层叠加错乱，并要求先解释为何反复修改仍失败，再修复。  
> 结论：问题不是“运行时勾号偏大”，而是修复链一直把带状态语义且偏离合同的旧 badge 当作可保留底盘。B2.7 已停止减法清理，改为整区退役并按冻结槽位重建。

## 一、这次实际查到的两个根因

### 1. 清理器和 gate 共享同一个盲区

B2.6 的 `badge_cream_components()` 只在合同 `action_badge` 范围内找奶油色连通块，`is_badge_outer_ring_component()` 决定哪些连通块算“应保留的外环”。旧 available 靶心圆弧与旧八角环在像素上相连，因此：

- 清理器把“外环 + 靶心圆弧”整块保留；
- `atlas_baked_state_glyph_pixels` 又使用同一分类器复核，于是把同一残留继续认作外环；
- 清理和验收不是两份证据，而是同一个错误判断互相背书。

这解释了为什么 manifest 写字形像素为 0，而 497 仍清楚可见旧圆弧。

### 2. 旧 badge 从一开始就不在合同中心

像素探针与 492 几何板显示：

- 旧 B badge 的视觉中心约为 `(331,246)`；
- 冻结合同 `action_badge=[316,212,392,288]`，中心为 `(354,250)`；
- Python / Godot 运行时图标按合同中心绘制。

约 23px 的水平错位意味着：即使旧底盘完全没有残影，只要继续保留旧环，再把 runtime icon 放到正确合同中心，也天然会出现不同心叠层。此前没有 `badge_geometry_contract_alignment`，所以一直把结构错位误读成图标大小、清理半径或贴片质量问题。

## 二、为什么会反复修改仍不行

1. **路径依赖**：B2.3-B2.6 都默认“旧外环可复用”，每轮只修当轮可见症状，没有重新验证该前提。
2. **把减法清理当成重建**：从压平图里擦掉字形，无法证明阴影、抗锯齿、内芯语义和错位外环都已退役。
3. **验证器与修复器耦合**：同一连通组件分类器既决定保留内容又决定是否通过，形成自证正确。
4. **证据顺序倒置**：主要看“底盘 + runtime icon”的最终合成图，没有先把空底盘设为阻塞依赖；图标覆盖后更难区分残影来源。
5. **gate 覆盖面被误述**：`ingredient_purity` 只能证明独立图标 PNG 干净，不能证明 atlas 底盘干净；非黑截图也只证明画面可读，不证明视觉成立。

## 三、B2.7 的止损修法

- 用实测多边形把旧 badge 足迹整区退役，不再按颜色或连通块决定局部保留。
- 在冻结合同槽内重建唯一中性底盘：72×72 八角奶油环 + 无语义低多边形内芯。
- 外环 bbox `[318,214,390,286]`，内芯 bbox `[331,227,377,273]`，中心与合同 `(354,250)` 的误差均 ≤1px。
- 四状态只从 available 单母版换色；atlas 不含任何状态字形。
- 四个 runtime icon 等比缩放进 42×42 设计盒，Python / Godot 使用同一合同中心。
- 生成流程加入阶段阻塞：先只出 499/500 空底盘证据；空底盘 gate 未通过时，脚本不生成 atlas、runtime 预览或 Godot 资产。

## 四、新增防线

1. `badge_geometry_contract_alignment`：外环、内芯、runtime icon、Python/Godot 锚点统一对合同中心断言。
2. `badge_clean_base_no_semantic_residue`：旧足迹原样像素复用 = 0、内芯奶油语义像素 = 0、源状态字形复制 = 0，并附 400% 空底盘证据。
3. 修复器与 gate 禁止共享同一分类器作为唯一依据；至少补合同几何、图层 provenance 或独立视觉证据。
4. 证据顺序锁为：源失败探针 → 空底盘 → 派生底盘 → 图标配料 → Python 合成 → Godot 合成。
5. 执行方目检只记 `evidence_ready`；用户视觉裁决前不得冻结生产资源或批量生产其它 class。

## 五、回归结果

- 旧足迹原样像素复用：`0`。
- 中性内芯奶油语义像素：`0`。
- 外环 bbox / 内芯 bbox：精确命中预定值；中心误差 `0.5px`。
- runtime icon：四状态均在中性内芯内，非目标色族像素 `0`，中心误差最大 `0.5px`。
- Godot 507/508：windowed OpenGL3、Godot 4.6.2，非黑且颜色多样性正常；执行方目检未见旧靶心圆弧或双环，但最终视觉通过仍等待用户。
