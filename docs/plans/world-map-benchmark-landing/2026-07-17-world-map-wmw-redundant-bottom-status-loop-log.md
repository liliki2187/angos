# WMW 紧凑回执仍无独立职责 Loop Log

## 三行决策条

- **结论**：v3 虽修正了回执体量，但没有继续验证信息是否独立；常驻红线 / 深链双条退出默认结构。
- **影响**：地图扩为 924×936；v3 左右职责闭合继续有效，中央两条 450×90 回执作废。
- **下一步**：默认只显示完整地图；真实事件差量存在时才显示单条条件回执，当前固定计数句不接入。

## 触发

用户直接追问两个组件“有什么用”。核对代码与 GDD 后确认：红线属于推进日后果与限时任务，深链属于具体任务类型；两者没有独立入口、动作或决策。

## 错误表现

1. 因 v2 用户要求“下方一小条”，直接保留了两个既有语义，而没有重新证明它们为何必须常驻。
2. 红线与深链同时在左下日程器、右侧任务情报和中央底带出现。
3. 七格刻度让深链看起来会随天数自动推进，与现行任务链规则不符。
4. `world_receipts` 的当前计数拼句被误当作可能的“最近变化”，但它没有事件因果和前后差量。

## 根因

- 容器体量审计替代了信息架构审计。
- 把“组件形式已经存在”误当成“组件职责已经成立”。
- 没有要求每个常驻组件独占回答一个玩家问题。

## 修正与防线

- 默认删除双条，地图连续落到中栏底部。
- 条件回执只接真实 `event_id / cause / before / after / changed_fields`。
- workflow gate 新增 `status_strip_repeats_schedule_and_dossier_without_unique_player_question`。
- harness 与 UX casebook 新增 unique-player-question 审计。
