# 资产化 UI 生产总链路

> **用途**：把 Angus 的 UI 风格稿、AI 生图、bitmap 资产、Godot / HTML 动态层和截图验收串成一条可执行流程，避免“图片很好看，但不能承载真实功能”，也避免“合同做了很久，界面迟迟出不来”。
> **定位**：这是资产化 UI 的操作细则真源。机器可读的产物类型与阶段跳转以 `docs/workflows/workflow-gates.yml` 为准；风险分级与回复格式以 `docs/workflows/angus-workflow-harness.md` 为准；几何与文字安全公共 gate 以 `docs/workflows/ui-geometry-and-text-safety-gates.md` 为准。四者冲突时，先补齐 YAML 与公共 gate 文档，再回来修订本文件。
> **适用范围**：世界地图、地区任务台、派遣签批台、发刊前报道板、票据、任务卡、地图 pin、按钮、索引册、签批纸和所有使用 PNG / 生图 / 拟物资产承载动态 UI 的界面。
> **最后更新**：2026-07-09（v2.1：新增资产分层结构与母版派生硬门槛、gate 三级制、缺陷→gate 闭环、宣称口径；来源为 WMW 左卡六轮拉锯复盘，案例见 ux-diagnosis casebook）

## 0. 一句话原则与当前版主链路

**风格稿不是生产底图，整屏图不是可交互 UI；合同不是产出本体，只是验收标尺。**

当前版主链路（页面级，唯一需要记住的顺序）：

| # | 阶段 | 产出 | 一票否决要点 |
| --- | --- | --- | --- |
| 0 | 功能合约 | 一句话职责、主 CTA、元素清单、状态矩阵 | 没有功能合约不进任何视觉阶段 |
| 1 | 功能分区与信息容量冻结 | 分区表、容量表、结构验证稿 | 装不下真实信息不得进风格稿 |
| 2 | 视觉标杆与风格方向 | 无字风格稿 / 颜色合同 / 已认可标杆登记 | 功能面倾斜的图只能降级为灵感图 |
| 3 | 组件比例分类 | `component_aspect_taxonomy`：按功能角色识别形状家族 | 方形默认只属于 icon / sticker / badge |
| 4 | **整页合同板**（批处理） | 全部主 class 的量测、归一合同、整屏回填、文案压力，一次用户裁决 | 无分辨率与倍率声明不得进素材生产 |
| 5 | **纵向切片** | 选 1 个已锁 class 走通：无字素材 → gate → 切图 → Godot 单组件 → 运行截图 | 切片未通过不得批量生产素材 |
| 6 | 批量无字素材生产 | clean-sprite brief → 生图 / 美术 → 几何与类一致性校验 | 素材不服从合同判素材失败，不得反改合同 |
| 7 | 真实内容整屏预览 | 有字整屏（imagegen mock 或分层回填预览），UI / UX / 像素艺术复审 | 像默认 Label 贴图即降级 |
| 8 | atlas / manifest | 切图、命名、`content_rects / no_text_rects / hit_rects`、状态矩阵 | 没有 manifest 只能算图片 |
| 9 | Godot / HTML 动态层装配 | 按 manifest 装配，清旧控件 | 不得用普通面板贴片补救 |
| 10 | 多状态截图验收 | 整屏 + 局部 + 关键状态 + 极端文案 | 控件 / 视觉 / 交互 / 语义四通过 |
| 11 | 生产候选复审与沉淀 | STATUS 更新、采纳记录、drift 检查 | 未经复审不得称生产真源 |

阶段 4 之后，剩余低风险合同（低密度状态条、icon 清单等）**与阶段 5-6 并行补完**，不阻塞素材生产；详见 §4.4。

## 0.1 两条结构性原则（2026-07-08 新增硬门槛）

### 批处理原则（batch rule）

- 同一页面的同类工作必须合并成板交付：组件合同以**整页合同板**为单位（一轮完成全部主 class 的源量测、合同候选、整屏回填、文案压力），用户裁决一次过整板。
- 禁止按组件逐轮开工、逐轮等待裁决，除非某组件被明确判定为高风险需要单独深挖，且在 Router Card 里写明理由。
- 1px 级归一、近似一致修正等小结论并入板内一行说明，不单独立评审文档、不单独写 Loop Log。
- 单轮交付原则上最多包含一个需要用户裁决的问题；多个可合并的裁决必须合并成一次提交。

### 纵向切片原则（vertical slice rule）

- 任何页面在锁定第一批 class 合同后，下一步**不是补完剩余合同**，而是选 1 个代表性组件走通全链：无字素材生成 → 几何 / 类一致性 gate → 切图 → Godot 单组件接入 → 运行截图。
- 理由：合同只能消除已知风险；“生图能否服从合同”和“引擎能否按 manifest 装配”是未知风险，只有真走一遍才能暴露。把它们推到最后等于把最大风险留到最贵的时刻。
- 切片通过后，批量素材生产与剩余轻合同并行展开；切片失败则按失败层退回（素材问题回 brief，合同问题显式升版本，引擎问题查 Godot 错题本）。

## 2. 阶段 0-2：功能合约、容量冻结与风格方向

### 2.1 功能合约（阶段 0）

每个页面先写一句话职责：

```text
地区任务台：在当前地区里选择一个可派遣任务，不配置队伍，不执行骰池。
世界地图：选择取材地区并进入地区，不直接选择任务。
派遣签批台：为当前任务配置本次骰池并确认执行。
发刊前报道板：确认本期版面和送印风险。
```

同时明确：玩家这一屏做什么决定、主操作是什么、哪些信息会改变决定、哪些属于上下游不该塞进本页、哪些对象可点击。没有功能合约，不进入任何视觉阶段。

元素清单按四类归属（烘焙底图 / 独立组件 / 动态 UI / 运行时反馈），可交互元素必须有状态矩阵；两张表的格式与最低状态要求见 §8.1、§8.2。

### 2.2 功能分区与信息容量冻结（阶段 1）

**硬门槛（2026-06-16 确立）：功能分区与信息容量先于风格稿。** 不能先确认一张漂亮整屏图，再让动态文字和真实状态去迁就画死的框体。

进入风格稿前必须交付：

| 产物 | 必须回答 |
| --- | --- |
| 功能分区表 | 这一屏分几区，每区负责哪个玩家问题 |
| 信息容量表 | 每区最多几个字段、最长中文、数字位数、状态章数量、行数 |
| 结构验证稿 | 低成本验证分区比例、元素数量、主 CTA、候选露出量（用真实首屏数量，不用空框占位） |
| 组件尺寸推导 | 宽高如何从字段容量、内边距、装饰禁入区和状态槽算出 |
| 溢出策略 | 长标题、禁用原因、两位数天数、满态列表如何处理 |

核心公式：

```text
组件宽度 = 最大文本宽 + 动态状态槽 + 内边距 + 装饰禁入宽
组件高度 = 行高 * 最大行数 + 上下内边距 + 状态 / 装饰槽
```

装不下时优先加大组件、拆分信息或改短字段；不靠缩小字号、贴边排版或面板盖图补救。

结构验证稿只回答“结构能否承载功能”，不评审美术；它与运行骨架图、有字预览稿的区别见 §8.3 稿件类型表。用户对现有效果稿提出“看不懂 / 功能区不对”时，先出 `problem_overlay`（原图问题层）+ `reframe_plan`（目标骨架层）的功能重排批注稿，不直接生下一张完整风格稿。

### 2.3 视觉标杆与风格方向（阶段 2）

风格稿阶段只确定美术语言和主承载物，不直接进入实现。

| 产物 | 作用 | 禁止用途 |
| --- | --- | --- |
| 无字风格稿 / no-text style draft | 确认主物件、材质、构图、留白、组件语法 | 烘焙真实动态文字后直接切图 |
| 颜色合同 / color contract | 锁定主色、纸色、明度关系（按 `imagegen-color-contract-gate.md`） | 用“有采样表”替代逐 token 阈值验收 |
| 已认可标杆登记 | 用户明确认可的整屏图登记为风格锚点 | 直接当生产切图母版 |

**硬门槛（2026-06-22 确立）：涉及调色的生图必须先过 Color Contract Gate**：唯一参考图、固定 ROI、`hex / RGB / Lab`、逐 token 阈值、失败边界；未过颜色闸门不得进入风格标杆或生产候选判断。

**硬门槛（2026-07-03 确立）：文字功能面不得继续依赖整屏有字生图纠偏。** 若同一类文字 / CTA / hit rect 功能面已因倾斜失败过，下一版 prompt-only 生图仍倾斜，必须停止整屏有字生成，改走**分层资产路线**：生图负责无字外观、低多边形主图、纸张外轮廓、贴纸、装饰；文字槽、按钮 label、状态条、hit rect 由正交 no-text 资产 + Godot / DOM 运行时层承担。分层路线是当前文字密集页面的默认路线。

风格稿的几何要求（功能面正交、装饰可斜、自动触发 `ui_geometry_gate`）统一见 `docs/workflows/ui-geometry-and-text-safety-gates.md`，不在本文件重复定义阈值。

## 3. 阶段 3：组件比例分类（component_aspect_taxonomy）

**硬门槛（2026-07-07 确立）：组件比例分类先于组件合同。** 从标杆图拆 UI 资产前，必须先按功能角色识别页面真实存在的形状家族，例如紧凑横卡、长 CTA 条、宽票据、竖向 dossier、地图板、顶部状态带、方形 icon / badge。

- 不得把某一张方便生成或方便切图的方形 / 近方形组件反向套到所有功能区。
- 方形资源默认只适用于 `icon_badge`、贴纸、徽章、纯符号按钮和装饰；承载标题、状态、行动文案、票据字段、图片槽或 hit rect 的主组件，必须先证明源图和信息容量确实需要方形，否则按参考图比例建立长方形 class。
- 未完成比例分类，不得进入整页合同板、clean sprite brief、imagegen atlas、manifest 或 runtime 回填。

产出示例（世界地图 v0.8）：每个 class 的功能角色、近似比例区间、是否允许方形、生产含义。

## 4. 阶段 4：整页合同板（page_contract_board）

这是本链路 v2 的核心新阶段，吸收并取代此前“逐组件合同轮”的做法。

### 4.1 一轮要做完什么

对页面上全部主 class（承载文字、状态、图片槽或 hit rect 的组件家族），在**同一轮**内完成：

1. **源量测**：从标杆图量出每个 class 各状态的实际尺寸，标出漂移（源图允许不一致，生产不允许）。
2. **归一合同候选**：每个 class 一个 `export_size` + 槽位（`photo_slot`、`label_plate`、`content_rects`、`no_text_rects`、`hit_rect`）+ 状态清单。
3. **整屏回填验证**（2026-07-08 硬门槛）：统一规格放回真实页面，检查越界、节奏、是否压主舞台、图片槽是否过浅、是否破坏标杆构图。未经整屏回填的 class 只能标 `component_contract_candidate`，不得冻结。
4. **文案压力测试**：正常态 + 压力态真实中文逐字段进框验证；贴上限的槽标记为弹性位。
5. **一次用户裁决**：整板提交，用户对全部 class 一次表态。

### 4.2 分辨率与导出倍率声明（2026-07-08 新增硬门槛）

class 合同 JSON 必须包含三个字段，缺任一项不得进 clean-sprite brief：

- `reference_resolution`：合同坐标所在的参考分辨率（如 `[1280, 720]`）。
- `runtime_resolution`：截图验收与运行目标分辨率（本项目默认 `[1920, 1080]`）。
- `export_scale`：素材制作倍率。参考分辨率与运行分辨率不是整数倍关系时，素材必须按 2x 或更高倍率制作、运行时缩小，禁止位图放大上屏。

### 4.3 合同字段分级：frozen 与 provisional（2026-07-08 新增硬门槛）

- `frozen`：几何骨架——`export_size`、`positions`、槽位矩形、`hit_rect`、间距。修改必须显式升合同版本号并重跑整屏回填，不得在美术或排版轮中静默改动。
- `provisional`：弹性位——贴容量上限的文字槽、依赖最终字体的字号假设、排版复审可能回改的视觉权重。美术 / 排版复审可以回改 provisional 字段，不算“打破合同”。
- 压力测试基于脚本字体渲染；最终字体确定后若更宽，必须重跑文字压力，这一条写进每份合同的 provisional 说明。

### 4.4 组件类几何一致（component_class_uniformity_gate，2026-07-07 硬门槛）

- `selected / available / warning / locked / disabled / hover / pressed` 等只能是同一 `class_id` 下的状态皮肤，不得改变 `export_size`、`photo_slot`、`label_plate`、`content_rects`、`hit_rects` 或九宫格边距。
- 源图裁切残缺、生图偶然留白、状态图案面积变化，都不能反向定义生产尺寸。
- 确需紧凑版 / 大卡版 / 横条版，必须建立新 `class_id`（如 `left_region_card_compact`），不得混入原 class 状态矩阵。
- 进 manifest 前必须跑 `scripts/ui-contracts/validate_class_contract.py`：同 class 全状态基础尺寸和功能槽位逐项一致，任一状态变矮、变宽、槽位漂移直接判失败。

### 4.5 文字落位三层合同（2026-07-02 硬门槛，归位于此）

承载动态文字的组件，可写区必须从图像本身推导，不得先画理想 safe-zone：

```text
raw source -> visible_color_module_rect -> carrier_rect -> inner_rect -> glyph_bbox -> role metrics -> 100% crop -> full-screen refill
```

每个动态字段必须声明 role（如 `receipt_field_lane`、`header_title_lane`、`button_label_plate`、`card_title_plate`、`stamp_slot`），不同 role 的居中、字号、行高、禁入区要求不同，不得用一个通用文本框套所有组件。交付时必须给 100% 局部 crop；crop 中文字没有落在真实颜色模块内，即使 overlay 数值 PASS 也判失败。

### 4.6 轻合同与并行补完

低风险组件（低密度状态条、纯装饰 HUD、icon / sticker 清单）不需要完整的量测-回填-压力三件套，用轻合同（尺寸 + 归属 + 禁入区一页说明）即可，且**与阶段 5-6 并行补完**，不阻塞素材生产。判断标准：不承载多字段动态文字、不含复杂状态矩阵、不做主要点击目标。

## 5. 阶段 5-6：纵向切片与批量素材生产

### 5.1 纵向切片（阶段 5）

按 §0.1 纵向切片原则执行。切片组件优先选：状态最多、文字槽最紧、或最能代表页面风格的 class。切片交付物：

- 该 class 的无字素材（真实生图 / 美术产出，非程序绘制）；
- 几何 / 类一致性校验记录（脚本 + 裁切证据）；
- Godot 单组件装配截图（动态文字进 `content_rects`，热区对位）；
- 切片结论：素材生产路径是否可复制到其余 class。

### 5.2 clean-sprite brief 与生图（阶段 6）

生产用生图只生产 bitmap 美术，不生产功能结论。brief 必须逐 class 写明：

- 引用的合同 JSON 路径与版本、`export_scale` 下的实际生产尺寸；
- 不要真实中文 / 英文 UI 文案、数字、假 pin、假 tooltip、假任务卡内容；
- 干净空白可写区；provisional 标记的文字槽必须保持安静（不得让低多边形尖角、折痕、阴影、贴纸边穿过）；
- 可交互组件单独输出 atlas 或透明 PNG，状态皮肤共享几何；
- 半调、套印、纸纹不得穿过动态文字区域。

本地脚本可以做：裁切、缩放、透明留白、纯色背景抠除、manifest 校验、安全区 overlay、打包截图。
本地脚本不得做：程序绘制纸纹 / 半调 / 像素边框冒充美术资产、用矩形面板盖住缺陷、重画按钮 / pin / 纸面主效果。

**素材与合同冲突的处理规则**：素材不服从合同（尺寸漂移、槽位被装饰入侵、状态几何不一致）判**素材失败**，回 brief 重生成；确实需要改合同时，显式升合同版本号、重跑整屏回填、在 STATUS 记录，不得静默迁就素材。

若本轮是有字效果预览（imagegen mock），prompt 可填真实文案，但文件名与交付说明必须标注 `text_mock`，该 prompt 不得复用为组件生产 prompt。

### 5.3 资产分层结构与母版派生（2026-07-09 新增硬门槛）

来源：WMW 左卡六轮拉锯复盘。核心原则一句话：**生图管风格，几何靠构造**——生成模型唯一做不到的就是精确几何，任何要求生成图直接服从像素合同的路线，都会把差异留给下游打补丁，而每次下游像素手术都是事故现场。

WMW 左卡的可执行规程与脚本入口见 `docs/workflows/wmw-hollow-shell-photo-pipeline.md`；其它含图片槽组件默认沿用同一结构，再按自身合同重建母版几何。

**分层 z 序结构（含图片槽组件的默认结构）**：

```text
底层：内容（照片 / 图片，普通矩形，cover 铺满窗口外接矩形，允许溢出，禁止任何形状裁切）
中层：镂空壳（框 + 纸签底板 + 干净徽章底盘，图片窗口挖穿为透明；边界全部由壳的轮廓定义；
      底盘内不烘焙任何状态字形）
静态装饰贴片：全状态共用的装饰覆盖物（如地球徽章），提取为冻结配料后叠放，见配料级验收
运行时：动态文字 + 状态图标 + 状态反馈
```

- **像素所有权**：每层各管各的像素。边界（圆弧、边缘、缺口）只归上层壳负责；内容层永远不需要知道窗口形状。原则上把"必须三样全对（形状/位置/尺寸）"的裁切问题，转化为"一样都不用对"的遮盖问题。
- **覆盖元素必须贴片化（2026-07-09 补）**：压在内容窗口上的覆盖元素（地球徽章、夹子、贴纸、角标）必须提取为独立贴片层叠在最上层；禁止用"保护区 / 豁免圆"近似——保护区会把旧内容快照一起保下来，形成叠层缺陷（B2.3 地球圆盘案例）。
- **状态语义元素归运行时层（2026-07-09 用户裁决 A172，2026-07-10 B2.8 补强）**：承载状态语义的字形（勾 / 靶心 / 警示三角 / 锁等 badge 图标）**不烘焙进壳、不做派生贴换**，一律作为独立图标小图由运行时（Godot / HTML）绘制进 `icon_badge` / `action_badge` 槽——图标是状态语义，与动态文字同属运行时层。壳的 badge 底盘必须是独立的无语义结构；若母版 badge 自带靶心等状态符号，禁止在旧底盘上做连通块清理或保留旧环，必须把旧 badge 足迹整区退役，并按当前有效合同重建“外环 + 中性内芯”。但合同校验只证明当前记录内部一致：若已采纳标杆与合同产生稳定视觉偏差，必须停下量测并交用户裁决，获批后显式升版合同，禁止一边坚持旧合同一边在素材上补丁迁就。外环中心、运行时图标中心、Python/Godot 锚点互差 ≤1px，同时必须验标杆视觉 gutter。`badge_state_color_consistency`、`badge_clean_base_no_semantic_residue`、`state_badge_contract_and_style_alignment`、`runtime_icon_shape_completeness` 分别验证状态色、空底盘、标杆几何和完整字形，互不替代。
- **配料级验收（2026-07-09 补）**：仍需烘焙的静态装饰贴片（如全状态共用的地球徽章），进入合成前必须逐个通过**纯度 gate**（贴片内非目标色族像素占比≈0，防夹带底图杂质）并做一次性 400% 目检后**冻结**；合成只准使用已冻结配料，配料变更需重新验收。背景：B2.5 地球贴片夹带母版旧照片像素，随状态换色被染色后连颜色签名扫描都无法识别。
- **内容配料来源纯度（2026-07-10 补）**：照片 / 场景只能从纯内容源裁取，禁止从已经叠过框体、globe、badge 或文字的 atlas / 运行截图回采。来源文件正确仍不够：裁源 bbox 必须完全落在实测内容区内、避开源覆盖元素，并通过边缘长直框线 / 色键 / UI 签名扫描；来源、bbox、阈值与统计写入 manifest。B2.8 首轮从 396 裁图仍因复用历史相对坐标带入三张源卡右框，说明 provenance 必须落到“文件 + 矩形 + 内容”三级。
- **源形状提取独立于目标槽（2026-07-10 补）**：runtime icon / 装饰线稿先在宽搜索区提取完整源 bbox，再等比装入带透明 padding 的目标画布；禁止用目标合同矩形直接裁源。目标槽只负责装配，不负责定义源形状。B2.7 四个状态字形都从旧合同左界起裁，导致 purity gate 放过“干净但残缺”的符号。
- **禁止**在压平的成品图上做补丁式像素手术（盖、擦、填色带）；发现缺陷回分层结构重拼，不修压平图。

**一类一母版（one master per class）**：

- imagegen 只为每个组件类生成**一个母版**（或配料）；状态皮肤、实例变体一律程序派生（色相映射、图标贴换、光晕叠加层）。
- 禁止让生成模型多次输出同类组件（如"2x2 四状态表"）当生产输入——方差就是从"生成 N 次"进来的；此类表只能作为风格探索稿。
- 派生保证同类几何**构造性全等**（diff=0），状态切换无窗口跳动；类一致 gate 从"容差检测"升级为"断言"。

**风格稿与生产资产的边界**：风格稿允许同类组件尺寸略有差异（为了好看）；进入生产链的第一步就是"从风格稿提取 / 重建母版到合同几何"，此后**母版是唯一几何真源**，风格稿降级为参考。

**gate 三级制**（详见 `ui-geometry-and-text-safety-gates.md`）：

1. **构造性断言**（最高）：由构造保证的性质（母版派生 → 状态几何全等），装配时 assert，失败即代码 bug。
2. **测量容差 gate**：只用于"母版 vs 合同"“素材 vs 合同”这类源头校验，容差必须写明依据，禁止拍脑袋。
3. **人工目检清单**（兜底）：难程序化的内容完整性（接缝、叠化、气质），定点 200%-300% 放大目检并留截图。
能升级为上一级的检查，不要停留在下一级。

修复器和验证器不得共享同一个分类器作为唯一依据。涉及清空 / 抠图 / 贴片时，证据顺序固定为：源失败探针 → 空底盘 / 空壳 → 派生底盘 → 独立配料 → Python 合成 → Godot 合成；上一层未成立，不得靠下一层成品图宣称通过。

## 6. 阶段 7：真实内容整屏预览

**硬门槛（2026-06-16 确立，2026-07-08 修订）：图文融合必须在拆分推进前被真实验证。** 验证方式按页面路线二选一：

- **整图生成路线**：无字风格稿确认后，用真实 UI 文案和代表性头像生成 `filled-state text mock`。适用于 prompt-only 文字生成尚未失败过的页面。
- **分层路线（当前文字密集页面默认）**：合同板 + 无字素材通过后，用运行时文字层回填真实内容做整屏预览。此时阶段 7 的交付物是“无字素材 + 真实文案回填”的整屏图，验收标准与 filled mock 相同：图文融合、信息密度、字体气质、商业截图感。

无论哪条路线：

- 有字预览稿只做目标截图和视觉参考，**不得进 manifest、不得切组件、不得当 runtime 底图**。
- 程序把文字 / 头像叠到底图上只能叫“安全区 / 容量验证稿”；真正的视觉评审稿必须图文像同一系统，不像默认 Label 贴在 bitmap 上，否则当场降级（降级细则见 §8.3）。
- 预览结论反向修正 `content_rects`、字体 token、行高、CTA 文案长度；显得贴边、太挤、太空就回容量或合同阶段。
- 必须通过 UI / UX / 像素艺术复审后，才能宣称“图文融合通过”。

## 7. 阶段 8-11：atlas / manifest、装配与验收

### 7.1 atlas / manifest（阶段 8）

没有 manifest 的资产只能算图片。最低字段（完整示例见 §8.4）：

- `content_rects`（动态文字可进区域）、`no_text_rects`（禁入区）、`hit_rect` / `hover_rect`（点击与悬停区）、`anchor_points`（tooltip / 选中环挂点）；
- `states`（与代码状态一致）、`feedback_spec`（按下 / 选中反馈）、`overflow_policy`（溢出策略）、`qa_cases`（必须截图的边界状态）；
- atlas 必须写 `target_size / frame_size / frame_order`，与 prompt、切图脚本、代码 loader 对齐；
- 同一条功能事实只能有一个主承载位（按钮 label 不能同时属于详情纸和按钮 atlas）；
- manifest 中的几何必须与 `design/ui-contracts/` 合同 JSON 一致，冲突时以合同为准并回修。
- 程序合成或局部拼接后的 manifest 必须包含 `composite_cleanliness` gate：逐状态人工目检是否有重复元素、接缝、槽外溢出、源图边框 / 色键残留、边框连续性破坏、底层照片 / 图片泄漏、卡体轮廓内透明洞，并写明检查截图。涉及图片槽 / 状态皮肤 / atlas 拼接时，必须附关键边缘 100% 或 200% close-up（例如上下左右 32px-48px 带状裁切）；涉及可见卡壳 / 按钮 / 票据轮廓时，必须补 `card_body_opacity_probe`，卡体可见区域 alpha 不得低于阈值。几何、颜色统计、非黑像素和文件存在只证明机器口径通过，不能替代内容目检。修边前必须区分合法 shell / frame / bevel 与源图残留，不能直接擦除整条边缘带；不能用纯色带或状态色渐变冒充壳体纹理修复。若可见美术窗口与合同槽位不一致，必须新增 `photo_window_vs_photo_slot_conflict` / 同类 gate 并先裁决语义，禁止边做边改 gate。QA 判据变更必须写入 manifest，禁止改到能过为止。

### 7.2 Godot / HTML 装配（阶段 9）

Godot / HTML 负责：动态文字、数值、状态、点击、hover、pressed、selected、disabled；按 manifest 读取贴图、热区、安全区和锚点；`TextureButton` / `TextureRect` / `NinePatchRect` / Control 热区装配；动态文本只进 `content_rects`；回收旧控件、旧 tooltip、旧调试框。

Godot / HTML 不负责：重新模拟纸纹、半调、按钮质感；用普通面板贴片补救美术缺陷；把视觉上不可点的装饰做成隐形按钮。

涉及 Godot 场景 / 脚本改动时，交付前跑 `scripts/run_godot_agent_smoke.ps1`（规则见 harness §4.1）。

### 7.3 多状态截图验收（阶段 10）

最低验收：

- 桌面 16:9 主视口截图（默认 1920x1080）+ 关键对象 100% 局部裁切；
- 与本次改动相关的状态帧（default / hover / selected / pressed / disabled）；
- 长中文、两位数、倒计时、锁定缺口、禁用原因、空态和满态；
- 文字不压 `no_text_rects`；点击热区与视觉对象一致；无新旧控件混层；
- 几何证据按 `ui-geometry-and-text-safety-gates.md` 自动触发（含 `text_geometry_pass` + `art_shell_geometry_pass` 双通行证、`image_aspect_pass`、`image_slot_contract_pass`）；
- 组合素材必须补 `composite_cleanliness`：槽内掩膜、图标单轨制、无重复 badge / globe / warning、无源图边缘或色键残留、边框连续、无底层照片泄漏、卡体轮廓内无透明洞，至少用 1 张放大对比板、关键边缘 close-up 裁切和 alpha 探针证明；整卡缩略图不能替代边缘检查；alpha 探针只能证明“无透明洞”，还必须单独检查 `art_shell_texture_integrity`，避免用程序色带把洞补成新缺陷；
- 美术复审：像素颗粒、半调、纸质、套印仍像 Angus；
- 运行截图与目标稿并排对照：左中右职责、主物件、主 CTA 任一大项漂移，退回对应上游阶段。

四个通过必须区分并全部满足：

- **控件通过**：Control / DOM rect 没越界。
- **视觉通过**：文字稳稳落在物件上，不压装饰、不贴边、不穿纸纹。
- **交互通过**：hover / click / pressed / disabled 有可见状态变化。
- **语义通过**：文字、状态、图标和主动作共同说明同一个当前决策。

**逻辑烟测截图不等于视觉验收**（2026-06-17 硬门槛）：把状态机塞进旧承载页只能证明逻辑可运行，不能证明页面职责、视觉主物件或布局成立。**safe-zone 通过不等于正式 UI 通过**（2026-06-16 硬门槛）：manifest、overlay 和默认截图通过，但文字像贴上去的、CTA 不像场景动作，只能算组件验证稿。

### 7.4 生产候选与沉淀（阶段 11）

- 更新资产线 `STATUS.md`（见 §9 交付定义）；
- 用户采纳 / 撤回写入 `docs/设计采纳记录.md` 与对应分册；
- 文档 / 实现 drift 判断；
- 未经 UI / UX / 美术复审的产物不得称生产真源。

### 7.5 缺陷→gate 闭环与宣称口径（2026-07-09 新增硬门槛）

**缺陷→gate 闭环**：每个由人眼（用户或复审 agent）抓到的**新缺陷类型**，收到反馈的当轮必须二选一沉淀，不许悬空到下轮：

1. 写成程序 gate（登记到 `ui-geometry-and-text-safety-gates.md`，注明来源案例，可追溯）；
2. 或明确登记为"不可程序化"，进人工目检清单（同文档目检节）。

背景教训：UX 复审在 B 轮就诊断出"非 selected 绿色残边"（P1），但未进 gate 也未进清单，悬空五轮后同一缺陷仍出现在下游资产里。诊断留在文档里是散文，进了 gate 才是制度。

**宣称口径**：

- "文件已生成 / 退出码 0 / 程序 gate 全零" ≠ "通过"。通过 = 程序 gate 全零 **且** 定点放大目检截图已贴出。
- 截图类产物必须做内容校验（非黑、颜色多样性、alpha 探针）后才可引用为证据；空文件、黑帧、色带补丁都曾骗过纯存在性检查。
- 运行时证据分级：Python 回填预览只能作临时证据；宣称"引擎装配通过"必须有真实 Godot / HTML 运行截图。

## 8. 通用规则表

### 8.1 元素归属四分类

| 归属 | 说明 | 可放内容 | 禁止内容 |
| --- | --- | --- | --- |
| 烘焙底图 | 不随数据和状态变化的主视觉 | 地图质感、纸纹、夹具、低权重装饰 | 文字、任务名、按钮、pin 状态、动态标签 |
| 独立组件 | 可复用物件或控件底材 | 按钮底板、pin、卡片底、票据、签批章 | 固定真实文案、固定状态结论 |
| 动态 UI | Godot / DOM 渲染的数据层 | 标题、任务名、数值、倒计时、按钮文案 | 纸纹、半调、边框风格主效果 |
| 运行时反馈 | 交互时出现的短效 | hover 高亮、pressed 位移、选中环、音效 | 长期状态信息、主视觉纹理 |

禁止烘焙清单：任务名 / 地区名 / 角色名、标题正文按钮文案、天数倒计时风险状态、pin / 选中环 / tooltip / 短签 / 锁定标识、路线高亮、可点击按钮 / 筛选签 / CTA plate、空白任务牌 / 常驻白标签、会被误读成真实信息的假文字假数字。
允许烘焙：大陆轮廓 / 网格 / 裁切线、低权重半调 / 纸面 / 印刷质感、不可交互氛围点、夹具 / 纸边 / 阴影 / 桌面材质。

### 8.2 交互状态矩阵最低要求

| 组件 | 必需状态 |
| --- | --- |
| 主 CTA / 返回按钮 | default / hover / pressed / disabled / focus / loading |
| 地图 pin | normal / hover / selected / locked / completed / urgent |
| 任务卡 / 地区卡 | normal / hover / selected / unavailable / deadline / assigned |
| 筛选签 / 标签页 | default / hover / selected / disabled |
| 拖拽槽 | empty / hover / drag-over / occupied / invalid |
| 签批章 | idle / ready / pressed / stamped / disabled |

每个状态回答：贴图不同还是状态层；文字是否仍在同一 `content_rect`；热区是否随视觉；hover 是否改布局；pressed 的反馈形式；disabled 是否明显不可点。

### 8.3 稿件类型 Gate 与降级规则（2026-06-18 硬门槛）

每次交付可见图前，必须在回复和文件名 / 记录中声明稿件类型（完整机器可读定义见 `workflow-gates.yml` 的 `artifact_types`）：

| 稿件类型 | 可以有 | 不允许声称 |
| --- | --- | --- |
| `structure_wireframe` | 低保真框架、真实容量、功能区、主 CTA | 美术完成、可切图 |
| `problem_overlay` / `contract_overlay` | 红框、连线、编号、热区说明 | 玩家可见最终效果 |
| `interaction_fix_sketch` | 粗糙覆盖、局部移动、操作关系验证 | 真实内容风格稿、生产母版 |
| `safe-zone / capacity validation` | 程序贴字、临时矩形、最长文案压力 | 图文融合、高保真效果稿 |
| `component_aspect_taxonomy` | 形状家族分类、比例区间、方形许可判定 | class 合同、可切素材 |

### 8.5 典型失败模式速查

| 失败模式 | 症状 | 处理 |
| --- | --- | --- |
| 整屏风格稿直接进实现 | 截图好看，长标题一换就出框 | 回元素清单，拆底图 / 组件 / 动态层 |
| 可交互对象画在底图里 | 按钮没有 pressed，pin 无法 selected | 拆状态资产或状态层 |
| 只有 content_rect 没有 hit_rect | 文字放得下但点不准 | manifest 补 `hit_rect / hover_rect / feedback_spec` |
| 斜透视纸面承载正文 | 局部有质感但正文和 CTA 不稳 | 斜面只做装饰；正面必须正交（见公共 gate 文档） |
| 普通面板贴片补救 | 读成“底图 + 临时 UI” | 重出分层资产或退回低装饰功能布局 |
| 只截默认态 | 默认通过，hover / disabled 一用就坏 | 每个可交互组件截相关状态帧 |
| 方形组件反向定义全页 | 主组件全变方，标杆比例语法丢失 | 先跑 `component_aspect_taxonomy` |
| 源图漂移变成生产尺寸 | 同类状态高矮不一，回填对不齐 | 类一致 gate + 归一合同 |
| 素材出来才发现分辨率错位 | 位图 1.5x 放大发糊 | 合同先声明 `export_scale` |
| 几何 / 统计全 PASS 但肉眼叠化 | 重复图标、双 badge、照片越界、源图框边、右缘暗带、绿底残留、边框被擦断、底层照片泄漏、卡体透明洞、程序色带冒充壳体纹理 | 加 `composite_cleanliness`，逐状态放大目检；槽内掩膜 + 图标单轨制 + 边缘 close-up + `right_frame_continuity` / `layer_order_integrity` / `card_body_opacity_probe` / `art_shell_texture_integrity`；发现可见窗口与槽位冲突时先裁决语义 |
| 逐组件开轮逐个裁决 | 进度极慢，用户决策疲劳 | 批处理原则：整页合同板一次裁决 |
| 合同做完才第一次碰引擎 | 生图 / 引擎风险最后爆 | 纵向切片先行 |

## 9. 交付定义

一次资产化 UI 落地完成，至少应交付：

1. 功能合约与元素清单；
2. 功能分区表、信息容量表、状态矩阵；
3. 比例分类与整页合同板（合同 JSON 落 `design/ui-contracts/<页面>/`，含倍率声明与字段分级）；
4. 纵向切片证据；
5. 无字风格稿与真实内容整屏预览（预览不进 manifest）;
6. 资产文件：底图、组件 atlas、状态贴图；
7. manifest（与合同 JSON 一致）；
8. Godot / HTML 拼接（动态层只按 manifest 放置）；
9. 截图验收：整屏、局部、默认态、关键交互态；
10. 复审记录：UI、UX、美术至少覆盖各自风险；
11. **资产线 `STATUS.md` 更新**：路线环状态、已锁合同清单、当前 gate、下一步。每轮交付都必须更新，这是交付定义的一部分。

落盘与命名规则：

- 评审、合同说明、STATUS 一律**简体中文**落盘（代码、路径、字段名可英文）。
- 同一评审文件夹内版本号单调递增；路线重启必须换新前缀，不得让两条版本线共存一个目录。
- 评审引用的生成 / 校验脚本必须位于 `scripts/`（推荐 `scripts/ui-contracts/`），不得引用 `tmp/` 路径作为证据。

不满足以上项目时，只能称为风格稿、灵感草图、临时止血版或功能原型，不能称为生产资产、生产标杆或正式 UI 落地。

### A.1 世界地图（WMW 支线）

当前进度、已锁合同与下一步见 `docs/plans/world-map-benchmark-landing/STATUS.md`；合同 JSON 见 `design/ui-contracts/world-map/`；生产规格见 `docs/plans/world-map-assetized-ui-production-spec.md`。

### A.2 地区任务台

用户已明确认可：上一套地区任务图的整体风格与配色方向；中央地图的深蓝 / 多边形 / 纸质 / 半调 / 红青路线方向是视觉锚点，不应重画；地图底图比例不被 HUD 或侧栏压缩；纸张是现代杂志社新鲜印刷纸，不是旧档案。

必须重建：顶部 HUD 压缩为低权重频道条；左侧任务栏重出空白卡 + 索引签 + 状态章 + 安全区；右侧详情外轮廓可拟物斜切但正文区正交；地图标签全部拆出（pin、短签、tooltip、选中环、锁定态）；主 CTA 拆独立组件至少五态。

不得重建：不得顺手更换视觉主题、主色、地图材质、纸面风格或红青印刷关系；干净地图底图只能是同风格清洁版；不得用程序化几何图、PIL / Canvas / SVG 低保真绘图替代已认可的地图视觉源（这类图只能进 `tmp/whitebox` 或明确标注交互占位）。

2026-06-17 v3 口径：用户认可的整屏图可登记为 `visual_lock_backdrop` 接入运行时，但它只锁定不可变视觉锚点；动态文字、按钮、状态、热区仍必须由动态层或独立组件承担，不是生产切图母版的豁免权。

建议资产包（摘要）：`region_map_base_clean`（烘焙底图）、`region_map_pin_atlas`（六态）、`region_task_card_base`（六态）、`region_detail_sheet_base`（三态）、`region_cta_enter_dispatch`（五态）、`region_hud_strip`（两态）。
