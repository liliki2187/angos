# UI 资产化：决策、风险与证据

目标是在真实内容和交互中保留风格稿的吸引力。先依据用户目标、当前原图与功能事实形成判断；下表按本次决定选读，不是依次完成的阶段。

| 当前决定 | 主要风险 | 最小有用证据 | 可自主选择 |
| --- | --- | --- | --- |
| 选择视觉方向 | 只继承小装饰，大形、色彩关系与趣味已经跑偏 | 实际看原标杆及带代表内容的整体效果 | 构图、媒介、层叠和表达方法 |
| 决定资源怎么拆 | 静态烘焙妨碍动态文字、共享图片或状态变化 | 一个最能暴露风险的真实装配样本 | 整张底板、分层、九宫格、连续轮廓、运行绘制等 |
| 批量生成同类资产 | 母件缺陷复制到整批，回填后视觉降级 | 代表件在实际缩放与关键状态下成立 | 批次大小、优先件、工具及复用方式 |
| 正式接入或替换 | 内容、热区、状态和消费者不一致 | 受影响真实输入、运行截图/动态和必要回归 | 实现方式、检查工具与迁移方法 |

会造成昂贵返工的素材结构或批量决定之前，按当前材料/操作检索 [经验索引](../experience/ui-assets/README.md)。只读命中案例的原因、证据和限制；不等失败后才查，也不先套案例答案再做设计。

## 装配时需要回答的问题

- 当前真实内容、常态与容量极端值怎样进入？同一图片在各处使用什么母资源和适配方式？
- 文字、图片、底板、装饰和输入分别归谁？实际可写面是否与控件矩形不同？
- 状态变化及折叠、滚动、锁定等适用行为会不会改变内容身份、遮挡主操作或损伤整体关系？
- 实际显示尺寸下，宽块面、纸物件层次、色彩、字体与幽默是否仍成立？常态成品不能只为极端容量让路。

按这些答案建立有消费者的合同，不预先冻结全页 exact rect 或组件库存。合同记录足够的身份、适配、层级、可写区、热区、状态与数据来源；修改后迁移实际消费者。可以提前做隔离技术实验，但它不自动授权正式替换。

## 证据各自能证明什么

| 证据 | 能回答 | 不能代替 |
| --- | --- | --- |
| 风格稿/生图 | 构图、色彩、材质、情绪与吸引力 | 真实字体、输入、复用与运行验证 |
| 真实内容合成 | 图文归属、容量与组合效果 | 事件接线和实际热区 |
| 隔离运行样本 | 所覆盖状态的装配与交互可行性 | 全屏质量与未覆盖流程 |
| 正式运行截图/动态 | 当前实现的视觉和反馈 | 未测状态与用户视觉认可 |
| 自动检测 | 路径、尺寸、比例、像素变化或具体断言 | 好看、有趣、继承标杆 |

技术通过而视觉不成立，不能扩为美术母本；局部漂亮也不证明整屏成立。用户确认方向不等于工程全部通过。

当前目标、产物身份、最新决定和未解决问题写在已有 STATUS。仅在复杂交接有需要时用 [交付记录模板](../workflows/templates/delivery-manifest.md)，不每轮新建一套文档。页面参数留在该页合同；共性故障进入带适用条件的案例；复用工具经实际验证后再提炼。
