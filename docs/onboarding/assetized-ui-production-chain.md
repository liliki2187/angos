# 资产化 UI 生产总链路

> **用途**：把 Angus 的 UI 风格稿、AI 生图、bitmap 资产、Godot / HTML 动态层和截图验收串成一条可执行流程，避免再次出现“图片很好看，但不能承载真实功能”的问题。  
> **定位**：这是总链路和检查入口，不替代 `ui-interaction-guidelines.md`、美术规范、GDD 或具体页面规格。  
> **适用范围**：世界地图、地区任务台、派遣签批台、发刊前报道板、票据、任务卡、地图 pin、按钮、索引册、签批纸和所有使用 PNG / 生图 / 拟物资产承载动态 UI 的界面。  
> **最后更新**：2026-06-18

---

## 0. 一句话原则

**风格稿不是生产底图，整屏图不是可交互 UI。**

正式链路必须先拆功能，再拆资产，再生图，再拼接，再按状态验收。

新增硬门槛（2026-06-16）：**功能分区与信息容量先于风格稿。** 资产化 UI 不能先确认一张漂亮整屏图，再让动态文字和真实状态去迁就已经画死的框体。正式生产顺序必须是：`功能冻结 -> 信息容量冻结 -> 组件尺寸推导 -> 无字风格稿 brief -> 无字风格稿确认 -> 有字效果预览稿 -> 独立组件 / 状态 atlas 生产 -> manifest -> Godot / HTML 动态层 -> 多状态截图验收`。没有功能分区表、字段容量表、最长文案、状态矩阵、`content_rects / no_text_rects / hit_rects` 的风格稿，只能算灵感图或视觉草稿，不得进入生产切图。

新增硬门槛（2026-06-16）：**有字效果预览稿是图文验收，不是生产资产。** 当页面包含动态标题、状态、数字、倒计时、CTA、列表、头像组或角色卡信息时，必须在无字风格稿确认后，用真实 UI 文案和代表性真实头像 / 角色数据生成或制作一张 filled-state text mock，用来检查信息密度、头像裁切、字体气质、图文融合、商业截图感和 Godot / HTML 动态层目标。该图可以烘焙真实文字和头像，因为它只允许作为目标截图和视觉参考；不得从中切组件，不得进入 manifest，不得作为 runtime 底图，也不得削弱生产 PNG “不烘焙动态文字 / 动态头像”的规则。

任何会随数据、玩家选择或交互状态变化的内容，都不能烘焙进底图。任何会被点击、hover、选中、禁用、拖拽或按下的对象，都必须从底图中拆成独立组件、状态贴图或等价状态层。

新增硬门槛（2026-06-16）：**safe-zone 通过不等于正式 UI 通过。** 资产化 UI 的最终目标不是“图片好看且文字没越界”，而是图像、文字、状态和功能像同一个可操作的游戏物件系统。若动态文字像贴在 bitmap 上、字体像默认 Label、CTA 不像场景动作、pin / 卡片 / 档案 / ticker 状态不联动，即使 manifest、overlay 和默认截图通过，也只能算组件验证稿。

新增硬门槛（2026-06-17）：**逻辑烟测截图不等于目标界面落地。** 如果只是把 P0 逻辑、阻断条件、按钮状态或候选选择塞进旧 Godot / HTML 承载页，它只能证明状态机和交互条件可运行；不能证明资产化 UI 的页面职责、功能分区、视觉主物件、图文融合或最终布局成立。正式交付前必须把目标 filled-state mock / 用户认可风格稿与运行截图并排对照；左中右职责、主物件、候选区、当前选择区、复核区和主 CTA 任一大项漂移，都必须退回功能分区或 mock 阶段。

新增硬门槛（2026-06-17）：**运行骨架图不是给人评审美术效果的产物。** 低保真 Godot / HTML 承载截图只用于验证“动态字段、状态机、点击热区、阻断原因、CTA 状态和回流路径是否能挂到目标分区上”，不能用于判断画面是否好看、是否像 Angus、是否达到 filled-state mock 的图文融合效果。若截图仍由抽象面板、默认控件、临时清单或旧布局承担主体，只能标为 `承载合同验证 / 运行骨架图`；交付时必须说明它回答的是“能不能承载”，不是“最终会长什么样”。用户需要判断效果时，优先交付目标效果稿、AI 重绘有字效果稿或资产回拼后的真实运行图。

新增硬门槛（2026-06-18）：**先判定稿件类型，再交付截图。** 资产化 UI 每张图在交付前必须明确标注为 `structure_wireframe`、`interaction_fix_sketch`、`problem_overlay`、`contract_overlay`、`filled-state text mock`、`no-text asset master`、`runtime_skeleton`、`runtime_state_preview` 或 `production_candidate` 之一。不同稿件回答的问题不同，不能把只验证操作关系的局部纠偏草图包装成真实内容风格稿，也不能把合同标注图、热区说明图、运行骨架图或程序覆盖图称为可拆分落地的高保真效果稿。

新增硬门槛（2026-06-18）：**真实内容风格稿必须像可继续拆资产的高保真目标图。** `filled-state text mock / 真实内容风格稿` 可以包含真实 UI 文案，但美术上必须自洽：左右栏、底部条、主 CTA、任务卡、地图节点和纸面边缘应像同一轮美术生成或同等精修后的统一系统。不得出现粗暴盖图、旧组件残边、调试黑条、红框连线、合同说明文字、普通面板贴片、PIL / Canvas 临时纸片、旧底图与新 UI 断层、或多套视觉系统叠在一起。若出现这些痕迹，该图必须降级为 `interaction_fix_sketch`、`safe-zone / capacity validation` 或 `contract_overlay`，不能进入无字资产母版和组件拆分阶段。

新增硬门槛（2026-06-18）：**功能承载页必须方正。** 任何会承载动态文字、数值、头像状态、按钮文案、hover / pressed / disabled 状态或 hit rect 的 UI 正面，都必须是 square-on、axis-aligned、可测量的矩形。斜切、透视、叠纸、折角、票据舌片、夹子和半调可以制造拟物层次，但只能进入背景 / 外轮廓 / `no_text_rects`。如果高保真生图中可写纸面、右侧票据、任务卡内框或 CTA 文本槽整体倾斜，即使视觉气氛更好，也必须降级为灵感图或偏差案例，不得进入 `filled-state text mock`、`no-text asset master`、manifest 或生产候选。

新增硬门槛（2026-06-22）：**颜色匹配必须过 Color Contract Gate。** 任何涉及调色、去黄、提亮、压暗、冷暖、纸色、主色或“更接近参考图”的生图 / 修图，不能只凭“有采样表”或“没有明显偏黄 / 过白”通过。必须按 `docs/onboarding/imagegen-color-contract-gate.md` 建立唯一参考图、固定 ROI、`hex / RGB / Lab`、逐 token 阈值、整图均亮度、纸面 / 暗部比例和失败边界。未过颜色硬闸门时，不得进入像素颗粒、风格标杆或生产候选判断。

新增硬门槛（2026-06-22）：**风格锁定稿后必须先过真实内容填充预览 Gate，不能跳到资产拆分。** 当一张图只完成视觉方向、色彩合同、材质或像素颗粒确认时，它只能标为 `visual_style_reference` / `color-locked style draft` / `no-text style draft`，不得把下一步说成组件拆分、atlas 生产、manifest 或切图。若尚未存在通过复审的 `filled-state text mock`，下一步必须是：`轻量内容合同 -> 真实内容填充预览稿 -> UI / UX / 像素艺术复审`。只有真实内容填充预览稿证明图文融合、信息密度、CTA、状态和可读性成立后，才允许进入无字资产母版 brief、组件拆分和状态 atlas。

## 2. 总流程

### 2.1 功能分区与信息容量冻结

目标：先证明界面装得下真实信息，再让美术去服务这个信息结构。

每个页面进入风格稿前，必须先交付：

| 产物 | 必须回答 |
| --- | --- |
| 功能分区表 | 这一屏分几区，每区负责哪个玩家问题 |
| 信息容量表 | 每区最多几个字段、最长中文、数字位数、状态章数量、行数 |
| 结构验证稿 | 在不追求最终美术的情况下，快速验证分区比例、元素数量、主 CTA、候选露出量和局部状态是否成立 |
| 组件尺寸推导 | 组件宽高如何从字段容量、内边距、装饰禁入区和状态槽算出 |
| 可用区草图 | `content_rects`、`no_text_rects`、`hit_rects`、`hover_rects`、锚点 |
| 状态矩阵 | default / hover / selected / pressed / disabled / locked / loading 等状态如何表现 |
| 溢出策略 | 长标题、禁用原因、两位数天数、满态列表如何处理 |

世界地图这类页面，建议先按以下分区冻结信息容量：

| 分区 | 主要职责 | 动态内容 | 美术承载物 | 容量风险 |
| --- | --- | --- | --- | --- |
| 顶部周状态带 | 周次、剩余天数、阶段、资源概览 | 数字、短状态、返回 | 低权重频道 / 信号条 | 不能压缩主舞台 |
| 左侧地区索引 | 地区列表、锁定、可进入、异常状态 | 地区名、短状态、缺口 | 索引册 / 档案签 | 文字贴装订 / 纸边 |
| 中央地图主舞台 | 选择地区、观察全球异常 | pin、选中态、路线、hover 短签 | 地图墙 / 异闻地图 | 常驻标签变白框噪音 |
| 右侧详情 / 签批 | 当前选中对象的理由和行动 | 标题、摘要、任务预览、风险、CTA | 签批纸 / 调查单 | 信息量最大，不能靠装饰框硬塞 |
| 底部 ticker / 回条 | 最近变化和低权重反馈 | 1-2 行短句、提示 | 电报码 / 印刷回条 | 横向文字压色块和边框 |

示例字段容量：

| 字段 | 最大长度 | 行数 | 溢出策略 | 禁止 |
| --- | ---: | ---: | --- | --- |
| 地区名 | 8-12 汉字 | 1 | 短名 / 省略号 + tooltip | 缩成小字硬塞 |
| 摘要 | 44-56 汉字 | 2 | 超出进详情层 | 三行挤进纸片 |
| 节点卡标题 | 10-12 汉字 | 1 | 省略号 | 与状态章重叠 |
| CTA 文案 | 6-10 汉字 | 1 | 改短动词 | 烙进 PNG |
| 底部反馈 | 28-36 汉字 | 1-2 | 第二行降权 | 穿过色条 / 半调 |

核心公式：

```text
组件宽度 = 最大文本宽 + 动态状态槽 + 内边距 + 装饰禁入宽
组件高度 = 行高 * 最大行数 + 上下内边距 + 状态 / 装饰槽
```

如果公式算出来装不下，优先加大组件、拆分信息或改短字段；不要靠缩小字号、贴边排版或普通面板盖图补救。

### 2.1.1 结构验证稿

结构验证稿是功能分区之后、风格稿 / 生图之前的低成本布局确认图。它不追求最终美术，也不替代 filled-state text mock；它只回答“这个页面结构能不能承载真实功能”。

结构验证稿必须使用真实或近似真实的信息量，而不是空框占位：

- 候选列表要放到真实首屏数量，例如派遣页首屏至少验证 6-8 名候选，而不是只画 3 个。
- 槽位必须自解释；空位不能只画小方块，应写 `空`、`+支援`、`空槽`、`可加入` 等短语。
- 主 CTA 只能出现一个当前状态；组件状态矩阵不得混入结构验证稿。
- 局部阻断与全局阻断要分开，例如“队伍已满不能继续加人”应在候选卡附近提示，不得让右侧签批变成不可执行。
- 辅助资源、道具骰、临时线人必须独立表达是否占人位、是否可撤回、是否消耗。
- 如果某个模块的真实容量放不下，应在结构验证阶段改分区，不要等到生图后再用缩小字号或遮盖补救。

结构验证稿与运行骨架图的区别：

| 产物 | 回答的问题 | 是否要求程序运行 | 是否评审美术 |
| --- | --- | --- | --- |
| 结构验证稿 / `structure_wireframe` | 分区、数量、空间、主操作和字段容量是否成立 | 否 | 否 |
| 运行骨架图 / `runtime_skeleton` | 动态字段、状态机、点击热区和回流路径能否挂上 | 是 | 否 |
| 有字效果预览稿 / `filled_state_text_mock` | 图文融合、字体气质、头像裁切和商业截图感是否成立 | 否 | 是 |

结构验证稿通过后，才能进入功能重排批注稿或有字效果预览稿；若结构验证稿已经暴露候选数量不足、CTA 多重、空槽不明或右侧阻断语义错误，应先回到功能分区表。

### 2.1.2 功能重排批注稿

当用户对现有效果稿提出“看不懂 / 和原界面差距大 / 功能区不对 / 这块有什么用”这类反馈时，不应直接继续生下一张完整风格稿。必须先交付一张或一组**功能重排批注稿**，让问题和改法在视觉上可对照。

推荐采用“双层批注法”：

| 批注层 | 目的 | 做法 | 禁止 |
| --- | --- | --- | --- |
| 原图问题层 | 让用户看到现图错在哪里 | 在原图上用编号、半透明框和短句标出职责错位、状态反转、规格污染、信息缺失 | 在复杂图上堆满长段说明，或把问题批注冒充下一版布局 |
| 目标骨架层 | 让用户看到下一版要怎么改 | 与原图并排画功能骨架，标出每个功能区、主承载、动态字段、唯一 CTA 和需要移出到规格页的内容 | 直接再画一张漂亮 UI，导致用户看不出功能差异 |

批注稿必须回答：

- 当前图中哪一处是问题，而不是只给抽象结论。
- 下一版每个功能区放在哪里，负责回答玩家什么问题。
- 哪些字段继续留在真实信息图，哪些移到组件规格页或状态矩阵。
- 哪些语义属于主阻断，哪些只是局部提示，避免把局部不可加入误写成全局不可执行。
- 后续生图、切图、manifest 和截图验收是否沿用同一套颜色、编号与功能区名称。

批注稿的产物命名应明确区分：

- `problem_overlay`：只用于现图问题定位。
- `reframe_plan`：用于下一版功能骨架与生图 / 资产拆分前置说明。

如果用户要“看下一步准备怎么改”，优先交付 `reframe_plan`；如果用户问“现在到底哪里有问题”，优先交付 `problem_overlay`。两者都不是生产资产，不进入 manifest，也不得代替 filled-state text mock。

### 2.2 风格稿阶段

目标：在功能分区和信息容量已经冻结后，只确定美术语言和主承载物，不直接进入实现。

风格稿阶段必须拆成两张图或两类产物：

| 产物 | 作用 | 允许内容 | 禁止用途 |
| --- | --- | --- | --- |
| 无字风格稿 / no-text style draft | 确认主物件、材质、构图、留白、安全区和组件语法 | 地图、纸面、夹具、半调、空白卡片、空按钮底板、无文字状态槽 | 烘焙真实动态文字后直接切图 |
| 有字效果预览稿 / filled-state text mock | 用真实文案和代表性头像验证图文融合、字体目标、头像裁切和信息密度 | 真实地区名、状态、数字、CTA、列表示例、满态 / 中间态内容、代表性角色头像 / 头像组 | 进 manifest、切组件、当 runtime 底图、替代动态文字层或动态头像层 |

有字效果预览稿必须基于已冻结的信息容量和无字风格稿制作。它的结论要反向修正 `content_rects`、字体 token、行高、状态槽、CTA 文案长度和组件尺寸；如果有字稿里文字显得贴边、像默认 Label、压装饰、信息太空或太挤，就回到功能容量或组件尺寸，不进入组件生产。

如果只是用本地脚本把文字、头像或图标叠到既有底图上，这只能叫“安全区 / 容量验证稿”，不能叫最终有字效果稿。真正用于视觉评审的 filled-state text mock 必须让图像、文字、头像、字段、卡片和按钮在同一轮美术生成或同等精修中融合，效果应接近正式截图，而不是像开发期 Label 贴在 bitmap 上。

风格稿应该回答：

- 主物件是什么：地图墙、档案夹、签批纸、杂志、印刷机、票据等。
- 视觉语言是什么：深海军蓝、暖白新印刷纸、红 / 青套印、半调、高清微像素、低多边形纸质地图等。
- 物件密度和材质方向是否像 Angus。
- 哪些已被用户明确认可，哪些只是探索草稿。

正式生产用无字风格稿不得直接承担：

- 任务名、地区名、地点标签、标题、数值、倒计时、按钮文案。
- hover、pressed、selected、disabled、locked、completed 等状态。
- 可点击热区、tooltip、选中环、路线高亮、动态任务牌。

如果一张图已经包含大量真实 UI 文案、假任务卡、假按钮、假 pin 或假 tooltip，它只能被标注为“有字效果预览稿 / 灵感图”，不能作为生产底图。要进入生产，必须另有对应的无字资产、组件 atlas、状态矩阵和 manifest。

阶段跳转禁令：

- `visual_style_reference` / `color-locked style draft` / 纯风格锁定图只回答“视觉方向是否可继续”，不回答“真实内容是否装得下”。
- 如果用户问“按资产 UI 链下一步是什么”，父级必须先检查是否已有通过复审的 `filled-state text mock`。没有时，下一步只能是轻量内容合同和真实内容填充预览稿。
- 在 `filled-state text mock` 通过 UI / UX / 像素艺术复审前，不得把“组件分组 / atlas / manifest / 切图 / 资产拆分”描述为当前下一步；最多只能说这是后续阶段。
- 如果父级误把风格锁定稿之后的下一步说成资产拆分，应当立即纠正并更新本链路或采纳记录。

### 2.2.1 稿件类型 Gate 与降级规则

每次交付可见图之前，必须先在回复和文件名 / 记录中声明稿件类型：

| 稿件类型 | 可以有 | 不允许声称 |
| --- | --- | --- |
| `structure_wireframe` | 低保真框架、真实容量、功能区、主 CTA | 美术完成、可切图 |
| `interaction_fix_sketch` | 粗糙覆盖、局部移动、临时按钮、操作关系验证 | 真实内容风格稿、生产母版 |
| `problem_overlay` / `contract_overlay` | 红框、连线、编号、热区、规则说明 | 玩家可见最终效果、可拆资产图 |
| `safe-zone / capacity validation` | 程序贴字、Label 覆盖、临时矩形、最长文案压力测试 | 图文融合、高保真效果稿 |
| `filled-state text mock` | 真实文案、代表性状态、统一美术精修后的图文融合 | 生产底图、manifest 源、runtime 底图 |
| `no-text asset master` | 无动态文字、干净可写区、可切组件边界 | 最终玩家截图、真实内容效果 |
| `runtime_skeleton` | 真实状态机、动态字段、点击热区、旧壳层占位 | 美术效果通过 |
| `runtime_state_preview` | 真实运行页面、单状态或少数状态截图 | 全状态生产通过 |
| `production_candidate` | 无字资产、动态层、状态矩阵、截图验收基本齐备 | 未经复审的生产真源 |

`filled-state text mock / 真实内容风格稿` 交付前必须做局部裁切自检，至少检查：

- 主容器边缘：是否有旧底图、旧纸边、旧夹板、旧装饰露出。
- 左侧列表 / 任务卡：卡片、状态章、文字槽是否属于同一美术系统。
- 右侧详情纸：正文纸面、夹子、边框、CTA mount 是否统一，不像新纸粗暴盖旧纸。
- 底部日程条 / ticker：是否与整屏材质和层级一致，不像额外贴上的网页条。
- 主 CTA 与全局动作：是否各自拥有独立物件语法和状态，不共享或误邻近。
- 地图节点 / 标签：是否保留地图质感，节点和短签不被烘焙成不可复用假组件。

如果任一裁切出现旧组件残留、调试标注、明显贴片、视觉断层或动态 Label 贴图感，必须当场降级该图，不得交付为真实内容风格稿。降级后可以保留其中的功能结论，但不能进入无字资产母版、组件 atlas、manifest 生产或“下一步拆分落地”。

### 2.3 功能合约阶段

每个页面先写一句话职责：

```text
地区任务台：在当前地区里选择一个可派遣任务，不配置队伍，不执行骰池。
世界地图：选择取材地区并进入地区，不直接选择任务。
派遣签批台：为当前任务配置本次骰池并确认执行。
发刊前报道板：确认本期版面和送印风险。
```

同时明确：

- 玩家这一屏要做什么决定。
- 主操作是什么，通常是流程终点按钮。
- 哪些信息会改变当前决定。
- 哪些信息属于上游 / 下游，不应塞进本页。
- 哪些对象可点击，哪些只是只读预览。

没有功能合约，不进入生图。

### 2.4 元素清单与归属判定

每个元素必须先归属到四类之一：

| 归属 | 说明 | 可放内容 | 禁止内容 |
| --- | --- | --- | --- |
| 烘焙底图 | 不随数据和状态变化的主视觉 | 地图质感、纸纹、夹具、低权重装饰、不可交互半调 | 文字、任务名、按钮、pin 状态、动态标签 |
| 独立组件 | 可复用物件或控件底材 | 按钮底板、pin、卡片底、票据、签批章、短签 | 固定真实文案、固定状态结论 |
| 动态 UI | Godot / DOM 渲染的数据层 | 标题、任务名、数值、倒计时、按钮文案、状态文字 | 纸纹、半调、边框风格主效果 |
| 运行时反馈 | 交互时出现的短效 | hover 高亮、pressed 位移、选中环、点击音效、loading | 长期状态信息、主视觉纹理 |

建议使用这张表作为每个页面的首个产物：

| 元素 | 玩家问题 | 数据源 | 是否动态 | 是否交互 | 归属 | 状态 | 验收 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 主地图底图 | 我在哪个地区 | 地区配置 | 否 | 否 | 烘焙底图 | 无 | 比例不被 HUD 压缩 |
| 地图 pin | 哪些任务可选 | 任务列表 | 是 | 是 | 独立组件 | normal / hover / selected / locked | 可点区与 pin 对齐 |
| 进入派遣按钮 | 下一步做什么 | 当前选中任务 | 是 | 是 | 独立组件 + 动态 UI | default / hover / pressed / disabled / loading | pressed 有明确反馈 |

### 2.5 交互状态矩阵

只要元素会响应交互，就必须写状态矩阵。没有状态矩阵的可点击元素，不算生产可用资产。

常见最低状态：

| 组件 | 必需状态 |
| --- | --- |
| 主 CTA / 返回按钮 | default / hover / pressed / disabled / focus / loading |
| 地图 pin | normal / hover / selected / locked / completed / urgent |
| 地图短签 | hidden / hover / selected / disabled |
| 任务卡 | normal / hover / selected / unavailable / deadline / assigned |
| 筛选签 / 标签页 | default / hover / selected / disabled |
| 拖拽槽 | empty / hover / drag-over / occupied / invalid |
| 签批章 | idle / ready / pressed / stamped / disabled |

每个状态要回答：

- 贴图是否不同，还是用同一贴图加运行时状态层。
- 文字是否仍在同一个 `content_rect` 中。
- 点击热区是否跟视觉对象一致。
- hover 是否会展开额外标签或改变布局。
- pressed 是下沉、压章、变暗、换帧还是播放动效。
- disabled 是否明显不像可点对象。

### 2.6 生图阶段

生产用生图只生产 bitmap 美术，不生产功能结论。

若本轮是有字效果预览稿，prompt 可以填入真实 UI 文案和代表性头像 / 角色数据来观察目标效果，但文件名、评审记录和交付说明必须明确标注为 `text_mock` / `filled-state text mock`。该 prompt 只服务图文预览，不得复用为组件生产 prompt；正式组件 prompt 仍必须回到无文字、无烘焙头像、可切分、可动态渲染的版本。

生产组件 prompt 必须明确：

- 不要真实中文、英文 UI 文案、数字、任务名、地区名、按钮文案。
- 不要假 pin、假标签、假 tooltip、假任务卡内容。
- 需要干净空白可写区，保留低噪声纸面。
- 可交互组件要单独输出 atlas 或透明 PNG。
- 按钮、pin、卡片、票据、签批章需要多状态版本或足够稳定的状态层。
- 半调、套印、纸纹不得穿过未来动态文字区域。

本地脚本可以做：

- 裁切、缩放、透明留白。
- 纯色背景抠除。
- manifest 校验。
- 安全区 overlay。
- 打包和截图。

本地脚本不得做：

- 程序绘制纸纹、半调、噪点、像素边框冒充正式美术资产。
- 用矩形面板盖住缺安全区的美术图。
- 重新画按钮质感、pin 质感或纸面主效果。

### 2.7 切图与 manifest

没有 manifest 的资产，只能算图片，不能算生产资产。

如果资产来自生图 prompt，prompt 与 manifest 必须能互相对上：每个 atlas 都要写清 `target_size`、`frame_size`、`frame_order`；每个文字组件都要写清 `content_rects`、`no_text_rects`；每个可点击组件都要写清 `hit_rect`、`hover_rect` 和 `feedback_spec`。同一条功能事实只能有一个主承载位，例如按钮 label 不能同时属于详情纸和按钮 atlas。

最低字段：

```json
{
  "id": "region_task_cta_enter",
  "role": "primary_cta",
  "asset_paths_by_state": {
    "default": "cta_enter_default.png",
    "hover": "cta_enter_hover.png",
    "pressed": "cta_enter_pressed.png",
    "disabled": "cta_enter_disabled.png"
  },
  "base_size": [320, 72],
  "nine_slice": [18, 18, 18, 18],
  "content_rects": {
    "label": [42, 14, 226, 40]
  },
  "no_text_rects": {
    "arrow": [274, 12, 32, 40],
    "bottom_stripe": [0, 58, 320, 10]
  },
  "hit_rect": [0, 0, 320, 72],
  "hover_rect": [-6, -6, 332, 84],
  "anchor_points": {
    "tooltip": [160, 0]
  },
  "states": ["default", "hover", "pressed", "disabled"],
  "feedback_spec": {
    "pressed_offset": [0, 2],
    "sound": "stamp_soft",
    "duration_ms": 90
  },
  "overflow_policy": {
    "label": "ellipsis"
  },
  "z_index": 40,
  "qa_cases": ["long_label", "disabled_reason", "pressed_frame"]
}
```

关键字段说明：

- `content_rects`：动态文字、数字和按钮文案可进入的区域。
- `no_text_rects`：书签、折角、螺丝、箭头、色条、纸边、强纹理等禁入区。
- `hit_rect`：真实点击区，必须和视觉对象匹配。
- `hover_rect`：鼠标靠近后允许触发 hover 的扩展区。
- `anchor_points`：tooltip、短签、选中环、连线的挂点。
- `states`：状态名必须和代码状态一致。
- `feedback_spec`：点击 / 按下 / 选中时玩家能看见或听见什么。
- `qa_cases`：必须截图或自动审计的边界状态。
- `target_size` / `frame_size` / `frame_order`：atlas 与 prompt、切图脚本、代码 loader 对齐的机器契约。
- `overflow_policy`：长文案、两位数、禁用原因、空态提示超出时如何处理。

### 2.8 拼接实现阶段

Godot / HTML 负责：

- 动态文字、数值、状态、点击、hover、pressed、selected、disabled。
- 用 manifest 读取贴图、热区、文字安全区和锚点。
- 使用 `TextureButton`、`TextureRect`、`NinePatchRect`、Control 热区或等价结构装配。
- 保证动态文本只进入 `content_rects`。
- 保证点击热区不覆盖不可点击装饰。
- 回收旧 UI 控件、旧 tooltip、旧调试框、旧按钮框和重复状态层。

Godot / HTML 不负责：

- 重新模拟正式纸纹、半调、主按钮质感、pin 质感。
- 用普通面板贴片补救美术资产缺陷。
- 把视觉上不可点的装饰做成隐形按钮。

### 2.9 验收阶段

验收不是只看默认整屏截图。

最低验收：

- 桌面 16:9 主视口截图，默认优先 1920x1080。
- 关键对象 100% 局部裁切。
- 默认态、hover、selected、pressed、disabled 至少覆盖和本次改动相关的状态。
- 长中文、两位数、倒计时、锁定缺口、禁用原因、空态和满态。
- 视觉安全区检查：文字没有压到 `no_text_rects`。
- 交互热区检查：点击区域与视觉对象一致。
- 旧控件回收检查：没有新资产和旧面板混层。
- 美术复审：像素颗粒、半调、纸质、套印是否仍像 Angus。
- 图文功能融合检查：文字是否被纸面 / 票据 / 档案 / 频道 / 按钮吸收，是否拥有字体 token、`content_role` 和状态联动。
- 单状态决策检查：至少用一个真实选中态验证玩家 5 秒内能说出当前对象、关键风险、下一步动作和动作后果。

要区分：

- **控件通过**：Control / DOM rect 没越界。
- **视觉通过**：玩家截图里文字稳稳落在物件上，不压装饰，不贴边，不穿过纸纹。
- **交互通过**：玩家 hover / click / pressed / disabled 时能看见状态变化，并能理解对象是否可用。
- **语义通过**：文字、状态、图标和主动作共同说明同一个当前决策，而不是各自重复解释。

四者都通过，才算资产化 UI 通过。

## 3. 禁止烘焙清单

以下内容默认不得烘焙进底图：

- 任务名、地区名、节点名、角色名。
- 标题、正文、说明、按钮文案。
- 天数、倒计时、风险、需求、奖励、状态。
- pin、选中环、hover tooltip、地图短签、锁定标识。
- 路线高亮、可达 / 不可达路径、当前推进路径。
- 可点击按钮、返回按钮、筛选签、标签页、CTA plate。
- 空白任务牌、黄色提示框、白色常驻标签。
- 会被玩家误读成真实信息的假文字、假数字、假图标。

允许烘焙：

- 地图大陆轮廓、网格、裁切线。
- 低权重半调、纸面、印刷质感。
- 不可交互的氛围红青点。
- 夹具、纸边、阴影、桌面材质。
- 不承载动态文字的纯装饰纹理。

## 4. 典型失败模式

### 4.1 整屏风格稿直接进实现

症状：截图好看，但文字只能硬贴，长标题一换就出框。

处理：回到元素清单，拆出底图、组件、动态文字和运行时反馈。

### 4.2 可交互对象画在底图里

症状：按钮没有 pressed，pin 无法 selected，空白标签无法隐藏。

处理：按钮、pin、任务卡、签批章全部拆出状态资产或状态层。

### 4.3 只有 content_rect，没有 hit_rect

症状：文字放得下，但点起来不确定，hover 不对位。

处理：manifest 加 `hit_rect`、`hover_rect`、`anchor_points` 和 `feedback_spec`。

### 4.4 斜透视纸面承载正文

症状：局部有质感，但 UI 被斜边限制，正文和 CTA 难以稳定。

处理：斜纸只能做背景、背后叠页、边缘厚度或装饰，正文进入正交 `content_rects`。如果一个页面需要承载动态标题、正文、状态、数字或按钮文案，承载这些内容的**正面纸张本身**必须水平 / 垂直对齐；不能只在斜纸上画一个看似正的内框，也不能把 “orthographic text area” 写进 prompt 后继续接受整体倾斜的可写纸面。生成结果只要可写纸面倾斜，就必须降级为失败样本 / 灵感图，不进入 `filled-state text mock`、`no-text asset master` 或生产候选。

Prompt 必须写成一票否决句：`front writable paper faces are square-on and axis-aligned; no tilted/skewed/perspective writable document faces; angled sheets are background decoration only`。验收时必须裁切左侧卡片、右侧详情纸和底部按钮文字槽，确认可写正面没有斜。

### 4.5 普通面板贴片补救

症状：右侧粗暴盖了一个页面，读成“底图 + 临时 UI”。

处理：重出分层资产，或临时退回低装饰功能布局，不在高完成度底图上叠普通控件。

### 4.6 只截默认态

症状：默认截图通过，hover / pressed / disabled 一用就坏。

处理：每个可交互组件至少截和本轮相关的状态帧。

## 5. 地区任务台当前应用结论

用户已明确认可：

- 上一套地区任务图的整体风格、视觉和配色方向。
- 中央地图底图的深蓝、多边形、纸质、半调、红青路线方向；这是视觉锚点，不应被重画成另一套风格。
- 地图底图比例不应被顶部 HUD 或侧栏压缩。
- 纸张应是现代杂志社新鲜印刷纸，不是旧档案 / 旧报纸。

当前必须重建：

- 顶部 HUD：压缩为低权重频道条或微仪表，不再占大块高度。
- 左侧任务栏：重出空白任务卡、索引签、状态章和安全区，不再使用整张生成档案图硬贴文字。
- 右侧详情栏：外轮廓可以有拟物斜切，正文区必须正交。
- 地图标签：地图底图只保留地图；pin、短签、tooltip、选中环、锁定态全部拆出。
- 主 CTA：拆为独立按钮组件，至少有 default / hover / pressed / disabled / loading。

当前不得重建：

- 不得因为功能拆层顺手更换地区任务台的视觉主题、主色、地图材质、纸面风格或红青印刷关系。
- 干净地图底图只能是“同风格清洁版”，不是新地图方向。
- 不得用程序化几何图、PIL / Canvas / SVG 低保真绘图、白盒调试地图或简化矢量大陆轮廓替代已被用户认可的地图视觉源；这类图只能放入 `tmp/whitebox` 或明确标注为交互占位，不得写入正式 `assetized` 资源目录。
- UI 布局可以重新分工，但截图第一眼必须仍像上一套图的同源生产版，而不是另一个界面方案。

2026-06-17 v3 追加口径：当用户明确认可一张地区任务台整屏图的整体美术效果，并且当前任务目标是“先恢复该视觉效果再增强功能性”时，可以把整屏图登记为 `visual_lock_backdrop` / 高保真恢复底图接入运行时。这样做的前提是：该图只锁定不可变视觉锚点，特别是中央地图、工作台、纸张、夹具和红青印刷关系；动态文字、按钮文案、任务状态、阻断原因、点击热区和需要 pressed / hover / selected / disabled 的对象仍必须由动态层或独立组件承担。`visual_lock_backdrop` 不是生产切图母版的豁免权，也不能让按钮、任务卡、短签和状态章重新烘焙回底图。

## 6. 交付定义

一次资产化 UI 落地完成，至少应交付：

1. 功能合约：这一页负责什么、不负责什么。
2. 元素清单：每个元素的动态性、交互性和归属。
3. 状态矩阵：所有可交互对象的状态。
4. 无字风格稿和有字效果预览稿：有字稿只做目标截图和图文融合验证，不进入 manifest。
5. 资产文件：底图、组件 atlas、状态贴图。
6. Manifest：`content_rects`、`no_text_rects`、`hit_rect`、`hover_rect`、`anchor_points`、`feedback_spec`。
7. Godot / HTML 拼接：动态层只按 manifest 放置，不硬贴临时控件。
8. 截图验收：整屏、局部、默认态、关键交互态。
9. 复审记录：UI、UX、美术至少覆盖各自风险。

不满足以上项目时，只能称为：

- 风格稿。
- 灵感草图。
- 临时止血版。
- 功能原型。

不能称为生产资产、生产标杆或正式 UI 落地。
