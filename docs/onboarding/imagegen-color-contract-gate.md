# Imagegen Color Contract Gate

> 用途：给 Angus 的 UI 风格稿、生图、修图和像素 / 半调资源建立可复用的颜色硬审核机制。  
> 适用范围：世界地图、地区任务台、派遣签批台、报道主板、票据 / 卡片 / 地图 / dossier 等所有需要“接近参考图颜色”的 bitmap 资产。  
> 状态：2026-06-22 起作为生图调色硬门槛。颜色不通过时，不得把候选图称为通过、生产标杆、资源标杆或真源候选。

## 1. 为什么需要硬闸门

颜色不是“更高级 / 更干净 / 更冷一点”这类审美描述能稳定控制的对象。AI 生图会天然做全局重染，像素 / 半调颗粒也会改变肉眼对颜色的平均感知。

本机制来自 2026-06-22 世界地图像素颗粒度分支实验：

- Variant B：颗粒方向可取，但纸面偏黄。
- B2：试图去黄，却滑向灰白 / 过白。
- B5：宽色彩合同通过，但用户肉眼仍觉得与参考图不同；复采样证明它整体偏暗，红橙和青色偏沉。

因此，后续不能再把“没有明显偏黄 / 过白”当成“颜色匹配通过”。

## 2. Color Contract v1

任何涉及调色、去黄、提亮、压暗、冷暖、纸色、主色或“更接近参考图”的任务，写 prompt 或修图前必须先建立 `Color Contract v1`。

最小字段：

| 字段 | 要求 |
| --- | --- |
| `reference_image` | 唯一用户认可基准图；不得用失败候选图当基准 |
| `candidate_image` | 当前待修图或待审候选图 |
| `roi_tokens` | 固定采样区域与 mask，例如 `right_paper`、`left_card_paper`、`bottom_card`、`map_light`、`navy_board`、`alert_red_orange`、`signal_cyan`、`ink_dark` |
| `sample_values` | 每个 token 记录 `hex / RGB / Lab / mean luminance / luminance std / ROI 坐标或 mask` |
| `global_values` | 整图平均亮度、纸面占比、暗部占比 |
| `failure_boundaries` | 已知失败样本及原因，例如偏黄、过白、过暗、红青偏沉、旧纸脏点 |
| `acceptance_thresholds` | 每个 token 的通过阈值 |
| `post_check` | 候选图必须用同一 ROI 复采样并并表比较 |

没有上述合同，不得继续写调色 prompt，也不得让 `@像素艺术` 只凭“感觉更接近”通过。

## 3. 推荐阈值

默认阈值用于视觉参考图匹配；如果用户明确允许大幅风格变体，必须另行记录。

| 指标 | 默认通过线 |
| --- | --- |
| 品牌 / 信号核心色 `alert_red_orange`、`signal_cyan`、`navy_board` | `DeltaE00 <= 3.0`，且 `|dL| <= 2.5` |
| 纸面 / 地图浅色 `right_paper`、`left_card_paper`、`bottom_card`、`map_light` | `DeltaE00 <= 4.0`，且 `|dL| <= 2.5` |
| 整图平均亮度 | 与参考图差值 `<= 3.0` |
| 纸面占比、暗部占比 | 与参考图差值 `<= 0.01-0.015` |
| 失败边界 | 不得向任何已登记失败边界靠近 |

如果环境暂时只能计算 RGB / luminance，必须至少报告 `RGB diff`、`dL`、整图均亮度、纸面占比和暗部占比；这种情况下只能给“临时色彩检查”，不能给最终颜色通过。

## 4. 颗粒与纸面闸门

颜色通过只说明色彩没漂移，不代表美术通过。颜色 Gate 之后仍必须由 `@像素艺术` 检查颗粒和纸面。

颗粒通过条件：

- 可见 2-4px 方块簇、块状半调、套印错位、清晰图形边缘。
- 半调 / 像素参与结构：地图、报道图、票据边、信号区、套印边。
- 不得把正文区、按钮文字区、动态信息区打脏。
- 若颗粒主要表现为细碎灰尘、霉点、旧档案污渍或高清摄影噪声，直接不通过。

纸面通过条件：

- 纸面是现代刊发 / 新鲜印刷纸，不是旧档案、旧报纸或怀旧办公室。
- 米白纸面接近参考图冷暖与明度，不偏黄、不惨白、不灰脏。
- 折痕、污点、半调不得穿过动态正文和 CTA。
- 画面第一眼不能读成历史案件档案或泛黄文件。

## 5. 职责分工

父级 Codex：

- 冻结参考图、ROI、色号合同、失败边界和阈值。
- 对每个候选图复采样，并输出逐 token 对比。
- 不得在缺采样表或候选图未复采样时继续要求“更冷 / 更白 / 更接近”。
- 最终只能说“哪些 token 通过 / 哪些 token 失败”，不得用宽泛 PASS 替代。

生图 / 修图工具：

- 只执行受控 prompt / edit，不负责判断是否像 Angus。
- Prompt 必须包含采样 token、允许范围和 `preserve sampled palette; do not globally retone the image`。
- 输出后必须回到父级复采样。

`@像素艺术`：

- 只读风格守门。
- 先看颜色是否过硬闸门；颜色未过时，不进入生产标杆判断。
- 颜色通过后，再审颗粒 / 半调是否是结构语言、纸面是否滑向旧档案 / 旧报纸 / 摄影噪声。

## 6. 熔断条件

出现以下任一情况，停止继续生图或修图：

- 没有唯一参考图和固定 ROI。
- 没有 `hex / RGB / Lab` 采样表。
- 未定义已知失败边界。
- 上一轮候选没有复采样，只靠肉眼或 prompt 意图评价。
- 关键 token 超阈值，尤其是纸面、深蓝、红橙、青色。
- 用户指出肉眼不同，而父级仍只能给“整体接近 / 风格通过”。
- Prompt 只有“更高级 / 更干净 / 更像参考”，没有具体色号、阈值和禁区。
