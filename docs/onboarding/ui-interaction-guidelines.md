# UI 交互与视觉协作原则

适用 Angus 桌面 16:9，默认 1920×1080。此处不预设三栏边框、签批夹、固定字号、固定配色或固定按钮位置；具体页面的有效功能与当前用户授权决定设计范围。

## 理解玩家在做什么

先理清当前目标、主要选择、需要的信息、操作结果与回流路径。区分浏览、选中、可进入、锁定、禁用与风险；不能用一个状态的装饰同时表示几种相反含义。只读信息不能伪装成操作，装饰不能制造虚假点击承诺。

必要信息之外，允许世界观、职业身份、氛围和幽默占据有设计价值的空间；“不影响决策”不等于“必须删除”。减少无效噪音，而不是把游戏做成后台报表。

## 视觉设计的自由与责任

- 先对照实际标杆，找出形体概括、色彩角色、材质和趣味的生成规律，不只复制零散夹子、阴影或批注。
- 有功能的组件需清楚归属，装饰可以跨分区建立整体感；不要求每个功能区都有独立硬框。
- 字号、字重、行长和留白按实际显示比例与内容决定。禁止拿“容器没溢出”替代肉眼可读；也不把一套 px 数字强加所有组件。
- 已存在的字体、主题、布局系统是实现起点，不是审美重构的上限。新实验可以有独立样式和结构，但不能悄悄替换主界面。

## 实现时验证真实承载

动态文字放在资产实际可写区域，避开夹具、折角、亮斑和强纹理；内容、可视物件与热区对齐。功能阅读面通常正向排版，具体正交、倾角和 hit rect 以该实现合同为准；装饰倾斜不能盖住内容。

同类状态优先共享图片规格和数据结构，状态不应迫使内容资产另做裁切版本。明确母图、适配方式、长文案、计数、空态、锁定/选中与展开状态；只检查实际存在且受改动影响的状态。不得为保住旧壳而强行缩字、截掉关键信息，必要时调整承载结构并同步合同。

看组合后的真实内容，不只看无字母件。图片复用、alpha、装配接缝、重复烘焙图标、焦点与遮挡，见 `../workflows/ui-geometry-and-text-safety-gates.md`。看真实交互，不以静态预览假称事件已接线。

## 历史规则的适用范围

旧地图、地区任务台、发刊页等具体尺寸和流程保留在各自的 `design/ui-contracts/`、状态页和采纳记录，不能跨页自动套用。旧实现仍遵守其有效合同；用户授权的新设计候选可以重新提方案，正式替换时再更新相关合同。

样式实验不必先冻结所有槽位；正式资产化也不能以“自由探索”为由省略功能验证。资产化决策见 [资产链](assetized-ui-production-chain.md)；选择材料、拆层或批量方案前，按风险检索 [共享经验](../experience/ui-assets/README.md)。案例不指定本页必须采用的工艺。
