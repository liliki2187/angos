# 子代理协作说明

2026-09-08 修订。专家提供有证据的独立判断，父级对最终作品负责；不是每个请求都要经过全部角色。

## 1. 派什么、何时派

有独立、有边界且结果可被当前工作使用的子任务才委派。明确用户目标、输入文件/原图、当前阶段、允许改变什么、只读或文件所有权，以及希望解决的问题。研究可并行；产物复审应看实际产物，不凭作者承诺。

用户显式点名始终响应；工具不提供角色时按技能在父级执行并说明。其他委派须符合当前会话权限，并有具体独立问题，例如未知操作链、争议素材的风格证据或共享组件的消费者遗漏；重要布局本身不自动触发固定双审。父级可以独立完成方案，不要求先设计后诊断或相反顺序。

## 3. 美术分支隔离

clean low-poly weekly 自动路由继续不调用旧像素/半调美术指导。父级直接看两张 benchmark 与候选，评判宽块面、形体概括、材质、色彩和幽默；涉及实际功能时同时判断操作与状态，是否委派依 §1 的具体问题决定。

显式调用艺术指导时必须传入当前分支与参考，其意见不能用其他分支标准作否决。技能增加分支识别不等于用户已批准恢复自动路由。角色仍以专用四人标杆为准，不把其高清微像素规范套在地图底板上。

## 4. 交叉检查和分歧

让评审者说明看到了什么、推断了什么、证据支持多大范围。作者“已经处理”不等于独立验证通过；新证据可修正先前问题等级。

父级比较的是作品与用户目标，而非哪个角色权力更大。可逆设计取舍自主整合；真实功能冲突、新权限或关键偏好缺失才请用户裁决，不强制让用户转发多轮意见。

## 5. 输出与维护

回答当前问题，报告长短随问题而变，不凑问题数、不固定 Top 3 或完整表格。父级默认展示关键结论、实际结果和未解决风险；需要审计时保存完整报告可追溯。

启动壳只写角色、只读边界和 SKILL 入口，不复制流程。五个 UI 配套角色默认继承父级模型与推理档位；已有运行代理不会因磁盘文件更新自动热切换，下一次启动需确认加载新入口。

技能只维护决策方法；页面数字进页面合同，跨 UI/美术/工程的装配经验统一进入 [共享索引](../experience/ui-assets/README.md)，角色专属经验才进技能案例。案例不是硬门槛，也不因为某次失败就自动新增全局规则。不要再建立多处手写 KB 数量和版本计数。

### 冻结含义

- 保留 `.codex/agents/*.toml` 注册壳与 `skills/` 技能目录，随时可用。
- 用户显式触发词（`@制作人`、`@系统架构`、`@数值策划`、`@逻辑审查`）调用时仍正常执行，不需要先走解冻流程；但 AI 应在执行时顺带提醒该 agent 处于冷备，并询问是否正式解冻。
- 冻结期间不再为这四个 agent 投入维护：不新增规则、不扩写 SKILL.md、不补 references / casebook、不做能力校准。
- AI 不主动 spawn 它们参与常规任务链路（其他角色按本文件的任务相关性路由）。

### 解冻提醒义务（硬规则）

用户明确表示自己无法判断解冻时机，且可能忘记冻结这件事。因此 AI（父级 Codex / 任何后续会话）在任务中识别到下列价值窗口时，**必须当场主动提醒用户**，不得默默替代该 agent 职责而不提醒，也不得等用户自己想起：

| 冷备 agent | 解冻触发条件（命中任一即提醒） |
| --- | --- |
| `game_producer` | 用户讨论要不要做某个大功能、立项 / 砍范围 / 里程碑 / 熔断、项目方向变化；或 AI 自检发现范围膨胀、工期风险、系统增殖失控迹象 |
| `game_sys_architect` | 要新增玩法系统或长期玩法层、准备更新 `design/gdd/systems-index.md`、多系统耦合冲突、资源流产消不清 |
| `game_numerical` | 玩法数值调校启动：达标率、概率校准、任务目标值、黑骰反噬、周压力、发刊结算数值、势力 / 宏观属性参数、配表或平衡验证 |
| `game_logic_check` | 规则 / 状态机 / 配表 / 剧情时间线成形并准备实现前；或原型出现重复结算、流程卡死、exploit、状态永久锁死类问题 |

提醒格式：一句话说明命中了哪个触发条件 + 建议解冻哪个 agent + 不解冻时的替代方案（通常是父级在当前线程按对应 `SKILL.md` 执行同等流程，但不做能力沉淀）。是否解冻由用户决定；用户未回应时按替代方案继续当前任务，不算解冻。

### 解冻流程

1. 用户明确同意解冻后，更新本节冻结状态表（填解冻日期）。
2. 本节是冻结状态的唯一清单；核对 AGENTS.md 的入口说明仍然准确，不恢复顶层重复名单。
3. 恢复该 agent 的正常维护投入；首次实战后仅在有可迁移经验时记录案例，按本文维护原则决定是否修订技能，不自动追加规则。
