## 读取总规则

1. 先读本总索引，确认任务关键词、主分册和 cross-read tags。
2. 分册按检索式读取（2026-07-08 修订）：先用本索引的条目 ID 与 tags 定位相关条目，再用 `rg` 在对应分册中检索条目标题 / 关键词，完整读取**命中条目及其修订备注**；不要只凭“这是 UI / 这是机制 / 这是美术”单点分类。`ui-ux-decisions.md` 等大分册已超出单次全文阅读的合理体量，“读全文”不再是默认要求；只有小分册（如 `backlog-and-deferred.md`）或用户明确要求全面盘点时才通读。
3. 任务跨玩法、UI、视觉或流程时，必须按 tags 补检相关分册的命中条目；分类只用于加速检索，不用于截断上下文。
4. 不确定时，用 `rg` 同时搜索本文件与 `docs/design-decisions/` 全目录；检索不能替代阅读命中条目全文，条目内的修订 / 撤回备注必须读到。

## 写入规则

- 用户在讨论中明确采纳 / 待定 / 进阶 / 撤回时，AI 必须在当次回复结束前更新本索引，并把完整条目追加到最合适的主分册。
- 只记录用户明确表态；不记录 AI 单方面设想。
- 新条目继续沿用 `A/B/C/D/M` 编号语义：`A` 已采纳，`B` 特殊任务/角色，`C` 后期进阶，`D` 待定，`M` 机制库备查。
- 条目跨领域时，主分册按“最主要影响域”选择，但本索引必须补全 cross-read tags；必要时在相关分册加回链，避免后续漏检。
- 修订 / 撤回时保留原条目，在对应分册条目末尾追加时间与新表述；不要直接覆盖原文。
- 采纳记录不是规格真源；需要落到实现、配置或 GDD 时，同步对应规格 / `design/gdd/` 文档，并在条目状态里回引。
