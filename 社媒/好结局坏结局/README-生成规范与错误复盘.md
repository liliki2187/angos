## 固定尺寸

- 单卡画布：`1024 x 1536`
- 上图区域：`1024 x 872`
- 下方文字区域：`1024 x 664`
- 成对长图：`2208 x 1632`
- 成对长图边距：左 / 上 `48`
- 成对长图间距：`64`
- 成对图中单卡裁切：
  - Good：`x=48, y=48, w=1024, h=1536`
  - Bad：`x=1136, y=48, w=1024, h=1536`

## 文字层级

通用层级：

1. 英文 Ending 类型：Old English 字体，顶部最大。
2. 橙色路线 / 类型名：统一使用通用橙色，不随路线主色变化。
3. 中文标题 / slogan：粗体、居中、配短橙色下划线和两侧端点。
4. 正文：居中、松弛排布，宁可减字或降一档字号，不要挤。
5. 解锁成就：底部通用橙色。

推荐字体与颜色：

- 英文 Ending：`C:\Windows\Fonts\OLDENGL.TTF`
- 中文正文：微软雅黑 `msyh.ttc`
- 中文粗体：微软雅黑 Bold `msyhbd.ttc`
- 通用正文米白：约 `#F6F1D6`
- 正文柔和米白：约 `#E7E8D3`
- 通用橙色：`#E2603D`

重要规则：

- 路线主色只能进入上图、底板氛围和背景 wash，不得改变路线名、下划线、端点和成就的通用橙色。
- 同一对 Good / Bad 的字号、字体、行距、标题位置、成就位置必须完全一致。
- 字号差异不能靠肉眼“感觉差不多”，必须用同一套模板常量生成。
- `True Ending` 的卡面中文标题是“我们还不知道。”；“开天窗”是内部结局名 / 成就名，不进入标题层。
- 特殊结局的橙色行统一写“特殊结局”，不要写具体结局名。

## 上图生成规范

用户说“生图 / 生成图片 / 再生一张 / 重新生图”时：

- 必须调用真实图像生成模型。
- 不得用 SVG、Canvas、HTML/CSS、PowerShell、Python、C# `System.Drawing` 或程序化色卡冒充生图。
- 程序只能用于：复制文件、裁切、文字排版、合成、bbox QA、尺寸检测。

上图提示词必须明确：

- 用于 `1024 x 872` 卡牌上图窗口。
- 画面满幅，不要 16:9 横幅、不要窄竖图、不要留左右空边。
- 不要模糊侧边、镜像补边、暗色侧栏、pillarbox / letterbox。
- 主体必须完整：塔尖、塔基、核心物件、人物动作、空白头版边缘不能被裁掉。
- 一个核心符号为主，不要整屏讲故事。
- 风格为干净低多边形、概括色块、印刷纸感、半调颗粒；避免写实摄影、复杂插画、细节堆满、旧档案泛黄。

## 图像主题经验

- 公信 / 科学线：核心是公共灯塔。Good 不是消灭异常，而是解释掉恐慌；Bad 是把求救者也排除成“不存在”。
- 诡名 / 怪谈线：核心是城市梦话。Good 承认怪谈背后有真实痛苦和情感；Bad 是世界学会制造怪谈。
- 声望 / 小报流量线：核心是商业化周刊大楼 / 商业陈列架城市。Good 必须有人味，Bad 必须是资本异化。
- 守序 / 势力合作线：核心是绿色官僚空间。Good 有保护性的沉默，Bad 是无尽流程和未公开事项。
- 狂性 / 深层真相线：核心是深渊和头版主体。Good 是看见深渊但保护他人，Bad 是主编成为最大真相 / Boss。
- Loop Ending：核心是报纸套报纸递归，不要只画招聘场景。
- Super Bad Ending：核心必须一眼是巴别塔，不要只是信息拼贴塔。
- True Ending：核心是空白头版，不是普通桌面静物。

## QA 清单

每次生成正式卡前必须逐项检查：

1. 是否真实生图，而不是程序生成主视觉。
2. 上图源是否接近或适配 `1024 x 872`，且满幅。
3. 是否没有模糊补边、镜像补边、侧边暗栏、强行 contain。
4. 上图下缘是否两张卡完全在同一水平线。
5. Good / Bad 是否同一模板、同一字号、同一字体、同一行距。
6. 路线名、标题、正文、成就是否层级正确。
7. 标题是否一行；如果变两行，优先改文案或降级到正文。
8. 正文是否有呼吸感，是否比早期样张更挤。
9. 成就文字是否同字号同字重。
10. 通用橙色是否保持一致。
11. 核心符号是否一眼可读，是否被细节淹没。
12. 角色是否融入画面风格，不得像贴上去的高清角色。
13. 是否输出 bbox QA 或等效检查图。
14. 是否展示真实成品图给用户，而不是只报文件名。

## 错误复盘

### 1. 用程序图冒充生图

曾经用程序生成色卡 / 示意图，被用户明确否定。之后所有“生图”请求都必须真实调用图像生成模型；程序只做后处理。

### 2. 上图比例错误导致文字被挤

多次把图片生成得过高、过长或过窄，导致下方文字区被压缩。正式卡必须锁定 `1024 x 872` 上图窗口，不能后期硬塞。

### 3. 用模糊补边伪适配

曾经把窄图 contain 到上图区，两侧用模糊背景补齐。用户明确指出这是伪适配。后续如果源图不适配，必须重新生图，不得补边。

### 4. 两张卡上图下缘不齐

曾经 Good / Bad 两张上图底边不在同一水平线。后续必须固定 `UPPER_H=872`，并用同一个合成模板。

### 5. 字号和字体不一致

曾经路线名、标题、正文、成就分别出现细微字号差异。原因是分开排版、靠肉眼判断。后续必须使用同一个脚本模板和固定字体常量。

### 6. 正文越来越挤

曾经为了塞下文案压缩行距，失去早期样张的松弛感。后续应先改文案长度，再微调字号；不要让文字变成密集说明书。

### 7. 路线主色污染文字系统

守序线曾把文字装饰色改成路线色，破坏系列统一。后续路线色只进入图像与背景氛围，文字装饰统一橙色。

### 8. 图像细节过多，核心符号不突出

怪谈线、声望线多次变成完整场景叙事，失去低多边形概括感。后续必须先确定一个核心符号，再生图。

### 9. 角色画风不融入

声望线女主一度像高清角色贴纸。后续角色只保留基础辨识度，必须与建筑 / 画面共享低多边形、半调和纸感。

### 10. 特殊结局文字层级误判

Loop Ending 曾把“编辑部来了个年轻人”放到橙色路线行，把“你消失了。”放到标题。正确做法：橙色行是“特殊结局”，中文标题是“编辑部来了个年轻人”，正文从“你消失了。”开始。

### 11. 内部结局名误排成卡面标题

True Ending 曾把“开天窗”放成中文标题。正确做法：卡面标题是“我们还不知道。”；“开天窗”只作为成就名 / 内部结局名。

### 12. 没有先验收上图就进入带字卡

曾经上图主体被裁、过窄或补边后仍继续排文字。后续流程必须先验收上图窗口，再进入文字层。

## 推荐工作流

1. 先写清楚该结局的标题、正文、成就和核心符号。
2. 生成 `1024 x 872` 上图专用素材。
3. 只验收上图：主体完整、比例正确、无补边、核心可读。
4. 用统一模板合成 `1024 x 1536` 单卡。
5. 成对图只从两个单卡拼出，不重新调整文字。
6. 输出 bbox QA，检查字号、下缘、成就位置。
7. 把用户确认的最终版复制到本社媒目录，不把实验版混进来。
