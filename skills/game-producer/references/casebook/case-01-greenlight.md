# Case 01 · 立项评估样本（Desktop Operator Sim 品类）

> **场景**：独立开发者想做一款"桌面操作员模拟 + 恐怖/悬疑"类游戏，给了两款竞品参考（The Operator、Home Safety Hotline），然后提出自己的创意方向。
> **演示重点**：竞品分析 → 品类提炼 → 创意验证 → 立项评估报告全流程。

---

## 用户输入

> 分析一下 The Operator 和 Home Safety Hotline 这两个 Steam 游戏，然后帮我评估：我想做一个类似品类的游戏，设定是玩家当一家《世界未解之谜周刊》的主编，每周选选题、决定报道方向，报道会影响城市和势力。

### 品类提炼：Desktop Operator Sim

这两款属同一微品类，共性基因：

| 基因 | 描述 |
|------|------|
| 叙事伪装 | 表面日常工作，暗藏大叙事 |
| 信息查阅核心玩法 | 翻资料→对照→判断 = 每 30 秒循环 |
| 拟物桌面 UI | 90s/00s 计算机审美是核心差异化来源 |
| 音频叙事 | 语音/来电/环境音承担氛围 |
| 短时体验 | 2-4 小时 |
| 低成本高传播 | 无 3D / 直播友好 / 截图梗 |

### 对你项目的创意验证

**【致命质疑】**

你的"周刊主编选选题影响城市"方向有 2 个致命问题：

1. **核心循环模糊** — "选选题→发刊→看世界反应"听起来好，但**玩家每 30 秒在做什么操作？** The Operator 是"翻数据库对照证据"，HSH 是"翻百科匹配来电"。你的是什么？翻什么？对照什么？判断什么？如果答不上来 → 核心循环还没成立。

2. **反馈周期过长** — "报道影响城市"是**周级别反馈**，但两个竞品的反馈是**分钟级**（查到证据→案件推进 / 选对答案→来电结束）。如果玩家选完选题要等一整个"游戏周"才看到结果 → 即时满足感崩塌 → 流失。

**【市场佐证】**

- Papers Please（2013）= 同品类鼻祖，$5M+ 收入，核心循环 = 30 秒/人次判断。**每次判断都有即时反馈**（放行/拒绝→对方反应→你的收入变化）。
- The Operator 和 HSH 同样是"分钟级反馈循环"成功。
- 尝试"长反馈循环"的同品类游戏（如某些报社模拟）表现平平 → 证据指向"短循环"是品类刚需。

**【制作人的引导】**

方向 A · **压缩反馈到分钟级**：
- 每天（不是每周）有 5-8 个来信/线索/举报到达编辑部
- 每条线索 = 1 次"翻资料→判断真假→决定报不报"的 30 秒循环
- 报完**立刻**看到城市/势力的即时微反馈（如"科学会打来电话施压"）
- 周结算只做**汇总**，不做核心玩法

方向 B · **把"选选题"变成"编辑来电热线"**：
- 玩家不是选选题的主编，而是**接热线的值班编辑**
- 市民来电报告异常 → 你翻资料库判断"这是真异象还是胡说八道"
- 判断结果决定上不上刊 → 上了 → 世界变化 → 新来电
- 核心循环 = HSH 的"接电话→翻百科→给答案"，但你的判断有**后果**

**评分**：创意差异化 7/10（"新闻影响世界"确实新鲜），但核心循环成熟度 4/10（还没具象化到"每 30 秒做什么"）。

### 立项评估报告

**项目概况**

| 项 | 值 |
|---|---|
| 暂定名 | World Mysteries Weekly |
| 一句话 | 桌面操作员模拟 × 报刊编辑 × 你的报道改变城市 |
| 核心 Fantasy | "我是一个诡异周刊的主编，我的报道正在改变这座城市" |
| 目标受众 | Papers Please / Her Story / Obra Dinn 玩家（PC 独立叙事解谜爱好者） |
| 目标平台 | PC（Steam） |
| 预期时长 | 3-5 小时 |
| 定价策略 | $12-15 买断 |

**可行性评分**

| 维度 | 评分 | 关键风险 |
|------|------|---------|
| 创意差异化 | 7/10 | "新闻影响世界"是新视角，但需验证循环 |
| 市场验证 | 7/10 | 品类已被 2 款 89%+ 好评验证，容量还在 |
| 技术可行性 | 9/10 | 纯 UI + 文本 + 音频，无技术难点 |
| 成本控制 | 8/10 | 1 人 6-12 个月可完成 MVP |
| 商业化路径 | 7/10 | $12 买断 × 20K 份 = $144K（合理独立游戏目标） |
| 团队匹配 | 7/10 | 需要：文案能力 + UI 设计 + 少量配音 |
| **综合评定** | **7.5/10** | |

**风险清单**

| # | 类型 | 描述 | 严重度 | 应对 |
|---|------|------|--------|------|
| 1 | 设计风险 | 核心循环未具象化到 30 秒级 | 🔴 | 2 周内出 paper prototype 验证 |
| 2 | 设计风险 | 反馈周期可能过长 | 🟡 | 采用方向 A 压缩到分钟级 |
| 3 | 内容风险 | "世界反应"内容量大（每条报道→多种后果） | 🟡 | 控制分支≤3 条/报道 |
| 4 | 市场风险 | 品类小众 + 需要文字阅读 | 🟢 | 同品类已验证 $1M+ 天花板够用 |

**里程碑建议**

| 阶段 | 目标 | 周期 | 可验证产出 |
|------|------|------|-----------|
| Paper Prototype | 验证核心循环是否有趣 | 2 周 | 让 3 个朋友玩 20 分钟，记录他们是否觉得"再来一天" |
| Vertical Slice | 1 个完整"游戏日"可玩 | 6-8 周 | 5 通来电 + 资料库 + 1 次发刊 + 即时反馈 |
| Alpha | 5 天流程完整 | 4 月 | 完整递进（日常→异常→高潮） |
| Release | 打磨 + QA + 配音 + 发行准备 | 6-8 月 | Steam 页面 + 宣传片 + 试玩 Demo |

**制作人最终判定**

### 🟡 CONDITIONAL（条件通过）

**条件**：在 2 周内完成 paper prototype，验证"30 秒核心循环"确实有趣。

如果 paper prototype 验证通过（朋友玩 20 分钟后说"我想继续玩下一天"）→ 升级为 🟢 GREENLIT。

如果验证失败（朋友 5 分钟后觉得无聊）→ 必须 Pivot 核心循环（考虑方向 B "编辑来电热线"）。
