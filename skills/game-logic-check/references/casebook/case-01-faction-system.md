# Case 01 · 势力系统逻辑审查

> **场景**：独立叙事游戏《世界未解之谜周刊》的势力好感度系统提交审查。
> **演示重点**：四把刀逐条扫描 + 结构化报告输出。

---

## 提交审查的规则文档

```
势力系统 v0.1 规则清单

R001: 报道含"蓝光"标签 → 科学会好感度 -1
R002: 报道含"蓝光"标签 → 读者关注度 +2
R003: 连续 3 期报道蓝光 → 读者觉得炒冷饭 → 关注度 -3
R004: 科学会好感度 < -5 → 触发"禁令事件"
R005: 禁令事件：禁止报道蓝光话题
R006: 禁令期间报道蓝光 → 触发"搜查编辑部"
R007: 市政府好感度 > 3 → 解锁"内部消息"选题来源
R008: 黑手党好感度 < -3 → 每期有 20% 概率遭遇"威胁事件"
R009: 报道含"腐败"标签 → 市政府好感度 -2，读者关注度 +3
R010: 每期结束时所有势力好感度自动向 0 衰减 1 点
```

```yaml
## 逻辑验证报告

### 概览

### 问题清单
```

| ID | 严重度 | 维度 | 位置 | 描述 | 影响 | 修复方向 |
|----|--------|------|------|------|------|---------|
| LOGIC-001 | 🔴 FATAL | boundary | R004 | `< -5` 还是 `<= -5`？未明确。如果是 `<`，好感度恰好 = -5 时永远不触发禁令 | 边界行为不确定，策划意图与实现可能不符 | 明确为 `<= -5` 并在文档中注明 |
| LOGIC-002 | 🔴 FATAL | exploit + cross_system | R010 + R004 | 每期自动衰减 +1（向 0 靠拢）。如果科学会从 -6 衰减到 -5 → 禁令是否自动解除？R005 没有解除条件。**如果禁令永久但好感度在回升 → 矛盾**：好感度已不满足触发条件但惩罚仍在 | 玩家被永久锁死"禁令"状态即使关系已修复 → 卡死 | 禁令需要解除条件（如"好感度回升到 -3 以上"或"持续 3 期后自动解除"） |
| LOGIC-003 | 🟡 ERROR | causal_closure | R006 | "搜查编辑部"触发后结果是什么？扣资源？暂停 1 期？Game Over？**孤立动作：有触发无结果** | 程序不知道搜查事件做什么 → 事件触发后什么都不发生 | 补全搜查事件的具体后果 |
| LOGIC-004 | 🟡 ERROR | causal_closure | R003 | "连续 3 期"的定义模糊：必须连续 3 期还是最近 5 期中有 3 期？跨存档/跨 run 是否重置？ | 不同解读下触发频率天差地别 | 明确定义："最近 N 期中有 M 期含蓝光标签"，并声明 run 重置行为 |
| LOGIC-005 | 🟡 ERROR | cross_system | R002 + R003 | R002 说报蓝光 → 关注度 +2。R003 说连续 3 期报蓝光 → 关注度 -3。**净效果**：第 3 期报蓝光时关注度 +2 -3 = -1。计算顺序是什么？先加后减？还是看最终结果？如果关注度已经很低，R003 的 -3 会不会让它变负数？ | 执行顺序未定义 → 结果不确定 | 明确规则优先级（先基础效果后惩罚），并设关注度下限 `max(0, value)` |
| LOGIC-006 | 🟢 WARNING | mda | R005 | 禁令"禁止报道蓝光"= 直接剥夺玩家选择权。如果游戏核心体验声称"玩家自由选择报道方向"→ 禁令与自由选择 MDA 矛盾 | 玩家可能觉得"被惩罚了不能玩某个内容"→ 挫败感 | 改为"可以报但代价极高"（如搜查事件更频繁）而非"完全禁止" |
| LOGIC-007 | 🟢 WARNING | boundary | R008 | 黑手党"20% 概率遭遇威胁" → 如果玩家运气极差连续 5 期都遇到？如果运气极好 20 期都没遇到？无保底也无上限 | 体验方差过大，部分玩家觉得"被针对"另一部分觉得"黑手党形同虚设" | 加入伪随机保底（连续 3 期没触发 → 第 4 期必触发；连续 2 期触发 → 第 3 期必不触发） |

### 规则依赖图

```
            └→ R006 (违反禁令→搜查) → ???（无后果定义）

  └→ R007 解锁条件(市政府>3) → 如果报腐败太多→永远解锁不了内部消息？
```

## 审查结论

**2 个 FATAL 级问题必须修复后才能进入开发**：
1. 禁令解除条件缺失（最严重：可能导致卡死）
2. 边界值 `<` vs `<=` 未明确（影响核心触发逻辑）

**建议处理顺序**：LOGIC-002 → LOGIC-001 → LOGIC-003 → LOGIC-004 → LOGIC-005 → LOGIC-006 → LOGIC-007
