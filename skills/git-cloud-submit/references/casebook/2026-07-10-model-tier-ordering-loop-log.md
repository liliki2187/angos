# Loop Log：GPT-5.6 型号层级误判

结论：父级在未核对官方资料时，凭名称直觉把 Luna 当成高能力模型、把 Sol 当成低成本模型；原路由设计已停止并按 `Sol > Terra > Luna` 重做。

影响：如果错误映射进入固定工作流，会把机械盘点交给最高成本模型，并把历史、安全和真源裁决交给最低能力模型，形成持续性的成本与放行风险。

下一步：模型路由落盘前必须先冻结“型号能力顺序、reasoning effort、运行时是否真的能切换”三项事实；任一未核实就只能写条件式方案，不能写成已可自动执行。

- **触发来源**：用户反馈。
- **原始问题**：用户指出“到底是 Sol 最高还是 Luna 最高”，并展示了父级把两者写反的文本。
- **失败归因**：证据与 agent 路由误判；先设计后核实，把命名联想当成产品事实。
- **复发判定**：新错误；未命中 `ai-collaboration-guidance.md` §7.0 的 F1—F5。当前仅一例，不新增错误家族。
- **本轮处理**：暂停工作流落地；用 OpenAI 官方资料确认 Sol 为旗舰最强、Terra 为中档、Luna 为最快且成本最低；检查仓库 A173 既有试运行；重写模型矩阵。
- **复发保护**：每次新增或修订模型路由，开工先核对官方当前资料与项目既有采纳记录；交付前反向检查“最高能力任务是否指向 Sol、机械任务是否指向 Luna”；无法验证运行时模型绑定时显式回退，不声称自动切换。
- **沉淀判断**：写入本技能 casebook，并把防线落到 SKILL 的路由前置条件；不升级为全项目新错误家族或 hard gate，后续若同类再现再按二次复发律升级。

## 前向验证修订

2026-07-10 使用冻结审计摘要做独立前向测试时，测试 agent 仅凭“391 个未跟踪文件、188.08 MiB 二进制、无 LFS、跨 6 个顶层目录”就建议 `Terra -> Sol`。这与“数量本身不触发 Sol”冲突，说明初版升级条件仍可被过度解释。
