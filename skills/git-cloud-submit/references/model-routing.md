# GPT-5.6 提交任务模型路由

## 已核实映射

- **Sol**：旗舰、能力最强，成本最高。
- **Terra**：能力与成本平衡，作为提交任务默认协调模型。
- **Luna**：最快、最省成本，用于确定性、低判断负担的工作。

官方能力与成本定位参考：[OpenAI Help Center：A preview of GPT-5.6 Sol, Terra, and Luna](https://help.openai.com/en/articles/20001325-a-preview-of-gpt-56-sol-terra-and-luna)。型号信息具有时效性；以后若官方定位变化，先更新本映射再改路由。

项目内已有 A173 的受控试运行支持同一原则：固定采集使用 Luna，归纳使用 Terra，Sol 只处理重大节点。提交工作流复用这个分层，不把“文件数量多”本身当作升级理由。

## 路由矩阵

| 子任务 | Luna / low | Terra / medium | Sol / medium | Sol / high 或 xhigh |
| --- | --- | --- | --- | --- |
| `git status`、文件数、体积、扩展名、LFS 规则、分支 / 上游盘点 | 默认 | 可回退执行 | 不使用 | 不使用 |
| 疑似密钥文件名、超大文件、冲突状态的规则化标记 | 默认，只标记不裁决 | 复核 | 安全事件升级后裁决 | 历史泄密且处置复杂时按需 |
| 阅读 diff、识别主题、划分 commit | 不使用 | 默认 | 多真源冲突时升级 | 跨系统且存在不可逆取舍时按需 |
| 生成 include / exclude、验证命令、commit message | 不使用 | 默认 | 仅复核高风险批次 | 通常不使用 |
| 精确暂存、staged diff 复核、测试、普通 commit | 不使用 | 默认 | 不直接执行 | 不直接执行 |
| 普通非 force push | 不使用 | 在明确授权后执行 | 不直接执行 | 不直接执行 |
| LFS 新增 / 迁移 | 只盘点 | 提方案 | 默认裁决 | 涉及历史迁移与多协作者时按需 |
| merge / rebase 冲突 | 只盘点 | 简单局部冲突 | 跨主题或真源冲突默认裁决 | 历史复杂、证据相互矛盾时按需 |
| amend、rebase、force push、历史清理 | 不使用 | 收集事实并停下 | 默认裁决 | 大规模历史手术时按需 |
| 第三方资源许可 / 是否可公开上传 | 只列路径 | 收集来源证据 | 默认裁决 | 多许可证冲突或法律风险高时按需；仍需用户决定 |

## Sol 升级不应被滥用

以下情况继续使用 Terra：

- 文件多但都属于同一明确任务；
- 图片多但没有单文件阈值、许可或 LFS 问题；
- commit 数量多但每批边界清晰；
- 只是运行既定测试或修正文案；
- 用户已给出精确 include / exclude 清单。
- 审计仅出现 `MANY_UNTRACKED`、`BINARY_WITHOUT_LFS`、`MIXED_TOP_LEVEL`、`DELETIONS` 或 `PRIMARY_BRANCH`；这些是 Terra 复核条件，不是 Sol 自动升级条件。

Sol 升级必须引用 Terra 已确认的具体冲突或不可逆取舍，不能只引用文件数量、总字节数、顶层目录数或脚本 `review` 标记。

以下情况立即停下，而不是仅靠升级模型继续：

- 缺少 push、force push、历史改写或删除授权；
- 需要联系第三方确认许可证或资源所有权；
- 远端策略、保护分支或组织权限不明；
- 敏感信息疑似已公开，需要用户 / 安全负责人决定处置。

## Reasoning effort

- Luna 默认 `low`。
- Terra 默认 `medium`；复杂 diff 可升 `high`，但不因此切到 Sol。
- Sol 默认从 `medium` 开始；同时命中两类以上高风险条件、复杂历史或跨真源冲突时再升 `high`。
- `xhigh` 只用于已证明 medium / high 无法稳定裁决的少数复杂问题，或用户明确要求的对照验证。

模型家族和 reasoning effort 是两个维度。不要把“Sol”与“high”绑定，也不要把“Luna”误写成最高能力模型。

## 运行时真实性

固定工作流定义的是路由政策，不自动证明当前 Codex 客户端能在同一任务中切换模型。

1. 运行时提供显式模型绑定接口时，按矩阵分派。
2. 只提供通用 subagent 时，不在 prompt 中假装它是 Luna / Terra / Sol。
3. 无模型切换能力时，让 Terra 执行全链路；Luna 阶段由脚本压低判断自由度，Sol gate 则暂停并请求用户切换。
4. 回执必须写明“实际使用模型”与“政策建议模型”，两者不得混写。
