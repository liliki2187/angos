# 2026-07-09 WMW 左卡六轮拉锯：一个不难的问题为什么烧了六轮

## 场景

WMW `left_region_card` 资产化：生图候选 B 通过几何比例 gate 后，进入地区照片替换（B1）。此后连续多轮出现视觉缺陷：B1 双地球 / 红三角双层 / 照片越界 → B1.1 右缘残带 → B1.2 残带被擦成透明洞（gate 全过）→ B1.3 洞被填成程序色带 → B2 矩形照片贴不规则窗口再露旧图。每轮均由用户肉眼首先发现缺陷。最终解法（用户提出结构、AI 打样验证）：矩形照片垫底 + 镂空框体盖顶 + 运行时文字的三层 z 序结构 + 一类一母版派生，问题一轮收口。

## 调用

- 执行方为另一 AI（多轮补丁）；父级 AI 负责评审、对白、打样；UX 老哥曾在 B 轮复审。
- 用户触发复盘："整个 UI 资产链和 UX 老哥 agent 是否有不完善的地方，为什么运转起来没有解决这个并不难的问题"。

## 判断

五层失效叠加（详见 `docs/design-decisions/process-and-research-decisions.md` A171）：

1. 生图被要求做它做不到的精确几何，差异全部留给下游像素手术；
2. 假设冒充事实：传闻几何值（"18px 残带到 x408"，实测 x366）、单帧调参的判定式部署到四帧偏差 101px、gate 容差 ≤2px 无依据；
3. gate 只量几何 / 统计，色带和透明洞都是 gate 满分废品；每个新缺陷类型都靠用户眼睛先抓到；
4. 五轮补丁每轮流程合规，没有任何机制强制"换思路"；
5. UX 老哥 B 轮已诊断出"非 selected 绿边"P1，但结论没有被 gate 或清单消费，悬空五轮。

## 用户反馈（强纠偏原话摘录）

- "很明显右侧的边框处被图片隔断了，且图片下方能看到遮盖的另一部分图片……为什么那个 ai 会犯这种问题"
- "ai 似乎又在小修小补，只是在右边额外加了一条"
- "美术生成了一张我满意的界面风格稿，但每次到落地的时候，有一些裁切、尺寸等乱七八糟的问题"
- 结构裁决（被采纳为 A168）："生成一张标准长方形的图片，不在左上角弧形裁切，单纯把绿色框体盖在上面"

## 可迁移规则

- **UX 侧**：复诊必须先核对上轮 P0/P1（回归清单前置）；程序合成资产按"资产生产完整性检查项"扫重复元素 / 接缝 / 叠化 / 透明洞 / 状态色独占（本 SKILL.md 已固化）。
- **父级侧**：UX 每条 P0/P1 在下轮 manifest 记录消费方式（进 gate / 进清单 / 接受风险）；同类缺陷两轮不过触发止损（harness §6.2）；brief 区分已实测事实与待验证假设（harness §6.3）。
- **产线侧**：含图片槽资产默认分层 z 序 + 一类一母版（产线文档 §5.3）；新 gate 组见 gates 文档 §5.1。

## 不升级原因

无——本案例已全量升级：五条制度落盘（A171），结构决策落盘（A168/A169），gate 组与目检清单进 gates 真源。本文件仅作案例追溯入口。
