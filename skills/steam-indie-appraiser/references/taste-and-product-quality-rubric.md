# SIA 品质感与产品品位判断尺

本文用于让 SIA 在功能 ROI 之外判断一个设计是否有独立游戏的品质感、诚意、吸引力和可借鉴价值。它不是美术审美表，也不替代 UX 诊断；它回答“这个建议为什么值得做、为什么显得高级、为什么适合 Angus”。

## 使用时机

读取本文：

- 用户问“这个设计有没有品质感 / 诚意 / 小爆款感”；
- SIA 准备把外部游戏经验转成 Angus 建议；
- 新功能看似有趣，但不确定是否值得进入 MVP / 垂直切片；
- SIA 与 UX 老哥或 UI Designer 协作前，需要先说明产品意图。

不要默认读取本文来评价所有普通文案或单个 UI 细节。

## 五个品位问题

每次只回答最相关的 3-5 个问题，不要机械全列。

1. **职业动作是否成立**：它是否让玩家更像主编、编辑、调查协调者、解释权操作者？
2. **世界是否记住玩家**：玩家的行为是否被物件、角色、读者、势力或版面记住？
3. **反馈是否具体**：反馈是否落在画面、声音、物件状态、版面变化、来信语气或规则后果上，而不是只写一句结算文案？
4. **不确定性是否被尊重**：它是否允许玩家先提出解释，再通过后续线索被确认、动摇或反噬？
5. **成本是否克制**：它是否能用轻状态、轻表现、内容分支或已有动作验证，而不是立刻扩成大系统？
6. **截图 / 复盘是否自然出现**：玩家能否用一句话复述“我做了 X，游戏居然 Y”？
7. **是否属于 Angus 自己**：它是否强化“办周刊并决定解释权”，而不是把 Angus 拉成普通探案、视觉小说、经营或卡牌？

## 品质感高分信号

- 一个小动作带来正式感：拖入、盖章、封存、上头版、撤稿、拨号、接线、剪贴。
- 一个普通物件承载状态：信箱、电话、剪报墙、退稿箱、印刷机、版面边角。
- 玩家行为被后续引用：标题词、发刊立场、压稿选择、错误解释、失败线索。
- 系统不急着判对错：先允许暂时解释，再通过后续信息锚定或修正。
- 失败变成素材：失败不是空扣数值，而是可歪写、可遮掩、可被读者误读的内容。
- 新鲜感来自职业动作，不是来自额外 UI、长设定或高成本演出。

## 低品位警报

- 只说“更有氛围”“更丰富”“更像某游戏”，但没有玩家动作。
- 只把案例表层题材搬过来，例如学 `Papers, Please` 的官僚题材，而不是学正式动作的重量。
- 把小反馈扩成完整系统，例如一条读者来信扩成读者生态模拟。
- 案例需要大量动画、AI、内容池或状态追踪，却只换来一条轻微反馈。
- 让 UI 多一个面板，但没有增加发刊立场、职业幻想或复盘故事。
- 为了“真实”增加重复劳动，让玩家每天机械操作同一套工具。

## Angus 迁移评分

| 评分 | 含义 | 处理 |
| --- | --- | --- |
| 5 | 直接强化周刊职业动作，低成本、高感知、可进入前 10 分钟 | 立即做或优先原型验证 |
| 4 | 方向很适合，但需要一点内容或 UI 支持 | 垂直切片验证 |
| 3 | 有启发，但需要改写成 Angus 自己的动作 | 先做纸面方案或低保真验证 |
| 2 | 有趣但偏离主循环、成本偏高或阶段太早 | 后续观察 |
| 1 | 只剩题材相似或氛围相似 | 不采纳 |

评分时必须写一句“为什么不是更高分”。这能防止 SIA 因为喜欢某个样本而过度推荐。

## 和 UX / UI 子 agent 的交接

SIA 输出给 UX 老哥或 UI Designer 时，只交接产品意图，不代替他们做布局：

- 这个设计要制造的玩家感受是什么；
- 它必须保留的职业动作是什么；
- 哪个反馈必须被玩家第一眼看见；
- 哪些部分可以被 UX / UI 压缩、合并或降噪；
- 哪些地方不能为了漂亮而损伤产品意图。

如果 SIA 的产品建议会显著增加操作负担、信息层级或屏幕元素，必须明确标记“需要 UX 老哥复核”。
