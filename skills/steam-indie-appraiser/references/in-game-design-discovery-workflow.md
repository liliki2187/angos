# 游戏内小设计发掘工作流

本工作流用于研究其它游戏中真正发生在游玩里的小设计：有输入、有反馈、有表现、有后果或有传播价值的系统细节、互动彩蛋、隐藏功能和微型惊喜。目标不是“收集好玩的网页介绍”，而是为 Angus 找到可以低成本验证的游戏内设计种子。

## 适用场景

当用户要求下列任一内容时读取本文：

- “找一些游戏内有趣小设计 / 小系统 / 小彩蛋”；
- “不要只看商店页，想办法挖真实游玩内容”；
- “这个功能有没有其它游戏里的小而巧参考”；
- “研究玩家会截图、会转发、会记住的互动瞬间”。

本文不替代 `product-diagnosis-modes.md`。做产品取舍时仍按功能 ROI 和垂直切片目标收束。

## 采样边界

优先采样：

- 玩家主动输入触发的互动：点击、拖拽、组合、等待、重复、错误操作、反常路线；
- 有表现反馈的小系统：音画变化、UI 反应、物件状态、环境变化、角色回应、数值或规则分支；
- 有后续记忆的小点：持久状态、隐藏成就、后续台词、世界回响、路线变化、玩家复盘；
- 能转译为 Angus 的职业动作：调查、采访、核验、剪辑、组稿、排版、发刊、读者反馈、势力反应。

默认剔除：

- 纯文本段子、剧情菜单、百科条目、单次静态彩蛋；
- 只靠设定好玩、没有玩家动作的“背景故事”；
- 只在商店页或媒体文章里被描述、没有实机证据的功能；
- 成本明显高于收益的大系统，除非能拆成一个小型验证动作。

## 证据等级

引用案例时必须标注证据等级：

| 等级 | 证据 | 用法 |
| --- | --- | --- |
| A | 直接游玩、录屏或可复现步骤 | 可作为正式案例 |
| B | 带时间戳的实机长视频、直播切片或无剪辑流程 | 可作为正式案例，但标注未亲测 |
| C | 攻略 / Wiki / 成就说明 + 至少一个实机截图或视频佐证 | 可作为条件案例 |
| D | 玩家评论、论坛讨论、短视频口述、媒体二手描述 | 只能作为待验证线索 |
| E | Steam 商店页、宣传文案、短描述、标签 | 只能作为找样本入口，不能当案例 |

没有 A-C 证据时，不要写“这个游戏做了某机制”。只能写“有待验证线索显示可能存在某机制”。

## 发掘路径

按由浅到深的顺序推进，不要停在第一层。

1. **网页线索只做候选池**：从 Steam 截图、预告片、短描述、评测标题里找可能的互动词，例如 `stamp`、`broadcast`、`inspect`、`combine`、`secret`、`reacts`、`hidden`。
2. **找真实游玩切片**：优先检索或观看 `gameplay no commentary`、`longplay`、`first 30 minutes`、`all endings`、`secrets`、`hidden mechanics`、`achievement guide`、`tips I wish I knew`。
3. **扫玩家语言**：在 Steam 评测、论坛、攻略评论和视频评论里找“我没想到可以”“当我发现”“你居然能”“小细节”“隐藏互动”“失败也会”等表达。
4. **用成就反推互动**：隐藏成就、低完成率成就和奇怪成就名常能暴露非主线行为；必须继续找复现步骤或视频。
5. **看失败和边界**：很多小设计藏在错误输入、等待、重复点击、反复失败、拒绝主路径、返回旧地点、组合无关物件里。
6. **能亲测就亲测**：如果本地已有 demo、网页版或可运行原型，优先直接游玩并记录步骤；不能亲测时必须明确证据限制。

需要最新 Steam 页面、公开视频、评价数、版本状态或攻略内容时，父级 Codex 必须联网验证并保存来源、采集日期和时间戳。

## 观察清单

看实机视频或亲测时，逐项扫：

- **输入反常性**：玩家是否做了非主线、错误、重复、拖延或组合输入？
- **反馈可见性**：反馈是否在画面、音效、动画、UI、状态栏、道具、地图或角色行为中出现？
- **后果持续性**：它是否只闪一下，还是会留下记录、改变后续文本、解锁路线、影响结算？
- **系统连接**：它是否连接主循环，还是只是孤立段子？
- **成本层级**：它需要新系统，还是只需要已有状态、文案、音效、动画或一次分支？
- **传播价值**：玩家能否用一句话复述“我做了 X，游戏居然 Y”？

## 批量研究输出

每批样本结束后输出：

1. **证据概况**：A/B/C/D/E 各多少；D/E 只能列入待验证，不进入结论。
2. **可迁移模式**：本批重复出现的 3-6 种互动结构。
3. **Angus 种子**：每种结构对应一个最小可玩验证，不写大系统愿景。
4. **成本警报**：哪些看起来惊艳但需要大量动画、AI、内容池或状态追踪。
5. **下一批缺口**：下一轮应该补哪些类型、哪些游戏、哪些实机证据。

## 批次硬门槛

正式输出“可迁移结论”前必须满足：

- 每批至少列出 10 个候选游戏或 20 个候选时刻；
- 每批至少沉淀 6 个 A-C 级案例；
- 每批至少覆盖 3 类样本，例如媒体 / 编辑、调查 / 证据、工作台物件、公众回响、边界输入、状态显化；
- D/E 级只能进入待验证线索，不能支撑结论；
- 如果不足 6 个 A-C 案例，只输出候选清单和下一步验证计划。

## 能力压缩流程

多轮采样后按以下路径沉淀，防止 SIA 越学越臃肿：

1. **单个案例**：进入样本库或 casebook，只记录触发链和可迁移点。
2. **重复结构**：同类经验至少出现 3 次，再提炼为模式卡。
3. **模式卡**：进入 `patterns.md`，用于日常诊断；每次最多主动激活 1-3 张。
4. **核心规则**：只有影响所有任务的判断姿态或协作方式，才进入 `SKILL.md`。
5. **淘汰 / 降级**：只剩题材相似、成本过高、证据过弱或让决策更犹豫的内容，留在样本库，不进入模式卡。

样本用于训练眼光，模式用于诊断问题；不得在一次具体建议中展示全部知识。

## Angus 转译门槛

把外部案例转成 Angus 建议前，必须回答：

1. 它能否让玩家更像“周刊主编 / 编辑 / 解释权操作者”？
2. 它能否发生在首个可玩区域或前 10 分钟内？
3. 它能否进入 `调查 -> 核验 -> 解释 -> 组稿 -> 发刊 -> 回响` 中至少一环？
4. 它是否能形成截图、短视频或玩家复盘句？
5. 它是否能用现有原型动作先验证，而不是先建完整新系统？

少于 3 个“是”时，只能作为远期灵感；不要建议进入当前垂直切片。

## Angus 常见转译方向

- **稿件物件反馈**：拖动、撤稿、重排、强行刊发时，稿件卡、版面或印刷层出现可见反应。
- **核验工具小彩蛋**：对明显不该核验的对象使用工具时，给出短反馈或隐藏记录，但不打断主流程。
- **标题 / 版面反噬**：玩家用极端标题、矛盾解释或违规版面时，读者/势力/现实回响出现可见偏移。
- **编辑部日常物件**：电话、信箱、便签、剪报墙、印刷机、广告位对玩家行动做轻状态回应。
- **失败可玩化**：失败不只是扣数值，而是变成可刊登角度、读者来信、线人失联或势力塞稿。
- **重复行为回应**：反复追问、反复退稿、反复改标题时，系统给出逐步变化的表现或记录。

这些方向都必须先做“小而可见”的验证，不要一次扩成完整生活模拟或隐藏路线系统。
