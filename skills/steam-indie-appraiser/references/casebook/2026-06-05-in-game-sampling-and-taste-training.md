# 2026-06-05 · 游戏内小设计采样与 SIA 品位训练

## 案例 1：网页线索必须和游戏内证据切开

- **场景**：用户希望 SIA 研究其它游戏里的交互彩蛋、系统小点和让人眼前一亮的设计，不要只看网页介绍。
- **调用**：父级 Codex 按 `steam-indie-appraiser` 技能试跑，SIA 子 agent 做只读 workflow 检查。
- **判断**：Steam 页面、媒体概述和玩家二手口述只能作为候选线索；正式案例至少要有直接游玩、带时间戳实机视频、攻略步骤、成就线索或多源玩家记录支撑。
- **用户反馈**：用户要求继续多跑游戏，用更多案例判断这个 workflow 是否有价值。
- **可迁移规则**：SIA 做竞品借鉴时，先标证据等级，再谈迁移；没有输入、反馈、后果链的样本不能当设计证据。
- **升级说明**：已沉淀到 `in-game-design-discovery-workflow.md` 的证据等级和批次硬门槛。

## 案例 2：样本价值不在“知道更多游戏”，而在提炼模式

- **场景**：多轮试跑覆盖了 `Inscryption`、`DREDGE`、`Papers, Please`、`Return of the Obra Dinn`、`TUNIC`、`ANIMAL WELL`、`The Stanley Parable`、`Not For Broadcast` 等游戏。
- **调用**：父级 Codex 按游戏内设计采样模式总结样本。
- **判断**：散案例应被压缩成模式卡，例如“世界记住玩家”“工具即职业身份”“物件承载不可逆决定”“批量验证防试错”“公开表达带回响”。模式卡比游戏名更适合日常诊断。
- **用户反馈**：用户担心 SIA 越跑越臃肿，决策反而犹豫和掣肘。
- **可迁移规则**：案例进样本库，重复结构进模式卡，核心只保留决策纪律；每次诊断最多激活 1-3 张模式卡。
- **升级说明**：已沉淀到 `patterns.md` 和 `SKILL.md` 的防臃肿纪律。

## 案例 3：SIA 的品位来自判断“为什么高级”，不是判断“哪里有趣”

- **场景**：后续试跑转向 `Pacific Drive`、`Disco Elysium`、`Heaven's Vault`、`Pentiment`、`Blue Prince`、`Lorelei and the Laser Eyes`、`Hypnospace Outlaw`、`Killer Frequency` 等游戏。
- **调用**：父级 Codex 以“世界记住玩家”“职业工具有尊严”为主题做资料级采样。
- **判断**：SIA 需要判断一个小设计为什么显得有诚意：玩家行为是否被记住，职业动作是否具体，反馈是否落到物件和世界，失败是否变成可用内容，不确定解释是否被尊重。
- **用户反馈**：用户明确希望 SIA 日常给出的建议有效、有借鉴价值，能和 UX 老哥等子 agent 合作，提升产品品质感、吸引力和诚意。
- **可迁移规则**：SIA 提建议前要说明产品意图和品质感来源；UX 老哥再检查操作链、信息层级和噪音，父级负责取舍。
- **升级说明**：已沉淀到 `taste-and-product-quality-rubric.md`，并在 `patterns.md` 中保留与 Angus 直接相关的模式卡。

## 案例 4：防臃肿也是能力建设的一部分

- **场景**：用户指出 SIA 如果越学越臃肿，可能导致决策更犹豫、更掣肘。
- **调用**：父级 Codex 按 `skill-creator` 的 progressive disclosure 原则整理技能结构。
- **判断**：SIA 应保持“轻核心 + 可检索 reference + 样本库”的结构；能力增强靠蒸馏，不靠堆规则。
- **用户反馈**：用户要求按此方式整理 SIA 核心规则和几轮跑新游戏经验总结。
- **可迁移规则**：`SKILL.md` 只放身份、读取入口和决策纪律；详细品位尺、模式卡和样本经验进入 references / casebook。
- **升级说明**：本案例作为本轮升级来源；后续如果模式卡继续增长，应先合并同类项，不要无上限新增。
