# 探索与节点派遣

> **状态**：草案
> **作者**：Codex + 仓库综合整理
> **最后更新**：2026-07-17
> **对应支柱**：调查必须导向发刊

## 概览

这个系统覆盖周循环前半段的探索部分：区域可用性、节点选择、员工分配、派遣校验，以及线索输出准备。它的任务，是把有限时间和员工能力转化为可进入内容生产链的素材。

## 玩家幻想

玩家应感受到自己正在指挥一支脆弱但有能力的调查团队，在投入报社本周有限资源之前，先阅读风险、稀缺性和潜在收益。

## 详细设计

### 核心规则

1. 世界按区域组织，每个区域包含常驻、临时或隐藏节点。
2. 区域通过与宏观属性、标记或既有证据相关的显式规则解锁。
3. 普通派遣可选择 1-3 名员工；大关卡 / 黑骰终局等特殊行动最多可扩展到 5 名员工。员工属性定义角色倾向；正式判定使用角色骰面与节点需求属性匹配后生成的“相关骰面有效点”。
4. 只有当玩家剩余天数足够、节点可见、选择了合法人数，并且当前骰池存在达到 `need_target` 的可能时，该节点才可执行。
5. 普通任务成功会生成线索或推进任务；失败可能只产生弱线索、压力效果或关闭一次性机会。黑骰任务另按四档结果处理。
6. 当玩家主动停止，或本周预算已不足以支持有效行动时，探索结束。
7. 本系统只运行在 `weekly-run-loop.explore` 父阶段内；是否切到 `editorial` 由周循环根据 `remaining_days`、玩家输入和 `legal_dispatch_count` 判定。

### 取材地图选择 UI

取材地图是探索阶段的区域选择层，不直接承担区域内派遣，但必须提供与地区任务台同源的全局日程推进入口。当前 HTML 首轮包装使用美国范围地图；玩家先在地图或右侧小卡中选中区域，再通过主按钮进入选中区域，也可以在左下独立日程器中推进到下一天。

- 地图页当前对象主操作仍为“进入选中区域”；全局 `推进到下一天` 固定在左下独立日程器中，视觉权重低于右侧进入 CTA，并与地区列表、地图、右侧 dossier、CTA 的材质、颜色、箭头和命中区分离。
- `推进到下一天` 第一击只进入原位确认态，必须就近预览推进后剩余天数、到期结算、红线 / 截稿窗口变化和任务过期风险；第二次确认才执行。它是独立全局日程命令，不得复用“结束探索”或任务派遣命令冒充。玩法命令尚未接入的运行版本只能显示明确 disabled 状态，不得展示伪可用按钮。
- 进入地区后，本周默认停留在当前地区继续安排。推进到第二天、完成到期结算后，若本周仍有天数，应保留玩家推进前的世界 / 地区选择上下文并刷新任务状态；若天数归零或不再存在合法派遣，再由周循环进入后续阶段。区域页顶部可以返回取材地图，但不得提供直接 `结束探索周 / 进入编辑部` 的跨阶段按钮。`返回区域`、`返回取材地图`、`返回回合简报` 这类层级导航应保持清晰可点面积与一致样式，但视觉重量低于当前页主操作，且不为按钮放大重排页面布局。
- 右侧面板只展示当前选中区域详情，不再平铺所有区域。地图点与右侧区域小卡需要 click 固定选中；hover 只做高亮，不临时切换详情。
- 选中区域详情使用固定信息槽位表达：可见目标、限时机会、线索、深度链；具体任务选择只在进入地区后发生，取材地图只显示少量只读情报预览。地区级“推荐人数”不成立：人数建议只能在具体任务已选定、需求已知后进入任务详情 / 派遣签批，世界地图不得展示固定推荐人数。
- 锁定区域允许选中并预览，但不能进入。面板必须显示进度和缺口，例如宏观属性数值、前置线索或深度链进度，而不是只写公式条件。
- 这一层是按地区选择的 `region-centric` 地图：地区可以有稳定的点击轮廓、入口和选中反馈，但这些地区入口不得被复用为区域内部的任务坐标。

### 区域任务台与派遣签批台

区域任务台只负责“在当前地区选择哪个报道线索值得派人去追”，不直接组队、不显示完整骰池，也不执行消耗天数的派遣。玩家在左侧任务列表或中部区域地图上选中节点后，右侧只显示当前任务详情、风险摘要、链条进度、限时状态和“进入派遣签批”主操作。

- 区域任务台可以显示任务在地图上的位置、任务列表筛选、当前线索 / 连续追踪 / 限时截稿等信息，但这些信息都服务“选哪一个任务”。
- 区域地图是按事件位置组织的 `event-centric` 地图：当前可见节点数量为 `0–N`，每个节点使用事件坐标或地点锚点生成图钉；同一地理分区可以同时存在多个标记，事件不必位于版块中心。禁止把世界地图的“一地区一入口”关系下沉为区域地图的固定五点表。
- 区域任务台不显示候选员工、已选员工槽、完整达标率拆解或“签批外勤”按钮；这些属于派遣签批台。
- 派遣签批台是独立下游界面，包装为编辑桌 / 签批台 / 本次骰池工作台。进入后才显示任务 brief、候选员工、已选槽、需求覆盖、达标率、风险复核和真正消耗天数的主按钮。
- 从派遣签批台返回区域任务台时，保留当前地区和当前任务选中状态，帮助玩家继续比较其它任务；切换到另一个任务时再清空本次已选员工。
- 该三段式结构的目的是避免世界地图选择、区域任务选择和员工派遣在同一屏争夺主语。地图可以承载世界与地区空间感，派遣则承载周刊主编的签批职业幻想。

### 任务类型与首区试玩落地

首轮 HTML 原型验证中，纽约市承担任务类型教学；后续锁定区域也先限定在美国范围内。任务卡与派遣配置页必须同时展示任务类型名称与行为说明，确保玩家在点击前后都能理解差异。

| 入口 / 标识 | 试玩承载 | 行为 |
|------------|----------|------|
| 白色调查 | `皇后区旧机库围栏` | 可反复追踪；失败不封死题材，后续派遣会继续累积同一条调查线。 |
| 红色截稿 / 临时情报 | `突发：哈德逊河上空异常光点` | 一次性情报窗口；成功、失败或超过截止日期后都关闭并从地图消失。 |
| 深度调查连续任务 | `纽约飞碟剪报残页`、`布鲁克林厨房火球`、`M330 末班车 · 乘客口述` 起点 | 每阶段完成后生成下一阶段任务，事件逐层推进，直到最终完结；地图只显示当前最新任务入口，用叠层表现背后有链。 |
| 危险标识 | 普通任务、红色截稿或深度链中的高难节点 | 不是独立任务类型，只表示难度较高、失败后果更重，可能带来 debuff，但不使用黑骰特殊机制。 |
| 黑骰任务 | 深度调查终局，例如 `复现实验前夜`、`三秒空白录音`、`M330 末班车 · 车载录像最后三秒` | 使用黑骰特殊判定机制与四档结果，通常不是普通地图高危任务。 |

首轮不要求全地图普及这些类型；核心目标是让玩家在首个可玩区域明确感知“任务不同，派遣决策也不同”。

### 探索故事内容层

任务包装不只存在于任务标题。当前 HTML 原型为探索阶段增加一层按任务 id 绑定的故事文案，用于让玩家在派遣、判定和结算三个时刻都能感知“我正在追一条具体报道”。

- 派遣配置页在任务头内显示 `调查简报`，包含事件钩子、外勤目标和本次压力。它服务玩家派遣决策，不承担教程说明。
- 骰子判定弹窗显示一条短现场对白，按摇骰、黑骰介入、选择计入阶段切换。后续正式接入重投 / 锁定时，重投对白应复用同一现场对白槽位，靠近刚发生变化的骰子结果，不丢到全局 toast。
- 探索结算页在判定结果前显示 `现场记录`，奖励弹窗中的线索使用任务专属标题和描述；深度链推进奖励优先显示下一环任务的简报钩子。
- 每日推进弹窗保留普通日常文本池，同时以小概率抽取 `探索余波` 文本。探索余波可引用当前执行中的任务、最近获得的线索或当前地区，但不能提前泄露未结算任务结果。
- 这些文本属于首轮内容包装层，不改变判定公式、任务耗时、区域解锁和线索数据结构。

### 深度调查任务链 UI

深度调查任务链必须让玩家感知“这是连续调查”，但地图不再完整摊开整条链。地图层只承担当前行动入口；链条结构通过同一个入口的叠层与展开动效表达。

- 地图上只显示当前最新任务环。完成第 1 环后，地图标识替换为第 2 环；旧环不继续留在地图上占位。
- 默认态是规整对齐的任务页叠层，提示“多个任务合一”；不使用斜散、扑克牌式堆叠。
- 鼠标悬停只做轻量预展开，让几张卡略微错开，不完整暴露下一环信息。
- 点击入口后，同一组叠层卡片平滑展开成线性链，显示当前环与下一条 `?` 线索；未到达的后续环不得提前完整展示。
- 展开、进入和收起必须分离：第一次点击入口只展开链；展开后点击当前环任务直接进入任务界面；再次点击同一入口不负责收起。收起应由点击任务之外的地图空白、切换对象或离开区域完成。
- 未解锁的后续环如果被点击，应在该环附近弹出明确提示（例如 `该任务未解锁`），而不是沉默、收起链条、进入当前任务或把反馈丢到远离地图对象的全局提示区。
- 侧栏任务卡仍展示链条进度、上一环结果、当前环风险和成功后是否解锁下一环。
- 结算弹窗必须明确说明下一环是否出现，以及旧环如何归档为已完成历史。

### 地图标签避让

区域地图上的任务点、线索点与可展开任务入口必须经过碰撞避让，而不是依赖固定数量或固定版块中心。节点先落在真实事件坐标 / 地点锚点；同一点位附近出现多个事件时，深度链、黑骰、高危等高优先级入口优先保留原位，普通任务与线索点做轻微偏移、聚合或展开，标签在不离开区域视觉范围的前提下翻转与让位。验收时应覆盖 `0 / 1 / 多节点 / 同区密集节点`、默认态、hover 态、深度链展开态，以及宽 / 中 / 窄视口，确认图钉与标签不互相压盖。

已派遣任务在地图层需要直接暴露“谁正在占用这个任务”。当前 HTML 落地口径是：地图点右上角显示派遣角色小头像组，而不是只显示微型“派”字；右侧任务列表中，“已派遣”作为任务当前状态放在任务名称右侧，不放进耗时 / 危险 / 对手骰等任务属性标签行。

### 状态与切换

| 状态 | 进入条件 | 退出条件 | 行为 |
|------|---------|---------|------|
| `region_browse` | 进入探索阶段 | 进入选中区域 | 浏览取材地图、选中区域详情与解锁缺口 |
| `node_select` | 已选中区域 | 进入派遣签批台 | 浏览区域地图、任务列表、当前任务详情与可用性 |
| `dispatch_config` | 已选中合法任务 | 组好本次骰池 | 在编辑部派遣签批台选择员工、查看需求覆盖与风险 |
| `dispatch_ready` | 存在合法的节点与员工组合 | 按下签批执行 | 展示概率、任务摘要与执行按钮 |
| `dispatch_resolved` | 事件检定返回结果 | 玩家选择下一步 | 应用线索与状态变化 |

### 与其他系统的交互

- **周循环与状态** 提供 `explore` 父阶段、`remaining_days`、`active_tasks`、`opportunity_ids`、当前周与宏观快照。
- **事件检定结算** 消耗本次选择的员工骰池，根据节点需求属性计入相关骰面有效点，再返回结果层级。
- **宏观属性与现实偏移** 会影响隐藏节点和区域解锁规则。
- **线索与内容素材库存** 会消费本系统产出的线索对象。

## 公式

### 员工属性与相关骰面

```
relevant_faces = staff_faces where face.attr in node.need.keys()
effective_points = sum(rolled_face.points for each rolled face if rolled_face.attr in node.need.keys())
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|------|------|------|------|------|
| `staff_i[attr]` | int | 0-10+ | 员工数据 | 单个员工在某属性上的倾向值，用于理解角色擅长方向 |
| `staff_faces` | array | 6 面 | 员工数据 | 单个员工本次可能掷出的骰面 |
| `node.need.keys()` | array | 1-6 项 | 节点数据 | 本节点哪些属性骰面可计入有效点 |
| `need_target` | int | 1-4 | 节点数据 / 折算值 | 本节点需要达到的有效点目标 |

**预期输出范围**：0 到当前选择员工可贡献的相关骰面点数上限
**边界情况**：未选择任何员工时，派遣无效。

### 派遣风险预览

派遣配置页的整体风险预览用于帮助玩家判断“当前队伍实际掷骰后大概能不能达标”。风险口径必须和结算公式一致，不能只看整套骰面池的潜在覆盖度。当前角色骰首版使用“相关骰面有效点”达标：任务需求属性决定哪些骰面算相关，掷出并计入的相关点数达到 `need_target` 即成功。`need_target` 由需求总量折算，不再用需求属性数量作为硬下限；多属性应该扩大相关骰面范围，而不是天然惩罚成功率。首周红色截稿样例“突发：雷达异常光点”已从旧口径的 `探索5 / 生存3` 下调到 `探索2 / 生存1 / 洞察1`，确保适配 2 到 3 人队从几乎不可能回到可搏区间。风险预览应基于所选角色 / 道具骰的实际达标率给出低 / 中 / 高，并显示有效点目标、潜在相关点和实际达标率。低贡献角色应单独提示为“无相关面 / 占用人数槽 / 贡献低”，让玩家理解这是效率问题，而不是任务本身变得更危险。

### 任务档位难度职责

普通任务是探索系统的最低压力层，不应被调成“满编 3 人才勉强能过”。如果所有任务都要求 3 人满编，玩家就没有派遣取舍、并行安排和资源节奏，只剩下把最强队伍塞进一个任务里赌运气。

- 普通 / 常驻任务：用于让玩家用 1 到 2 名适配角色推进基础素材和尝试不同角色。2 人应是默认舒适编制，3 人应接近稳妥或提效，而不是刚刚可玩。
- 线索追查 / 深度链第 1 环：用于引导题材方向，难度略高于普通任务，但仍应允许 2 人尝试，3 人明显稳。
- 深度链中段：开始要求更强适配、道具或临时资源；2 人可冒险，3 人可搏。
- 红色截稿 / 临时情报：难点来自时限、一次性关闭和失败后果，不应再叠加过低基础成功率；适配 3 人应可搏，使用正确道具应明显变稳。
- 危险 / 高危任务：难点来自后果更重，可以让 2 人冒险、3 人可搏、支援资源拉高胜率。
- 黑骰终局：难点来自黑骰反噬、选择压力和四档结果。基础达标率不能过低到让玩家不愿进入；5 人满编与支援资源应能把“进入终局”变成合理选择。

### 派遣配置 UI

派遣配置页是区域任务台下游的独立“编辑部派遣签批台”。核心感知应是“我正在为这条报道组本次骰池，并签批外勤”，而不是浏览一张角色属性表，也不是继续在地图上选点。

- 顶部任务头部保持紧凑，只展示任务名、任务性质、关键需求与耗时等会影响本次派遣的轻量信息。耗时是执行成本，不单独占用大模块；探索周剩余天数属于全局资源，不放入任务属性组；截止状态属于红色截稿 / 突发任务的特殊约束，只在对应任务上以高权重倒计时块表达，例如 `截稿关闭 / 剩余 3天`，不要同时重复显示“红色截稿”标签和红色说明条。
- 中部以“本次骰池 / 本次队伍牌桌”为主：已选角色占用固定角色槽，并保持完整角色牌表达。普通任务显示 3 个角色槽，大关卡 / 黑骰终局打开 5 个角色槽；UI 容量必须按 5 张已选角色牌 + 1 个本次道具槽验收，不能只按普通 3 人队伍设计。本次队伍牌桌的权威已选区必须同时包含 `已选角色 N/3 或 N/5` 与 `本次道具 0/1`；道具 / 支援不占员工人数限制，但属于本次出发配置，不能掉到候选池或库存区里才显示。下方候选区分为可选角色池与可选道具池：角色候选池默认露出 1 行与上方队伍槽同尺寸的完整候选角色卡，hover / focus 时整区扩展为 2 行同尺寸卡以检索更多角色；不得把候选角色压成小卡、列表行或用单张候选卡放大来替代整区展开。道具候选池默认也必须成区可见，至少露出若干可用道具摘要或空态原因，hover / focus 时展开道具检索 / 更换 / 撤回。首版每次行动最多绑定 1 个道具 / 支援；选中道具后应回写到上方本次道具槽，并从可选道具池移出或降级为已占用状态。
- 候选员工池只显示当前还能加入本次队伍的员工。员工被选入本次队伍后，应从候选池移出；若未来为了排序稳定保留原位置，也只能显示为不可操作占位，不得同时作为候选主卡和已选主卡出现。
- 需求覆盖面板显示有效点目标、潜在相关点、实际达标率、各属性相关点与 hover 预览。风险口径必须使用与结算相同的实际掷骰达标率；各属性条用于解释哪些骰面相关，不再作为单次结算的逐属性硬门槛。若适配 3 人队仍只有 0% 到 20% 左右的达标率，应优先检查任务需求、目标公式、骰面密度或可用支援资源，而不是只把 UI 风险标签改得更诚实。
- 候选角色默认按本任务贡献排序。hover 需要预览“加入后补哪些需求 / 仍缺什么 / 风险如何变化”，click 则即时更新骰池。
- 临时资源区只承担补骰池决策：一次性道具、临时线人等应和角色选择分层展示，避免玩家误以为它们是同一类操作。
- 配置页主操作是“签批外勤 / 开始调查（消耗 X 天）”；全局“下一天”不应在派遣配置页作为浮动按钮出现，避免抢焦点或遮挡候选角色。

### 节点可用性判定

```
dispatch_enabled =
  (remaining_days >= node.days)
  and staff_count in [1, node.max_staff]
  and potential_effective_points >= node.need_target
  and node_visibility == true
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|------|------|------|------|------|
| `remaining_days` | int | 0-7 | 周状态 | 可用时间预算 |
| `staff_count` | int | 0-5 | 选择状态 | 已分配员工数；普通任务 `max_staff = 3`，大关卡 / 黑骰终局可为 `5` |
| `node.need` | dictionary | 1-6 项 | 节点数据 | 决定哪些属性骰面可计入有效点；数值用于折算目标与解释需求强度 |
| `potential_effective_points` | int | 0-员工上限 | 当前选择 | 当前员工队伍理论上能掷出的相关有效点上限 |
| `node.need_target` | int | 1-4 | 节点数据 / 折算值 | 本节点的有效点目标 |
| `node_visibility` | bool | true/false | 解锁逻辑 | 玩家是否能看到该节点 |

## 边界情况

| 场景 | 预期行为 | 理由 |
|------|----------|------|
| 未选择员工 | 节点不可执行 | 防止非法派遣状态 |
| 临时节点已被处理 | 本周内禁用该节点 | 保留时间压力 |
| 运行中途满足隐藏节点解锁条件 | 立即揭示，而不重建整个循环 | 让宏观压力显得是活的 |
| 潜在有效点达不到目标 | 节点仍不可用，UI 必须解释“缺少可计入的相关骰面” | 保持可读性 |

## 依赖

| 系统 | 方向 | 依赖性质 |
|------|------|----------|
| 周循环与状态 | 本系统依赖它 | 读取阶段、天数、标记与周状态 |
| 事件检定结算 | 本系统依赖它 | 使用它结算派遣结果 |
| 线索与内容素材库存 | 它依赖本系统 | 消费线索输出 |
| 宏观属性与现实偏移 | 双向依赖 | 决定区域/节点解锁，也可能被结果修改 |

## 调参旋钮

| 参数 | 当前值 | 安全范围 | 提高后的效果 | 降低后的效果 |
|------|--------|----------|--------------|--------------|
| MVP 区域数 | 2 | 2-4 | 内容更多样，但制作压力更大 | 引导更紧凑 |
| 普通派遣员工上限 | 3 | 2-4 | 组合深度更高 | 更难满足需求 |
| 大关卡 / 黑骰终局员工上限 | 5 | 4-5 | 终局队伍感更强 | 挤压界面容量与周内调度 |
| 节点天数消耗 | 1-3 | 1-4 | 周压力更高 | 单周可派遣次数更多 |
| 节点需求阈值 | 按节点配置 | 低到中 | 需要更强配队 | 更容易进入，张力下降 |

## 视觉 / 音频需求

| 事件 | 视觉反馈 | 音频反馈 | 优先级 |
|------|----------|----------|--------|
| 区域选择 | 明显的选中状态与提示面板刷新 | 轻量 UI 确认音 | 中 |

| 执行派遣 | 任务面板强调与结果揭示 | 强确认与结算提示音 | 高 |

## 验收标准

- [ ] 玩家能使用 1-3 名员工完成一次普通合法派遣，并能在大关卡 / 黑骰终局中使用最多 5 名员工完成一次合法派遣。
- [ ] 所有不可用节点都必须明确说明原因。
- [ ] 探索阶段产出的线索数据可被下游系统消费。
- [ ] 区域解锁规则与隐藏节点可见性会响应宏观状态变化。
- [ ] 线索很少的一周依然合法、依然可发刊。
